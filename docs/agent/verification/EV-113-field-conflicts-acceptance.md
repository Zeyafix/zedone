## Попытки и границы доказательств

- Первые Windows product/UI wrappers остановлены до списка тестов Bun с
  относительным фильтром `tests/<file>`. Локальный launcher повторил исходные
  runners, заменив только этот фильтр абсолютным путём того же файла; состав
  проверок, assertions и таймауты сохранены. Точная причина задержки не
  устанавливалась. Для vue-tsc — локальный Node 26.8.1 override; закреплённый
  baseline 24.22.1 не менялся. Все raw logs/launcher остаются в ignored reports.
- Первый APK runner прошёл все API-сценарии, но ручной Device-checkpoint
  превысил штатные пять минут. Его finally восстановил исходные APK/файлы по
  SHA-256 и очистил свои ключи/правила; это не успешный полный runner.
  После повторной сборки acceptance APK новый полный запуск прошёл, включая
  Device и restoration/cleanup. Таймауты/матрица/правила не ослаблялись.
- При первом Device-проходе один Ref потребовал complete snapshot; штатный
  свежий snapshot и единственный повтор прошли. Часть исходных элементов
  отсутствовала в доступном AX-срезе: использованы координаты после свежего
  `device_screenshot`. Выход без записи закрыл всю карточку; точный cancel/focus
  формы отдельно подтверждён общим desktop/touch runner, а не этим касанием.
- Короткий локальный Device-driver после relaunch сначала увидел штатное
  «Обновляем данные…» и остановился на преждевременной проверке. После готовности
  обычные snapshot/Device UI подтвердили сохранённые названия и пару карточки;
  checkpoint принят только после этого. Все действия driver выполнял тем же
  выданным `agent-device`, UI через adb не использовался.
- Локальная проверка пустых каталогов сначала отказала на диагностике
  отсутствующего каталога в stdout `adb exec-out`; обработано только точное
