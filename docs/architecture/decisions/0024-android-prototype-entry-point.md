# ADR-0024: граница генерируемой точки входа Android

Дата: 2026-10-28.

Статус: техническое решение P01.04 в рамках ADR-0001; прикладной транспорт
и полная пригодность оболочки остаются предметом P01.11/P03.

## Контекст и решение

Спецификация §9 запрещает собственный unsafe в ядре, хранении и синхронизации,
но допускает обоснованную минимальную платформенную границу. Макрос
`tauri::mobile_entry_point` (tauri-macros 2.7.4, Tauri 2.12.5) создаёт bootstrap
с `android_binding!`, который связывает JVM/NDK и Rust. Этот нативный вход
требует JNI/FFI; эквивалентного входа из Android в чисто безопасном Rust нет.
Собственную реализацию JNI вместо поддерживаемого макроса не добавляем.

В `prototypes/src-tauri/src/lib.rs` действует `deny(unsafe_code)`, а исключение
ограничено модулем `entry_point` с макросом и запуском event loop/WebView.
Собственных unsafe-блоков, разыменований указателей или FFI-объявлений нет.
Команда IPC находится вне исключения и вызывает существующую безопасную echo.
В `prototypes/core` сохраняется `forbid(unsafe_code)` для всех платформ.
Хранение/синхронизация сюда не переносятся. Ошибка создания platform runtime
фатальна для запуска: продолжить без него невозможно; это не обработка
ожидаемой ошибки прикладной команды.

Условия корректности: application ID, Kotlin package, имя библиотеки и
генерируемые bindings соответствуют конфигурации Tauri; Rust/Tauri/CLI/NDK
закреплены, вызывающая JVM и жизненный цикл управляются Tauri. Изменение этих
компонентов требует повторной Android-проверки. Исключение не распространяется
на другие модули и не служит разрешением добавлять собственный unsafe.

Проверка: APK для x86_64/arm64 собирается; Android 13 AOSP x86_64 исполняет
реальные команды/отказы и проходит закрытие/повторный запуск. Физический arm64
телефон и итоговая приёмка приложения пока не проверены; [EV-016](../../agent/verification/EV-016-android-ipc.md).

Исходник макроса: [tauri-macros 2.7.4](https://docs.rs/crate/tauri-macros/2.7.4/source/src/mobile.rs).
