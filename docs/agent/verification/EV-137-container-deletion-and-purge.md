- База `5318364`, ветка `feat/p06-09-2-container-deletion`.
  Зависимости [EV-135](EV-135-card-deletion-conflicts.md) и
  [EV-136](EV-136-card-restore-exchange.md).
- Охват P06.09.2.2, P06.09.2.3, P06.09.3 и P06.09.4. Критерии A06, A14,
  A15, A22, A24, S06 и S09. Общий T09 включает оставшиеся сценарии P06.
- Правила, API и источник состояния —
  [ADR-0074](../../architecture/decisions/0074-container-deletion-and-late-purge.md).
- Матрица включает оба решения колонки и пространства, независимые правки
  и новые карточки, старую корзину, атомарный отказ очистки, минимальное
  восстановление и доставку второй поздней правки после частичного восстановления.
- Парный селектор `--container-deletion` запускает одиночное удаление и
  восстановление карточки, решения колонки/пространства и поздний конфликт
  очистки через TLS/CLI на Windows ↔ Android.

## Ход проверки

При первом запуске теста поздних правок обнаружено, что финальная очистка
пространства возвращала `NotFound` и при проверке входящей синхронизации.
Проверка структуры теперь также читает очищенное пространство. Пользовательским
запросам оно доступно только при наличии конфликта. Повтор матрицы по карточке,
колонке и пространству прошёл на Windows с обоими решениями.

Первый парный прогон подтвердил одиночное удаление и восстановление в другую
колонку. На обмене после удаления пространства стенд получил `access_denied`:
выбранное пространство исчезло из каталога. Каталог сохранён для уже выбранных
пространств с существующими правами. Исходный APK, файлы приложения и локальный
debug APK восстановлены по SHA-256.

Браузерный набор `--conflicts` прошёл на Chromium. Новые формы проверены
на ПК и в сенсорном режиме. Проверены отмена, необходимость явного выбора,
оба результата и сохранность текста после перечитывания. Первый запуск
взял прежний бинарник стенда из корневого target, повтор использовал
пересобранный бинарник из того же каталога.

На Android API 33/x86_64 прошли 40 нативных тестов выборки `trash_groups`,
`cleanup`, `deletion_conflicts` и `sync_engine`. Выборка включает повторный
обмен, отказ записи, появление второй поздней карточки после частичного
восстановления и повторное открытие конфликта при разных решениях.

Финальный Windows `cargo test --locked --workspace --all-features` прошёл:
419 обычных проверок, включая 317 тестов хранилища. Строгий Clippy прошёл.
Браузерный набор `--main` прошёл с обычной корзиной, явным восстановлением
в другую колонку, проверками актуальности и атомарного отказа очистки.
Сгенерированные OpenAPI, TypeScript и валидатор совпали с Rust. Отдельный
поиск вернул 1000 из 1000 карточек за 11 618 мс при пороге 30 секунд.

На Device показаны три формы: удаление колонки, удаление пространства и
очистка с поздней правкой. Во всех выбран возврат данных. После перезапуска
Android-приложения видна восстановленная карточка. Для продолжения начатой
проверки использовались необработанные accessibility-узлы: обычный снимок
дерева свернул часть элементов WebView, а восстановленная карточка оказалась
ниже видимой области.

Повтор `--container-deletion` прошёл на Windows Credential Manager ↔ Android
APK/Keystore через TLS, общий Service и CLI. Синхронизация выбранного
пространства продолжилась в корзине и после очистки. Проверены атомарный
отказ прямой очистке карточки спорной группы, минимальное восстановление,
повторная доставка и исчезновение прежних очищенных соседей на обоих
устройствах. Итог стенда `passed/restored=true/cleanup=true`.
Исходные APK, данные приложения и локальный debug APK сверены по SHA-256.
Временные ключи и правила транспорта очищены. Device выключен.

Локальная приёмка P06.09.2–P06.09.4 пройдена. Интеграция и GitHub CI
этой ветки ещё не выполнялись. Полная приёмка T09 остаётся открытой.
