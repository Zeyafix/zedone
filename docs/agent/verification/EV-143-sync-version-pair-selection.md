# EV-143 — выбор пары версий для общей приёмки обмена

Дата: 2026-11-21. Шаг P06.13.2, ветка
`test/p06-13-2-version-compatibility`, база `d80995e`.

## Карточка

- Цель: определить проверяемую пару реальных сборок для GAP-050/A47,
  сохранив действующую политику ADR-0047 и границы доказательств EV-142.
- Зависимости: P06.13.1 интегрирован в `bce6fc4`; аудит и тесты EV-142
  интегрированы в `d80995e` после 26 успешных проверок.
- Исходное дерево: три локальных документа с итогами PR #119 сохранены
  побайтно вместе с локальным состоянием; переключение ветки проверено SHA-256.
- Охват: проверка истории, идентичности продуктовых исходников и имеющейся
  матрицы совместимости; уточнение доказательств и точки продолжения.
  Поддержка новых протоколов, схем или прошлых сборок не вводится.
- Проверки: сравнение Git-объектов выбранных ревизий и конфигураций версий;
  сверка 98 определений/состояний критериев и 36 строк матрицы EV-142;
  сохранность исходных документов, ссылки и `git diff --check`.
- Обратимость/отказы: пользовательские данные, APK, OS-хранилища и сеть
  не изменяются. Неподдержанная пара не объявляется поддержанной.
- Результат: аудит кандидатов завершён; подходящая пара не установлена.
  Разработчик сохранил отсрочку поддержки прошлых версий (LOG-781).
  Новые runtime/CI-проверки не выполнялись.
- Следующий шаг: P06.13.2.1 — приёмка текущего обмена в явно ограниченном
  охвате; межверсионное обязательство сохраняется в POST.01 после основного
  плана. A47 partial/GAP-050 open не превращаются в успешную приёмку.

## Кандидаты и ограничения

| Пара | Что установлено | Граница вывода |
| --- | --- | --- |
| `bce6fc4` ↔ `d80995e` | В product crates добавлены только S07-тест и его регистрация; UI/API/конфигурации сборки прежние. | Различие Git-ревизий само по себе не доказывает совместимость разных реализаций приложения. |
| `fd5e47d` ↔ `d80995e` | В старой ревизии присутствует BUG-010, исправленный P06.13.1; EV-141 подтверждает потерю независимого выбора сохранённых вариантов. | Совпадение protocol 1 / format 1 не позволяет объявить пару совместимой по правилам конфликтов. |

ADR-0047 и DEV.01 откладывают поддержку прошлых версий до реализации
всего плана. ADR-0065 отдельно сохраняет эту границу для обмена.
Текущая конфигурация APK использует номер `0.0.1`; номер приложения
не является признаком совместимости протокола или формата.
Таблица в `docs/development/sync-compatibility.md` не содержит принятой
пары разных выпусков. Создание искусственного protocol 2, исторической
схемы или замена номера приложения не восполняет это доказательство.

GAP-050/A47 и текущие P06.13.2/P06/T09 остаются незавершёнными. Определения
и состояния критериев сохранены; изменена только зависимость текущей приёмки
от отложенного межверсионного обязательства по решению разработчика LOG-781.
Результаты текущей реализации из EV-142 сохраняют свой проверенный охват;
повтор неизменных тестов не даёт недостающего доказательства пары версий.

## Проверки аудита

- Git-объекты `fd5e47d`, `bce6fc4`, `d80995e` прочитаны без переключения
  рабочего дерева. Во всех трёх APK имеет номер `0.0.1`, workspace — `0.0.0`,
  протокол и числовой формат обмена — 1. Список tags origin пуст.
- Полный diff `bce6fc4..d80995e` для crates/UI/API/manifest/lock-файлов
  содержит только `pairing/tests.rs` и `pairing/tests/long_offline.rs`.
  Регистрация находится в тестовом модуле; новой продуктовой реализации нет.
- Все 316 source/contract fingerprints EV-142 совпали. Подтверждённые
  проверки этой реализации сохраняются; новый runtime/Device запуск
  не нужен для документального аудита и не заменяет отсутствующую пару.
- Все 98 определений и состояний критериев сохранены; 36 строк EV-142
  соответствуют закреплённым критериям P06. A26 остаётся `passed`.
- Полный diff и относительные ссылки изменённых документов проверены,
  `git diff --check` прошёл. Новых commit/push/PR/CI нет;
  оптимизация CI на паузе.

Исходное противоречие LOG-780: журнал требовал поддержанную пару до приёмки
P06, а ADR-0047/0065 откладывали её поддержку до реализации всего плана.
Разработчик разрешил его решением LOG-781: сохранить отсрочку, отдельно
проверить текущий обмен и оставить межверсионную гарантию незавершённой.
Остальная приёмка не объявляется завершённой этим решением.

## Принятая граница текущей приёмки — LOG-781

| Часть | Условие приёмки |
| --- | --- |
| Текущая реализация Windows ↔ Android | Protocol 1 / space format 1; данные, история, конфликты, права, выбор пространств, повторы, обрывы, restart и обратные действия по всем применимым частям EV-142. |
| Неизвестный protocol/format | Общий отказ UI/API, сохранность локальных правок и pairing/progress, автоматическое продолжение после устранения причины. Изолированный test peer не считается другим выпуском. |
| Явная пауза | Оба направления остаются приостановленными после restart и восстановления совместимости до отдельного resume. |
| Разные реальные версии | A47 остаётся partial, GAP-050 open; отдельный POST.01 после основного плана. Не входит в условие завершения текущего P06.13.2/P06/T09. |
| Готовность поставки | P09.03 проверяет все 98 критериев и явно указывает отсрочку. Успех текущего обмена не означает полную межверсионную гарантию или разрешение публикации. |

P06.13.2.1 должен сопоставить все 36 строк EV-142 с полными требованиями,
точными ревизиями/fingerprints и доказательствами отдельных платформ/способов
доступа. Результат для каждой обязательной части — проверена и актуальна,
требует конкретного прогона либо отложена по названному решению. Пробелы
текущей реализации не переносятся вместе с A47. Выполняются только недостающие
или утратившие актуальность проверки; независимый дефект получает малый шаг.

POST.01 зависит от P09.03, а P09.03 принимает отчёт текущего охвата с явной
отсрочкой и не зависит от POST.01. Таким образом, P06 → P07 → P08 → P09
не получает обратную зависимость от межверсионной проверки. Состояния
98 критериев и прочие GAP/DEC остаются прежними; новых продуктовых
схем, форматов, сборок и прав этим изменением плана не вводится.

## Пять правил

- Обратимость: новых действий с пользовательскими данными нет;
  исходные локальные записи сохранены.
- Человек и агент: общий Service/API и действующие проверки прав прежние.
- Документация: результат выбора и ограничения записываются в EV/журнал;
  новое поведение пользователя не вводится.
- Паритет: прежние Windows/Android доказательства сохраняют свой охват;
  новая межверсионная матрица не объявляется проверенной.
- Источник истины: реестр критериев остаётся в плане-журнале,
  продуктовый граф и правила допуска не меняются.
