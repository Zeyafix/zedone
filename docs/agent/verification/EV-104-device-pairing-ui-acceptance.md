## Завершение продолжения — LOG-567/568

### Обычная IME и сохранение формы

На актуальном заново собранном x86_64 acceptance APK с instrumentation/manifest
через Device введены peer-address, peer-label с русским текстом и peer-code.
Каждый ввод выполнен при обычной видимой LatinIME. После каждого поля системная
Back скрыла клавиатуру; отдельные assertions подтвердили значение и маршрут
settings. Следующее поле выбиралось по свежему snapshot при скрытой клавиатуре.
Неверный код вызвал ожидаемый invalid_request через общий host; вся форма
сохранилась, session.status остался unconfigured. Все assertions прошли;
`keyboard dismiss` не вызывался, нового отказа Device не было.

Это завершает недостающую обычную IME/Back-ячейку предыдущей попытки вместе
с уже пройденными native формами/обеими сторонами/правами/сроками/ключами/
stale/retry/отказами/обратными действиями. Исходные APK/app files восстановлены
перед отдельным полным парным прогоном, свои fixture OS slots очищены.

### Полный парный APK/API/CLI

Штатный `bun scripts/check-pairing-app.mjs` выполнен с ANDROID_SERIAL и
актуальной возвращённой Device командой AGENT_DEVICE_COMMAND. Вызовы app
open/relaunch/close шли через эту команду. CI-only UI-драйвер не использовался.
Host Windows использовал настоящий Credential Manager; Android — APK/Rust/
Kotlin/Keystore и TLS. Итог exit 0 и отдельный result.json status passed:

- request/replay/no-access, явное confirm/read-only;
- process restart с прежними pin/OS-сессией;
- stale unlink, исходный replay и безопасная terminal cleanup;
- отказ использованному коду, новый запрос/ключ, явная RW-правка и обратная правка;
- revoke, cancel/reject/unlink и их повторы;
- конечный срок, отказ replay после истечения без автоматической отвязки;
- блокировка после пяти отдельных неверных попыток;
- сохранность исходного пространства, fixture OS-key/transport cleanup;
- восстановление исходных APK и всех app files с точной сверкой SHA-256.

Два независимых прогона восстановили одну исходную установку: SHA-256 APK и
полные manifests сверяются также между исходными backup UI/paired runner.
Никаких фоновых проверок не оставлено; Device выключен. Локальные версии,
команды, raw output, backups, manifests и результат находятся только в ignored
reports. Прежние остановки и причина первоначальных fill failures сохранены.

GAP-029 resolved по условию полной актуальной ручной .3.2/.4, а не доказанной
первопричине внешнего драйвера. Наблюдение `scroll`/AX compression из предыдущей
попытки сохраняется; подтверждённая native матрица использовала Device-owned
ввод/касания/жесты. Продуктовых исправлений, изменений dependencies/схемы/
assertions/CI budgets нет; для нового документационного итога не запускался CI.
