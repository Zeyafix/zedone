## Карточка шага

Просмотр синтетического текста существующего echo API, без продуктового редактора
и хранения карточек. Исходный текст проходит общий Rust HTTP/IPC без изменения;
HTML и состояние загрузки изображений — производные данные общего Vue-компонента.
CommonMark с `html: false`, без таблиц и чекбоксов; DOMPurify с HTML-профилем.
Изображения заменяются инертными маркерами до очистки. Только отдельное нажатие
создаёт запрос выбранного HTTP/HTTPS-изображения. Ссылки открываются вне экрана
прототипа; Android использует штатный Tauri Opener с ограниченными полномочиями.
Остальные URI не активируются в этом срезе; продуктовая политика не расширяется.

Проверки: `bun run check`, `bun run check:http` в Chrome/Opera, обе debug-сборки
APK и `bun run check:android` на AOSP API 33. Общий сценарий проверяет базовый
синтаксис, буквальный HTML/XSS, Unicode и неизменность исходника, отсутствие
запросов при разборе/очистке, выбор одного изображения, загрузку/ошибку/повтор,
внешнюю ссылку, сброс просмотра и отказ API без потери ввода.

Обратимость: очистка текста/просмотра, скрытие загруженного изображения,
повтор загрузки после ошибки. Ошибки загрузки и открытия ссылки не меняют текст.
Продуктовые операции/история/конфликты и полная приёмка A50 остаются в P05;
QR и последующие шаги, коммит/публикация/PR/слияние не входят в поручение.

Ориентир 300 строк может быть превышен единым срезом безопасного просмотра,
платформенного открытия ссылок и сквозных проверок; независимых функций нет.

## Результаты

Реализован общий просмотр ответа echo: markdown-it с явным `html: false`,
DOMPurify HTML profile, инертные маркеры изображений и контролируемые Vue-узлы.
Версии закреплены: markdown-it 15.0.3, DOMPurify 3.4.17, Tauri Opener 2.7.2;
основание CommonMark — 0.31.2. У markdown-it используются встроенные типы.
HTML не хранится, исходный текст возвращается Rust без изменения через HTTP/IPC.

| Проверка | Результат |
| --- | --- |
| `bun run check` | Пройдено: fmt, Clippy без предупреждений, 14 Rust-тестов, release, совпадение OpenAPI/TS/IPC, vue-tsc strict под закреплённым Node, Vite/Bun, HTTP/Chromium |
| Chrome и Opera: `bun run check:http` | Пройден полный набор на отдельных временных профилях, без изменения пользовательских профилей |
| Чистая JS-установка | Frozen-установка без node_modules/dist, применение существующего Bun patch, строгие типы и Vite пройдены в отдельном каталоге; bundle совпал с рабочим |
| APK x86_64 и arm64 | Обе debug-сборки пройдены, включая native/Android-часть Opener |
| `bun run check:android` | Пройден полный набор на Android 13/API 33 AOSP x86_64 без GMS; реальный WebView 101 и Rust IPC |
| Визуальная проверка | Снимки ПК и APK просмотрены локально; машинные пути и изображения не включаются в Git |

Общий сценарий проверяет заголовки, выделение, оба вида списков, цитату,
код, title ссылок/изображений, Unicode/составной символ, буквальный HTML с
`script`/`img onerror`/`iframe`, отсутствие выполнения и загрузки. Таблиц,
интерактивных чекбоксов и активности неподдерживаемых URI нет; маркеры сохраняются.
Ссылки и кнопки вложенного Markdown-изображения не создают вложенных интерактивных
элементов. До нажатия нет ни одного запроса изображений, включая HTML-парсинг
и DOMPurify. Отдельное нажатие загружает только выбранный PNG, скрытие удаляет
`img`; при отключённой через CDP сети получен отказ, текст остаётся доступен
для чтения/ввода, после включения сети явный повтор успешен. Смена ответа сбрасывает
разрешение на загрузку, очистка убирает весь просмотр и исходный ввод.

На ПК проверены отдельная вкладка с точным адресом, отсутствие `window.opener`
и неизменный URL страницы прототипа. На Android проверены настоящий ACTION_VIEW,
точный URL и активная отдельная browser activity, затем возврат к тому же
WebView без замены его URL. Native capability отклоняет file/mailto/javascript;
ошибка Android bridge при открытии даёт сообщение и успешный явный повтор.
Автоматический JS-обработчик Opener отключён; полномочия ограничены локальным
окном main и HTTP/HTTPS, удалённым источникам/файлам доступ не выдан.
CSP расширен только для HTTP/HTTPS в `img-src`, `data:` удалён.

Проверки прежних срезов echo/SQLite/доски прошли: API/IPC, неверные аргументы,
тайм-аут/повтор без потери ввода, жесты и обратные команды, реальные SQLite
ошибки/блокировки/потеря ответа, force-stop/перезапуск с сохранностью данных.
Производительность A62 не измеряется. PNG и внешняя вкладка ПК обслуживаются
локальными перехваченными фикстурами; Android открывает зарезервированный
`.invalid`-адрес во внешнем браузере, успешная загрузка внешнего сайта не требуется.

## Исправленные ограничения проверки

Первый Desktop-прогон выявил неоднозначные CSS-селекторы кнопок изображений;
драйвер использует внутренний индекс и первую кнопку (загрузка/повтор).
На Android роль-локаторы и `locator.evaluate` нового Playwright требуют
`checkVisibility`, которого нет в WebView 101. Использованы DOM-чтение/
`page.evaluate` и настоящие CDP touch events, приложение не патчится под тест.
Формат dumpsys различается: активность определяется через реальный системный
HTTP-resolver и строки resumed activity, без предположения имени браузера.
После force-stop CDP socket иногда готов до появления page target; вместо
немедленного assert драйвер ограниченно ожидает цель страницы.
Повторные проверки с исправленным драйвером пройдены.
