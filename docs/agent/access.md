# Работа с доступом

P03.05 предоставляет ограниченные команды `access.inspect` и `access.revoke`
через общий Service HTTP/CLI/IPC. Обе требуют отдельно выданного
администрирования; обычный доступ к пространству не разрешает их. Агент не
получает право вызывать storage или писать SQL напрямую. Все входы применяют
core guard/executor внутри `Storage::timed_transact`, после ожидания worker,
до чтения цели или прежнего результата. Клиент не задаёт Clock, субъект и права.

Контракт и точные поля — производные `api/openapi.json`/`api/schema.d.ts`.
HTTP: POST `/v1/commands/access.inspect` или `/v1/commands/access.revoke`,
JSON-конверт `id`/`operation`/`parameters`, ключ отдельно в Authorization Bearer.
Лимит 64 KiB. `access.inspect` принимает `subject`; `access.revoke` — `subject`
и `expected` из версии актуального просмотра. Subject — 32 lowercase hex,
ID — 16 ненулевых в совокупности случайных байтов, expected — 32 байта.
Просмотр также имеет ID/receipt: для нового состояния нужен новый read-запрос.
Отзыв повторного ID возвращает исходный результат и не отзывает новую выдачу.
Успех определяется JSON `status:ok`, а не HTTP 200.

CLI использует ту же установку и авторизацию:

```text
zedone --database <existing-device.sqlite> --key-file <private-key-file> --operation access.inspect
```

Исходный JSON передаётся на stdin, JSON-ответ приходит на stdout. Код завершения
0 — подтверждённый успех, 1 — ошибка команды, 2 — ошибка вывода. В key-file
находится только одобренный ключ в 64 lowercase hex, необязательный перевод
строки; секрет не передавать в argv. Путь выбирает установку, а не выдаёт права.
CLI не создаёт установку, не выполняет bootstrap и не обходит миграционный gate.
Host сначала завершает защищённый startup с собственными настройками копии.

IPC `zedone_command` принимает `invocation: { operation, request }` и отдельно
`credential`; request — исходная JSON-строка, invocation выведен из Rust.
Сетевой listener, разрешённый origin UI и IPC State задаёт доверенный host.
Ключ доставляется через уже одобренный канал, не через обычный API-bootstrap.
Формы выдачи/подтверждения и подключение устройств остаются P06.

Доступ к пространству точный: Read не разрешает запись, ReadWrite разрешает
чтение и запись только выбранных пространств. Administration выдаётся отдельно,
позволяет управлять устройствами/доступами, не читать данные пространств и не
восстанавливать всю базу. Локальный транспорт и название участника прав не дают.

P04.01.1 поддерживает совмещение отдельно выданного администрирования и точных
прав: `scope.kind = administration_and_spaces`, `scope.spaces` содержит режимы
конкретных пространств. Права на остальные пространства из совмещения
не следуют. Снятие администрирования и снятие доступа к данным независимы;
ключ/срок/отзыв относятся к тому же разрешению субъекта.

Согласованное правило [ADR-0040](../architecture/decisions/0040-space-creation-access.md):
любое действующее разрешение позволяет создавать пространства с RW создателю
без отдельного права создания. P04.01.2 реализует [команды пространств](spaces.md)
через тот же общий вход; storage/SQL не становятся альтернативным способом
работы агента.

Отзыв/замена действуют со следующей сериализованной операции, включая повторы.
При явной новой выдаче используется новый ключ; прежние ключи не оживают.
Субъект и прежние receipts при замене сохраняются. Для передачи последнего
административного доступа сначала выдают другой доступ без ограниченного срока.
Начальную выдачу выполняет только доверенная точка сборки с подтверждением,
однократно; повторный bootstrap не является восстановлением доступа.

Не помещать секреты в текст команды, receipt, логи, документацию, граф или
снимок пространства. Подготовленный ключ сохраняют до выяснения результата
commit, затем используют предусмотренное защищённое хранилище host; pending intentions ключ не содержат.
Восстановление снимка пространства не выдаёт доступ на новой установке;
полный откат базы остаётся отдельной операцией P07.09.

Договор: [ADR-0037](../architecture/decisions/0037-persistent-access.md).
Проверки: [EV-055](verification/EV-055-persistent-access.md).

Часы проверяются перед обработчиком и перед commit. При откате ниже
наблюдённой отметки — unavailable до восстановления корректного времени;
restart отметку не сбрасывает. Не менять часы/SQLite для обхода срока.
Истёкший ключ требует новой явной выдачи. Политика —
[ADR-0038](../architecture/decisions/0038-trusted-access-time.md), адаптеры —
[ADR-0039](../architecture/decisions/0039-command-adapters-and-delivery.md).

Сохранённое намерение привязано к исходному субъекту как к метаданным доставки,
не к доверенному полю команды. При смене учётной записи клиент останавливает
отправку; незавершённое действие не переносится незаметно к другому субъекту.
Замена ключа того же субъекта сохраняет возможность исходного повтора.
