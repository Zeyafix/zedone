# EV-071: единая стартовая схема до завершения плана

Дата: 2026-11-07. Шаг: DEV.01. База: e092e3b (runtime e6bf604).
Ветка: `refactor/single-initial-schema`.

## Рабочая карточка

- Основание: прямое поручение разработчика — поддерживать прошлые версии
  только после реализации всего плана; сейчас свести базу к одной стартовой версии.
- Цель: новый и повторный запуск используют единственную схему v1 со всеми
  текущими возможностями; прежние базы разработки не мигрируют и не сбрасываются.
- Охват: SQL/реестр/валидация прав, связанные тесты и эталон, политика в docs.
  Общая инфраструктура безопасных миграций остаётся, её цепочки — синтетические.
- Превышение ориентира 300 строк обусловлено одной сменой базовой схемы:
  её реестр, исторические тесты и инструкции должны измениться согласованно.
- Проверки: полный Windows product-check, native Android x86_64 product-check,
  release обеих Android ABI, unsafe guard и контракт; отказ старым схемам без
  записи, повторное открытие/обратные действия/receipt и crash/restart матрица.
- UI не меняется; визуальная проверка не требуется. Данные установок не удалять.

## Результат

DEV.01 verified локально в рабочем дереве указанной ветки от e092e3b.
По последующему поручению разработчика разрешены коммит/push/PR, а после
успешных проверок — merge и удаление ветки (LOG-350). CI ещё ожидается.

- Продуктовый реестр содержит только v1 с полным DDL, seed часов и текущим
  validator прав/часов. SQL-файлы access-v2/clock-v3, старые продуктовые
  переходы и validators прав удалены. Проверки доступа не зависят от номера схемы.
- Тесты переходов реальных v1/v2/v3/v4/v5 заменены проверками текущей v1:
  restart сохраняет права/отозванные ключи/графы/причинные версии/receipts,
  повтор не дублирует действие. Два теста прежней семантики v3 и один тест
  продуктовой v1→v2 удалены как утратившие предмет; новые проверки покрывают
  единственную стартовую схему, отсутствие выдуманных прав и отказ прежним базам.
- Синтетическая цепочка v1→v2→v3 остаётся в test-only реестре startup:
  rollback всей цепочки, writer exclusion, ошибки backup/target/commit,
  process-crash/restart, публикация/сверка без повторного перехода и retry passed.
- Прежние схемы разработки 2–6 и исходный layout v1 отклоняются с сохранением
  DB/WAL/journal и без создания backup/сброса, включая Startup с options.
  Новая/текущая база открывается без MigrationOptions.
- Эталон schema-v1.sqlite обновлён только текущими таблицами/seed. Независимое
  сравнение всех строк documents/changes/peers/command_results с базовой ревизией
  подтвердило точное сохранение данных; integrity/FK passed. Тест hash/DDL/restart
  работает на обеих платформах. Формат и эталон space-v1.bin не менялись.

  release-сборка, 7 unsafe guard, Rust/OpenAPI/TS/standalone-validator,

  release обеих ABI, 14 unsafe guard, равенство контракта host/Android,

  штатный native-runner удалил свои временные sandboxes.
- `git diff --check`, ссылки изменённых Markdown и сверка эталона passed.
  Raw logs находятся только в игнорируемой docs/reports/dev-01-*.log.

## Пять правил и ограничения

- Обратные прикладные операции и история сохраняются; restart/replay и
  атомарный откат отказов проверены. Откат схемы/перенос прежних баз не добавлялся.
- Человек и агент используют прежний Service/HTTP/CLI/IPC; контракт не менялся.
- User/agent/development/architecture docs и ADR-0047 обновлены вместе с кодом.
- Windows/нативный Android проверены одинаковой матрицей. UI не менялся;
  повторная UI-приёмка, физический arm64 и release APK не выполнялись.
- SQLite/Automerge и Rust-derived контракт остаются единым источником истины.

T10/M01–M04/M07/M08 и A08 не объявляются полностью пройденными. Доказательства
прежних продуктовых переходов остаются историей соответствующих ревизий;
актуальная миграционная матрица подтверждает только инфраструктуру на синтетике.
Новых BUG/GAP нет. Принятое ограничение: несовместимые базы прошлых сборок
разработки не поддерживаются; их файлы и копии не удалены.
