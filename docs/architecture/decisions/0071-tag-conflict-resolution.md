# ADR-0071: явные решения связей и позднего моста тегов

Дата: 2026-11-18. P06.07.2–.4, продолжение ADR-0012/0070.
Продуктовые правила не меняются.

`card.inspect_tags` возвращает свежую карточку и причинные варианты каждой
связи, включая снятые. `card.resolve_tag` выбирает одно булево значение одной
спорной связи с версиями карточки и тега. Запись принимает любой alias,
поглощает наблюдавшиеся варианты всех aliases и сохраняется вместе с receipt.
Обычная `card.set_tag` не разрешает конфликт. Независимые одинаковые решения
сходятся, разные сохраняют конфликт. Остальные поля и конфликты не изменяются.
Корзина, спорные родители и спорный тег не допускают такого решения.

Automerge может пропустить присваивание уже имеющегося скалярного значения.
Поэтому запись связи удаляет известные значения ключа и записывает выбранное
значение в одной транзакции. Между удалением и записью нет видимого состояния.
Это создаёт причинную операцию и для выбора текущего видимого значения;
независимое противоположное решение сохраняется. Формат bool не меняется.

Историческая компонента позднего моста остаётся раздельной навсегда. Снимок
каждого её тега содержит `name_group`: полный отсортированный набор исходных
ID, включая уже переименованный тег. При отсутствии группы поле опущено.
`tag.resolve_names` принимает целиком набор ID, имён и версий группы. Пустые,
повторные ID, неполный набор, одинаковые Unicode-ключи и занятые вне группы
имена отвергаются до записи. Удаления против назначений и прочие коллизии
вне позднего моста остаются P06.08; команда не обходит их блокировки.

В одной транзакции для каждого тега заменяется только регистр имени. Запись
принудительно оставляет новую причинную операцию, даже если имя сохранено.
Блокировка исходного моста снимается, когда все актуальные имена наблюдали
все создания компоненты и имена однозначны и уникальны. Новое позднее создание
расширяет компоненту и требует нового полного выбора. Разные независимые
решения сохраняют варианты; конфликт любого имени блокирует всю группу.
Последующее обычное переименование остаётся допустимым и сохраняет ID/связи.

UI использует те же Service/HTTP/IPC/CLI, токены и сохранённые намерения.
Устаревшее решение сохраняет ввод, требует перечитывания и нового явного
подтверждения. Повтор receipt подтверждает исходный результат и не отменяет
поздние правки. Производные группы и варианты не хранятся на клиенте или в SQL.
Схема SQLite/документа, зависимости и правила полномочий остаются прежними.

Продолжение P06.08: [ADR-0072](0072-tag-name-and-deletion-collisions.md)
расширяет выбор имён на коллизии переименований/создания и добавляет оба решения
удаления против назначения. Граница первоначального EV-129–131 сохраняется.
