- База: main/1a71b72e5282eed0f626821814e9eb13d44022e3.
- Ветка: feat/p05-06-tags-ui по поручению разработчика.

  те же tag.create/list/read/rename/delete и card.set_tag, что доступны агенту.
- Требования: T08/A20/A30/A32, спецификация, ADR-0012/0046/0052.
- Охват: UI/типизированный адаптер, общие браузерные/native UI-сценарии, docs.
  Ядро, схема хранения, Unicode-политика и синхронизация не меняются.
- Дизайн: существующие Segoe UI/Georgia, цвета canvas #e4e8e6, surface #f2f4f3,
  ink #202d28, accent #315b50 и соответствующая тёмная тема. Слева выровненный
  раскрываемый список тегов пространства, компактные подписи на карточках,
  явные кнопки назначения/снятия. Новые цвета, шрифты и анимация не нужны.
- Обратные действия: назначить/снять, переименовать обратно, отменить форму.
  Удаление без отдельного restore — согласованное исключение ADR-0046;
  подтверждение объясняет снятие со всех карточек и отсутствие восстановления.
- Ошибки: занятое/пустое имя, устаревшие версии, отказ доступа, недоступное
  хранилище намерений, потерянный ответ и точный повтор исходной команды.
- Проверки: vue-tsc, `bun run ui:check` на подготовленных Chrome/Opera,
  общий сценарий тегов на host touch/Android CI; локальные debug APK обеих ABI,
  Android Device/agent-device с проверкой native IPC, IME/Back/перезапуска.
- Результат: реализация и локальная матрица пройдены. Коммит/PR/CI/слияние не выполнены.
- Следующее действие: ревью и интеграция ветки в рамках отдельного поручения.

## Проверенное поведение

`SpacesView.vue` читает tag.list вместе с доской, показывает раскрываемое
управление тегами и выполняет прежние команды через общий клиент. Имя отправляется
буквально, сравнение и сортировка остаются в Rust. Формы переименования/удаления
фиксируют исходные subject/version. Удаление требует отдельного подтверждения.
Одна вычисляемая Map имён на доску используется для подписей всех карточек;
доменный каталог и назначения не сохраняются в localStorage.

`CardEditor.vue` показывает назначения и отдельные кнопки для одного тега.
card.set_tag сохраняет expected/expected_tag/present в прежнем намерении.
Изменение тегов не подменяет версию открытого текстового черновика: во время
редактирования текста назначения недоступны. Старый receipt после повтора
не устанавливается как текущее состояние. Свежая карточка читается отдельно;
расхождение останавливает запись до явного нового решения.

| Область | Результат |
| --- | --- |
| Lifecycle | Создание, назначение нескольких тегов, отдельное снятие и обратное назначение прошли через UI/общий Service |
| Unicode/имена | Все→Всё→Все; занятые имена с иным регистром/краевыми Unicode-пробелами, Straße/STRASSE и пробельное имя отклонены без изменения тегов/назначений |
| Удаление | Отмена не отправляет удаление; подтверждение снимает тег с активной карточки и карточки в корзине; карточки/текст/выполнение/положение/история неизменны |
| Новое создание | То же имя получает другой ID, прежние назначения не возвращаются |
| Актуальность | Конкурирующая правка агента делает исходное переименование/назначение stale; ввод и внешняя правка сохраняются |
| Отказы/доставка | access_denied и невозможность записи намерения не меняют тег; потерянный ответ сохраняет точную команду после reload, позднее снятие агента переживает replay |
| Android | Device/agent-device: создание, русский ввод/IME, Все→Всё, занятое имя, Back, назначение/снятие, отмена/удаление/новое создание, обе темы и restart прошли через native IPC |

## Проверки и ограничения

Финальный `bun run ui:check` с документированным локальным Node override и Chrome/Opera
passed (exit 0). Выполнены vue-tsc, production Vite build, fmt, Clippy -D warnings,
три shell-теста, сборка host/fixture и весь прежний UI lifecycle/editor/moves/
Markdown/replay/failure-набор. Новый `check-ui-tags.mjs` прошёл в обоих браузерах
на desktop и touch 360px/тёмной теме. Проверены отсутствие горизонтального
переполнения и отсутствие непредусмотренных внешних запросов/ошибок страницы.
Типы также отдельно проверены на фактическом локальном Node. База CI прежняя.

Первый полный прогон остановился в новом тесте после ожидаемого отказа:
общая обработка ошибки скрывает доску, а после нового чтения details снова
свёрнут. Сценарий исправлен явным раскрытием после refresh, без DOM-мутаций,
увеличения таймаутов или ослабления assertions. Целевой desktop/touch и затем
финальный полный Chrome/Opera прошли. Продуктового обхода для теста нет.

`bun scripts/build-ui-android.mjs x86_64` и `aarch64` passed на финальном UI:
debug APK обеих ABI и manifest launch/identity/cleartext проверки. Локальные
действия Android выполнялись только через Device/agent-device. На копии
сохранённой базы после закрытия приложения проверены два прежних ID карточек,
их текст/выполнение/положение/состояние/история, удалённый ID тега, новый ID
с прежним именем и отсутствие восстановленных назначений, в том числе в корзине.
После проверки исходные product/WebView восстановлены: имена и SHA-256 всех
23 файлов совпали. Синтетика/ключи/архивы удалены, Device закрыт и выключен.

Новый общий сценарий включён в Android CI, но в этом поручении CI не запускался.
Нативный локальный автоматизированный прогон CI-драйвером не подменяет Device;
выполнен отдельный Device-сценарий. Физический arm64, release UI, синхронизация,
конфликты между устройствами и восстановление из полного снимка не принимаются.
Vite сообщает прежнее предупреждение о размере основного chunk >500 kB;
оптимизация всего bundle не относится к этому шагу.

## Пять правил и передача

- Обратимость: назначить/снять, переименовать обратно, отмена; удаление без restore
  остаётся ровно согласованным исключением спецификации, объяснённым в UI.
- Человек/агент: прежние команды, права, версии и журнал намерений; прямой записи
  пользовательских данных в SQLite нет.
- Документация: user/agent/development/ADR-0046, очередь, журнал и этот EV обновлены.
- Паритет: общий UI проверен Windows/Android Device, обе debug ABI собраны;
  полный финальный native CI ещё не получен.
- Источник истины: Service/SQLite/Automerge и Rust-компаратор; UI/receipt/локальная
  очередь не становятся отдельным авторитетным состоянием.

Исходные посторонние документы сохранены. T08/A20/A30/A32 остаются partial;
P05 целиком не завершён. P05.06 verified локально. Далее ревью/интеграция ветки,
после неё готов P05.07 (поиск); P03.06 также остаётся готовым независимым шагом.
Локальные логи, снимки и доказательства находятся только в игнорируемом docs/reports/.
