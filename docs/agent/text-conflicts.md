# Разрешение текста карточки

Прочитайте `card.read`. Все актуальные варианты находятся в `titles` и
`descriptions`; несколько разных значений хотя бы одного поля означают
текстовый конфликт. Обычные изменения всей карточки до решения её собственных
конфликтов запрещены, включая выполнение, теги и неконфликтующий текст.

Отправьте `card.resolve_text` с `space`, `card`, итоговыми `title` и `description`,
а также `expected` из прочитанного `card.version`. Можно выбрать значения разных
вариантов или явно объединить текст вручную. Заголовок обязателен, описание
может быть пустым. Сохраняется одна пара новой версией истории; `card.history`
предоставляет прежние пары. Версия истории не подходит для `expected`.

Действуют прежние envelope `id`/`operation`, HTTP `/v1/commands/card.resolve_text`,
CLI `--operation card.resolve_text` и IPC. Нужно действующее право изменения
пространства; право чтения и административное право сами по себе недостаточны.
Результат — `CardSnapshot`. Команда без текстового конфликта возвращает `conflict`.

Разрешение не меняет ID/место/выполнение/теги/удаление и не выбирает остальные
конфликты. Оно не восстанавливает карточку или родителей из корзины. Если после
него остался другой собственный конфликт, обычные изменения по-прежнему запрещены.

При `stale_state` сохраните подготовленный текст, перечитайте карточку и явно
подготовьте новое решение. При неизвестном результате повторяйте сохранённое
намерение с теми же ID/параметрами/expected; не заменяйте его автоматически новым.
Отзыв доступа блокирует и повтор. Разные независимые решения вновь конфликтуют.
После разрешения всех собственных конфликтов обратите изменение обычным
`card.edit` либо `card.restore_text` с новым прочитанным состоянием.

Техническое решение: [ADR-0067](../architecture/decisions/0067-card-text-resolution.md).
