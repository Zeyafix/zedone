# EV-072 — P04.07: поиск через общий API

Состояние: verified локально. База: main/f5c089a после DEV.01/PR #67;
исходное дерево чистое.
Рабочая ветка: feat/p04-07-search.

## Рабочая карточка

- Цель: общий авторизованный поиск текущих и конфликтующих текстов карточек
  в одном пространстве или во всех доступных пространствах.
- Требования: T07, A19, A34, ADR-0011/0048; разработчик подтвердил
  канонический full case folding и NFC для поиска.
- Зависимости: P04.05/EV-069/PR #63 и P04.06/EV-070/PR #65 интегрированы;
  DEV.01/EV-071 сохраняет одну стартовую схему.
- Охват: Rust-правило поиска и группировки, общий Service, производные OpenAPI/
  TypeScript/validator, проверки ядра/хранения/адаптеров и документация.
- Проверки: `bun scripts/check-product.mjs` на Windows и с `--android` на
  встроенном Device-эмуляторе; производные через `--write-openapi`/`--write-types`;
  литеральный Unicode-поиск, область/права/отзыв/replay, порядок/конфликты,
  перезапуск, неизменность данных и проба нагрузки.
- Обратимость: поиск не меняет карточки; новый запрос или очистка строки
  снимают фильтр, сохраняя область и права. Ошибочные запросы не возвращают данные.
- Размер: один связный контракт поиска с проверкой конфиденциальности и групп;
  производные генерируются из Rust, ручной объём может превысить 300 строк.
- Исключено: интерфейс P05.07, синхронизация/публичное разрешение конфликтов,
  физический arm64, выпуск и полная приёмка этапа.
- Результат: общий API реализован, локальная матрица ниже passed;
  PR/CI/merge не выполнялись.
- Далее: проверка и интеграция изменения; зависимые шаги не начаты.

## Результат и матрица

`card.search` доступна через общий Service HTTP/CLI/Tauri IPC с Rust-derived
OpenAPI, TypeScript и standalone validator. Области `space` и `all` строгие:
лишние поля, неверные ID/типы отклоняются одинаково всеми адаптерами.
Клиент сохраняет исходные ID/строку/область при потере ответа и повторе.

Полные `bun scripts/check-product.mjs` Windows и `--android` прошли:
по 232 Rust-теста (17 core + 7 contract + 21 adapters + 187 storage),
20 client/190 assertions. Windows fmt/clippy/release/7 unsafe guards passed;
обе Android ABI release/14 unsafe guards passed. Нативные x86_64 Android-тесты
исполнены на эмуляторе, открытом через Device, и контракт побайтово совпал
с хостом. Собственный sandbox native-runner удалён, эмулятор выключен через
Device и возвращён в исходное состояние. Предварительная попытка Android
без штатного доступа adb не смогла создать служебный каталог; повтор с
необходимым доступом прошёл. Исходные данные установок не менялись.

- Unicode: NFC/NFD, full folding Straße/STRASSE и греческих форм, кириллица,
  различие «е»/«ё», сохранение диакритики/ширины/внутренних пробелов, краевые
  Unicode White_Space, нулевая ширина не считается пробелом.
- Буквальность: часть слова, непрерывная фраза, отказ при перестановке/вставке,
  пробел/табуляция/перенос без подмены, `C++`, `*`, `%`, `_`, `?`, кавычки,
  скобки, обратная косая черта. Поля/варианты не склеиваются, история не ищется.
- Области/права: только доступные пространства, чтение без записи, запрет
  чужой области и старого ключа, сужение прав с новым ключом того же субъекта
  отклоняет старый all-space receipt целиком; новый ID использует текущие права.
- Порядок: ручная доска, изменение порядка колонок и перемещения, одинаковые
  имена с ID-разрешением порядка, конфликт имён первым, отсутствие пустых
  групп, возврат после разрешения имени. Текстовый конфликт остаётся на доске,
  конфликт места карточки/колонки выделяется, карточка возвращается один раз;
  разрешение места возвращает обычный порядок при оставшемся конфликте текста.
- Обратные состояния: очистка запроса, выполнение/корзина/восстановление;
  совпадающие снимки до/после поиска, сохранение истории, restart/replay,
  изменённый запрос со старым ID отклоняется. Сбой записи receipt не меняет
  карточку и позволяет повторить исходный ID после устранения отказа.
- Нагрузка: 1000 карточек/1000 совпадений, половина выполнена, полный порядок
  и наличие всех результатов проверены на Windows и нативном Android.
  Защитный порог теста 30 секунд не является продуктовым бюджетом и не
  подтверждает итоговые задержки/ОЗУ/пики или физический Galaxy A32 (P09).

Локальные команды/сырые логи остаются только в игнорируемой `docs/reports/`
под префиксом `p04-07-`; в общие документы не включены сведения машины/ключи.
Связанные Markdown-ссылки и `git diff --check` проверены.
`vue-tsc -p ui/tsconfig.json` и `bun run ui:build` passed с новым производным
контрактом/validator; это проверка сборки, не UI-приёмка поиска.

## Пять правил и границы

Поиск не меняет данные, строку можно изменить/очистить. Человек и агент
используют общий Service, проверки прав и один контракт. User/agent/development/
architecture docs обновлены; ADR-0048 фиксирует подтверждённый Unicode-выбор.
Нативный Windows/Android-паритет проверен; SQLite/Automerge и Rust-derived
контракт остаются авторитетными, отдельного индекса/схемы нет.

Полные T07/A19/A34 остаются partial: UI P05.07 и продуктовые обмен/разрешение
конфликтов не приняты. Нагрузочная проба не заменяет P09, физический arm64 и
release APK не проверялись. Новых открытых BUG/GAP нет. P04.07 verified в рабочем
дереве указанной ветки; коммит/push/PR/новый CI/merge отсутствуют.
