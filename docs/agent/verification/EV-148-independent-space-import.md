## Реализация

`snapshot/import` декодирует архив с явными бюджетами и проверяет полноту графа.
Один visitor проверяет все исторические действия, поля, типы и ссылки, затем
преобразует те же поля. Новые случайные ID/actors сопоставлены монотонно;
пересчитаны hashes/deps/object/pred IDs, сохранены оп-счётчики, история и
причинность. Пользовательский текст, время и авторство сохраняются.

Только после проверки преобразованной модели и выходного бюджета создаётся
документ с отдельным локальным actor. Ошибка помечает WriteContext failed;
даже перехват вызывающим кодом не разрешает частичный commit. Документ и
changes используют прежнюю схему SQLite; права/подключения/сессии/receipts
не копируются и не создаются автоматически. Публичная команда должна добавить
явного получателя и replay receipt в той же транзакции с проверкой полномочий.

Ориентир 300 ручных строк превышен одним договором безопасного независимого
импорта полного причинного графа. Схему, преобразование ссылок, атомарную запись
и доказательства сохранности нельзя публиковать по отдельности как готовый
импорт. Сопутствующего рефакторинга, миграций или новых зависимостей нет.

  общий авторизованный импорт и replay остаются P07.02.3.
- Документация: agent/development/архитектура и журнал обновляются;
  пользовательский UI пока не меняется.
- Паритет: один Rust-код проверен Windows/native Android API33; release обеих Android ABI passed. APK UI, Linux и физический arm64 runtime здесь не проверялись.
- Источник истины: одна SQLite/Automerge; visitor — проверка/преобразование,
  не отдельное редактируемое представление данных.

Публичные полномочия/replay, ограниченное чтение файлов, экспорт/импорт через
