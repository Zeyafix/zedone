# Продуктовое Rust-ядро

Решение: [ADR-0027](decisions/0027-product-core-boundaries.md).
Текущее состояние — P03.01; реализован контракт, продуктовых операций ещё нет.

## Владение и зависимости

| Граница | Ответственность | Состояние |
| --- | --- | --- |
| `zedone-core` | Прикладные правила, запросы/результаты, общие ошибки; без платформы и прямого доступа к SQL/Automerge | Контракт в `crates/core`; операции впереди |
| `zedone-storage` → core | Одна SQLite устройства; внутренняя модель Automerge, транзакции и проекции | P03.02, пакет ещё не создан |
| Адаптеры → core | HTTP/CLI и Tauri IPC; декодирование, передача учётных данных, кодирование | P03.05; пакеты/оболочка ещё не созданы |
| Точка сборки → core/storage/адаптеры | Создание рабочего контекста хранения и управление жизненным циклом | Вместе с соответствующими входами |

Прототипы — независимый workspace и доказательства, а не библиотека продукта.
`scripts/check-product.mjs` проверяет наследование запрета unsafe и границу
зависимостей core; добавление зависимости требует явного пересмотра этой границы.

## Модель команды

Каждый реализованный запрос будет обычным строгим Serde/utoipa-типом с
`Command::NAME` и `Command::Output`. Обработчик в core получает запрос и
проверенный контекст доступа; адаптер не может подменять проверки прав,
актуальности или повторов. Сам trait только связывает типы, не выдаёт полномочий
и не выполняет операцию. Контекст доступа реализуется P03.03.

Изменяющая операция должна проходить общую последовательность: проверка входа
и доступа → проверка прежнего результата команды → исходные условия актуальности
для ещё не выполненной команды → изменение → согласованная фиксация данных,
истории, обмена и результата → ответ. Повтор по известному ID возвращает
прежний результат без новой правки. Это договор для P03.02–04, а не уже
реализованный механизм. Результат локальной записи не означает доставку реплике.

Внутренний `CommandResult<T>` — Rust Result. Его стандартные JSON-теги `Ok`/`Err`
не становятся транспортным протоколом; отображение закрепляется P03.05.
Имена полей, типы, ошибки и описания операций имеют один Rust-источник;
OpenAPI и будущие TypeScript-типы — проверяемые производные.

| `CommandError.code` | Смысл |
| --- | --- |
| `invalid_request` | Вход не соответствует контракту |
| `access_denied` | Действие не разрешено; отсутствие объекта не должно обходить проверку доступа |
| `not_found` | Разрешённая цель не найдена |
| `stale_state` | Исходное состояние устарело; нужны перечитывание и новое явное действие |
| `command_mismatch` | Тот же ID повторён с иной операцией/целью/параметрами |
| `unavailable` | Действие недоступно, достоверно не зафиксировано |
| `outcome_unknown` | Факт фиксации неизвестен; успех или окончательный отказ не подтверждены |

Это категории контракта; их выдача реальными обработчиками проверяется
в соответствующих шагах. Ошибка не переносит произвольную строку исключения
на границу API. Диагностика остаётся локальной; UI локализует коды отдельно.

## Хранение после P02

Правила из [модели Automerge](automerge-model.md) сохраняются как вход P03.02:
одна база устройства, изоляция сырого снимка одного пространства, стабильные
прикладные ID, сохранение конфликтов/отложенных изменений, согласованная запись
документа/actor/peer. Вне транзакции нет успешного частичного изменения.
Сырые Automerge ID и SQLite-строки не входят в командный контракт.

Полная загрузка всех пространств, полное view на каждую правку и полный save
не выбираются готовым горячим путём. В P03.02 до кода схемы нужно определить
границы загружаемых документов, применение записи и проверяемую стоимость
производных представлений. Независимого второго хранилища текущих полей нет.
Проверенный общий снимок всего файла SQLite не заменяет снимок пространства.

## Текущая проверка

Host и Android используют одинаковые тесты контрактов и бинарник экспорта.
Проверка компилятором запрещает unsafe в библиотеке, генераторе и интеграционных
тестах на host и обоих Android targets. APK/UI, продуктовые права/хранение,
HTTP/CLI/IPC и полный бюджет приложения в P03.01 не принимаются.
