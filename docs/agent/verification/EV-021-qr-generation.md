## Карточка шага

Общий Rust-контракт принимает непрозрачную синтетическую строку и возвращает
матрицу QR. Один Vue-компонент строит SVG без вставки HTML, с белыми полями
по четыре модуля и целым масштабом. Данные не сохраняются, приглашение не
создаёт подключение, сетевых запросов к адресу из строки нет. Формат приглашения
и права не определяются; сканер камеры — P01.09, протокол — P03/P06.

Проверки: `bun run check`, `bun run check:http` в Chrome/Opera, обе debug-сборки
APK и `bun run check:android` на AOSP API 33. Общий сценарий сверяет HTTP/IPC,
независимо декодирует растровое изображение SVG, проверяет UTF-8, длины,
поля/масштаб, отказ без обрезки, сохранение ввода, повтор и очистку.

Обратимость: изменение ввода убирает устаревший QR, очистка убирает ввод/результат,
масштаб меняется обратно. Невозможность кодирования оставляет исходную строку
доступной вручную; транспортный отказ допускает явный повтор. Продуктовое
подключение, чтение камерой, физическое устройство и измерения не принимаются.
Изначальное поручение не включало коммит/PR/слияние; публикация и merge при успехе разрешены отдельным поручением разработчика (LOG-130).

Ориентир 300 ручных строк превышен единым срезом генератора, двух адаптеров,
общего представления, независимого декодирования и документации; отдельные
функции сканирования или подключения в изменение не включены.

## Результаты

Общий Rust `qr` кодирует байтовый сегмент UTF-8 с ECI 26 на qrcodegen 1.8.0:
Medium ECC с автоматическим повышением без увеличения версии, версии 1–40,
автоматическая маска. HTTP и Android IPC используют одну функцию и модели.
OpenAPI/TypeScript/имя IPC сгенерированы из Rust. Строка нигде не сохраняется,
адрес из неё не открывается, новых полномочий APK не добавлено.

Один `QrCode.vue` отображает матрицу в SVG, только числовыми координатами,
без `v-html`. Четыре белых непрозрачных модуля вокруг кода, чёрные модули,
масштаб 2/4/8 и горизонтальная прокрутка. Правка текста сбрасывает прежний QR,
ошибки/потеря ответа сохраняют ввод и позволяют повтор, очистка удаляет результат.

| Проверка | Результат |
| --- | --- |
| `bun run check` | Пройдено: fmt/Clippy, 15 Rust-тестов, release, OpenAPI/TS/IPC, strict vue-tsc под закреплённым Node, Vite и HTTP/Chromium |
| Chrome и Opera: `bun run check:http` | Полный набор пройден на отдельных временных профилях |
| APK x86_64 / arm64 | Обе debug-сборки пройдены; общая Rust-зависимость собрана для обеих ABI |
| `bun run check:android` | Полный набор пройден на AOSP Android 13/API 33 без GMS, реальный WebView 101/Rust IPC, сеть WebView выключена для QR |
| Визуальная проверка | Снимок QR в реальном APK просмотрен локально; изображения и машинные пути остаются вне Git |

Независимый jsQR 1.4.0 декодирует матрицу и PNG отображённого SVG; pngjs 7.0.0
читает снимки. Обе зависимости используются только в проверках, не в приложении.
Точно совпадают байты UTF-8 и текст: пустая строка, синтетические адрес/код,
кириллица/составной символ/эмодзи, перенос/кавычки/обратный слеш, HTML как данные,
NUL, 1000 и 2330 байт. Все успешные матрицы Android IPC равны HTTP.
2330 байт помещаются в версию 40; 2331 не помещается при выбранном ECC/ECI.
Rust также проверяет длину многобайтового текста и заведомо большой ввод.
Невозможность кодирования — HTTP 422 JSON `"too_long"` / тот же IPC error,
поле ввода не меняется, QR отсутствует. Неверные/лишние поля отклоняются.

Снимки небольших кодов декодируются после фактического SVG-отображения
на обеих платформах. Пустая строка проверяется во всех масштабах, остальные
короткие примеры — при масштабе 2; белые поля проверяются по пикселям.
Большие коды декодируются из матрицы, их SVG-размер/поля/прокрутка проверяются
через DOM без подмены масштаба реального WebView. Отказ bridge/HTTP и потеря
ответа приводят к понятной ошибке через пять секунд и успешному явному повтору.
Прежние echo/SQLite/доска/Markdown и реальные отказы/перезапуски прошли.

## Исправленные ограничения драйвера

Стандартные Axum 422 для неверных полей возвращают текст, поэтому драйвер
разбирает ответ по Content-Type. JSON `"too_long"` проверяется отдельно.
Playwright boundingBox требует отсутствующий в WebView 101 `checkVisibility`;
координаты снимка читаются через DOM, приложение не патчится. Округление
scrollLeft на Android допускает один CSS-пиксель, край и отсутствие переполнения
страницы остаются обязательными. IPC error сравнивается внутри WebView:
Playwright оборачивает отклонение Promise в собственный Error.
