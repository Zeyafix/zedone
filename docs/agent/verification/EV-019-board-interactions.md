## Карточка шага

Один синтетический срез: порядок карточек, перенос между колонками и порядок
колонок существующего пространства A. Reka UI Dialog даёт явную команду,
VueDraggablePlus/SortableJS — жест. Оба вызывают один Rust API через HTTP/IPC.
SQLite остаётся источником данных. Команда содержит исходный снимок: устаревший
запрос отклоняется в транзакции. Это ограниченный прототип, а не продуктовый
протокол актуальности/повторов, прав, истории и конфликтов P03–P06.

Проверки: Rust сохранность/актуальность/обратимость/ошибочные координаты;
полный `bun run check`; Chrome/Opera; обе сборки APK и Android 13 AOSP;
мышь/касание, прокрутка и автопрокрутка, Reka фокус/Tab/Escape/«Назад», явное
обратное перемещение, SQL-отказ и потеря ответа с перечитыванием состояния.
После ошибки запрещено объявлять успех или откат без чтения БД.

Обратимость: явная команда перемещения в прежнюю позицию; удаление/восстановление
синтетического набора уже доступны в P01.05. Соседнее пространство B не меняется.
Перезапуск сохраняет порядок. Не входят Markdown, QR, Automerge, HTTP-сервер APK,
продуктовые операции, измерения A62, публикация/коммит/PR/слияние.

Размер превышает ориентир 300 строк: единый срез требует общего контракта,
транзакции, UI, двух транспортов и сквозных проверок. Независимых функций нет;
сгенерированные OpenAPI/TypeScript проверяются отдельно.

## Результаты

Реализованы перенос карточек внутри/между колонками и изменение порядка колонок,
явный Reka Dialog и обратная команда. Rust сравнивает исходное состояние и
сохраняет изменение в одной транзакции. UI хранит отдельное временное представление,
перечитывает БД при отказе, скрывает неподтверждённый порядок при отказе чтения.

| Проверка | Результат |
| --- | --- |
| `bun run check` | Пройдено: fmt, Clippy с запретом предупреждений, 14 Rust-тестов, release, OpenAPI/TS/IPC, vue-tsc strict под закреплённым Node, Vite/Bun, HTTP/Chromium |
| `bun run check:http`, Chrome | Пройдено на отдельном временном профиле после всех изменений |
| `bun run check:http`, Opera | Пройдено на отдельном временном профиле после всех изменений; предыдущие прогоны остановлены общим лимитом |
| Чистая установка JS | Frozen-установка без node_modules/dist, применение Bun patch, строгие типы и Vite пройдены в отдельном каталоге |
| APK x86_64 и arm64 | Обе debug-сборки пройдены |
| `bun run check:android` | Пройдено на Android 13/API 33 AOSP x86_64 без GMS, реальный WebView 101/IPC и работа формы без сети |

Rust проверяет 270 сочетаний позиции/карточки/колонки и их обратные действия,
перестановки колонок с сохранением принадлежности карточек, пустую колонку,
последнюю карточку, неверные координаты и ID, повтор и устаревшее состояние,
сохранность B. Конкурирующие команды с одним исходным снимком имеют одного
победителя. Реальный SQLite trigger отклоняет вставку после разрушительных
SQL-операций, прежнее состояние сохраняется. Изменённый порядок проверен после
повторного открытия БД, реального перезапуска HTTP-процесса и force-stop APK.

Общий UI-сценарий использует настоящие CDP mouse/touch events и Rust API,
проверяет порядок, перенос между колонками, равенство жеста явной команде,
обратное перемещение, Tab/Escape/focus trap/возврат фокуса, обычную прокрутку
и автоматическую прокрутку по двум осям. На ПК явная команда карточки выполнена
стрелками/Tab/Enter; на Android диалог открыт/сохранён сенсорными нажатиями,
значения стандартных select заданы драйвером через DOM. Системная «Назад» Android
закрывает диалог, не выполняя перемещение. Снимки интерфейса просмотрены локально.

SQL-ошибка проверена именно после жеста: UI перечитывает БД и возвращает прежний
порядок без дубликатов. При потере HTTP/IPC-ответа после реальной записи UI
не сообщает об успехе/откате, чтение обнаруживает сохранённый перенос. Для IPC
test-only bridge перенаправляет callback успешной записи в ошибку транспорта;
неизменяемая функция invoke не подменяется. Устаревшая команда не затирает
перенос другого клиента. HTTP дополнительно проверяет недоступность перечитывания:
временные карточки скрыты, новые команды блокируются до успешного явного чтения.

## Уточнения драйвера и зависимостей

Первые остановки выявили несовместимые TypeScript-декларации зависимостей,
неподдерживаемую WebView 101 проверку видимости Playwright и слишком раннее
измерение координат во время 150-мс анимации Sortable. Драйвер читает DOM,
ожидает завершения анимации и использует последовательные CDP mouse/touch events.
Scroll измеряется во время жеста; быстрые искусственные движения учитывают
throttle Sortable. Приложение ради драйвера не патчилось. Прогон Opera после
расширения набора не укладывался в прежние 90/180 секунд; финальный набор с
лимитом 300 секунд пройден целиком. Это ограничение драйвера, не измерение A62.

Reka UI 2.11.0, VueDraggablePlus 0.6.1 и дополнительные type-пакеты закреплены
в package.json/bun.lock. VueDraggablePlus содержит Sortable 1.15.2 внутри bundle;
отдельная runtime-копия не добавлена. Однострочный Bun patch исправляет только
унаследованные типы callback, runtime и strict не меняет. Причина, воспроизведение
и условие удаления описаны в [инструкции разработчика](../../development/board-prototype.md).
Это явная сопровождаемая правка зависимости, не исправление upstream.
