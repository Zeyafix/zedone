# ADR-0043: жизненный цикл пустой колонки в общем ядре

Дата: 2026-11-06. Техническое решение P04.02; продуктовые правила
ADR-0008/0014 и права пространства сохраняются. Проверки —
[EV-065](../../agent/verification/EV-065-column-lifecycle.md).

## Общий контракт

Шесть строгих Rust-команд: column.create/read/list/rename/trash/restore.
HTTP/CLI/IPC вызывают одну фиксированную таблицу Service и core handlers
внутри timed_transact. Чтение/список требуют Read пространства, изменения —
ReadWrite; создание не выдаёт новых полномочий. Проверка доступа действует
и при возврате receipt. Имена — точный Unicode, включая пустую строку,
без нормализации/уникальности. ID колонки — ненулевой случайный 128-битный ID
в 32 lowercase hex; клиент сохраняет его до первой доставки. ID команды
независим от ID объекта. Совпадение существующего ID даёт stale_state.

Новая мутация допускается только при активном состоянии пространства.
Спорное состояние даёт conflict, корзина — invalid_request. Повтор выполненной
команды подтверждает прежнее выполнение и не повторяет действие даже после
изменения родителя; он не представляет актуальное состояние.

Read возвращает space/column, все различные names/positions, состояние
active/trashed/conflicted, deletion_groups, empty и version. List возвращает
columns в порядке positions, затем ID; include_trashed обязателен и исключает
только однозначную корзину при false. Новое намерение чтения даёт свежий снимок,
повтор прежнего — исходный снимок. TypeScript/validators выводятся из Rust;
operation_id колонок имеют собственные имена, без изменения прежних space IDs.

## Хранение и порядок

Один существующий документ zedone.space.v1 расширяется необязательными
корневыми Map-объектами `column:<id>`: format=zedone.column.v1, name, lifecycle
и position. Независимые новые ID получают разные корневые ключи: не возникает
конфликта ленивого создания общего контейнера columns. Пространства без колонок
и их версии/receipts сохраняют прежний смысл. SQL v4 и формат архивного
контейнера не меняются; старый runtime уже отвергает корзину пространства
с неизвестным ему содержимым по ADR-0041.

Position — целый индекс добавления: max существующих позиций плюс один,
включая корзину; первая колонка получает 0. Переполнение отклоняется.
Восстановление сохраняет исходную позицию. При независимых добавлениях
одинаковые позиции упорядочиваются ID; явное изменение порядка — P04.05.
Разные варианты position/name/lifecycle читаются без потери, обычная правка
их не разрешает. Конфликт идентичности Map или повреждённый формат дают отказ
вместо выбора одного объекта. Разрешение доменных конфликтов относится к P06.

## Актуальность и обратимость

Перед rename/trash/restore core сверяет expected с причинной версией
целевой колонки в той же writer-транзакции. Проекция включает корневой ключ
колонки и все операции её потомков, включая перезаписанные/удалённые объекты,
значения, связи и ID операций. Возврат прежнего значения/состава не оживляет
старую версию. Версия привязана к space и column, без heads/часов/счётчиков.
Другая колонка, другое пространство, корневая history, receipt и peer progress
исключены. Неизвестные корневые поля потенциально могут ссылаться на колонку:
их причинная история включается консервативно в каждую column.version,
в том числе после удаления этих полей. При их наличии empty=false у всех
колонок. Это не распространяется на известные поля соседних колонок.
Версия всего пространства по-прежнему включает все колонки;
группировка операций по корневому ключу не меняет прежний алгоритм SHA-256.
Список строит проекции за один проход по журналу, без отдельного полного
сканирования операций для каждой колонки и без постоянного кэша.

Удаление записывает `trash:<subject>:<command-id>`, восстановление — новое active.
Объект, журнал, actor, ID и позиция сохраняются. Повтор выполненного удаления
после восстановления возвращает прежнюю группу без повторного удаления;
повтор восстановления не отменяет новое удаление. Обратное переименование —
новая команда. Граф и receipt коммитятся атомарно; потерянное подтверждение
не становится ложным успехом, повтор сохраняет весь исходный запрос.

Этот срез работает с пустыми колонками. Любое поле вне известного формата
в колонке или корне пространства делает empty=false и блокирует trash/restore.
Модель размещения карточек этим решением не выбирается; вложенная Map в тесте
проверяет отказ неизвестному содержимому, не задаёт будущую структуру карточки.
До первой публичной команды карточки P04.03 должен расширить empty и причинную
проекцию составом/данными карточек по их реальным связям, включая перемещения
и удалённую принадлежность, без копирования карточек ради смены колонки.
Нет частичного удаления или обхода проверки состава. space.trash/restore
продолжает отвергать пространство с любыми колонками, в том числе в корзине:
группы целого контейнера — P04.09. Полные A55/A56, карточки P04.03, UI P05.02
и продуктовая синхронизация этим решением не объявляются завершёнными.
