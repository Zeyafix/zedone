# Разрешение места карточки

`card.inspect_placements` принимает `space` и `card`, требует чтения пространства.
Ответ содержит `card` с актуальной версией и `choices`: каждое значение хранит
целую `placement` (колонка и ранг) и `before` — ID ближайшей однозначно размещённой
карточки после этого места, либо null для конца. Сосед вычисляется ядром по
текущему состоянию; это подпись для выбора, а не параметр записи.

Отправьте `card.resolve_placement` с `space`, `card`, неизменённой выбранной
`placement` и `expected` из полученного `card.version`. Действуют обычные envelope
`id`/`operation`, HTTP `/v1/commands/card.resolve_placement`, CLI
`--operation card.resolve_placement` и IPC. Нужно право изменения пространства.
Самостоятельно вычислять ранг или составлять пару из разных вариантов нельзя:
несохранённая пара возвращает `invalid_request`.

При отсутствии нескольких сохранённых мест команда возвращает `conflict`.
Карточка с удалением, пространство или выбранная колонка в корзине не
восстанавливаются этой командой. Конфликт только названия или порядка родителя
не блокирует выбор места карточки. Текст, история, теги, выполнение и ID не
изменяются; другие собственные конфликты по-прежнему блокируют обычные действия.

При `stale_state` перечитайте варианты и явно подготовьте новое решение.
При неизвестном исходе повторяйте исходные ID/параметры/expected; не подменяйте
их свежими. Отзыв доступа блокирует и replay. Разные независимые решения
становятся новым конфликтом; одинаковые места сходятся. Обратное действие после
разрешения всех собственных конфликтов — обычная `card.move` с новой версией.

Разные карточки между одинаковыми соседями сохраняются автоматически в общем
устойчивом порядке. Спорная карточка остаётся одним объектом вне обычных колонок.
Позиции колонок и их интерфейс разрешения относятся к P06.06.2.
