# EV-069 — перемещения и порядок через общий API

## Рабочая карточка

- Шаг: P04.05. База: чистая main/0cfcfa0. Ветка: feat/p04-05-move-order.
- Цель: относительные перемещения карточек и колонок без перенумерации соседей.
- Требования: T07/A07/A35/A41, ADR-0002/0007/0008. Зависимость: P04.04/EV-068/PR61/4810735.
- Охват: core/storage/schema v5/общий Service HTTP/CLI/IPC/контракт/тесты/docs.
- Проверки: bun scripts/check-product.mjs, тот же --android, bun run ui:check, git diff --check.
- Обратимость: новая move возвращает объект обратно. Исходные ID/expected сохраняются при повторе.
- Отказы: stale/ABA, права, корзина, конфликт, чужое пространство и rollback без частичной записи.
- Результат: verified локально. Следующий шаг: ревью/публикация по поручению, CI точного head и интеграция.

Пара действие/обратное действие использует одну модель ранга и целого положения;
совместимость, строгий контракт и проверки превышают ориентир 300 строк.
UI остаётся P05.05, продуктовый обмен/решение конфликтов — P06.


## Реализация

Общие `card.move` и `column.move` используют исходную версию перемещаемого
объекта, ReadWrite, активных родителей и прежний guard/replay/SQLite transaction.
`before=null` — конец активного списка, иначе вставка перед конкретным соседом.
Соседи не перенумеровываются. Возврат — новая команда; noop не меняет версию.
Поле `placement` сохраняет колонку/ранг карточки вместе. ID/текст/история/теги/
выполнение не меняются. Legacy positions/receipts не переписываются.
Схема v5 с прежним DDL использует штатную защищённую цепочку обновления;
старые writers отклоняются. Решение — [ADR-0045](../../architecture/decisions/0045-relative-placement.md).

## Матрица проверки

| Область | Доказательство |
| --- | --- |
| Порядок | Вставка перед соседом, в конец и обратные операции внутри/между колонками; 70 перестановок; версии соседей/карточек при переносе колонки не меняются |
| Ранги | 600 вставок на границах и между равными legacy u64 с разными ID; 10 000 добавлений в конец и 10 000 в один промежуток с ограниченной длиной; максимальный u64; одинаковый промежуток разных объектов и вставка между ними |
| Сохранность | Текст/история/выполнение/теги/ID сохраняются; после move работают edit/completed/trash/restore; удалённая принадлежность и ABA меняют версии обеих колонок |
| Отказы | Исходная версия после правки/переноса устаревает; недопустимый/собственный/отсутствующий сосед, колонка другого пространства, корзина, конфликт без частичной записи |
| Права | Read запрещает обе move даже для noop; истёкший доступ и отзыв запрещают изменение/replay; guard общий для всех входов |
| Атомарность | AfterWork/AfterChanges/AfterResult/BeforeCommit для обеих move; настоящий SQL abort receipt для карточки; AfterCommit даёт OutcomeUnknown и подтверждается replay |
| Конкуренция | Два workers: move и edit с одной версией допускают только одного; независимые whole-place изменения сохраняют две пары вместо смешанных положений |
| Совместимость | v4→v5 требует проверенную копию, сохраняет raw graph bytes/версии/receipt; старый registry не допускает v5; старый numeric receipt повторяется после новых перемещений |
| Адаптеры | HTTP/IPC/настоящий CLI, обе move и обратные действия, stale/неправильные типы/лишние поля, общий replay после перезапуска и отказ Read/отозванному субъекту |
| Клиент | Исходные ID/колонка/before/expected остаются после stale/restart/потерянного IPC-ответа; явный отказ не повторяется автоматически; ранги проверяются Rust-derived validator |

## Границы приёмки

Только API-срез P04.05. UI/перетаскивание/жесты остаются P05.05;
продуктовый обмен и решения конфликтов — P06. Физический arm64/release APK,
полный масштаб/память и совместимость обмена со старым writer не принимаются.
T07/A07/A35/A41 остаются partial; весь P04 не закрыт.
Публикация/PR/новые CI/merge не выполнялись.

## Пять правил

- Обратимость: относительная move обратно с новой версией, корзина/восстановление сохраняют место.
- Человек/агент: одни Service/core HTTP/CLI/IPC без прямой записи агента в SQL.
- Документация: user/agent/development/architecture, ADR-0045, очередь/журнал.
- Паритет: общие нативные тесты Windows/Android и release двух Android ABI; UI не включён в приёмку.
- Источник истины: одна SQLite/Automerge; новый placement авторитетен целиком, прежние поля только legacy baseline; API/TS/валидатор выведены из Rust.
