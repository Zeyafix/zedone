# ADR-0050: группы корзины колонки через общий API

Дата: 2026-11-07.

Статус: принято для реализации P04.09.1; проверка —
[EV-074](../../agent/verification/EV-074-column-trash-groups.md).
Продуктовые требования ADR-0014 и раздела 1.2 спецификации не меняются.

## Решение

Прежние column.trash/restore расширяются на известный состав колонки без
новых команд или клиентских списков удаления. Авторитетную область определяет
ядро в той же writer-транзакции, где проверяются права/expected и пишется receipt.
Для предварительного просмотра column.read/list возвращают `contents` —
снимки всех текущих членов, включая ранее удалённые карточки и сохранённые
спорные положения. Это производная одного SQLite/Automerge, без копирования
текущих данных в отдельное хранилище. Отсутствие/None contents не означает
пустую колонку: неизвестное содержимое блокирует обе операции.

Core получает CardStore; сначала проверяет всю область на конфликты, затем
передаёт запись прежним lifecycle-методам. Нерешённые текст/место/теги/выполнение/
удаление карточки блокируют действие. Конфликт названия/положения/состояния
самой колонки тоже блокирует его. Карточки соседних колонок не удаляются.

Удаление назначает один `trash:<authenticated subject>:<command id>` колонке
и её активным карточкам. Прежние отдельные группы карточек не меняются.
Восстановление назначает active колонке и только карточкам этой же группы,
сохраняя прежнюю корзину. Новое удаление после восстановления создаёт другую
группу, а повтор выполненной команды возвращает исходный receipt без мутации.

Текущая column.version сохраняет причинные операции колонки и текущую/удалённую
принадлежность карточек. Для колонки, где когда-либо были карточки, добавляются
версии текущих членов: так изменения назначенных тегов и их конфликтов тоже
отклоняют устаревший запрос, включая возврат старого значения. У никогда не
занятой колонки прежняя форма токена сохраняется. История текста, чтение,
receipts и peer progress не участвуют. Отказ требует нового явного действия
после перечитывания; автоматическое обновление expected запрещено.

Каждая меняющая lifecycle карточки запись завершает pending text series и
удаляет editing session. Вся группа, история, session и receipt сохраняются
либо откатываются совместно в прежней транзакции. При неизвестном commit
повторяется тот же запрос. HTTP/CLI/IPC используют один Service/guard/replay.
OpenAPI/TypeScript/runtime validator генерируются из Rust, включая вложенный
CardSnapshot. Необязательное contents допускает чтение прежних receipts.

## Границы

Структура графа/SQL v1 и зависимости не меняются. Старые базы разработки
не мигрируют/не сбрасываются по ADR-0047. UI групп относится к P05.08,
пространство и отдельное восстановление карточки в другую колонку — P04.09.2,
окончательная очистка — P04.09.3, очистка истории — P04.09.4, продуктовый обмен
и разрешение конфликтов — P06. Эти критерии не принимаются данным срезом.
