## Реализация и граница изменения

Продуктовые API, UI, схема и зависимости прежние. Новая матрица
`check-pairing-app.mjs --agent` использует обычный Windows CLI `--endpoint`,
HTTP поверх pinned TLS и собственные явно зарегистрированные ключи агента.
Административный ключ стенда только создаёт данные и выдаёт/меняет/отзывает
доступ. `fixture.peer_command` не используется для действий агента.

Отдельный debug-only marker подготавливает изолированную установку до открытия
оболочки. HTTP fixture получает клон того же `Shell.service`, который
обслуживает локальный IPC: данные не копируются из удалённой реплики в UI.
Прежний запрет сборки release с `pairing-acceptance` сохранён.
Старый парный стенд продолжает использовать собственную изолированную базу.

Новый самостоятельный Android job `pairing-agent` использует прежние подготовку,
обычный APK bootstrap CI и acceptance build. Fixture budget 240s и Android
15m сохранены; локальные Device checkpoints используют прежние 300s и общий
UI-fixture 600s. Default runner добавляет новый срез после прежних, отказы
и сигналы каждого дочернего процесса не позволяют объявить общий успех.
Превышение ориентира размера diff связано с одним результатом: матрица API,
общий IPC/HTTP-стенд, обязательное включение в CI и документация доступа.

## Исходные остановки

1. После закрытия APK forward продолжал принимать TCP и обрывал TLS, поэтому
   ожидание unavailable получило access_denied. Runner теперь убирает свой
   forward вместе с закрытием приложения и проверяет отказ соединения по
   прежнему endpoint. Продукт и строгая проверка кода ошибки не менялись.
2. Проверка истечения ждала Unix-границу по часам ПК. Измерение показало
   отставание календаря Android; обращение ещё попадало до его границы.
   Срок по-прежнему десять секунд, но задаётся по календарю телефона; runner
   ограниченно ждёт эту календарную границу, затем один раз строго проверяет
   отказ. Часы не меняются; клиент не поставляет Clock продуктовой команде.
   В финальной пробе календарь телефона уже пересёк expires_at до запроса.

Обе исходные попытки/логи и успешное SHA-256 восстановление сохранены отдельно.
Успешный повтор не объявляется исправлением продуктового дефекта.
Ошибка кавычек PowerShell при Device fill исправлена после `help fill`;
проверенное значение и «Сохранено» зафиксированы. Открытое по неточному
сопоставлению действие перемещения отменено без изменения данных.

GAP-045: изменение матрицы привело к новому exact SDK key и холодной установке.
Текущий [официальный каталог](https://dl.google.com/android/repository/repository2-3.xml)
не содержит URL закреплённой Platform Tools 37.0.1. Её официальный
versioned-архив остаётся доступен и содержит прежнюю revision. Холодная
подготовка теперь получает архив по закреплённому URL, проверяет SHA-256
до распаковки и revision после неё, не переустанавливая пакет через CLI.
Pins и общий verifier на cold/hit сохраняются. Это необходимое исправление
воспроизводимости CI; отложенная оптимизация CI не возобновляется.

Реальный архив и новый блок установки проверены в изолированном каталоге.
Пять синтетических случаев valid/download failure/hash mismatch/wrong revision/
