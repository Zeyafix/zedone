# Карточки через общий API

Карточка принадлежит пространству и колонке. Используйте общие
HTTP/CLI/IPC, как у [колонок](columns.md); прямые записи в SQLite не являются API.
Rust — источник `api/openapi.json`, TypeScript и валидаторов ответов.

| Операция | Параметры | Доступ пространства |
| --- | --- | --- |
| `card.create` | space, card, column, title, description | ReadWrite |
| `card.read` | space, card | Read/ReadWrite |
| `card.history` | space, card, after, limit, expected | Read/ReadWrite |
| `card.list` | space, include_trashed | Read/ReadWrite |
| `card.edit` | space, card, title, description, expected | ReadWrite |
| `card.begin_editing` | space, card, expected | ReadWrite |
| `card.autosave` | space, card, session, title, description, expected | ReadWrite |
| `card.finish_editing` | space, card, session, expected | ReadWrite |
| `card.restore_text` | space, card, text_version, expected | ReadWrite |
| `card.move` | space, card, column, before, expected | ReadWrite |
| `card.set_completed` | space, card, completed, expected | ReadWrite |
| `card.trash` | space, card, expected | ReadWrite |
| `card.restore` | space, card, expected | ReadWrite |

Создайте `card` через `newCardId()` и сохраните вместе с точным намерением:

```ts
const card = newCardId();
const pending = await prepare(subject, "card.create", {
  space, column, card, title: "Прочитать книгу", description: "",
}, store);
await client.deliver(pending);
```

ID команды независим от ID карточки. Изменения требуют активных родителей.
Заголовок не может быть пустым или состоять только из Unicode whitespace;
описание может быть пустым. Текст сохраняется точно. edit задаёт оба поля
одной дискретной правкой; он не является автосохранением непрерывного ввода.
Карточка добавляется в конец колонки, корзина/восстановление сохраняют место.

CardSnapshot содержит space/card, titles/descriptions/columns/positions/completed
со всеми различными вариантами, tags, state, deletion_groups и version.
CardList содержит cards; include_trashed обязателен. Спорные карточки
остаются в списке, обычные изменения блокируются. card.history содержит пары
title/description с id, subject и локальным sequence; sequence не определяет
порядок независимых правок на разных устройствах. Начальная пара сохраняется
при создании, каждая отдельная правка — новой версией; чтение/повтор/отказ
или правка неизменившихся данных не создают версию. Историю можно вернуть
новой edit с выбранной парой и актуальной version без удаления прежних версий.

История читается страницами: первый запрос задаёт after=null, expected=null
и limit от 1 до 100. Ответ содержит versions, next и собственную version истории,
а также space/card. Для следующей страницы передайте next в after и эту version
в expected; если next=null, чтение закончено. При изменении истории между
страницами получаете stale_state — начните чтение заново новым намерением.
Не передавайте version истории вместо version карточки при редактировании.
Снимки карточек и результаты их изменений не содержат копии всей истории.

Для expected используйте version самой карточки. Изменение текста, тегов,
выполнения, колонки, порядка или корзины делает старое действие устаревшим,
даже после возврата прежнего значения. stale_state требует перечитать карточку
и подготовить новую команду. Ввод сохраняют отдельно от результата команды;
нельзя подменять expected и автоматически отправлять старую правку.
conflict требует разрешения, которое остаётся отдельным шагом P06.

`card.set_completed` явно задаёт `completed: true` или `completed: false`.
Обе операции требуют активной карточки и родителей. Колонка не определяет
выполнение: команда не меняет принадлежность, порядок, текст, теги и историю.
То же значение с актуальной version — успешный noop без новой версии карточки;
устаревшая version отклоняется даже при совпадении требуемого значения.
После изменения описания старая отметка выполнено получает `stale_state`.
Корзина/восстановление сохраняют выполнение. Для снятия отметки прочитайте
актуальную карточку и подготовьте новое намерение:

```ts
const pending = await prepare(subject, "card.set_completed", {
  space, card, completed: false, expected: snapshot.version,
}, store);
await client.deliver(pending);
```

При неизвестном результате повторите исходное сохранённое намерение с тем же
ID, параметрами и expected. Receipt подтверждает прежнее выполнение и не
является свежим состоянием для замены view. Для нового read/list нужен новый
ID. После отзыва или истечения доступа повтор также запрещён.
Ключ не сохраняется в намерении, не передаётся как параметр команды и не логируется.

Назначение/снятие тегов: `card.set_tag`, [общий API тегов](tags.md).
UI редактора/тегов, серии истории и групповая корзина
контейнеров остаются последующими шагами. Наличие карточек, в том числе в корзине,
блокирует текущую корзину/восстановление колонки. Архитектура —
[ADR-0044](../architecture/decisions/0044-card-lifecycle.md).


## Перемещения и порядок (P04.05)

`card.move` перемещает существующую карточку в `column` того же `space`.
`before` — ID активной карточки этой колонки; `null` помещает в конец.
Для перестановки внутри колонки используйте ту же команду. `expected` берётся
из свежей `card.version`. Нельзя указывать себя, карточку другой колонки или
колонку другого пространства. Отсутствующий/недопустимый сосед отклоняется.
Положение соседа берётся в момент исполнения; правка соседней карточки сама
по себе не делает вашу команду устаревшей. Собственная правка/выполнение/перенос
делает старую версию устаревшей. Stale не повторяют с автоматически обновлённой
версией; неизвестный исход повторяют точным исходным намерением.

```ts
const pending = await prepare(subject, "card.move", {
  space, card, column: destination, before: null, expected: snapshot.version,
}, store);
await client.deliver(pending);
```

Перенос обратно — новая команда с актуальной версией и прежними колонкой/соседом.
Уже достигнутое место — noop. Текст, история, выполнение и теги сохраняются;
корзина/восстановление не меняют место. `positions` содержит прежние числа либо
массивы компонентов ранга. Ранги непрозрачны для клиента: порядок даёт общий
список. У перемещённой карточки `placements` содержит целые варианты
`{column, rank}`; `columns`/`positions` — их производные. Без `placements`
действует прежнее однозначное положение или прежний receipt, который нельзя
использовать как свежий view. Все варианты доступны; разрешение конфликтов — P06.
Архитектура — [ADR-0045](../architecture/decisions/0045-relative-placement.md).

## Серии ввода и восстановление версии

Для дискретной правки используйте card.edit. Для непрерывного ввода:

1. Прочитайте карточку и выполните card.begin_editing с её version. Сохраните
   намерение до доставки; ID команды, возвращённый prepare, станет session.
2. После подтверждения начала используйте card.autosave с этой session,
   обоими полями и version последнего подтверждённого текущего состояния.
   Каждая новая правка имеет новый ID, повтор — исходный ID и неизменные байты.
3. При завершении выполните card.finish_editing с session и свежим expected.
   После него для ввода нужна новая begin_editing.

Новая изменённая пара до 30 секунд продолжает серию. Неизменившиеся данные,
чтение, отказ или повтор не откладывают границу. После паузы >=30 секунд
свежая card.history покажет одну версию последней сохранённой пары. Снимок
карточки не включает открытый журнал серии; частота автосохранения этим
интервалом не задаётся. Историю перечитывают новым ID; старый receipt остаётся
прежней страницей. Материализация истории не меняет card.version.

Новая begin_editing явно завершает прежнюю серию карточки и заменяет старую
сессию, включая сессию другого участника. Сессия принадлежит доверенному
субъекту; чужая или завершённая session даёт stale_state. При stale сохраняйте
локальный ввод, перечитайте и подготовьте новое явное действие; не подменяйте
expected в уже сохранённом намерении. Вызов CLI сам по себе не закрывает сессию.
После перезапуска клиента сначала выясните исход старых намерений точным
повтором, затем начните новую сессию до просмотра истории/нового ввода.

Для восстановления выберите versions[i].id из card.history, перечитайте
карточку и вызовите card.restore_text с text_version и card.version в expected.
Прежняя пара станет текущей, к истории добавится отдельная версия; прежние
версии останутся. Версия истории не подходит для expected этой операции.
Можно восстановить состояние до восстановления той же командой с другим ID
версии. Теги, выполнение, положение и состояние не восстанавливаются этой
командой. Для карточки в корзине сначала требуется card.restore.

restore_text завершает открытую серию отдельно; восстановление не группируется
с соседним вводом. Даже уже совпадающая пара получает новую видимую версию.
Неизвестный исход повторяют исходным намерением; повтор не возвращает карточку
назад после позднейшей правки. Техническое решение —
[ADR-0049](../architecture/decisions/0049-card-editing-history.md).
