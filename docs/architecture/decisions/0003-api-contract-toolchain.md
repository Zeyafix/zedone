# ADR-0003: генерация HTTP-контракта и типов клиента из Rust

Дата: 2026-10-26.

Статус: принято разработчиком. Цепочка инструментов и совместимость с Bun ещё не проверены на ZeDone.

## Контекст

Разработкой ZeDone занимается AI-агент. Общие модели запросов, ответов и ошибок должны иметь один авторитетный источник в Rust. Автоматическая генерация уменьшает объём кода, который агенту нужно согласовывать вручную; фактическое снижение частоты ошибок пока не измерено.

Разработчик явно выбрал utoipa + OpenAPI + openapi-typescript + openapi-fetch и потребовал отдельно отметить совместимость с Bun.

## Решение

- Rust-описания данных и операций служат источником HTTP-контракта. utoipa создаёт его представление в OpenAPI.
- openapi-typescript генерирует типы TypeScript из OpenAPI.
- openapi-fetch использует эти типы для HTTP-вызовов из общего веб-интерфейса. Это клиентская библиотека; генератор типов сам по себе не создаёт реализацию клиента.
- Генерация OpenAPI и типов выполняется воспроизводимой командой. Генерируемые представления не редактируются вручную; CI проверяет их согласованность с Rust-источником и выполняет проверку типов. Способ хранения артефактов и точные команды определяются при реализации.
- Проверка типов не заменяет проверку входных данных и прав доступа в Rust-ядре. Прикладные правила общие для интерфейса, HTTP, CLI и Android-адаптера.

## Совместимость с Bun — обязательная открытая проверка

Bun остаётся выбранным менеджером JavaScript-зависимостей и средой запуска инструментов разработки и CI. Совместимость всей новой цепочки с Bun пока не подтверждена. Документация openapi-typescript описывает запуск с Node.js; установка пакета через Bun сама по себе не доказывает, что генератор выполняется под Bun.

В P01 на Windows и в CI необходимо:

1. Закрепить совместимые версии utoipa, openapi-typescript, openapi-fetch и Bun и выполнить чистую установку JavaScript-зависимостей по одному lock-файлу Bun.
2. Сгенерировать OpenAPI из минимального Rust-контракта и запустить openapi-typescript под Bun. Зафиксировать команду и фактическую среду выполнения каждого шага; исключить неучтённый запуск через Node.js из-за строки запуска CLI.
3. Проверить импорт и сборку openapi-fetch через Vite, проверку типов Vue/TypeScript и работу HTTP-клиента. В полном охвате проверить целевые браузеры Windows и Android WebView; отдельный успешный запуск под Bun не подтверждает работу интерфейса на устройствах.
4. Проверить воспроизводимость генерации и обнаружение несогласованных артефактов или несовместимого изменения контракта автоматическими проверками.
5. Если обнаружится обязательная потребность в Node.js, явно записать затронутый шаг, причину и версию как дополнительное требование разработки/CI. Такой запуск не отмечать как успешную проверку выполнения под Bun. Bun сохраняется менеджером пакетов; необходимость Node.js для отдельного шага не добавляет его в зависимости готового приложения.

## Android IPC и границы решения

OpenAPI описывает HTTP и само по себе не генерирует адаптер команд Tauri IPC. Android-адаптер использует те же сгенерированные типы данных и прикладные операции Rust-ядра. Связь имён команд, параметров, результатов и ошибок с Rust-контрактом, способ её проверки и окончательный внутренний транспорт остаются техническими вопросами P01/P03; независимые ручные копии моделей не допускаются.

Проверки T01 и T06 остаются not_run. Выбор цепочки до проверки совместимости принят как ограничение. Требования обратимости, общего API человека и агента, паритета Windows/Android и единого источника данных и контрактов сохраняются.
