# EV-016 — минимальный Android APK и общий Rust через IPC

## Карточка P01.04

- База: `1a764a807561d89d302f69af579384c52caa9557`, чистый `main`;
  ветка `feat/p01-04-android-ipc`.
- Цель: та же синтетическая форма вызывает общий Rust echo внутри APK без сети.
- Требования: T02/T04 (частичный вклад), ADR-0001/0003, спецификация §3.
- Зависимость: P01.03 `done`, PR #10, EV-015; код доступен в базе.
- Охват: Tauri Android shell, IPC-адаптер, выбор транспорта общей формы,
  закреплённые зависимости/генерируемый Android-проект, команды проверки и документация.
  Ожидаемый размер превышает ориентир 300 строк главным образом из-за шаблона
  Android/lock-файла и проверки на устройстве; это один результат APK→Rust.
- Проверки: `bun run check`; debug APK x86_64 и arm64 на Windows;
  Android 13 AOSP/WebView: echo/Unicode/пустой ввод, отказы IPC,
  сравнение с HTTP, очистка, клавиатура/«Назад», force-stop/перезапуск.
- Обратимость/отказ: форма очищается; синтетический ввод не хранится,
  после остановки процесса начинается пустая сессия. Ошибка сохраняет ввод;
  APK удаляется по отдельному prototype application ID. Общие инструменты не меняются.
- Результат: `verified` локально; CI/PR/интеграции нет, коммит не создавался.
- Локальные логи, версии среды и артефакты — только `docs/reports/p01-04/`.
- Далее: проверить Windows/Linux и Android Actions при публикации P01.04,
  затем интегрировать; P01.05 разрешён после `done` и пока не начат.

## Реализация

Tauri 2.12.5 в отдельном Android crate общего Cargo workspace использует
существующую Rust echo и её модели. В браузере тот же Vue-клиент использует
openapi-fetch, в APK — `@tauri-apps/api` 2.12.4. Типы обоих транспортов и имя
IPC-команды генерируются из Rust/OpenAPI и сверяются общей командой.
Неверные IPC-аргументы отвергаются десериализацией Rust; независимых копий
DTO нет. Общая проверка TypeScript также отклоняет неверный запрос к адаптеру.
Для деклараций API Tauri добавлен `ESNext.Disposable` в TypeScript lib;
runtime-полифиллы не добавляются.

Cargo CLI берётся из JSON среды; версии Cargo/JS-зависимостей — из manifest/lock.
Android-проект создан штатным CLI, wrapper проверяет SHA-256 Gradle.
Выявленная библиотечная потребность в SDK/Build-Tools 36 закреплена явно,
автоустановка SDK отключена. Системные инструменты не переустанавливались.
APK изолирован application ID; backup отключён. Сервер HTTP в APK не запускается.
Нативная точка входа изолирована по [ADR-0024](../../architecture/decisions/0024-android-prototype-entry-point.md),
запрет unsafe ядра сохраняется. Rust IPC-адаптер находится вне исключения.

## Выполненные проверки

- `bun run check` на Windows: rustfmt, Clippy `-D warnings`, Rust-тесты,
  release-сборка, согласованность OpenAPI/TypeScript/IPC-имени, vue-tsc под
  закреплённым Node LTS, Vite и HTTP/Chromium. Дополнительно тот же сценарий
  production bundle пройден в Chrome и Opera с отдельными временными профилями.
- Новая копия без `target/node_modules/dist` и локальных Gradle-ссылок:
  frozen-установка Bun, общая проверка, сборка APK. Финальные исходники повторно
  проверены в этой копии. Cargo.lock/bun.lock и генерируемые контракты не меняются.
- Debug APK x86_64 и arm64 собраны на Windows с JDK/SDK/NDK из общей базы.
  Android Clippy проверил реальный target `x86_64-linux-android` с `-D warnings`.
- `bun run check:android` на Android 13/API 33 AOSP x86_64 без GMS:
  реальный Rust через IPC и host HTTP возвращают одинаковые пустой текст,
  русский/Unicode, emoji, переносы, кавычки и буквальный HTML.
  Форма проходит те же сценарии при заблокированной через CDP сети.
- IPC отклоняет отсутствующий `request`, отсутствующий `text`, `null`, число
  и неизвестную команду. Моделируемые в тестовом Android bridge ошибка и потеря
  ответа не дают ложного успеха, сохраняют ввод, допускают явный успешный повтор.
  Потерянный ответ ограничен 5 секундами, интерфейс выходит из состояния busy.
- Проверены сенсорные нажатия формы, очистка, русский ввод через CDP Input.insertText,
  открытие штатной клавиатуры, её скрытие системным «Назад», сохранение формы
  при возврате в тот же процесс и пустая сессия после force-stop/перезапуска.
- Устаревший и отсутствующий `ipc-command.ts` отклоняются без перезаписи;
  восстановление проходит. Неверный ABI и отсутствие явного serial дают отказ.
- Проверены удаление prototype APK и отсутствие его пакета после удаления;
  принадлежащий проверке AVD остановлен, adb forward не остался.
- Actionlint/ShellCheck, ссылки/блоки/JSON документации, сохранность всех 98
  требований и полный diff проверены. Локальные логи/отпечатки — в `docs/reports/p01-04/`.

## Ограничения и приёмка

P01.04 — `verified`, T02/T04 — `partial`; T01 остаётся `partial`, DEC-001 открыт.
Android workflow теперь собирает оба ABI и вызывает тот же тест на собственном
AVD до очистки. Его новая версия локально проверена статически, Actions этой
ветки не запускались. Коммита, PR, слияния и релиза нет.

Старый AOSP WebView потребовал тестового CDP-подключения без desktop download/context
настроек и DOM-проверок вместо новых Playwright visibility API. Приложение и
WebView не патчатся. Русская IME с составным вводом и физический Galaxy A32
не проверены; сборка arm64 не доказывает работу на телефоне. Gradle выводит
предупреждения о legacy DSL и Java source/target 8 в шаблоне/зависимостях Tauri;
они не скрываются, переход на будущие major потребует повторной проверки.

Нет прикладных операций, хранения, фоновой службы или внешнего агентского HTTP
в APK; эти будущие функции не являются дефектами P01.04. Приёмка P00 не меняется.
Обратимость, документация, общий Rust API и источник моделей соблюдены в охвате
echo; паритет формы проверен на ПК/эмуляторе. Полный паритет продукта и внешний
доступ агента к открытому APK остаются предметом следующих шагов.
