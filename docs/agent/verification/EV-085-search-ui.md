# EV-085 — P05.07: интерфейс поиска карточек

Состояние: verified локально. Ветка `feat/p05-07-search-ui`, база
`20f34b356984bf674b7170fa94934c9d83f3ab6c`; исходное дерево чистое.

## Рабочая карточка

- Цель: поиск в текущем пространстве или везде через прежний `card.search`,
  очистка без смены области, порядок/конфликты и открытие свежей карточки.
- Требования: T08/A19/A34, разделы поиска/§11 продуктовой спецификации,
  ADR-0011/0048; зависимости P05.03/EV-078 и P04.07/EV-072 интегрированы.
- Охват: общий SearchPanel, минимальная интеграция SpacesView/workspace-api,
  стили существующей темы, shared browser/native сценарий и документация.
  Ядро, контракт, схема, зависимости, поиск Unicode и CI-бюджеты прежние.
- Обратные действия: смена/очистка запроса, переключение области, закрытие
  поиска и возврат к доске. Поиск не меняет карточки, порядок или историю.
- Отказы: доступ/некорректный ответ/поздний результат; старые результаты
  удаляются, ввод/область остаются. Новый поиск имеет новый случайный ID.
- Дизайн: прежние Segoe UI/Georgia и токены светлой/тёмной темы; форма и
  линейные результаты с группами пространств. Порядок передаётся Service.
- Размер >300 ручных строк обусловлен одним сценарием поиска: сам интерфейс,
  безопасное открытие результата другого пространства и его обязательная
  общая матрица desktop/touch/native, включая отказ и сохранность.
- Проверки: `bun run ui:check` Chrome/Opera; debug Android x86_64/aarch64;
  Device/agent-device, IME/Back/restart, сохранность исходного sandbox.
- Результат: локальная матрица ниже passed; commit/PR/push/новый CI/merge
  не выполнялись. Далее ревью и интеграция ветки; новый UI-шаг не начат.

## Границы

Настоящие данные поиска создаются прикладными командами через Service.
Проверка представления конфликтных групп на host использует отдельно
обозначенные валидные тестовые ответы; она не доказывает продуктовый обмен
или разрешение конфликтов P06. Физический arm64 и release UI вне этого шага.
Полные T08/A19/A34 до итоговой приёмки остаются partial.

## Реализация и локальная матрица

`SearchPanel.vue` передаёт исходный запрос и явную область в disposable
`card.search`. Список не сортируется по тексту браузером: отображаются группы
Service с сохранением порядка внутри них. Текущие варианты текста показаны
буквально, без HTML или загрузки изображений. Пустой запрос снимает текстовое
условие, сохраняя область. Выполненные карточки не скрываются.

Изменение ввода/области, новый поиск и unmount инвалидируют прежний ответ.
Ошибки убирают результаты, сохраняя форму; read не попадает в очередь мутаций.
Каждый поиск получает новый случайный ID. Старый поисковый snapshot не
используется для записи: открытие результата читает текущую карточку и каталог
тегов её пространства. Обычный редактор сохраняет прежние права/версии и
журнал намерений, после его изменений выполняется новый поиск. Фокус после
замены результатов возвращается в поле запроса. Ссылка на текущее пространство
закрывает поиск даже без изменения URL; ссылка на другое ведёт к его доске.

| Проверка | Доказательства |
| --- | --- |
| Текущая область/везде | Начальный пустой запрос, явное переключение, очистка без переключения; порядок пространств и доски, выполненные включены, корзина исключена |
| Текст | Full folding Straße/STRASSE, NFC Café/Café, «е»/«ё», точные внутренние пробелы/перенос/табуляция, буквальные C++/HTML, пустой и отсутствующий результат |
| Представление конфликтов | Валидные тестовые ответы host: ведущая группа имён, группа места внутри пространства, один результат и оба текущих варианта; после обычного ответа группы исчезают |
| Свежесть/редактор | Правка агента после поиска видна при открытии; теги другого пространства; выполнение/обратное действие обновляют результат, фокус возвращается в запрос |
| Ошибки/конкуренция | access_denied, некорректный контракт, потеря ответа; нет старых/частичных результатов или mutation pending; новый ID; поздний ответ старому запросу не заменяет новый |
| Сохранность | Snapshots/history неизменны после поиска/очистки; Android restart сохраняет данные и общий порядок, обратное выполнение сохраняет текст/место/историю |

Локальные debug APK x86_64/aarch64 собраны с проверкой manifest/launch identity.
Device/agent-device проверил настоящий IPC (22 новых поисковых receipt в
синтетической Android-базе), русский ввод/системную IME, Back, обе области,
очистку, точные пробелы и многострочный запрос, обе темы, просмотр/обратное
выполнение карточки другого пространства и перезапуск. Прямого управления UI
через adb/CDP не было. После остановки приложения на копии базы общим API
сверены исходные карточки/история и свежие результаты; исходные product/WebView
восстановлены: имена и SHA-256 всех 23 файлов совпали. Синтетические базы,
ключи/архивы удалены, Device выключен.

## Ограничения и история проверки

Полный host-набор и финальный переход по ссылке подтверждены ниже.

Следующий прогон ошибочно запустил host из другого Cargo target с прежним
однострочным полем; после штатного корневого CARGO_TARGET_DIR многострочный

validator не ослаблялся. Полный прогон Opera обнаружил неверное ожидание теста:
поиск «Всё» везде нашёл также данные прежнего Chrome-прохода той же fixture.
Проверка позднего ответа ограничена собственным пространством, параметры
поиска/таймауты/проверки продукта сохранены. Эти отказы — тестовая подготовка,
продуктовые GAP не открываются. Отдельно самопроверка добавила закрытие поиска
при переходе по ссылке на уже выбранное пространство и общую регрессию.

Новый native CI не запускался. Shared сценарий включён в существующий Android
CI, без изменения лимитов, матрицы и assertions прежних сценариев. Локальный
Device-прогон не выдаётся за исполнение CI-драйвера. Время нового CI не доказано.
Прежнее предупреждение Vite о chunk >500 kB сохраняется, bundle целиком не
оптимизируется в этом шаге. Физический arm64, release UI, P06 и итоговый P05
вне приёмки; T08/A19/A34 пока partial. Commit/PR/push/merge не выполнялись.

## Итог и пять правил

Полный `bun run ui:check` на Chrome/Opera завершился exit 0: vue-tsc, Vite,
fmt/Clippy -D warnings, три shell-теста, host/fixture и все прежние сценарии
lifecycle/editor/moves/tags/Markdown/replay/failures/navigation/themes passed.
Его результат относится к состоянию перед последней навигационной правкой.
После неё финальный `serve-shell` собран заново, типы проверены, весь
`checkSearch` прошёл в обоих браузерах на desktop и legacy touch 360px/тёмной
теме, включая переходы в текущее и другое пространство, автоматическое
обновление после обратного выполнения и возврат фокуса. Ошибок страницы,
непредусмотренных внешних запросов и горизонтального переполнения нет.

Обе финальные debug ABI собраны заново. Заключительный Device-прогон финального
APK подтвердил поиск и возврат в уже выбранную доску по её ссылке. Первое
касание heading-группы попало в свободное место, фактический link получен из
raw snapshot и нажат по его ref; обхода UI нет. Повторное восстановление
исходных 23 файлов побайтово подтверждено, Device снова выключен. После
финальных прогонов менялись только документы; отпечатки исходников сверены.

- Обратимость: очистка/смена области/закрытие поиска и возврат к доске;
  прежний редактор выполняет и отменяет отметку выполнения.
- Человек/агент: одинаковый `card.search`, права и актуальность, свежие
  чтения карточки/тегов перед обычными изменениями; прямой записи в SQLite нет.
- Документация: user/agent/development/ADR-0048 и журнал/очередь актуализированы.
- Паритет: Chrome/Opera desktop/touch, Android Device IPC/IME/Back/темы/restart
  и обе финальные debug ABI; native CI/физический arm64/release UI не заявлены.
- Источник истины: Service/CardStore; результат поиска, локальная форма и
  receipt не становятся основанием для автономного изменения данных.

P05.07 verified локально, T08/A19/A34 partial; определения всех 98 критериев
сохранены. Новых открытых GAP/BUG нет, прежние GAP/DEC неизменны. Далее ревью
