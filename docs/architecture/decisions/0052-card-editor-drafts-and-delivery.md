# ADR-0052: черновик редактора и подтверждение сохранения

Дата: 2026-11-08. Статус: техническое решение P05.03, проверка —
[EV-078](../../agent/verification/EV-078-card-editor.md).
Продуктовые ADR-0007/0008/0013 и контракт ADR-0049 сохраняются.

## Данные и полномочия

Текущая карточка остаётся в общем Rust/SQLite/Automerge-хранилище.
Vue содержит прочитанную проекцию и ввод; UI не пишет в SQLite и не кэширует
доску, права либо ключ. `zedone.draft.v1.shell.<id>` — локальный черновик:
ID, subject/space/card, исходная version, текущая пара title/description и
последняя подтверждённая пара для сравнения. Это ввод и предусловие, а не
авторитетная версия карточки. Формат проверяется при восстановлении.

Каждое открытие нового редактора получает независимый случайный ID черновика.
Восстановление существующего берёт его lifetime-lock через
[Web Locks](https://w3c.github.io/web-locks/). Второй контекст не может
перезаписать этот же черновик; при закрытии/аварии браузер освобождает lock.
Блокировка относится только к локальному вводу, не блокирует API-агента,
другое устройство или другой независимый редактор. Актуальность/сессии/права
по-прежнему проверяет ядро. Если lock API недоступен, редактор сообщает отказ,
вместо молчаливого допуска конкурирующих записей. Базовые браузеры и WebView
проверяются в EV-078; новые зависимости не нужны.

Черновик записывается синхронно на каждом input, до сетевой/IPC-доставки.
Ошибку хранилища видно отдельно; при ней новые запросы не отправляются,
а закрытие с обещанием сохранённого черновика невозможно. Удаление черновика
явно подтверждается и не отменяет уже отправленную команду. Нормальный выход
удаляет его только после подтверждения последнего ввода и завершения сессии.
Subject черновика и нового намерения совпадают; смена учётной записи не
перепривязывает старые ввод/команду. Получение материала доступа для подготовки
команды ограничено 10 секундами также для неотменяемого IPC.

## Сохранение и история

Явное «Редактировать» вызывает begin_editing. Его ID становится session.
При восстановлении сначала проверяется исходное незавершённое намерение;
после перезапуска старый begin receipt не используется для возобновления
прежней сессии. Новый ввод получает новое begin_editing по ADR-0049.

Debounce отправки — 500 мс, максимальное ожидание непрерывного ввода —
2 секунды при свободной очереди и доступном ядре. Запросы последовательны;
новое нажатие не отменяет уже принятую команду. IME composition сохраняется
локально и отправляется после compositionend. Заголовок только из Unicode
White_Space остаётся несохранённым вводом; последняя пара в карточке/истории
не заменяется пустой. Частота отправки не меняет 30-секундную границу серии
ядра и не создаёт видимую версию на каждую доставку.

Намерение сохраняется прежним prepare/CommandClient до доставки. Новый ввод
во время запроса изменяет только черновик, не ID/JSON/expected исходного
намерения. Пока выполняются попытки, показывается «Сохраняем…»; неизвестный
исход, отказ доступа, stale и ошибка persistence не становятся «Сохранено».
После успеха клиент читает текущую карточку: старый receipt не заменяет более
новые данные. Продолжать автоматическую серию можно только при совпадении
свежей version с подтверждённым результатом собственной команды.

При несовпадении автоматическая запись останавливается, ввод остаётся.
Текущее состояние показывается отдельно. «Сохранить мой текст вместо
показанного» — новое явное действие с version именно показанного состояния;
ещё одна внешняя правка отклонит его снова. Удаление записи проверки требует
отдельного подтверждения и не утверждает, что прежняя команда отменена.

Выполнение задаётся явным bool через card.set_completed и снимается той же
операцией. Несохранённый текст блокирует кнопку. Команда использует исходную
version всей карточки, без автоматического перечитывания/повтора со свежей
версией. После неизвестного результата выполняется исходный replay; поздняя
правка/обратная отметка сохраняется, а UI читает актуальное состояние.

## Выход и перезапуск

Закрытие диалога, Escape/Android Back и переход по маршруту проходят через
один guard. Валидный ввод отправляется и сессия завершается; при отказе,
пустом заголовке либо неизвестном исходе предупреждение получает фокус.
Можно остаться или явно закрыть с локальным черновиком. Во время завершения
закрытия поля не допускают новый ввод, который мог бы быть удалён вместе
с уже подтверждённым черновиком.

При уходе в фон выполняются flush и finish; при возвращении проверяется
исходная актуальность и начинается новая сессия. Нельзя рассчитывать на
завершение асинхронной доставки при pagehide/убийстве процесса. До этого уже
сохранены ввод и подготовленное намерение; при восстановлении пользователь
разрешает неизвестный исход, затем новая сессия завершает прежнюю серию.
beforeunload предупреждает о незафиксированном вводе/запросе. Перезапуск
нативного host сохраняет принятую recover_editing_sessions из ADR-0049.

Схема SQLite, Rust-контракт и зависимости не меняются. Просмотр/восстановление
истории в UI — P05.09, CommonMark — P05.04, обмен/конфликты — P06.
