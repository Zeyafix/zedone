## Граница и договор

P06.01 разделён до реализации: .1 — общий API управления доступами;
.2 — постоянный процесс подключения и защищённый канал; .3 — UI; .4 —
приёмка двух устройств. Приглашения/подтверждение/удалённая доставка секрета,
формы UI и синхронизация этим срезом не принимаются. Полные A08/A51/T09
и DEC-003 остаются открытыми в прежнем охвате.

[ADR-0053](../../architecture/decisions/0053-access-registration.md): получатель
готовит subject и секрет один раз, администратор регистрирует только verifier.
Секрет не попадает в JSON команды, pending intentions, receipts или ответ.
Verifier не принимается как Bearer. access.issue не перезаписывает существующий
subject; access.replace требует expected и новый ключ, сохраняет subject и
receipts. access.list выдаёт до 50 снимков с исключительным subject cursor.
Все операции требуют отдельно выданного администрирования. Время — доверенное,
общий диапазон 0…253402300799999, новая конечная граница позже времени операции.
Схема, зависимости, права, авторизация и источник истины прежние.

## Проверяемая матрица

| Область | Ожидаемый результат |
| --- | --- |
| Выдача | Новый subject, явные выбранные пространства, read/RW; исходный секрет не хранится в SQLite/командах/ответах |
| Разделение прав | Read не меняет данные и не администрирует; administration не открывает чужие пространства; невыданный ключ/verifier как Bearer отклоняются |
| Смена и отзыв | Смена read→RW→read с новым ключом, отзыв, новая явная выдача после отзыва; все старые ключи остаются невалидными |
| Актуальность | stale после отзыва, две одновременные смены одного preview — только одна успешна, другой ключ не активируется |
| Повторы | HTTP/IPC/настоящий CLI возвращают исходный receipt после позднего отзыва/повторной выдачи/restart без отмены позднего состояния |
| Валидация | Неверный subject/длина verifier, пустая область, неизвестное пространство, лишний key и отсутствие scope, прошлый/слишком большой срок отклоняются без выдачи |
| Последний администратор | Последнего бессрочного администратора нельзя понизить; после явной выдачи другому передача допустима без особого владельца |
| Список | До 50, строгий порядок, cursor, следующая/пустая страницы; новые чтения требуют нового ID, старый receipt не становится текущим списком |
| Срок | Исключительная граница: 199 допустимо, 200 запрещено; повтор выдачи не продлевает 200, новый ключ даёт новое разрешение; верхняя граница одинакова на обеих платформах |
| Атомарность | SQL-отказ записи receipt отменяет выдачу целиком; нет subject/ключа/receipt, исходный повтор после снятия отказа выполняется один раз |
| Клиент | Криптографическая подготовка ключа/verifier, намерение без секрета, неизменность исходных байтов/expected после потери ответа и restart; строгий производный валидатор |

Новые проверки входят в прежние targets commands и storage. Публичного fault
API, нового runner, смягчения лимитов или автоматических повторов тестов нет.
Локальная подготовка тестов потребовала исправить синтаксис json! массивов,
число paths и ошибочное ожидание свежего чтения при прежнем command ID;
это исправления новых тестов. Первоначальный диапазон SystemTime уточнён до
общего ограниченного wire-диапазона, после чего повторена итоговая матрица.

## Пять правил

- Обратимость: отзыв, смена прав в обе стороны и новая явная выдача; последний
  администратор сохраняется, локальные данные от управления доступом не удаляются.
- Человек/агент: один Service/core guard/HTTP/IPC/CLI; bootstrap не публикуется.
- Документация: user/agent/development, границы архитектуры и ADR-0053 обновлены.
- Паритет: одинаковый API и нативные проверки Windows/Android; форм UI в этом
  подшаге нет, их паритет относится к P06.01.3–.4.
- Единый источник: прежний Service/SQLite access_* и receipts, производные
  OpenAPI/типы/валидаторы; новый независимый кэш прав не введён.

срезом; браузерные сценарии UI/новый APK/физическое устройство/две реплики и

получателя требует защищённого хранилища/канала будущего host; helper не

выдачи остаются P06.01.3. T06 passed сохранён в прежнем объёме, A08 partial,
T09 not_run и A51 partial не повышаются, DEC-003 остаётся open.

P06.01.1 verified локально; P06.01/P06 in_progress. Commit/push/PR/CI/merge
