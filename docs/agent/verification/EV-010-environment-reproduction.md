## Исправление инструкции

Windows Quick Start устанавливал часть Android SDK-пакетов по незакреплённым именам. Теперь список берётся из `android.packages` и `command_line_tools` общего [JSON версий](../../../scripts/environment-versions.json), как в Linux CI. При проверке `source.properties` ID пакета отделяется от суффикса `@version`; наличие файла не подменяет проверку ревизии.

[Инструкция воспроизведения](../../development/environment-reproduction.md) задаёт режимы проверки, сохранение выбранных переменных, перечитывание Android User-переменных в Process, ожидаемые результаты, обратные действия и отчёт. Повторный запуск и переустановка инструментов на существующей ОС имеют разный охват; непроверенные части должны оставаться явно отмеченными. Проверка на совершенно чистой системе исключена решением разработчика от 2026-10-28 (LOG-098).

## Проверки общих изменений

Проверены синтаксис PowerShell-блоков, существование файлов по Markdown-ссылкам, парность блоков разметки, сохранность ID, этапов и полного текста всех 98 требований приёмки, а также `git diff --check`. Проверочные скрипты, workflows и JSON версий не изменены. Доказательства ранее интегрированных Windows/Linux CI находятся в [EV-008](EV-008-windows-environment-ci.md) и [EV-009](EV-009-android-environment-ci.md); они не выдаются за новые CI-запуски этого PR.

Аудит публикации охватывает полный diff и состав коммита. Фактические версии установленного ПО, инвентаризация, состояние устройств/подключений, профили, авторизация, пути пользователя, stdout/stderr и снимки не публикуются. Закреплённые проектом версии и целевые платформы в общих инструкциях являются требованиями, а не описанием текущего устройства. Машинные отчёты хранятся только в игнорируемой `docs/reports/`, загрузки — в `temp/`.

## Уточнение охвата — LOG-098, 2026-10-28

Основание — указание разработчика: «На совершенно чистой системе проводить проверки не будем». Исходная ревизия — `f406df137588bb15f2892dd8b57b1b02f4aab397`, рабочее дерево до изменения чистое. Цель изменения — исключить эту проверку из ожидаемого охвата P00/T17. Изменяются только общие инструкции, очередь, этот EV и план-журнал; локальная точка продолжения обновляется отдельно в игнорируемой `docs/reports/`.

Проверки выполняются на существующей ОС. Отсутствие проверки на чистой системе не является блокировкой и не записывается как успешный тест. Сохраняется ограничение доказательств: независимость от ранее установленных компонентов и сохранённых настроек не подтверждена. Изменение не отменяет других проверок, не разрешает новую переустановку инструментов и не меняет состояние приёмки автоматически.

Проверка изменения: локальные ссылки и блоки Markdown, сохранность всех 98 ID и состояний критериев, неизменность остальных требований, полный diff и `git diff --check`. Скрипты, workflows, JSON версий и продуктовый код не меняются; новые проверки окружения и CI не запускаются. Обратное действие — явный пересмотр охвата разработчиком с сохранением истории решений. Следующее действие — сверить оставшийся охват P00/T13–T17 по имеющимся доказательствам.
