# ADR-0069: явный выбор сохранённой позиции колонки

Дата: 2026-11-17. Статус: реализовано в P06.06.2 и интегрировано PR #107/531cf34 после всех 18 успешных проверок; приёмка
[EV-115](../../agent/verification/EV-115-column-position-conflicts.md).

## Решение

`column.inspect_positions` возвращает снимок колонки и сохранённые ранги с
ближайшим однозначно размещённым соседом либо концом списка. Подпись вычисляет
ядро по существующему Rank/ID-порядку ADR-0045; колонки со спорным только именем
могут быть соседями. Собственные спорные позиции и удаления соседа исключаются.
Это описание текущего окружения, а не инструкция пересчитать выбранный ранг.

`column.resolve_position` принимает исходный ранг и актуальную версию колонки.
Общий Service под writer lock проверяет ReadWrite/replay, версию, несколько
сохранённых позиций, отсутствие удаления и активное пространство. Собственный
конфликт имени не запрещает выбрать позицию и сохраняется после выбора.
Обычная `column.move` по-прежнему блокирует собственные конфликты.

Запись удаляет прежние значения `position` и заново присваивает выбранное
значение в одной Automerge/SQLite транзакции с receipt. По результату P06.06.1
простого put наблюдаемого победителя недостаточно для нового независимого
решения. Две разные независимые позиции должны снова конфликтовать; одинаковые
сходятся по существующему семантическому чтению register. Новая схема данных,
протокол обмена, зависимости и пересчёт рангов соседей не нужны.

UI показывает спорную колонку с её карточками один раз в области «Конфликты»
перед обычной доской. Изменения самой колонки заблокированы, явный выбор позиции
и имени доступны независимо. Содержимое активной колонки доступно с учётом
собственных конфликтов карточек. При перемещении карточки в такую колонку
используется её собственный порядок карточек, независимо от позиции колонки.
Спорная колонка не может служить обычным соседом для перемещения другой колонки.

Форма требует явного выбора без предварительно отмеченного варианта. Отмена
не записывает доменное изменение. Ошибки/неизвестный исход используют общую
очередь намерений; обновление не подменяет параметры старого решения. Версия
колонки по-прежнему учитывает содержимое, поэтому правка карточки может сделать
открытое решение устаревшим. Обратное действие — новая `column.move` после
разрешения собственных конфликтов. ID, карточки и их история не меняются выбором.

## Границы

Приёмка P06.06.2 проверяет выбор колонки, доступность содержимого, независимые
решения и одинаковых соседей на общем контракте. Совместная матрица конфликтов
карточек и колонок — родитель P06.06. Полный T09, GAP-028/031, настоящий
Tailscale, целевой arm64 runtime и измерения не закрываются этим решением.

P06.06.2 также снимает ограничение позиции целевой колонки у `card.restore`
и в списке UI восстановления: спорное место колонки не меняет место карточки
внутри неё. Прежние проверки lifecycle, имени, версии, прав и собственного
состояния карточки сохраняются. Цикл trash/restore проверяется общими
HTTP/IPC/CLI и настоящим APK; карточка возвращается с прежним ID и историей.
