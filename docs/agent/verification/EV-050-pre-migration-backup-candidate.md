# EV-050: согласованный кандидат предмиграционного комплекта

Шаг: P07.07.1. База: `5c2cf33`, ветка `feat/p07-07-pre-migration-backup`.
Состояние: `verified` локально, без коммита/PR/CI/интеграции.

## Карточка

- Цель: отдельно создать и повторно проверить полную SQLite-копию и снимки
  всех пространств из одного состояния, сохраняя исходник и прежние копии.
- Требования: спецификация §1/1.1, T10/A28/A44/M03, DEC-006;
  [ADR-0033](../../architecture/decisions/0033-pre-migration-backup-candidate.md).
- Зависимости: P07.01/EV-049 в `5c2cf33`, P03.03/EV-046 в `ecb68b8`.
- Scope: `storage::migration_backup`, crate-visible прежний capture, общая
  проверка схемы без смены SQL, feature backup закреплённого rusqlite,
  tempfile dev → runtime без новой версии; проверки и документация.
- Проверки: `bun scripts/check-product.mjs` на Windows и
  `bun scripts/check-product.mjs --android` в нативном AOSP API33/x86_64,
  release/unsafe обеих Android ABI. Инструменты не устанавливаются.
- Обратимость/отказы: явный discard только своего кандидата; обратная правка
  в исходнике/restart сохраняет старые копии, ошибки не перезаписывают файлы.
- Размер: ориентир 300 строк превышен одним вопросом проверки полноты и
  сохранности комплекта SQLite/файлов, включая матрицу реальных отказов.

## Матрица проверок

11 новых `migration_backup::tests` входят в обычный product-check:

1. Полная SQLite-копия из живого WAL, точное содержимое всех таблиц/actor/peer/
   receipts, те же изменения во всех архивах, Unicode/ID с `../`, пустые
   пространства и ожидающая зависимость. Архивы не содержат служебные секреты.
   Исходные DB/WAL побайтово неизменны; копия автономна без WAL.
2. Обратная правка/restart и следующий кандидат сохраняют прежние файлы;
   drop сохраняет завершённый кандидат, discard удаляет только выбранный.
3. Отказы пяти бюджетов: база, число пространств, сумма архивов, размер/число
   изменений одного архива; исходник и прежний кандидат неизменны.
4. Отсутствующая папка и файл вместо каталога дают настоящий файловый отказ,
   без создания отсутствующей папки, fallback или изменения существующего файла.
5. Ошибка на каждой из пяти стадий создания/проверки не меняет исходник и старые
   копии; незавершённый собственный каталог удаляется.
6. Отсутствие/повреждение каждого файла, несогласованная дата манифеста,
   посторонние WAL/SHM/journal и каталог отклоняются; возвращённый исходный
   файл снова проходит проверку.
7. Конкурирующий SQLite writer получает SQLITE_BUSY под захватом; подтверждение
   его отказа получено до продолжения захвата.
8. Новая схема, пропущенная таблица, испорченный raw change и нарушенная внешняя
   ссылка исходника не дают проверенного кандидата и сохраняют исходные DB/WAL.
9. Повторно вычисленный SHA-256 не обходит проверку схемы/графа/FK/состава архивов.
10. Пустая база без пространств проверяется; синтетический незавершённый каталог
    не принимается, не удаляется и не мешает созданию нового кандидата.
11. Отмена ожидания после admission сохраняет полностью проверенный кандидат.

## Ограничения и передача

Это внутренний захват схемы 1. Продуктовые полномочия на всю базу, миграция,
проверка её результата и безопасная замена прежнего комплекта не реализованы.
Права не выдаются по наличию файла. Нет публичного UI/API, доменной модели P04,
импорта/восстановления/паузы/ротации или аварийного отката. Не проверены питание,
crash-публикация, физический arm64/APK, локальный Linux и производительность
всего приложения; arm64 release не считается нативным исполнением.
Бюджеты входа не являются гарантией пика памяти.

T10/A28/A44/M03 остаются частичными, M04 относится к P07.07.2 и не закрывается.
DEC-006 open. P07.07/P07 целиком не завершены. После локальной проверки —
публикация по поручению; после интеграции оценить P07.07.2. P07.08 ждёт весь
P07.07; защита от оживления старых намерений при откате по ADR-0030 сохраняется.

## Результат локальной проверки

Оба финальных product-check завершились с кодом 0:

| Проверка | Windows | Android |
| --- | --- | --- |
| Access/contract/storage | 10 + 7 + 62 passed | Те же 79 passed нативно x86_64 |
| Новые тесты комплекта | 11 passed | Те же 11 passed |
| fmt/Clippy/release host | passed | Host fmt/Clippy покрывают общие исходники |
| Release всех targets/features | passed | x86_64 + arm64 passed |
| Негативные компиляции unsafe | 4 отказа | 8 отказов двух ABI |
| Rust/OpenAPI/TypeScript | совпадают, TS compiled | Те же артефакты, native OpenAPI совпадает |

После первых целевых исправлений SQL-типов/импорта/Vec/тестового FK-отказа
выполнены полные прогоны. В итоговом просмотре добавлен отказ посторонним
sidecar-файлам; после него оба финальных прогона повторены. Runtime после
финальных прогонов не менялся. Изменений SQL/версий/Cargo.lock/API/прототипов/CI
нет; общая проверка схемы извлечена без второй копии SQL. Локальные условия,
полные логи, SHA-256 исходников и очистка — `docs/reports/p07-07-1/verification.json`.
Собственный read-only AVD остановлен, remote sandbox пуст; физические устройства
и инструменты не менялись. Локальный Linux, physical arm64 и APK не проверялись.

Пять правил: явный discard/обратная правка и сохранность прежних копий;
единая инфраструктура без публичного обхода прав; документация обновлена
(пользовательского поведения ещё нет); одинаковые тесты Windows/Android;
одна авторитетная SQLite/Automerge, без второй модели текущего состояния.
