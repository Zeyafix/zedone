# ADR-0032: версионированный снимок журнала пространства

Дата: 2026-11-05.

Статус: техническое решение P07.01 в границах DEC-006. Требования экспорта,
импорта и восстановления не меняются. Проверки —
[EV-049](../../agent/verification/EV-049-space-snapshot-format.md).

## Решение

`zedone-storage::snapshot` задаёт внутренний двоичный контейнер одного
пространства. Обычный архиватор и представление без ZeDone не требуются.
JSON-массивы байтов дали бы ненужный рост размера; ZIP добавил бы зависимость,
извлечение путей и сжатие без требуемой продуктовой пользы. Используются уже
закреплённые Automerge/Serde/sha2, без новых пакетов и изменения схемы SQLite 1.

Содержимое v1, в указанном порядке; целые числа — little-endian:

| Поле | Представление |
| --- | --- |
| Сигнатура | 8 байт ASCII `ZEDSPACE` |
| Версия контейнера | u32, значение 1 |
| Длина метаданных | u64, число UTF-8-байтов JSON |
| Число изменений | u64 |
| Метаданные | Строгий JSON `SnapshotMetadata`: непустой непрозрачный `space`, u64 `created_at_unix_ms` |
| Каждое изменение | u64 длины и ровно столько байтов `Change::raw_bytes()` |
| Контрольная сумма | 32 байта SHA-256 всех предшествующих байтов, включая заголовок |

Изменения следуют строго по возрастанию полного Automerge hash; повторы и иной
порядок отклоняются. Допускаются только несжатые change chunks Automerge,
которые возвращает `raw_bytes()`: chunk type 1 по смещению 8. Сжатый chunk
отклоняется до распаковки библиотекой. Проверяются парсинг операций, отсутствие
остатка и внутренний checksum: первые четыре байта hash против байтов 4–7
исходной записи. `Change::try_from` сам эту последнюю проверку не обеспечивает.
Совместимость совокупности изменений проверяется применением в отдельном графе;
изменения с отсутствующими зависимостями сохраняются как ожидающие.

Основания — закреплённые первичные исходники
[Change](https://docs.rs/crate/automerge/0.12.0/source/src/change.rs) и
[chunk](https://docs.rs/crate/automerge/0.12.0/source/src/storage/chunk.rs).
Использование их двоичного представления явно закреплено версией контейнера
и эталоном, а не предположением о совместимости любой будущей версии библиотеки.

## Полнота и границы

`Storage::snapshot` выполняется на worker в одной SQLite read-транзакции
с проверкой схемы. Извлекаются все строки `changes` выбранного `space`,
включая ожидающие зависимости; hash каждой строки сверяется с разобранной
записью. Нельзя подменять этот журнал `get_changes`, heads или save/view:
неприменённые изменения могут потеряться. Предварительная оценка размера,
чтение строк и проверка принадлежат одному снимку SQLite даже при записи
другим worker. Полученный объект автономен и не меняется вместе с базой.

Объекты, корзина, история и конфликты сохраняются как части того же графа,
без второй модели полей. P07.01 проверяет синтетический граф; полной продуктовой
модели P04 ещё нет. Формат не объявляет произвольный граф валидным пространством
продукта: проверка доменной схемы обязательна перед будущим импортом/восстановлением.
Это начальный внутренний формат, не утверждение о ранее выпущенных форматах.

В контейнер не входят локальный actor для продолжения записи, peer progress,
receipts, права, учётные данные и настройки установки. Исторические actor IDs
внутри самих CRDT-изменений сохраняются, но не выдают права. Исходный `space`
нужен для идентичности при восстановлении; независимый импорт должен выделить
новые ID и реализуется отдельно. Дата поступает от доверенного вызывающего
кода, не доказывает свежесть, не управляет правами или дневным лимитом.
Имя для будущего каталога выводится из продуктового графа при его появлении;
нынешний непрозрачный ID не считается отображаемым названием.

SHA-256 обнаруживает повреждения, но не подтверждает автора или доверие к файлу.
Архив содержит данные пространства открытым текстом в двоичном представлении;
шифрования и цифровой подписи нет. Чтение метаданных также требует успешной
проверки всего контейнера; нельзя ротировать копии по непроверенному заголовку.

## Отказы и ресурсы

Декодер получает неизменяемый `&[u8]` и не владеет исходным файлом/базой.
Ошибочная/неподдерживаемая копия не преобразуется на месте. Лишние байты,
неизвестные/двойные JSON-поля, неверные длины, записи и checksum дают отказ.
Неизвестная версия — отдельный `UnsupportedVersion`, без попытки угадать формат.
Будущие преобразования работают с отдельной копией и сохраняют исходник.

Каждый вызов получает явные `SnapshotLimits` для числа байтов и изменений.
Внутренних продуктовых лимитов нет. Перед чтением BLOB из SQLite размер
оценивается SQL в той же транзакции; декодер проверяет размер slice до хеширования,
число записей и доступность диапазонов до выделений по этим данным. Ошибка
бюджета захвата отображается в существующий storage `Unavailable`, декодер
возвращает `LimitExceeded`. Ошибка журнала — `InvalidDatabase`.

Эти бюджеты ограничивают вход, но не являются гарантией пика памяти/времени.
Контейнер, разобранные изменения и проверочный граф сейчас находятся в памяти.
Будущий файловый адаптер обязан ограничивать чтение до передачи slice; выбор
бюджетов/изоляции и измерения всего сценария нужны до его публичного включения.
Потоковый перенос и сжатие сейчас не добавляются без измеренной необходимости.

## Доступ, восстановление и совместимость

`Storage::snapshot` — доверенная инфраструктура, как `Storage::read`, без
публичного HTTP/CLI/IPC/UI-входа. Это не обход `core::access`: перед внешним
подключением авторизация и захват должны быть скомпонованы в одной транзакции,
со свежей проверкой после очереди. Декодирование файла не разрешает запись.

Загрузка графа в тесте проверяет чтение формата, а не продуктовое восстановление.
Нет записи архива в рабочую базу, восстановления старого actor/receipts,
отката состояния или автоматического импорта. Для P07.03/P07.09 сохраняются
защита старых намерений ADR-0030, отдельные права, страховочные копии,
пауза обмена и новое причинное действие. Полная копия базы для миграции P07.07
отдельна от контейнера пространства и включает служебные данные.

Эталон `crates/storage/tests/fixtures/space-v1.bin` содержит фиксированные
синтетические ID, Unicode, дату и одну правку. Он читается и воспроизводится
побайтово. При новых форматах прежние эталоны не перезаписываются; совместимость
официально выпущенных форматов проверяется по мере их появления. M07 целиком
и T10/A09/A25 этим внутренним срезом не закрываются.
