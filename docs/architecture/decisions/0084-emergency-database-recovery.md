# ADR-0084 — Аварийное восстановление базы вне обычных полномочий

Дата: 2026-11-28. P07.09; §1.1.5/6, ADR-0030/0033/0034/0036/0083.
Результаты и ограничения проверок — [EV-164](../../agent/verification/EV-164-emergency-database-recovery.md).

Служебное состояние, отдельный владелец, выдаваемые агентам права, receipts и
признак незавершённой замены хранятся рядом с базой в `.maintenance`, а не
в восстанавливаемой SQLite. Обычный ключ, включая Administration, не разрешает
аварийное восстановление. Локальный владелец может выдать чтение сведений либо
явное право восстановления, задать срок и отозвать доступ. Проверка права
предшествует replay; срок повторно проверяется перед публикацией эффекта.
Откат календарных часов ниже сохранённой отметки закрывает служебные действия.

Обычные workers удерживают общую файловую блокировку установки. Для захвата
и замены требуется исключительная блокировка после подтверждённого завершения
workers и остановки контроллеров обмена. Отказ блокировки не разрешает замену.
Межпроцессная control-блокировка сериализует внешнее служебное состояние.
Эти блокировки координируют процессы ZeDone; произвольный внешний писатель,
игнорирующий блокировки ОС, не является поддерживаемым владельцем базы.

После отказа запуска сохраняется raw-комплект ADR-0083; ошибка сохранения
закрывает замену. Prepare копирует полный предмиграционный комплект в staging,
проверяет manifest, бюджеты, хеши, SQLite и все снимки пространств. Только
рабочая копия мигрируется и очищается от прежнего доверия. Исходные исправные
копии и проблемный комплект сохраняются.

В кандидате отзываются старые ключи и субъекты, удаляются подключения,
приглашения и незавершённый входящий обмен, пространства ставятся на паузу.
Создаются новая локальная сессия, actors и namespace ключей устройства.
Старые файловые полномочия, очереди переноса/удаления копий и миграционное
свидетельство отсоединяются. Daily policy сохраняется, ссылки для ротации и
очистки снимаются, namespace новых ежедневных файлов меняется. Автоматическая
запись ждёт явного выбора папки с правом управления; выбор только для чтения
этот запрет не снимает. Прежние файлы доступны через каталог после выбора
папки. Полный откат возвращает исторические сведения политики, а не создаёт
новую гарантию дневного лимита относительно утраченного будущего состояния.

До изменения рабочей базы записываются внешний phase Applying и привязка
к исходному намерению. Замена сверяет raw и кандидат, удаляет только известные
sidecars, публикует проверенный файл через временный файл с sync, затем новую
локальную идентичность. Только после этого снимается durable запрет запуска.
Поколение записано в базе и внешнем состоянии; старый/пустой/утраченный файл
не становится обычной новой установкой. Утрата внешних метаданных не создаёт
автоматически нового владельца или историю повторов.

Прерванная замена сама при старте не продолжается. Требуется исходная команда
с прежним ID/параметрами либо отдельное подтверждённое Continue владельца.
Superseded-намерения получают сохранённый результат без повторной замены.
Подготовку можно отменить без изменения базы. Rollback возвращает сохранённые
проблемные байты, оставляя обычный доступ закрытым; возврат к обычной работе
требует отдельной успешной проверки с новой идентичностью. Raw удаляется
отдельной явной командой с durable manifest для продолжения после сбоя.

Общий `maintenance.execute` используется HTTP, CLI и IPC. UI показывает
причину, выбранную копию, охват всей базы и последствия; destructive действия
требуют отдельного подтверждения. Выбор локальной папки/Android SAF — доверенный
порт владельца; обычное право пространства не выдаёт файлового полномочия.
Клиент хранит исходное намерение до доставки и повторяет тот же запрос при
неизвестном результате. Credentials в намерение не записываются.

Sync и атомарные переименования проверяются тестами process-exit; аппаратный
power-loss и физический arm64 runtime требуют отдельных доказательств.
