Один вопрос проверки — воспроизводима ли минимальная основа для следующих
прототипов. Rust crate намеренно не содержит операций или контрактов; тестов
прикладного поведения пока нет. Внешних зависимостей нет. Добавлены один Rust
workspace с lock-файлом и runner на Bun без Node.js или shell-команд.
Версии инструментов берутся из существующего общего JSON.

[Инструкция](../../development/prototypes.md) задаёт структуру, границы изоляции,
команды, очистку и сценарии P01. Там же выбран начальный синтетический профиль
данных, условия времени, повторы, статистика и отдельная матрица платформ.
Генератор появится с моделью данных; измерения A62 ещё не проводились.

Каркас не обращается к данным приложения, сети или устройствам. Результаты Cargo
направлены в `prototypes/target/` с переопределением унаследованного
`CARGO_TARGET_DIR`. Для будущей БД требуется явный каталог отдельного запуска
в `temp/prototypes/`; переход к пользовательскому хранилищу по умолчанию запрещён.
Исполнение этого требования ещё проверяется в P01.05, где появится хранилище.

## Проверка и ограничения

Общая команда проверена в подготовленной среде Windows и новой копии исходников
без результатов сборки. После очистки выполняется повторная сборка. Неверная
версия Bun останавливает проверку до Cargo; ошибка компиляции останавливает
последующие команды. Исходный lock-файл не меняется. Сырые журналы и отпечатки
проверенных файлов остаются в игнорируемой `docs/reports/`.

Workflow проходит статическую проверку actionlint, но Windows/Linux Actions
этой ветки не запускались. P01.01 имеет `verified`, а не `done`; коммита,
публикации и слияния нет. Проверенная основа — рабочее дерево поверх указанной
базы; при публикации проверить полный diff и указать SHA новой ревизии.

Вклад в T01 — только начальная цепочка Rust/Bun; Vue/TypeScript/Vite/Tauri,
OpenAPI, клиент и Markdown не проверены. A62 остаётся `not_run`: методика не
заменяет измерения полного среза. DEC-001/007/009 остаются открытыми в оставшемся
объёме. Linux-host, Android-эмулятор, APK и физический телефон не принимаются
локальной Windows-сборкой. Будущая совместимость Bun с генераторами и потребность
в Node.js проверяются отдельно.

Обратимость проверяется очисткой и повторной сборкой. Человек и агент используют
одну команду; прикладной API ещё отсутствует. Документация обновлена. Паритет
Windows/Android задан матрицей и остаётся непроверенным. Источники истины сохранены:
версии в общем JSON, Rust-зависимости в lock-файле workspace, результаты приёмки
в журнале, состояние шагов в очереди, машинные сведения только в локальных отчётах.
