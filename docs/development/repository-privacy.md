# Публикуемые данные репозитория

В Git сохраняются требования, исходники и воспроизводимые команды. Целевые конфигурации ПК и телефона в [спецификации](../architecture/product-spec.md#целевые-устройства-и-нагрузка) — средства проверки проекта. Они не описывают личные устройства разработчика и не подтверждают наличие оборудования или результаты измерений.

Инвентаризация конкретной машины, абсолютные пути, имена хостов, сетевые адреса, идентификаторы устройств, сведения об учётных записях, stdout/stderr и снимки настроек остаются в игнорируемой `docs/reports/`. Удаляемые загрузки и примеры находятся в `temp/`. Правила действуют одинаково для человека и агента; локальные результаты не включаются в общие EV и журнал.

## Перед первым коммитом

Выберите GitHub noreply из настроек своего GitHub-аккаунта и задайте его только для этого репозитория. Перед изменением запишите прежнее локальное значение в локальный отчёт; при отсутствии локального значения используется глобальное.

```powershell
git config --local --get user.email
git config --local user.email '<your GitHub noreply address>'
git config --local push.default simple
git var GIT_AUTHOR_IDENT
git var GIT_COMMITTER_IDENT
```

Проверьте обе идентичности: переменные `GIT_AUTHOR_EMAIL` и `GIT_COMMITTER_EMAIL` могут переопределить настройку. Адрес noreply влияет на новые коммиты; личный email в старых коммитах от этого не исчезает. Для отмены верните прежнее локальное значение, а если его не было — выполните `git config --local --unset user.email`. Аналогично восстанавливается прежний `push.default`.

## Проверка перед отправкой

[`.gitignore`](../../.gitignore) исключает локальное окружение, учётные данные, закрытые ключи, материалы подписи, Android SDK-пути и состояние редакторов. Файлы `.env.example`, `.env.sample`, `.env.template` разрешены только с вымышленными значениями. Исключения не защищают содержимое обычных документов, уже отслеживаемые файлы или `git add -f`.

Перед коммитом и отправкой проверьте состав изменений и авторские метаданные. Вывод потенциально чувствительных строк анализируйте локально, не копируя значения в общую документацию, PR или чат.

```powershell
git status --short
git diff --cached --name-status
git diff --cached
git ls-files -ci --exclude-standard
git log -1 --format=fuller
```

Проверка `git ls-files -ci --exclude-standard` должна быть пустой. Если файл уже отслеживается, сначала сохраните нужные данные локально, затем уберите его из индекса; добавления правила в `.gitignore` недостаточно. Отзыв реального опубликованного секрета и очистка истории рассматриваются отдельно от удаления файла.

## Служебные refs остаются локальными

Отправляйте только именованные ветки и теги. `refs/t3/`, `refs/original/`, stash и другие служебные refs могут содержать локальные снимки. Не используйте зеркальную отправку рабочей копии. `push.default simple` ограничивает обычный push текущей веткой с согласованным upstream, но не отменяет явно переданные refspec.

[Проверка pre-push](../../scripts/git-pre-push.sh) отклоняет обновление, если исходный или целевой ref не является веткой или тегом; `HEAD` разрешён, когда он указывает на текущую именованную ветку с отправляемым коммитом. Удаление обычной ветки или тега разрешено. При наличии нескольких обновлений отказ любого из них отменяет всю отправку. Это защищает в том числе от отправки служебных refs через `--mirror`. Проверка не ищет секреты в содержимом файлов.

Git не устанавливает hooks при клонировании. В PowerShell из корня рабочей копии установите проверку в активный каталог hooks, сохранив существующий обработчик:

```powershell
$privacyHookPath = git rev-parse --git-path hooks/pre-push
if ($LASTEXITCODE -ne 0) { throw 'Не удалось определить каталог Git hooks.' }
if (Test-Path -LiteralPath $privacyHookPath) {
    throw 'Существующий pre-push нужно сохранить и включить в него вызов scripts/git-pre-push.sh.'
}
New-Item -ItemType Directory -Path (Split-Path $privacyHookPath) -Force | Out-Null
Copy-Item -LiteralPath scripts/git-pre-push.sh -Destination $privacyHookPath
```

На Linux/macOS после копирования добавьте право выполнения: `chmod +x "$(git rev-parse --git-path hooks/pre-push)"`. Git for Windows выполняет shell-hook через свой `sh`. После изменения скрипта обновите установленную копию, предварительно сверив, что она не содержит чужих изменений. Для отмены удалите только собственную установленную копию; существующие hooks и служебные refs удалять не требуется. Существующий hook должен передать исходный stdin проверке, а не уже прочитанный поток.

## Уже опубликованные данные

Исправление рабочего дерева не удаляет старые файловые версии и авторские метаданные. Переписывание опубликованной истории меняет SHA, подписи и ссылки на коммиты, может потребовать обновления рабочих копий и не удаляет чужие клоны или кэш GitHub. Перед ним нужны локальная резервная копия, проверенный результат в отдельной копии и согласованная замена удалённых refs с проверкой ожидаемой исходной ревизии. Резервная копия с исходными данными остаётся в игнорируемой `docs/reports/`.
