# EV-036 — карточка: корзина против независимой правки

## Карточка P02.05.1

- База: `f3ad72446940a823961a6974de4d13f53adf60fa`, чистая актуальная main.
- Зависимости: P02.03 (PR #21/#24, EV-027/029), P02.04 (PR #25/#27–#30,
  EV-030/032–035). PR #30 head `9c976ad` интегрирован в `f3ad724`;
  финальные Windows/Linux/Android checks SUCCESS, исходная ветка удалена.
- Цель: в изолированном пробнике сохранить карточку и независимые правки
  при отправке в корзину; явно выбрать корзину или восстановление.
- Требования: T05/A14, спецификация §1.2.4, §6–7, сценарий 14; общий запрет
  обычных правок карточки с конфликтом, проверка актуальности ADR-0007.
- Охват: новый модуль синтетического пробника, общий CLI/драйвер, проверки,
  документация и актуализация завершённого P02.04.3. Продуктовые входы,
  права, контейнеры, окончательная очистка и история вне этого среза.
- Оценка до кода: P02.05 разделён на .1 карточку, .2 группы контейнеров,
  .3 окончательную очистку/старую реплику, .4 очистку истории. Одна цель .1
  включает пару корзина/восстановление, оба решения, конкуренцию и атомарность;
  превышение ориентира 300 строк допустимо ради неделимой матрицы сохранности.
- Модель: неизменяемые Map-присваивания полей и регистра состояния. Каждая
  обычная правка в той же транзакции подтверждает активность карточки;
  независимое удаление остаётся конкурентным вариантом. Выбор поля при
  конфликте не выбирает состояние карточки неявно. Часы не используются.
- Фикстура: две карточки со стабильными ID; заголовок, текст, выполнение,
  целая позиция и одно назначение тега. Полная модель тегов/порядка проверяется
  прежними пробниками и не заменяется этой ограниченной фикстурой.
- Проверки: `bun run check` Windows; `bun run check:automerge --android`
  (API 33/x86_64, сборка arm64); отдельные CLI-процессы, оба решения,
  равные/разные/поздние решения, повторы/перестановки/SQLite reload,
  устаревший выбор, блокировки и AFTER UPDATE ABORT без частичной записи.
- Обратное действие: обычное восстановление с тем же ID/данными; повторное
  удаление после восстановления. Отказ не меняет документ/actor/peer.

## Проверяемая матрица

| Сценарий | Проверяемое поведение |
| --- | --- |
| Удаление против каждого поля | Заголовок, текст, выполнение, целая позиция и назначение сохраняются; оба решения доступны, ID/остальные поля не меняются |
| Блокировки/актуальность | Все обычные правки спорной карточки и карточки в корзине отвергаются с допустимыми значениями полей; другая карточка доступна и не обесценивает выбор; устаревший/чужой снимок, неверные поля/значения/позиция отвергаются без записи |
| Обратные состояния | Корзина → восстановление → корзина сохраняют ID и все поля; после восстановления обычное редактирование снова доступно |
| Конкурирующие решения | Равные решения не конфликтуют, разные сохраняются; допустимая правка после локального восстановления и позднее решение третьего независимого writer не теряются |
| Несколько конфликтов | Выбор состояния не снимает собственный конфликт текста; выбор текста не восстанавливает спорную/удалённую карточку; оба порядка явного разрешения допустимы |
| Старая реплика | Не виденная ранее независимая правка создаёт новый явный конфликт; рассмотренные старые, повторные и переставленные изменения после SQLite reload не возвращают карточку на доску |
| Атомарность | Одна правка с подтверждением активности — одна Automerge-транзакция; AFTER UPDATE ABORT при удалении, восстановлении, обоих решениях и правке сохраняет документы/actor/peer обеих реплик после открытия SQLite заново |
| Процессы | Три новые фазы в общих драйверах проверяют оба решения и обратные действия отдельными нативными процессами; повтор prepare не перезаписывает непустую фикстуру |
