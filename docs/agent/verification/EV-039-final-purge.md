# EV-039 — окончательная очистка и поздние изменения

## Карточка P02.05.3

- База: `4e7c5e1`, ветка `feat/p02-05-purge-history`, создана от чистой main.
- Зависимости: P02.05.1/EV-036, P02.05.2/EV-037/EV-038; последний PR #33
  head `6bd153b`, merge `4e7c5e1`, три PR checks SUCCESS.
- Цель: выбранная/вся корзина очищается атомарно; независимые поздние данные
  требуют явного выбора и минимального восстановления, старые не возвращаются.
- Требования: T05/A06/S07/S09, спецификация §1.2/4/7 и сценарии 6/7/9.
- Оценка до кода: один срез причинной границы, списка объектов/конфликтов,
  обоих решений, минимального восстановления и отказов; ориентир 300 строк
  превышается матрицей сохранности. История — отдельный P02.05.4/EV-040.
- Область: расширение изолированной иерархии EV-038, общий Rust/CLI/SQLite,
  тесты и документация. Продуктового формата/прав/зависимостей нет.
- Модель: регистр `life=purged` каждого затронутого объекта — причинная
  граница; независимое подтверждение активности остаётся вариантом. Все
  очищенные объекты исключены из логической выдачи, в корзине их тоже нет.
  Сырой граф Automerge хранит прежние байты: это логическая очистка,
  не безопасное стирание носителя. Физическое сокращение — P02.06.
  Постоянные `barriers` контейнеров содержат причинные ID известных объектов;
  монотонная Map `acknowledged` отличает новые создания после получения
  границы от поздних созданий со старой реплики даже после восстановления
  предков. Явное подтверждение очистки позднего контейнера тоже пишет границу.
- Проверки: выбранная/вся корзина, прежняя корзина, восстановленная в другую
  колонку карточка, другое пространство, список конфликтов и отказ всей операции,
  все пять полей, позднее создание, минимальные предки, равные/разные решения,
  старая реплика, повтор/перестановка, SQLite reload и AFTER UPDATE ABORT.
  Общие Windows `bun run check`, Android `bun run check:automerge --android`.
- Обратимость: обычная корзина остаётся обратимой; явная окончательная
  очистка — согласованное исключение. Поздние изменения сохраняются для
  обоих решений; обычное восстановление не обходит причинную границу.
