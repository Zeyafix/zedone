# Совместимость и восстановление обмена

Обе платформы используют общий guard core/storage/DeviceHost; UI, HTTP,
IPC и CLI не выбирают собственную политику совместимости.

| Отправитель / получатель | Решение |
| --- | --- |
| Protocol 1 / space format 1 с обеих сторон | Поддержано текущей реализацией Windows/Android. |
| Разные номера приложения, тот же поддержанный protocol/format | Номера приложения не передаются и не сравниваются. Отдельных выпущенных старых версий пока нет. |
| Неизвестный protocol или числовой format каталога | `incompatible_sync`, локальная работа и подключение сохраняются. |
| Неизвестный строковый маркер формата полного документа | `incompatible_sync`, пользовательский граф/история/progress не меняются. |
| Повреждённые changes, missing deps, ложные base/heads, чужой pairing | Отказ в запросе; не считается несовместимостью исправного формата. |
| Более новая/чужая локальная схема SQLite | Отдельный startup gate; отказ в записи без миграции/сброса. Не является тестом совместимости обмена. |

Возобновление использует сохранённые hashes. Потерянный запрос, ответ или push
ack не требуют нового идентификатора пространства/подключения. Незавершённая
первая загрузка остаётся скрыта; последняя страница и progress атомарны.
Автоматический цикл не зависит от открытой вкладки; явная пауза переживает
перезапуск и исправление совместимости. Срок отсутствия связи не ограничен
TTL подключения; явно заданный срок доступа и отзыв проверяются по-прежнему.

В `cargo test --workspace --all-features --locked --offline` входят тесты
`sync_engine::tests::recovery` и `device_host::tests::exchange_tests::recovery_tests`:
два независимых хранилища, настоящий TLS, потеря запросов/ответов, остановка
listener, повторное открытие баз, таймер Controller, несовместимые fixtures,
SQL-отказ и завершение процесса до/после commit. Ошибки вносит только test router;
производственных переключателей обхода протокола нет. Та же suite выполняется
нативно на Android через `bun scripts/check-product.mjs --android`.

На Windows полный native product-check и `check-pairing-app.mjs` запускать
последовательно: оба используют один host test exe, а работающий APK host
fixture не позволяет linker заменить этот exe. Повтор после его cleanup
сохраняет матрицу; параллельный LNK1104 не является результатом native-тестов.

Точные результаты и непроверенные сочетания — [EV-110](../agent/verification/EV-110-sync-recovery.md).
Несовместимый test peer не заменяет проверку отдельного старого выпуска;
настоящий Tailscale и вся матрица конфликтов проверяются отдельно.

`pairing::tests::long_offline` дополнительно проверяет подтверждённое подключение
без срока после 1 и 50 условных лет: повторное открытие двух SQLite-хранилищ,
сохранённые выбор/progress, независимые правки, повторную доставку и явный отзыв.
Используется test clock обычных core-команд, часы ОС не меняются. Это проверка
возраста сохранённого подключения; настоящий Controller/TLS и APK имеют
отдельные сценарии. Полная карта критериев и границы актуальной приёмки —
[EV-142](../agent/verification/EV-142-exchange-audit.md).

Двуххостовый `bun scripts/check-ui-pairing.mjs` по умолчанию использует bundled
Chromium. Для отдельной проверки установленного Chrome или Opera передайте
одним аргументом путь к executable браузера. `UI_BROWSER_PATHS` общего UI runner
сам по себе не переключает этот отдельный сценарий. Права, assertions и
очистка двух изолированных установок остаются одинаковыми.

## Пользовательская история

`cards::tests::cleanup::history_exchange` проверяет две SQLite-реплики:
обе стороны и области очистки, независимые версии/карточки, старую доставку,
retained, завершение серии при restart, права, stale и отказ записи.
Очистка удаляет известные ключи Automerge history Map; технические changes
сохраняются, новая версия получает sequence после известных, включая очищенные.
Нового хранилища или механизма сборки мусора нет.

`bun scripts/check-pairing-app.mjs --history` выполняет ту же основную
матрицу через настоящий Windows Credential Manager ↔ Android APK/Keystore,
общий Service, TLS и CLI. Она также входит в существующий `--fields` CI-набор
и `--standard`; число jobs и прежние бюджеты не меняются.
Локально для lifecycle требуется `AGENT_DEVICE_COMMAND` из `device_open`.
Точные результаты и границы — [EV-138](../agent/verification/EV-138-history-exchange.md).

Матрица истории использует отдельное пространство с явным grant и выбором
обмена на обеих сторонах. `fixture.peer_command` передаёт вложенный JSON
в обычном конверте 64 КиБ; старую страницу следует брать из пространства
матрицы, без данных предыдущих сценариев. Перед повтором стенд проверяет
размер полного конверта, а после матрицы — сохранность истории исходного
пространства. Продуктовые лимиты страниц и прежние бюджеты CI сохраняются.
