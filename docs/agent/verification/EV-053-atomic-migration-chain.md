# EV-053: атомарная цепочка и исторические предмиграционные комплекты

Шаг: P07.08.2. База: `9041216`, ветка `feat/p07-08-migration-startup`.
Прямое поручение: полностью реализовать P07.08 в одной отдельной ветке, LOG-268.
Состояние финальных проверок фиксируется вместе с EV-054.

## Карточка

- Цель: обновлять всю необходимую цепочку и служебные данные одной транзакцией,
  с новым проверенным историческим комплектом и допуском Storage только после
  подтверждённого результата и публикации.
- Требования: §1/1.1, T10/A45/A46/M01/M03/M04/M08,
  [ADR-0036](../../architecture/decisions/0036-atomic-migration-startup.md).
- Зависимости: P07.07 done (EV-050/051, merge `1fd2de7`);
  P07.08.1 done (EV-052, PR #44 head `244bb6c`, merge `9041216`, три PR checks
  Windows/Linux/Android SUCCESS, ветка удалена).
- Scope: реестр переходов и архивных адаптеров, исторический capture/validator,
  общий исполнитель публикации и worker startup, тесты/docs. Продуктовая
  схема/SQL v1, версии/lock, OpenAPI/TS, прототипы и CI не меняются.
- Проверки: `bun scripts/check-product.mjs`, затем `--android` с явно выбранным
  AOSP API33/x86_64; release all-targets/all-features двух Android ABI, unsafe.
- Обратимость: полный rollback до commit, обычная обратная правка после успеха
  не меняет архив; отдельное аварийное восстановление остаётся P07.09/ADR-0030.
- Ориентир 300 строк превышен одной неделимой матрицей цепочки/startup/сбоя:
  отделение копии, commit или допуска создало бы непроверенный промежуток.

## Матрица

Общий `startup::tests` использует копию независимого бинарного эталона v1 с
закреплённым SHA-256 из EV-052; добавляет синтетический peer-state. Тестовые
схемы 2/3 добавляют служебные таблицы и изменяют служебную запись результата;
их SQL/переходы не попадают в продуктовый реестр. Схема 2 имеет отдельный
архивный адаптер со своей проверкой служебных метаданных.

- Прямое обновление с каждой из 1/2/3 в целевую 3; новая копия строго исходной
  версии, все снимки согласованы с ней; текущая версия не запускает capture.
  Actor, история, peer-state и старый request/result сохраняются; после restart
  обычная обратная правка оставляет две версии истории и неизменные архивы.
- Ошибка второго перехода возвращает схему 1 и все служебные записи; успех
  callback с неверным layout также откатывает всю цепочку.
- Отказы CopyWritten/AfterCapture/BeforeCommit; другой writer исключён от
  захвата до commit. Настоящий deferred-FK отказ SQLite COMMIT в общем
  исполнителе возвращает OutcomeUnknown и оставляет исходную схему.
- Неудачный следующий переход 2→3 сохраняет прежний успешный комплект 1→2;
  успех заменяет только его, orphan предыдущей неудачи сохраняется.
- Ошибка исторического адаптера не допускает миграцию/публикацию;
  после исправления повтор проходит с новым захватом.
- Шесть отдельных process-crash: CopyWritten, AfterCapture, BeforeCommit,
  AfterCommit, BeforePublish, AfterPublish. На диске только исходная 1 или
  целевая 3, никогда промежуточная 2. После commit restart не повторяет переходы.
  Если до commit нужен hot-journal recovery, сначала проверяется безопасный
  отказ startup, затем только тест восстанавливает свою синтетическую базу;
  продукт такое восстановление автоматически не делает.
- Прежние 85 storage-тестов, в том числе семь publication/crash-проверок,
  ошибки целевого validator/реальной публикации/очистки, сохраняются.

## Результат и ограничения

Финальные результаты Windows/Android — [EV-054](EV-054-startup-attempts.md).
T10/A45/A46/M01/M03/M04/M08 остаются partial в общей продуктовой приёмке.
Механизм и его локальная инфраструктурная матрица не означают проверки
несуществующей официально выпущенной линейки пользовательских схем.
P07.08.2/.3 реализованы совместно по прямому поручению; без новых CI/интеграции.
Полномочия/публичные входы/служебный режим — следующие этапы; остальные границы
ADR-0036 сохраняются. Логи, условия и SHA-256 — только `docs/reports/p07-08/`.
