# ADR-0029: общая проверка уже выданного доступа

Дата: 2026-11-05.

Статус: техническое решение P03.03. Продуктовые права из ADR-0010 не меняются.
Проверки и ограничения — [EV-046](../../agent/verification/EV-046-core-authorization.md).

## Решение

`zedone-core::access::with_authorized` проверяет доступ перед синхронным
обработчиком. Он получает непрозрачные учётные данные, требования самого
обработчика и доверенную транзакцию `AccessTransaction`. Транзакция заново
аутентифицирует обращение и загружает актуальное разрешение; её реализация
обязана исключить параллельное изменение прав до завершения обработчика.
Проверка выполняется после ожидания очереди, до чтения целевых данных и ранее
сохранённого результата команды. Отдельный повторно используемый permit не выдаётся.

Права и субъект не десериализуются из запроса; localhost, CLI, IPC, Tailscale,
название участника и сам факт аутентификации не предоставляют полномочий.
Порт реализуется доверенной инфраструктурой, не HTTP/CLI/IPC-адаптером.
Низкоуровневый storage остаётся внутренней инфраструктурой, не альтернативным API.

- Отсутствующие/пустые/неверные учётные данные, отсутствие разрешения,
  несовпадение субъекта и отозванное разрешение дают `access_denied`.
- Для пространства проверяется точный ID. Чтение не разрешает изменения;
  чтение с изменением включает чтение. Wildcard, неявного доступа к новым
  пространствам и общего обхода для локального владельца нет.
- Каждая цель должна пройти проверку до вызова обработчика; пустой набор
  требований отклоняется. Требования определяет core по реальной операции,
  включая родительские пространства, а не по заявленному клиентом режиму.
- Администрирование устройств и доступов — отдельно выдаваемая область.
  Она не предоставляет чтение/изменение пространств; обычные права не дают
  администрирования. Полномочия обслуживания всей базы этим не определяются.
- `None` у срока разрешения означает «До отзыва», а не бессрочные учётные
  данные. Для ограниченного разрешения граница исключительная: при `now >= end`
  доступ запрещён. Время получает доверенный `Clock` после разрешения учётных
  данных; источник времени из запроса недопустим. При недоступности источника
  прав или часов обработчик не вызывается, исходная ошибка сохраняется.
- Ошибки не включают учётные данные или сведения о существовании цели.
  `Credential` не реализует Debug/Serialize; разрешения не входят в OpenAPI.

## Границы

В этом срезе реализована политика и порт, **не выпуск и хранение учётных данных**.
Конкретного `AccessTransaction`/`Clock` в продуктовой инфраструктуре ещё нет;
тестовая реализация существует только под `cfg(test)` и не является базой прав.
Схема SQLite 1 и хранимые данные не меняются. Перенос прав в граф пространства,
копию пространства, command_results или параллельное временное хранилище не вводится.

До включения пользовательских входов требуется реализация порта на локальном
авторитетном состоянии с проверкой аутентификации, валидности самих учётных
данных, сохранности отзыва после перезапуска и атомарности с операцией.
Изменение схемы сохраняемых пользовательских данных проходит P07.07/P07.08.
Bootstrap владельца, конкретные операции выдачи/изменения/отзыва, формат ключей,
подключение устройств и подтверждения остаются DEC-003/P03.05/P06.

Проверка времени сейчас определена только в точке входа в синхронный обработчик.
Поведение длительных операций на границе истечения, надёжность времени при
откате часов/перезапуске и невозможность оживления истёкшего разрешения
инфраструктура должна закрепить до открытия таких операций. Эта политика не
означает автоматическое продление или отмену уже зафиксированной команды.

T06/A08 остаются partial. UI с начальными чтением/«До отзыва», фактическое
подтверждение выдачи, реальные права на устройствах и адаптеры ещё не приняты.

## Основание и альтернативы

Одна политика в core сохраняет одинаковые права человека и агента на обеих
платформах. Копирование проверок в адаптеры расходится при отзыве и смене
транспорта. Кэш разрешений в контексте соединения пропускает поздний отзыв;
отдельный вызов проверки до ожидания транзакции создаёт окно между проверкой
и операцией. Выбран общий guard внутри доверенной транзакции, без второго
источника прав и без преждевременного формата выпуска.

Принципы отказа по умолчанию и проверки каждого обращения сверены с
[OWASP Authorization Cheat Sheet](https://cheatsheetseries.owasp.org/cheatsheets/Authorization_Cheat_Sheet.html).

Продолжение P03.05.2: постоянный источник AccessTransaction на том же
`WriteContext`, выдача/замена/отзыв и однократный bootstrap реализованы в
[ADR-0037](0037-persistent-access.md)/EV-055. Прежнее описание отсутствующей
реализации выше сохраняет границу P03.03. Доверенный Clock и реальные входы
ещё не реализованы; T06/A08 и DEC-003 остаются partial/open.

## Продолжение P03.05

Доверенные часы/откат/restart/граница commit реализованы в
[ADR-0038](0038-trusted-access-time.md), общий HTTP/CLI/Tauri IPC и клиентские
намерения — в [ADR-0039](0039-command-adapters-and-delivery.md).
Схема 3 дополняет неизменённые 1/2; paths включают только access.inspect и
access.revoke. Общий локальный результат — [EV-058](../../agent/verification/EV-058-p03-05-acceptance.md).
Прежние формулировки сохраняют границу исходного среза. Формы/подтверждение,
защищённое хранение/доставка ключа и устройства остаются P05/P06; служебное
восстановление/откат всей базы — P07.09. Полная приёмка T06/A08/A26 не закрыта.
