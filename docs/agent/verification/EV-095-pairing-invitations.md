Дата: 2026-11-14. Шаг P06.01.2.1, часть P06.01.2; критерии T06/T09/A51.

## Рабочая карточка

- База: main/90c869d; ветка feat/p06-01-2-pairing-protocol. Десять исходных
  изменённых agent-документов сохранены с SHA-256 в ignored локальном отчёте.
- Цель: администратор создаёт, просматривает, перечисляет и отменяет
  сохраняемое приглашение через тот же API человека и агента.
- Зависимости: P06.01.1 done, PR #90/90c869d, EV-093; P01.10 done.
- Охват: четыре invitation.* команды core/Service/storage, одна таблица
  стартовой v1/эталон, производный контракт, общий клиент, проверки и docs.
- Отдельные части P06.01.2: защищённый канал/host secrets; запрос устройства;
  подтверждение/отклонение/отвязка с атомарной выдачей/отзывом; общая приёмка.
  Этот срез не принимает неподтверждённые сетевые запросы и не выдаёт доступа.
- Отказ/обратимость: отмена с expected, непереиспользуемые ID/verifier,
  повтор не оживляет отменённое приглашение; новая выдача с новым кодом/ID.
- Проверки: штатные product-check Windows/native Android/arm64, HTTP/IPC/CLI,
  граница срока с управляемыми часами, rollback SQL/receipt, restart,
  конкуренция, права до replay, пагинация и отсутствие исходного кода в БД.
- Размер: жизненный цикл, авторизация, атомарное хранение и негативные проверки
  неделимы; превышение ориентира 300 строк обусловлено этим одним поведением.
- Результат: P06.01.2.1 verified локально; Windows/native Android и обе ABI
  passed. Полные A51/T09 прежние; commit/PR/новый CI/merge не выполнялись.
- Далее: ревью/интеграция P06.01.2.1, затем P06.01.2.2 (канал/host secrets).

## Реализация

`core::invitations`/`storage::invitations` и четыре фиксированных ветви Service
реализуют create/inspect/cancel/list с ManageDevices и прежними timed worker,
guard/clock/replay. Приглашение живёт десять минут от первой успешной выдачи,
на точной границе expired; cancelled приоритетен. Отмена требует expected,
без продления срока; ID/verifier остаются tombstones. Новый код/ID создаются
общим newInvitation(), секрет отделён от намерения. Ответы не содержат verifier.

Обновлены только стартовая v1 и синтетический эталон; исходные строки/DDL
эталона сохранены. SHA-256 текущего эталона:
`fd0441ca5e2ede275f084468e36038b20a08a3d690b4cdaa40509d717e722821`.
База прежнего layout отклоняется без записи; рабочие данные не пересоздаются.
Новых зависимостей/unsafe/таймаутов/CI-заданий нет. Канал, защищённое хранение
host secrets, запрос/подтверждение/отвязка и UI не входят в текущий срез.

## Пять правил и передача

- Обратные действия: отмена с expected и новое приглашение с новым ID/кодом;
  старый код не оживает при replay/restart. Это безопасное прекращение
  приглашения, без удаления локальных данных.
- Человек/агент: один Service/контракт/guard для HTTP/IPC/CLI. Формы отдельно.
- Документация: user/device-pairing, agent/invitations/access,
  development/product-core, architecture/sqlite-layout и ADR-0054 актуальны.
- Паритет: одна нативная матрица Windows/Android и обе ABI passed; APK/UI,
  реальный arm64 и связь двух устройств отдельно, не приняты.
- Один источник истины: SQLite/общая транзакция; Rust-контракт и производные
  OpenAPI/клиентские схемы. Статус истечения вычисляется по доверенным часам.

Device открыт/выключен штатными инструментами; нативные проверки не меняли
Application/WebView данные и настройки. Все исходные восемь dirty EV
побайтово сохранены, индекс пуст. Отпечатки 18 runtime/test/derived файлов
сохранены локально и проверены после всех прогонов. Последующие правки —
только документация. PR/CI/commit/merge не выполнялись; P06.01.2/P06
остаются in_progress. Следующий продуктовый подшаг не начат.
