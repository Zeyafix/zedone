P07.03 разделён до реализации согласно очереди. Этот срез не открывает
пользователю или агенту незавершённое восстановление. Самостоятельный кандидат
после возврата не подтверждает актуальность пространства и не разрешает
операцию. Последняя успешная страховочная копия заменяется только после
успешного восстановления в P07.03.2, не при подготовке кандидата.

Все 98 состояний критериев и 72 строки проблем сохраняются. Полные T10/A09/A44,
публикация, CRDT-восстановление, пауза, права/replay и файловый UI этим срезом
не принимаются. Ориентир 300 строк может быть превышен одной границей
проверенного файлового захвата с отказами, изоляцией и паритетом платформ.


## Реализация и результаты

Доверенный Storage::prepare_restore_backup использует прежний полный
capture_export под BEGIN IMMEDIATE. Отдельный create_new файл синхронизируется,
повторно читается с пределом захваченная длина + 1 и сверяется по исходным
длине/SHA-256/метаданным и контейнеру. Успешный drop сохраняет кандидат;
discard удаляет только его каталог. Схема/зависимости/API/UI прежние;
[ADR-0077](../../architecture/decisions/0077-pre-restore-backup-candidate.md).

## Проверка пяти правил

- Обратимость: создание/проверка/явное удаление кандидата; другие кандидаты,
  исходник и прежние копии сохраняются. Ошибки/перезапуск/остановка проверены.
- Человек/агент: нового публичного действия пока нет ни для одного; общий
  контракт прежний, обхода прав/SQLite нет. Подключение общего API — .3.
- Документация: user/agent/development/ADR/очередь/журнал описывают текущую
  границу и отсутствие доступного восстановления существующего пространства.
- Паритет: тот же storage-код и матрица прошли Windows/native Android;
  SAF/UI и физический arm64 runtime этим внутренним срезом не проверены.
- Единый источник: прежние SQLite/Automerge и полный capture_export;
  файл — неизменяемая копия, не второе текущее состояние.

## Границы и передача

Проверена остановка процесса, не отключение питания; Windows directory
durability и произвольные SAF-провайдеры не принимаются. Самостоятельный
кандидат после возврата не подтверждает свежесть рабочего состояния.
Последняя успешная страховочная копия, receipts и пауза здесь не меняются.
Следующий .2 обязан сделать новый захват и восстановление под непрерывным
writer lock со свидетельством commit и безопасной публикацией/cleanup.
P07.03.1 verified локально, родитель in_progress; новый CI/интеграция ожидаются
по поручению. Все 98 состояний и 72 проблемы прежние, A09/A44/T10 partial,
A47/GAP-050 в POST.01. Новых commit/push/PR/CI/merge нет.
