# EV-139: поиск и списки после обмена

Дата: 2026-11-20. Шаг: P06.11. Состояние: verified локально.

## Карточка работы

- База: `main/29e8148`, ветка `feat/p06-11-conflict-search`. Существующие
  локальные записи интеграции P06.10 в журнале, очереди и EV-138 сохранены.
- Цель: поиск и списки отражают сохранённые конфликтующие варианты один раз,
  а разрешение конфликтов возвращает обычный порядок без потери данных.
- Требования: T09, A19, S03; спецификация §5 и сценарий 19,
  ADR-0011/0048. Общая T09 не закрывается этим шагом.
- Зависимости доступны в базе: P05.07 (EV-085), P06.05 (EV-113),
  P06.06 (EV-117), P06.08 (EV-132–134), P06.09 (EV-137).
- Охват: матрицы реального обмена и частичного разрешения, поиск/списки
  через общий API, desktop/touch UI, Windows и native Android/APK.
  Продуктовый код меняется только при воспроизведённом расхождении.
- Проверки: Rust workspace/Clippy, целевые native Android тесты,
  Chromium desktop/touch и реальный парный APK с Device.
- Обратимость/отказ: изменение и очистка запроса, отмена решения,
  stale и ограниченные права, повтор/перезапуск, сохранность истории.
- Вне охвата: P06.12/P06.13, оптимизация CI, выпуск, новые фильтры/индекс.

## Результаты

Все 12 матриц двух реплик прошли на Windows: оба вида перемещения и все
шесть порядков решения имени пространства, места карточки и позиции колонки.
Второе пространство доставлено обеим сторонам отдельно и остаётся неизменным;
пустой поиск проверяет положение спорного пространства перед ним и возврат
к алфавитному порядку после решения имени, независимо от конфликта места.
Свежие результаты обеих сторон совпадают до и после каждого частичного решения.
Проверены Unicode-варианты заголовка/описания, пустые запросы, один результат,
группа спорного места, возврат в порядок доски, сохранение истории и restart.

Шесть новых Chromium desktop/touch сценариев прошли отдельно и в составе
полного прежнего `check-ui-browser.mjs --conflicts`. Проверены конфликтующие
имена и тексты, оба вида перемещения, область/очистка, отсутствие совпадений,
просмотр без записи, частичное разрешение и reload. Продуктовых расхождений
пока не обнаружено: изменения добавляют проверки, без изменения API/UI/схемы.

Первые попытки новой Rust-матрицы сохранены: отсутствовал импорт типа,
а два исходных перемещения оставляли прежнее место и не создавали конфликт.
Исправлена только подготовка теста: третья колонка и исходная средняя позиция
карточки гарантируют два разных перемещения. Итоговая матрица прошла полностью.

Все 426 обычных Rust-тестов workspace прошли, включая 324 storage. Общая
команда затем завершилась ошибкой doctest: при параллельных Cargo-сборках
в общем target отсутствовал промежуточный storage rlib. Исходный отказ сохранён;
последовательный `cargo test --workspace --all-features --doc --locked --offline`
прошёл. Это не отказ продуктового сценария; следующие Cargo-проверки выполняются
последовательно. Clippy с `-D warnings`, политика комментариев и 78 клиентских
проверок прошли. На native Android x86_64 весь обычный модуль поиска прошёл:
6 тестов, включая все 12 новых матриц, Unicode/буквальность, права, replay,
отказ receipt и restart. Прежняя отдельная ignored-проба тысячи карточек
локально повторно не запускалась; её штатная маршрутизация CI сохранена.
Приёмка Device прошла на изолированной базе прежнего стенда двух реплик.

Полный настоящий `--fields` Windows Credential Manager ↔ Android APK/Keystore
прошёл с прежними 240 секундами fixture (212.02s). Новые проверки сопоставили
свежий поиск обеих сторон по каждому текущему варианту текста, пустой запрос,
один результат, отсутствие спорного места при конфликте только текста,
порядок пространств в поиске везде и после обратного восстановления текста.
Все три порядка независимых решений, история/права/restart/recovery прошли;
исходные APK и все файлы приложения восстановлены по SHA-256, cleanup=true.

Парный `--positions-cross` прошёл оба порядка решений, в том числе одинаковые
и разные независимые решения, stale, соседей, сохранность и обратные действия.
Поиск совпал на Windows/APK до, между и после решений; группа места предшествует
обычным результатам, карточка с точным запросом возвращается один раз.

В Device обычный ввод «Спорная карточка» дал один результат. Очистка вернула
четыре карточки текущего пространства. Отмена выбора не разрешила конфликт;
после выбора места карточки все четыре результата оставались в группе из-за
позиции колонки. После выбора позиции колонки группа исчезла: порядок
«Доступная карточка», «Сосед карточки А», «Спорная карточка», «Сосед карточки Б».
Перезапуск сохранил четыре однозначных результата в том же порядке.

Первый вызов ввода отверг аргументы PowerShell из-за незаключённого в кавычки
`@ref`; после справки и свежего снимка ввод прошёл. Дополнительная прокрутка
вернула кнопку поиска в видимую область после решения. Эти действия сохранены
в локальном отчёте; весь checkpoint завершён в прежние 300 секунд. Срез с UI
использовал прежние 600 секунд fixture (308.41s), это не замер его CI-бюджета
240 секунд. Исходные APK/файлы восстановлены, cleanup=true.

`--positions-same` прошёл оба порядка и те же проверки поиска с прежними
240 секундами fixture (115.24s). Все три парных запуска завершились
`passed/restored=true/cleanup=true`; исходные APK и manifests между запусками
совпали по SHA-256. Локальный debug APK также восстановлен по SHA-256,
Device выключен. Финальная Windows-матрица прошла за 53.37s, обычный модуль
поиска на native Android — за 62.89s. Это времена проверок, не задержки поиска.

## Пять правил и границы

- Обратимость: изменение/очистка запроса и области, отмена выбора,
  обратные перемещения/переименования и восстановление текста проверены;
  чтение не меняет карточки и историю.
- Человек/агент: UI, HTTP, CLI и APK используют прежний Service; новые
  парные проверки вызывают обычный `card.search` с новым ID и прежними правами.
- Документация: актуализированы user/agent search и development product-core;
  нового архитектурного решения или изменения продуктового договора нет.
- Windows/Android: матрицы обеих платформ, Chromium desktop/touch,
  настоящий парный APK/Keystore и Device подтверждены в указанном объёме.
- Источник истины: прежние авторитетные снимки Automerge, общий порядок
  пространств/доски и производные ответы. API, продуктовая логика, схема,
  зависимости и UI не менялись; новый индекс не вводился.

Сохранены все 98 определений/состояний критериев и прежние GAP/DEC.
T09 остаётся открытой; P06.12/P06.13, новый GitHub CI/Linux, отдельная
локальная Opera, физический arm64 и итоговые измерения не входят в приёмку
этого изменения. Оптимизация CI остаётся на паузе. Следующее действие —
ревью diff и интеграция P06.11 по поручению, затем готов P06.12.

Коммита, PR и нового GitHub CI нет. Точные локальные команды, исходные
документы и артефакты — ignored reports.
