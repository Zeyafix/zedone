# ADR-0041: жизненный цикл пустого пространства в общем ядре

Дата: 2026-11-06. Техническое решение P04.01.2, продуктовые правила
ADR-0008/0014/0040 сохраняются. Проверка — [EV-063](../../agent/verification/EV-063-space-lifecycle.md).

## Контракт и авторизация

Шесть конкретных Rust-команд: `space.create`, `space.read`, `space.list`,
`space.rename`, `space.trash`, `space.restore`. Каждый вход декодирует строгий
тип из общего конверта и вызывает фиксированный core handler внутри
`Storage::timed_transact`. Доверенные часы/права/субъект не входят в параметры.

ID пространства — 128 случайных бит, 32 lowercase hex, ненулевой. Клиент
однократно генерирует его перед сохранением намерения создания; все доставки
сохраняют этот ID, имя, ID команды и исходные условия. Имена — точные строки
Unicode без скрытого обрезания/нормализации и без требования уникальности;
обязательный непустой заголовок карточки не переносится на имена пространств.

Создание требует ActiveGrant и отсутствия целевого ID. Объект, его журнал,
точный RW аутентифицированному создателю и receipt коммитятся вместе.
При совпадении существующего ID — stale_state без присвоения доступа;
данные существующего объекта не раскрываются. Администрирование, прежние
пространства, ключ, срок и субъект сохраняются. Никакого бессрочного владельца.
После снятия доступа повтор выполненного создания при действующем разрешении
возвращает только исходный результат собственного намерения, не выдаёт RW заново
и не читает позднейшее состояние. Обычное чтение цели требует точного Read,
переименование/корзина/восстановление — ReadWrite, включая возврат receipt.

Список требует действующего разрешения и перечисляет только текущую карту
точных доступных пространств. Администратор без прав данных видит пустой список.
Новый ID read/list нужен для актуального состояния; повтор возвращает исходное
чтение. По умолчанию клиент явно указывает `include_trashed=false`;
`true` включает корзину. Спорное состояние не прячется как окончательно удалённое.
Перед возвратом сохранённого списка core дополнительно проверяет текущий Read
сразу для всех его целей. Потеря любого права даёт отказ без старых данных;
IDs из receipt служат только целями проверки, не источником полномочий.

Сортировка общая в core: пространства со спорным именем первыми по ID;
остальные по Unicode lowercase имени, исходному написанию, затем ID. Никакой
локали/порядка файлов/SQL в клиенте. Read возвращает все различные варианты
имени, состояние active/trashed/conflicted, группы удаления, empty и version.

## Модель и версия

Один документ Automerge на пространство, строковый `format=zedone.space.v1`,
регистры `name` и `lifecycle` в корне. Состояние — active либо
`trash:<subject>:<command-id>`; отдельные удаления одного пространства имеют
разные группы даже при одинаковых command-id разных субъектов. Восстановление
сохраняет историю и идентичность, записывает новое active. Отдельное окончательное
удаление/очистка не вводится. Структура документа версионирована; SQL/схема v4,
формат архивного контейнера, прежние layout/эталоны остаются прежними.

space.version — SHA-256 версионированной области/ID и стабильной карты
семантических операций с причинными ID, значениями и связями. Декодированные
операции Automerge включают перезаписанные и удалённые поля/вложенные объекты;
поэтому изменение с возвратом не оживляет прежнее условие. Все варианты
проецируются независимо от порядка доставки. Глобальные heads/часы не используются.
Техническая корневая ветка history и все её потомки зарезервированы и исключены;
read/receipt/peer progress и другое пространство также не влияют на версию.
Проекция вычисляется из того же графа, без таблицы счётчиков/кэша полномочий.

Переименование разрешено активному объекту без конфликтов имени/состояния.
Корзина и восстановление — только пустому объекту. Проверка expected, проверка
допустимости и изменение выполняются под одним writer lock. Отказ `conflict`
означает необходимость разрешить доменный конфликт; `stale_state` требует
нового чтения и явного действия. В этом срезе нет команды разрешения конфликта
имени/состояния — она относится к продуктовой синхронизации; чтение сохраняет
все варианты, обычная правка не уничтожает конфликт.

Пустота определяется отсутствием корневых данных вне format/name/lifecycle/history.
Неизвестное/будущее содержимое блокирует корзину/восстановление. Расширение
модели колонками/карточками/тегами и семантики их групп удаления остаётся
P04.02–P04.09; текущий empty-срез не выдаётся за приёмку A56 целого контейнера.

## Повторы, транспорт и рост

Общий replay executor передаёт аутентифицированный субъект только доверенному
core callback. Исходная политика повторов/сроков/отзыва не меняется. HTTP route
передаёт имя в фиксированную таблицу Service; неизвестная операция отклоняется,
клиент не выбирает handler или политику. Ошибка декодирования UTF-8 в HTTP path
также возвращается общим JSON-конвертом invalid_request. CLI/IPC используют
ту же таблицу.

OpenAPI выводится из Rust. Генератор читает конкретные paths для вывода
операций, параметров, результатов и standalone validators. Клиент проверяет
ответ именно выбранной операции, поэтому корректный результат другой команды
не подтверждает намерение. Pending хранит только исходный запрос/субъект доставки.

Список посещает разрешённые документы по одному и освобождает прочитанный граф;
незафиксированные изменения доверенной композиции не выкидываются. Отдельного
индекса/постоянного кэша/клиентской базы нет. Загрузка журнала и вычисление
причинной проекции ограничены выбранным пространством; бюджеты больших
пространств и всего приложения остаются P09/DEC-009, не объявляются принятыми.
