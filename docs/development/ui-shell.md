# Разработка общей UI-оболочки

P05.08: `TrashPanel.vue` показывает весь состав корзины пространства из
прежних списков Service и хранит только одноразовый выбор ID. `TrashScope.vue`
отображает snapshots и подписи групп; списки клиента не определяют mutation
scope. `SpacesView` при открытии читает свежий контейнер/preview и фиксирует
identity/version/selection. Group trash/restore отправляет прежний root token;
card.restore — исходные версии карточки и выбранной активной колонки.
Отсутствующий contents не трактуется как пустой контейнер.

Для purge используется прежний `trash.inspect`, затем явные checkbox и submit;
core заново проверяет scope/expected/конфликты атомарно. При явном отказе
корзины перечитывается текущая доска, но форма не получает новый expected.
Unknown остаётся в прежнем журнале намерений, старый receipt не заменяет view.
После подтверждённого purge самого пространства выбирается общий список,
чтобы не читать уже отсутствующий root. Новых доменных кэшей/контрактов/
зависимостей/схемы/CI-бюджетов нет. История версий — отдельный P05.09.

`check-ui-trash.mjs` общий для desktop, host touch без checkVisibility и native
CI. Он проверяет состав/группы/прежнюю корзину, отдельное восстановление,
stale/card destination/теги пространства, отсутствие частичного действия,
purge/cancel/conflicts/доступ/storage/unknown/restart/replay и сохранность
полей/истории. Прежние проверки доступности действия непустым контейнерам
теперь ждут завершения перехода/чтения и проверяют доступность preview;
новая матрица проверяет само безопасное действие. Локальный Android — Device,
CI-драйвер локально не запускается. Результаты: [EV-086](../agent/verification/EV-086-trash-ui.md).

P05.07: `SearchPanel.vue` использует disposable `read("card.search")` с
Rust-derived `SearchResults` и прежним runtime validator. Сравнение, права,
порядок и единственность результатов определяет Service. Текст запроса не
нормализуется браузером; textarea сохраняет внутренние переносы. Изменение
ввода/области, новое чтение и unmount инвалидируют поколение ответа;
при ошибке старые результаты не остаются. Поисковое состояние не сохраняется.
`SpacesView` открывает свежую карточку и теги именно её пространства,
используя прежний редактор/журнал намерений. После его изменений выполняется
новый поиск. `check-ui-search.mjs` общий для desktop/touch/native CI;
его тестовые конфликтные ответы проверяют только представление, реальный
обмен не заявляется. Результаты — [EV-085](../agent/verification/EV-085-search-ui.md).

P05.06 добавляет теги в `SpacesView.vue`: disposable tag.list включён в общий
refresh и очищается вместе с остальными данными при смене пространства/доступа
или ошибке чтения. Управление раскрывается в «Теги пространства»; создание,
переименование и подтверждённое удаление идут через общий журнал намерений.
Исходные identity/version фиксируются при открытии формы и не подменяются refresh.
Unicode-сравнение выполняет только Rust Service.

`CardEditor.vue` хранит прочитанные версии карточки и тегов до явного действия.
`card.set_tag` отправляет один ID, present и обе исходные версии. Во время
редактирования текста назначения недоступны; это исключает подмену предусловия
текстового черновика операцией тегов. После успеха читается текущая карточка,
старый receipt не подменяет состояние. «Обновить карточку и теги» — явное новое
чтение, без автоматического повторения отказанного намерения. `TagNames.vue`
показывает назначения в общем списке и в карточке без сохранения доменных данных
в localStorage. Проверка `check-ui-tags.mjs` включена в desktop/touch и native CI;
фактические результаты и ограничения — [EV-083](../agent/verification/EV-083-tags-ui.md).

P05.03 завершает локальный срез карточки: `CardEditor.vue` управляет
просмотром/редактором, begin/autosave/finish и выполнением через прежний API.
`editor-drafts.ts` хранит только ввод/исходное предусловие с отдельным ID
и lifetime Web Lock. Параметры доставки не заменяются новым вводом; после
подтверждения сравниваются свежая version и receipt. Отличие останавливает
автозапись до нового явного решения. `mutationCredential` ограничивает
получение доступа 10 секундами до подготовки команды. Подробности —
[ADR-0052](../architecture/decisions/0052-card-editor-drafts-and-delivery.md),
проверки и границы — [EV-078](../agent/verification/EV-078-card-editor.md).

Debounce 500 мс/max wait 2 с применяется только при свободной очереди,
доступном ядре, непустом Unicode-заголовке и вне IME composition. Новый input
синхронно сохраняется отдельно; поле остаётся доступным во время доставки.
Выход из диалога/маршрута проходит через guard с фокусом предупреждения;
на время завершения закрытия ввод блокируется. visibility/pagehide пытаются
flush/finish, но не обещают асинхронный commit при остановке процесса.
После restart сначала разрешается прежнее намерение, затем новая сессия;
старый begin receipt не возобновляет завершённую сессию.

`check-ui-editor.mjs` добавлен в штатный `ui:check` с настоящими Service/history:
парные версии/30 с, непрерывный ввод и IME, ввод во время запроса,
guard/recovery, два контекста, потеря ответа/restart/replay и поздний агент,
stale выполнения/обратной отметки, доступ/persistence/deadline. Штатный Android
CI touch driver дополнен редактором/историей/выполнением/черновиком; его
desktop proof не заменяет локальный Device или новый Android CI.

P05.03.1 добавляет read/list/create/trash/restore карточки через прежний
`workspace-api.ts`. `SpacesView.vue` читает список карточек одним запросом
на пространство вместе с прежними тремя чтениями, проверяя общее поколение.
`CardsList.vue` отображает проекцию в порядке API и передаёт явные действия.
Корзина карточек отделена от корзины колонок; неоднозначное положение или
отсутствие активной колонки не скрывают карточку из просмотра.
В P05.03 описание выводилось Vue-интерполяцией; P05.04 подключает общий
безопасный просмотр сохранённого описания, описанный ниже.
Просмотр и подготовка корзины/восстановления читают свежий `card.read`;
старый expected никогда не заменяется автоматически. После подтверждённого
повтора перечитываются текущие данные, а не snapshot из старого receipt.
Редактор/сессии/автосохранение подключены P05.03.2; Rust/API/схема прежние.

`check-ui-cards.mjs` включён в штатный `ui:check`: настоящий HTTP/Service,
пара заголовок/описание, порядок/ID после восстановления/reload, буквальная
разметка, пустой заголовок/отказ доступа/ошибка localStorage, stale удаления,
потерянные уже принятые ответы и исходный replay после reload, сохранение
поздней правки и восстановления агента. Android shell CI дополнен теми же
созданием/просмотром/корзиной/восстановлением и отказом пустому заголовку
через настоящий IPC/native touch. Локальная проверка Android — только Device.
Текущие доказательства и ограничения — [EV-077](../agent/verification/EV-077-card-lifecycle-ui.md).

P05.02 расширяет оболочку жизненным циклом пространств/колонок;
[EV-066](../agent/verification/EV-066-space-column-ui.md).
`SpacesView.vue` хранит только текущую проекцию прочитанных данных и ввод формы.
`workspace-api.ts` использует прежние prepare/CommandClient и operation-specific
Rust-derived validator. HTTP и IPC выбираются общим `connection.ts`, ключ
перечитывается из локального хоста перед каждой доставкой. SQL/API/зависимости
не меняются; проверку прав, актуальности, конфликтов и содержимого выполняет core.

Открытие формы существующего объекта читает свежий snapshot и фиксирует его
исходную версию. Обновление списка её не подменяет. Успех доставки вызывает
новое чтение, а не установку snapshot из старого receipt. Поколение чтения
отбрасывает поздние ответы старого маршрута/сеанса, чтение ограничено 10 секундами.
Изменения сохраняют исходное намерение в `zedone.pending.v1.shell.*` до отправки;
это очередь доставки с введёнными параметрами, без ключа/прав/копии списка.
Успешное подтверждение удаляет намерение. После перезапуска нет автоматической
повторной отправки: пользователь явно проверяет исходный результат. Неизвестный
исход, отказ и ошибка persistence не показываются как успешное изменение.
Удаление записи из очереди требует отдельного подтверждения с предупреждением,
что принятая команда не отменена. Ошибка localStorage блокирует новые изменения,
но чтение и оформление доступны. Маршрут доски хранится только во fragment URL.

`ui:check` теперь включает `check-ui-workspace.mjs`: реальный HTTP/Service,
жизненный цикл обоих контейнеров, stale/сохранение ввода, потерю уже принятого
ответа и перезапуск с прежними байтами, настоящий отказ ключу и запрет отправки
при ошибке сохранения намерения. Исходные shell-проверки сохранены.
Android `shell` job собирает x86_64 APK и test-only host `shell-fixture` и
на свежем CI AVD проверяет общий UI через IPC с синтетической установкой;
намерения/ключ/база удаляются в finally. CI использует прежний native touch
драйвер с видимостью, ожиданием доступности, размером и hit-test. Независимый
`shell-arm64` job собирает тот же UI для aarch64 с проверкой manifest, без
эмулятора/host fixture. Последовательная сборка двух ABI вместе с UI-проверками
дважды превысила общий лимит; разделение сохраняет обе сборки и весь UI-набор
при прежних 10 минутах на job. Общий Android aggregate требует успеха всех шести
jobs, включая arm64; negative compiler/version/cleanup guards остаются во всех.
Для общего negative preflight arm64 job также устанавливает libpulse0 и
настраивает доступ к KVM: скрипт проверяет их до намеренного отказа rustc.
Сам эмулятор и положительный environment/UI-сценарий этот job не запускает.
Матрица/владение ABI/граница runtime проверяются штатным routing guard.
Один дополнительный runner повторяет подготовку окружения; суммарная стоимость
не измерена, новое время подтверждается только новым CI. Локальный
desktop proof native touch не является Android-приёмкой. Перед проверкой Back
формы CI отдельно скрывает видимую нативную IME и проверяет, что форма осталась
открытой. Видимость требует обоих mInputShown/mIsInputViewShown: активный метод
ввода может не иметь представления, а сервис может сохранять представление
после скрытия окна. Все прежние assertions и таймауты сохранены. Локальный
Android UI выполняется
только через Device, с сохранением и восстановлением исходного sandbox.

`ui/src` — один Vue UI для Windows-браузера и Android Tauri. Границы —
[ADR-0042](../architecture/decisions/0042-product-ui-shell.md), результат —
[EV-064](../agent/verification/EV-064-ui-shell.md). Runtime не зависит от прототипов.

## Сборка для пробного запуска Windows

Пользовательский порядок запуска и первых действий — в
[Quick Start для Windows 11](../user/quick-start-windows.md).
Установщика пока нет; для пробного запуска нужны рабочая копия репозитория
и базовые инструменты Windows из
[подготовки окружения](quick-start-windows.md#1-установите-базовые-инструменты):
PowerShell, Rust/MSVC с Windows SDK и Bun. Android SDK для Windows-оболочки
не требуется. Версии берутся из `scripts/environment-versions.json`.

Из корня репозитория в PowerShell выполните команды по очереди.
После ошибки остановитесь и устраните её перед продолжением:

```powershell
bun install --frozen-lockfile --ignore-scripts
bun run ui:build
$versions = Get-Content -Raw scripts/environment-versions.json | ConvertFrom-Json
cargo "+$($versions.rust)" build --locked --manifest-path ui/src-tauri/Cargo.toml --target-dir target --bin serve-shell --example shell-fixture
```

Сначала собирается UI, затем Rust-host, который встраивает эти ресурсы.
Результат — `target/debug/serve-shell.exe` и тестовый
`target/debug/examples/shell-fixture.exe`. При изменении исходников повторите
сборку в том же порядке. Это сборка для знакомства, без заявления полной приёмки.
Служебный example не входит в приложение и не заменяет пользовательскую выдачу
прав; он допустим только для отдельной тестовой установки.

## Проверки оболочки

Из корня, с подготовленными инструментами `scripts/environment-versions.json`:

```powershell
bun install --frozen-lockfile --ignore-scripts
cargo +1.99.1 fetch --locked --manifest-path ui/src-tauri/Cargo.toml
bun run ui:check
```

`ui:check` выполняет vue-tsc под Node (база CI 24.22.1), Vite под Bun,
fmt/Clippy/tests shell workspace, сборку host/example и браузерную проверку.
Host-прогоны используют корневой `target/` вместе с product-check: Cargo
переиспользует неизменённые зависимости, сохраняя различия profiles/features/flags.
Android-сборка также использует корневой `target/`; отдельные ABI располагаются
в его подкаталогах, прототипы сохраняют свой независимый `prototypes/target/`.
`UI_NODE_PATH`/`UI_NODE_VERSION` — явный локальный override уже подготовленной
среды; результат отмечается отдельно от закреплённой базовой версии.
`UI_BROWSER_PATHS` — JSON-массив путей Chrome/Opera. Без него используется
подготовленный Chromium Playwright. Скрипт не устанавливает браузеры или Node.

Windows development host после `ui:check`:

```powershell
target/debug/serve-shell.exe --data-directory docs/reports/ui-local
```

Он выводит loopback URL и встраивает собранные ресурсы без Vite-сервера и внешней
сети. Новая база остаётся без прав. Example `shell-fixture` требует пустого
каталога и создаёт только синтетическую установку; он не входит в приложение.
Автотесты сами создают и удаляют этот каталог. На рабочих данных fixture запрещён.

`local-session.json` — внутренний порт ранее выданного секрета в приватном
каталоге установки, строгий JSON с `subject` (32 lowercase hex) и `key`
(64 lowercase hex). Его содержимое не выводить/не коммитить. Наличие файла
не доказывает прав; решение принимает общий guard. ОС-хранилище/доставка/начальное
подтверждение остаются P06. Сетевой bootstrap отсутствует. При неподдерживаемой
базе host сохраняет отказ штатного startup, не сбрасывает её.

Android при подготовленных JAVA_HOME/ANDROID_HOME/NDK_HOME:

```powershell
bun scripts/build-ui-android.mjs x86_64
bun scripts/build-ui-android.mjs aarch64
```

Скрипт проверяет Rust/Tauri CLI/JDK/NDK, не устанавливает SDK; `--release` после
архитектуры собирает неподписанный выпуск. В текущем срезе проверены debug APK.
Готовый manifest проверяется на идентичность и категории запуска.
JS/CSS target Chrome 101 задан явно: стандартная оптимизация media query в
новый range syntax ломала mobile layout на штатном AOSP WebView. Для оформления
выбранной темы используется производный Vue-класс, а не неподдерживаемый :has.
JNI-исключение ограничено `entry_point`; core/storage/adapters сохраняют forbid.
Feature `android-shell` включает optional build-dependency tauri-build только
для APK. Его явно задаёт build-ui-android.mjs; прямой Cargo Android build
без feature отклоняется, чтобы не получить оболочку без настроенного JNI.
Обычный browser host не собирает Android packaging tools. Версии и набор
runtime-проверок не меняются.
Scaffold основан на проверенном шаблоне Tauri, без экранов/плагинов прототипов.

Локальная UI-проверка — только Device/agent-device/device_screenshot.
`check-ui-android-ci.mjs` допускается только в настоящем CI, внутри штатного
emulator callback. Он не заменяет локальную приёмку. Успешный IPC сеанса и
IPC прикладной команды учитываются отдельно. Логи/снимки — в `docs/reports/`.
CDP-подключение к WebView использует `noDefaults: true`: WebView не реализует
desktop browser context/download management, поэтому стандартная настройка
Playwright `Browser.setDownloadBehavior` даёт protocol error. Режим сохраняет
реальные настройки WebView, включая системное оформление; UI assertions
остаются прежними. См. [Playwright connectOverCDP](https://playwright.dev/docs/api/class-browsertype#browser-type-connect-over-cdp-option-no-defaults).

При запуске и перезапуске socket, discoverable page target и Playwright page
ожидаются отдельно в общем прежнем бюджете готовности 15 секунд (60 × 250 мс).
Shell CI использует проверенный helper обнаружения из прототипа; это зависимость
тестового драйвера, не приложения. CDP получает остаток того же бюджета,
закрытые страницы не принимаются. При отказе после port forward выводятся
targets/страницы/последние lifecycle logs до штатной очистки; диагностическая
ошибка не заменяет исходную. Повторов запуска и UI-сценариев нет, job остаётся 10m.

## Описание карточки: P05.04

Сохранённое описание в CardEditor использует общий ui/src/markdown/MarkdownView.ts,
ui/src/markdown/markdown.ts и ui/src/markdown/RemoteImage.vue, перенесённые из проверенного
прототипа P01.07. Прототип импортирует тот же модуль; runtime продукта от
prototypes не зависит. Профиль/версии прежние: markdown-it 15.0.3, CommonMark
0.31.2, html:false, DOMPurify 3.4.17. Заголовок/редактор/сверка и краткий текст
на доске показывают исходник. HTML/права/версии/история не сохраняются в viewer.

UI-модуль расположен внутри ui/src, отдельно от client/commands.ts общего
API-клиента. Строгий tsconfig.contract.json продолжает проверять все client/**/*.ts
обычным tsc, без Vue/WebView-зависимостей и специальных исключений. Общий viewer
проверяют оба Vue-проекта через импорт, включая прототип; обходы проверок
деклараций зависимостей и фиктивные объявления .vue не используются.

Image renderer создаёт инертные маркеры до DOMPurify; разрешённый HTTP/HTTPS
URL остаётся вне HTML. Только отдельная кнопка создаёт img с no-referrer.
Скрытие удаляет узел, повтор создаёт новую попытку; смена исходника/карточки
сбрасывает согласие и ошибку ссылки. Вложенное в ссылку изображение получает
отдельные элементы управления. Разные варианты описания не объединяются.
Пустое описание по-прежнему явно обозначается.

Windows открывает HTTP/HTTPS в _blank с noopener noreferrer; Android использует
JS/Rust Opener 2.7.2 с отключённым автоматическим JS-обработчиком. Capability
только для локального main разрешает open-url с http://* и https://*, без файлов
и иных команд. CSP расширяет только img-src на http:/https:, connect-src
сохраняет loopback/IPC-границу. Для явных HTTP-изображений Android manifest
разрешает cleartext также в release: иначе WebView блокировал бы разрешённый
профилем URL. Основание — [Android usesCleartextTraffic](https://developer.android.com/guide/topics/manifest/application-element#usesCleartextTraffic).
Это не транспорт синхронизации и не разрешение передавать ключи внешним сайтам.
TLS trust/проверка сертификатов не меняются. Исходник и адреса остаются в карточке,
содержимое изображения не копируется в БД/вложения. Ошибка не раскрывает точную
сетевую причину: UI предлагает проверку сети/адреса/формата и повтор.

check-ui-markdown.mjs проверяет настоящие HTTP/IPC-команды и production bundle:
CommonMark, буквальный HTML/XSS, точный исходник/историю, ссылки/выбранную
загрузку/скрытие/ошибку/повтор, независимое выполнение и обратную отметку,
перезапуск/сброс согласия, обычную UI-правку и обратную агентскую правку.
На host выполняется штатным ui:check в отдельном контексте; прежний контекст
сохраняет запрет неожиданных внешних запросов. Android CI использует тот же
сценарий с native touch и проверяет native-отказ другим схемам, ошибку bridge
и реальный внешний ACTION_VIEW. Локальная Android-приёмка — только Device.
Для ожидания Markdown на Android сценарий получает штатный nativeControls.visible:
обычный Playwright locator.waitFor использует отсутствующий в WebView 101
element.checkVisibility. Проверки стилей/размера и native touch сохраняются;
полнота сценария/таймауты не меняются, подмены DOM API нет.
После статуса сохранения сценарий сверяет точный edited исходник через card.read
до закрытия. При отказе до очистки выводит DOM-состояние и сохранённые descriptions
синтетической карточки, без повторов действий и подмены исходной ошибки.
Перед native touch драйвер ждёт окончания `aria-busy` у предков и одинаковой
геометрии того же элемента/viewport на двух последовательных animation frames.
Проверки видимости, enabled и `elementFromPoint` сохраняются; координаты берутся
после прокрутки и стабилизации. Ожидание укладывается в прежние 10 секунд,
затем отправляется ровно одно касание, без повторов или DOM click.
`check-ui-native-controls.mjs` в штатном host `ui:check` проверяет настоящий
CDP touch на движущейся кнопке с задержкой доставки в один кадр и при pending
refresh. Старый драйвер теряет касание в этом примере; новый активирует кнопку
после стабилизации. Этот host regression не заменяет native Android CI.
Доказательства и ограничения: [EV-080](../agent/verification/EV-080-card-markdown.md).
Host `check-ui-browser.mjs` запускает все Chromium-браузеры с
`--disable-frame-rate-limit`: в headless Opera 155 compositor ограничивал
подачу кадров примерно до 1Hz (`Viz: ThrottleUndrawnFrames`), и 24-кадровый
fixture не успевал остановиться в прежние 10s. Это настройка только host
тестового процесса, не продукта/WebView. Она отключает ограничитель BeginFrame
в scheduler ([Chromium switches](https://chromium.googlesource.com/chromium/src/+/refs/heads/main/components/viz/common/switches.cc)),
сохраняя настоящие rAF/CDP touch, задержку в один кадр, все assertions и
таймауты. Такой прогон проверяет поведение UI, а не частоту кадров/производительность.
Синтетический native-controls fixture выполняется в отдельном процессе с теми
же launch options. После успешного fixture процесс штатно закрывается, для
продуктовых сценариев создаётся новый. В Opera повторное использование процесса
после этого fixture блокировало открытие Markdown-ссылки даже в новом context:
trusted click/активная user activation были, но нового target не возникало.
Один context и bringToFront недостаточны. Процессная изоляция сохраняет сами
сценарии и все popup/URL/no-opener assertions; это не повтор упавшего сценария.

Диагностика и отрицательный контроль со старыми координатами —
[EV-082, GAP-017](../agent/verification/EV-082-board-moves-ui.md#gap-017--полный-локальный-набор-opera).


## Перемещение P05.05

`BoardView.vue` выделяет отображение колонок из SpacesView и координирует
два способа ввода. Явный диалог и окончание жеста вызывают один `move`:
createMutation → штатный CommandClient → перечитывание доски.
В Mutation добавлены только существующие card.move/column.move; Rust,
контракт, схема, алгоритм рангов и политика повторов не меняются.

VueDraggablePlus 0.6.1 использует встроенный SortableJS 1.15.2; зависимость
и проверенная правка TypeScript-декларации из прототипа закреплены также
в корневом lockfile. Это не runtime-fork. `board-order.ts` задаёт общие
настройки: ручки 44 px, задержка касания 250 мс, порог 5 px, fallback/AutoScroll.
Текст остаётся областью прокрутки; списки карточек имеют ограниченную высоту,
а пустой список — минимальную область переноса. Нажатие на доступную
с клавиатуры ручку открывает диалог. Два списка объединяются только
в пределах одного пространства; конфликтующие/удалённые объекты запрещены
в UI и повторно проверяются общим ядром.

Модели Sortable — одноразовые копии представления. При drop используется
исходный снимок перемещаемого объекта и относительный before из списка
назначения, исключая сам объект. После nextTick временный порядок сбрасывается;
после доставки (успеха или отказа) читается текущий API-порядок. Ранги в JS
не вычисляются. Чтение при открытии диалога не выполняется заново при submit;
жест также не получает свежую version. Исходный субъект проверяется перед
сохранением намерения, очередь не меняет учётную запись при повторе.

Во время жеста прежнее сообщение сохраняет геометрию доски. Соседние действия
и обновление блокируются до окончания операции, диалог сохраняет выбор
при отказе, а фокус возвращается после согласования данных. После unmount
старый компонент не начинает новое перемещение. Итоговые данные приходят
только из общего хранилища, не из receipt старой команды.

`check-ui-moves.mjs` использует реальные Service/SQLite/HTTP или IPC.
Общая часть проверяет явный порядок/обратные действия и сохранность истории;
host-часть — мышь/пустую колонку, выбор соседа, stale, потерянные ответы,
неизменный JSON после reload/позднего обратного действия, отказ доступа
и локальной записи. В ui:check добавлен также общий сценарий с native touch
в 360 px/dark; Android CI вызывает ту же общую часть через nativeControls.
Локальная Android-проверка выполняется отдельно через Device.
Результаты и ограничения — [EV-082](../agent/verification/EV-082-board-moves-ui.md).

Переименование колонки имеет стабильный marker `rename-column`.
Общий Android-сценарий выбирает это действие по marker, а не по позиции
кнопки: добавление Move перед Rename не должно превращать проверку
переименования в ожидание поля внутри другого диалога. После основного
host-набора `check-ui-workspace-touch.mjs` вызывает тот же полный
`checkWorkspaceTouch` с настоящими CDP-касаниями и отдельным пустым Service.
Его начальное состояние совпадает с Android fixture; данные других host-тестов
не влияют на selectors. Нативные IME/Back этим host-прогоном не принимаются:
Escape/history адаптируют только закрытие диалога/переход доски для host,
а настоящие системные действия сохраняются в Android CI. Таймауты,
проверки видимости/геометрии/hit target/одного касания не меняются.

При отказе Android shell драйвер до disconnect/force-stop/cleanup сохраняет
этап сценария, URL/readyState, наличие Vue mount и Tauri bridge, connection
heading/aria-busy, ограниченный список headings/alerts/scripts и page errors.
`check-ui-diagnostics.mjs` читает только статус `shell_session` (либо
`/host/session` в host-проверке): configured/unconfigured/unavailable,
invalid/rejected/timeout. Ключи и полный session object не возвращаются;
поля ввода и persisted intentions не читаются. Ожидание статуса ограничено
1s, всей диагностики — 3s; исходная ошибка пробрасывается после сбора.
Дополнительно читаются последние error-level Chromium/AndroidRuntime logs
этой синтетической CI-установки. Диагностика не повторяет действия и не меняет
таймауты/assertions сценария или job budget. Host-набор проверяет настоящий
configured/unconfigured Service и отсутствие credential key в проекции.
Причина первого native startup отказа c286cc4 пока не доказана —
[EV-082, GAP-020](../agent/verification/EV-082-board-moves-ui.md#первый-экран-c286cc4--gap-020--log-446).

### Совместимость драйвера с прежним WebView

В shared touch-сценариях читайте DOM-свойства через page.evaluate. Даже
locator.evaluate может вызвать Playwright visibility engine, который требует
checkVisibility, отсутствующий в целевом AOSP WebView. Реальные касания остаются
в nativeControls. Host-only withoutVisibilityApi удаляет этот API из page и
isolated execution realms перед проверкой moves/tags; продуктовый DOM и
нативный WebView не получают polyfill. Локальный red→green и native границы — EV-083.
