# EV-067 — жизненный цикл карточки через общий API

## Рабочая карточка

```yaml
step: P04.03
base_revision: e6a5dd7b3222f4cc53853f114c8ada3cc4e06223, чистое дерево
branch: feat/p04-03-card-lifecycle
goal: Создать, прочитать, изменить и обратимо удалить карточку с атомарной историей текста.
requirements: [T06, T07, A01, A05, A07, A18, A21, A33, A55]
dependencies_evidence: [P04.02/EV-065/PR54/889d4b0]
scope: [core card lifecycle and paged history, storage cards and column membership, Service HTTP/CLI/IPC, Rust-derived contract, client intentions, tests, docs]
checks: [bun scripts/check-product.mjs, bun scripts/check-product.mjs --android, git diff --check]
reverse_and_failure: Правка обратно, корзина/восстановление, stale/ABA, права/отзыв/срок, SQL/commit rollback, неизвестный результат, restart и конкуренция.
result: verified_publication_authorized
next: PR/финальный CI, проверка замечаний и merge/удаление ветки по поручению LOG-330; следующий продуктовый шаг P04.04 после done P04.03.
```

Ориентир 300 строк превышается неделимым жизненным циклом: создание сразу
имеет обратные действия, строгие проверки прав/версии, историю и атомарный
receipt через все входы. UI, автосохранение сериями, управление тегами,
выполнение, перемещения и группы удаления контейнеров остаются отдельными
шагами P04/P05. Каждая отдельная команда правки текста сохраняет оба поля
одной версией по ADR-0013; незавершённые серии этим API не создаются.

Сопутствующая строка UI ограничивает тип Mutation фактически поддерживаемыми
space/column-командами: прежний Exclude ошибочно включал новые card.read/list
и потребовал бы преждевременных действий карточки в формах контейнеров.
Видимый интерфейс не меняется; проверяется vue-tsc и production build.

Проверка полного diff выявила квадратичное копирование истории в receipts при
возврате всей истории из каждой edit. До приёмки она вынесена в card.history:
страницы 1–100 версий, отдельная причинная version/контроль между страницами,
компактные снимки карточек и результаты мутаций. Хранение истории не ограничено.

## Результаты

Реализованы card.create/read/list/edit/trash/restore и постраничный card.history.
Модель и границы — [ADR-0044](../../architecture/decisions/0044-card-lifecycle.md).
SQL-схема, зависимости и прежние операции сохранены. Данные/история/receipt
фиксируются в одной SQLite/Automerge-транзакции, доступ/срок/отзыв проверяются
перед эффектом и перед возвратом receipt через общий Service.

| Проверка | Результат |
| --- | --- |
| Жизненный цикл | Unicode/сырой Markdown, обязательный заголовок, положение/ID, корзина/восстановление и новые группы удаления |
| История | Начальная пара, отдельная версия каждой изменяющей текст команды, смена субъекта, обратная правка, отсутствие версий после noop/отказа/повтора |
| Страницы истории | Отдельная причинная версия, граница 1–100, cursor/expected, stale после изменения, replay прежней страницы, изоляция другой карточки; история исключена из receipt мутации |
| Актуальность | Текст/теги/выполнение/порядок/колонка/lifecycle отклоняют старую правку; возврат значения/связи не оживляет токен; чтение и запись только истории не меняют card.version |
| Контейнеры | Реальный состав делает колонку непустой; данные и удалённая принадлежность меняют column.version, несвязанная колонка не меняется; никакого частичного удаления |
| Конфликты | Все варианты текста/колонки/позиции/выполнения/lifecycle сохранены; обычные edit/trash/restore отклоняются |
| Права | Read не даёт изменять, отзыв запрещает повтор, истечение запрещает создание, корзина родителя запрещает новую мутацию |
| Атомарность | Отказы после работы/flush и перед commit откатывают создание; реальный SQL abort receipt откатывает текст/историю; потеря подтверждения commit возвращает OutcomeUnknown и безопасный replay |
| Конкуренция/перезапуск | Два worker дают один эффект создания и один replay; из одной версии сохраняется только одна конкурентная правка; исходные ID/параметры переживают restart |
| Транспорт/клиент | HTTP/IPC/реальный CLI используют те же результаты и отказы; дубли полей/подмена субъекта отклоняются; клиент сохраняет первоначальный текст/expected после отказа и restart |

Windows: `bun scripts/check-product.mjs` passed — 186 Rust-тестов
(12 core access, 7 contract, 152 storage, 15 adapters), 16 клиентских тестов/
123 assertions, fmt/Clippy с -D warnings, release всех targets/features,
7 независимых unsafe-отказов, побайтовая сверка Rust/OpenAPI/TypeScript/validator.
Относительно принятой базы добавлены 12 Rust-тестов и один клиентский.
vue-tsc и production build UI passed; видимый интерфейс не менялся.

Android: `bun scripts/check-product.mjs --android` passed — те же 186 нативных

16 клиентских/123 assertions, release x86_64/aarch64 всех targets/features,
14 независимых unsafe-отказов, побайтовое совпадение Android/host-контракта.

Машинные логи остаются только в игнорируемых docs/reports/p04-03-*-complete.log.
Полный handwritten/generated diff проверен; git diff --check passed.

P04.03 verified локально, без коммита/PR/новых CI/merge. Новых BUG/GAP/блокеров

точного head; после интеграции готов P04.04. Другие продуктовые шаги не начаты.

## Границы приёмки

Это API-срез карточки и дискретной истории. Выполнение/теги/перемещения,
серии автосохранения и их завершение после сбоя, UI редактора, групповые
операции контейнеров и продуктовый обмен остаются следующими шагами.
Постраничный ответ не заменяет будущие измерения роста графа/истории:
хранилище пока разбирает историю целевой карточки целиком при построении страницы.
Полные T06/T07/A01/A05/A07/A18/A21/A33/A55 остаются partial.
Физический arm64, release APK и полный UI-паритет не принимаются.
Публикация/условные merge и удаление ветки поручены разработчиком (LOG-330).
До фактического успеха финального head/CI и интеграции P04.03 остаётся verified.

## Пять правил

- Обратимость: создание имеет корзину/восстановление, текст возвращается новой
  правкой; история/ID/место и поздние обратные действия сохраняются.
- Человек и агент: один Service/core/guard/replay через HTTP/CLI/IPC;
  отдельного способа записи агента нет, UI редактора остаётся P05.03.
- Документация: user/agent/development/architecture, ADR-0044, очередь и журнал обновлены.
- Паритет: одинаковые 186 нативных тестов Windows/Android, release двух Android ABI;
  UI/APK/физический телефон вне текущей приёмки.
- Источник истины: одна SQLite/Automerge, транзакционная история/receipts,
  Rust-derived контракт; клиент хранит только исходное намерение доставки.
