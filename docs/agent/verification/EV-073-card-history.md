## Рабочая карточка

- Цель: непрерывные автосохранения с общей границей 30 секунд и участника, явное завершение, восстановление версии новой парой полей.
- Требования: T07/A18/A21/A54, ADR-0007/0008/0013; дискретные версии P04.03 сохраняются.
- Зависимости: P04.03/EV-067, DEV.01/EV-071; одна изменяемая стартовая схема v1.
- Охват: Rust core/storage/Service HTTP/CLI/IPC, производные контракта, lifecycle startup, документация.
- Проверки: управляемый отсчёт 29/30 секунд, noop/чтение/отказ/replay, смена участника/сессии, обе пары полей, три версии и два восстановления, stale/права/SQL rollback/unknown commit, restart, полный product-check Windows/Android.
- Обратимость: восстановление — новая версия; возврат к предыдущему состоянию тем же действием; открытие/закрытие редактирования. Очистка истории — отдельный P04.09.
- Размер: один связный API-срез; Rust-derived артефакты генерируются.
- Исключено: UI P05.03/P05.09, частота автосохранения, продуктовая синхронизация P06, физический arm64/release APK и P09.
- Результат: локальная матрица и семь CI checks passed; PR #71/head 528824b интегрирован в adfa765.
- Далее: готовый P04.09; новая реализация не начата.

## Реализация и доказательства

Четыре команды card.begin_editing/autosave/finish_editing/restore_text проходят
через общий Service/guard/replay/timed transaction. Субъект/время доверенные,
expected проверяет всю карточку. Сохранённая серия завершается после паузы
30 секунд, отдельной правки, новой сессии, завершения редактирования/корзины
или нового запуска host. Восстановление пары добавляет отдельную версию
и сохраняет прежнюю историю. Технический контракт —
[ADR-0049](../../architecture/decisions/0049-card-editing-history.md).

модули, общий CardStore/Service/OpenAPI, lifecycle shell, начальный DDL/эталон,
производные и тесты. Отпечаток затронутого runtime/test/contract набора,
SHA-256 с нормализацией текстов LF: `49c5e1d6aa240ce3ff0b293ce459df6301d61d7712955414bb3738d92e66f606`.
Перечень файлов и алгоритм — игнорируемый
`docs/reports/p04-08-runtime-fingerprint.json`. Требования ADR-0007/0008/0013

уточняет статус/ссылку, продуктовые правила не меняет. Его SHA обновлён в журнале.

Полные `bun scripts/check-product.mjs` Windows и `--android` passed:

### Проверенные сценарии

- 29 секунд без правок не закрывают серию; новая пара до 30 секунд продолжает
  её и сбрасывает отсчёт; точная граница 30 секунд создаёт одну версию последней
  пары. Отдельный последующий autosave после паузы начинает следующую серию.
- Чтение, повтор, совпадающая пара, пустой заголовок и stale-команда не
  продлевают серию/не добавляют ложных границ. Простой после закрытия не
  создаёт версий. finish без ввода не добавляет историю.
- «Человек → агент → человек», две отдельные команды агента, возврат человека,
  новая сессия/старые попытки/replay begin сохраняют отдельные этапы. Чужая
  session не даёт записать от имени прежнего владельца.
- Три разные пары → восстановление первой → восстановление третьей сохраняют
  всю историю и дают четвёртую/пятую версии. Явное восстановление совпадающей
  пары также добавляет видимую версию. Восстановление не поглощает открытую
  серию; выполнение/место/прочие поля сохраняются. NotFound/stale/корзина/права
  и replay после позднейшей правки дают ожидаемые результаты.
- SQL-отказ receipt, precommit checkpoints, неизвестный commit и повтор
  согласованно сохраняют/откатывают текст, журнал, историю и receipt.
- Новый host/клиент завершает сохранённую серию один раз. Повторные recovery,
  сбои фиксации и реальные process exit до/после commit не дают дубликатов.
  Сохранённая пара прежней серии не перезаписывает более новые текущие поля.
- HTTP/IPC/настоящий CLI используют те же результаты и receipts после restart;
  строгие декодеры отклоняют дополнительные поля/поддельные subject/clock/
  changed_ms/sequence и дубли полей. Read-only/revoked ключи не выполняют
  мутации/повторы. CLI-чтение не закрывает живую сессию host.
- Производные OpenAPI/TypeScript/validator совпадают с Rust. Клиент после
  unknown/stale/restart сохраняет исходную session/пару/ID версии и expected.
- Единственная стартовая схема v1 и синтетический эталон расширены пустой
  таблицей card_editing. Все прежние строки эталона сохранены; integrity/FK,
  synthetic migration/retry/crash тесты прошли. Старые базы разработки не
  мигрируют, не сбрасываются и не удаляются по ADR-0047.

Связанные Markdown-ссылки (421) и `git diff --check` passed; отпечаток
runtime после полной матрицы не менялся.

Сырые логи/машинные данные — только `docs/reports/p04-08-*`.
Предварительные ошибки fixture/layout и тестовых fixtures исправлены;
финальные Windows/Android проверки прошли. Продуктовые BUG/GAP не добавлены.

## Пять правил и границы

Восстановление обратимо новой командой с прежней версией; сессии открываются/
закрываются. Ручная очистка истории остаётся отдельным P04.09. Человек и агент
используют один API с одинаковыми правами, актуальностью и повторами.
User/agent/development/architecture docs обновлены. Native Windows/Android-
паритет API подтверждён; единая SQLite/Automerge и Rust-derived контракт
остаются авторитетными. Локальный журнал серии — часть одной транзакции,
без отдельного независимого хранилища текущей карточки.

T07/A18/A21/A54 остаются partial: UI/события вкладки/частота автосохранения,
продуктовый обмен/экспорт незавершённой серии/восстановление пространства,
очистка истории и бюджеты P09 не приняты. Полное обнаружение закрытия вкладки
и wiring begin/finish — P05; в этом срезе проверен общий контракт новой сессии.
Физический arm64 и выпуск не проверены. Итоговая интеграция — ниже.
P04.08 done в согласованном API-объёме; полная UI/обменная приёмка не расширяется.
