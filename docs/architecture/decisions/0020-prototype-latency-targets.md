# ADR-0020: первые ориентиры задержек прототипа и дальнейшее уменьшение ожидания

Дата: 2026-10-27.

Статус: принято разработчиком как стартовые ориентиры прототипа. Реализация и измерения ZeDone не выполнены.

## Контекст

После выбора контрольного ПК и верхних границ ОЗУ требовалось определить первые ориентиры времени отклика. Разработчик принял предложенные значения для прототипа и уточнил: в дальнейшем задержки должны быть как можно меньше.

Интерактивная иллюстрация искусственных задержек в обсуждении предназначена для объяснения ощущения ожидания; она не является измерением ZeDone или доказательством достигнутых показателей.

## Решение

- Открытие карточки, её перемещение или изменение отметки выполнения: стартовый ориентир прототипа — до 300 мс.
- Отображение первых результатов поиска: до 1 секунды.
- Первый доступный для работы экран после запуска: до 3 секунд. На ПК запуск самого браузера измеряется отдельно.
- Ориентиры общие для Windows и Android; условия и результаты фиксируются отдельно для каждого устройства и браузера/WebView.
- В дальнейшем задержки должны становиться как можно меньше. Попадание в начальные ориентиры не задаёт желаемую длительность действия и не прекращает работу над отзывчивостью.
- Сохраняются правила подтверждённого сохранения, отсутствия потери данных, общего API и принятые верхние границы памяти. Уменьшение задержек не подменяет эти требования.

## Значение результата и измерение

Для открытия карточки нужен доступный для работы контент. Для изменяющей команды требуется подтверждение сохранения общим Rust-ядром и отображение результата. Для поиска измеряется показ первых результатов после запуска запроса. Для запуска измеряется первый экран, с которым можно работать. Сама реакция на нажатие или показ индикатора не подтверждает завершение действия.

Перед проверкой фиксируются контрольные данные, история/корзина, открытые экраны, состояние запуска, фоновые обмен/копирование, устройства, версии и способ измерения. Число повторов, статистические показатели, условия холодного/повторного запуска и сравнение исходных и последующих результатов ещё определяются. Измерение эмулятора не подтверждает показатели Galaxy A32.

Для подготовки текстовых нагрузок разработчик указал частые заметки до 100 строк и иногда длинные описания более 100 строк. Размеры и доли конкретных текстов ещё выбираются; фиксируются объём UTF-8 и длина строк, чтобы число строк не подменяло размер. Этот профиль не вводит ограничение длины карточки.

Это исходные цели прототипа. Итоговые бюджеты выпуска и методика их приёмки определяются отдельно по результатам измерений, с направлением дальнейшего уменьшения задержек. Длительные импорт, синхронизация, резервное копирование и восстановление требуют отдельного профиля; требование отзывчивости интерфейса при них сохраняется.

## Проверка и правила проекта

Добавлены сценарий 62 и A62/P01, связанные с T02: цели фиксируются при подготовке прототипа, результаты снимаются на доступном срезе с явным указанием неполного охвата. A62 не закрывается по неполному набору действий. Критерий имеет статус `not_run`; дальнейшая матрица P09 сохраняет контроль регрессий и согласование итоговых бюджетов.

Документация отражает выбор. Продуктовые операции и обратимость не меняются. Общий API, паритет прикладных действий и одно авторитетное локальное состояние сохраняются; показатели ещё не доказаны реализацией.
