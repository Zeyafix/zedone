## Реализация и границы

`core::daily_backup` определяет допуск/начало и успешное/неуспешное завершение
одной попытки. Номер попытки не переиспользуется; завершить другую попытку
старым token нельзя. Сохраняется ревизия, захваченная при начале; последующие
правки не считаются включёнными в её успех. Успех учитывается по дате завершения,
повтор автоматически допускается через300000ms от завершения ошибки.

Ручной повтор ссылается на конкретную ошибку; новая ошибка делает старую ссылку
непригодной для нового запуска. Это не заменяет права или транспортный receipt.
Неубывающий отсчёт и локальный календарь передаются отдельно; их реальные
платформенные источники ещё не реализованы. При откате даты допускается только
день позже последнего успеха; при регрессе отсчёта переход отклоняется без записи.
Ошибка ранее неверной будущей даты может консервативно отложить следующую копию.

Round-trip проверяет номера и порядок времени; все поля, включая nullable,
обязательны. Отсутствие `running` не превращается в `None`; неверное состояние
не обнуляет дневной лимит. Сохранённая активная попытка после чтения остаётся
активной, её исход должен сверить будущий storage-слой.

Нет новых файловых/публичных операций, схемы, зависимостей или состояний API.
Сериализация не доказывает сохранение в SQLite; последовательный доступ к
одному объекту не доказывает блокировку между независимыми экземплярами.
Файлы/7 копий/сверка после crash — .2, worker/часы/права/receipt — .3,
Windows/Android UI — .4. [ADR-0079](../../architecture/decisions/0079-daily-backup-policy.md).

## Проверка пяти правил

- Обратимость: `fail` завершает допущенную попытку без отметки успеха;
  stale token, время и занятый лимит не изменяют состояние. Публичного
  создания файлов ещё нет. До его включения очередь требует явное удаление
  созданной копии через общий API/UI без сброса дневного лимита.
- Человек/агент: HTTP/CLI/IPC и права прежние, нового неполного действия
  не открыто. Будущий UI использует те же авторизованные команды ядра.
- Документация: добавлены user/agent/development инструкции и ADR-0079,
  обновлены очередь, журнал и карточка; граница реализации указана явно.
- Паритет: те же14 новых сценариев прошли Windows/native Android API33.
  Нового UI нет; APK/SAF/физический arm64 runtime и реальные часы не принимаются.
- Единый источник: текущее SQLite/Automerge-состояние и контракт прежние.
  Политика не ведёт отдельное пользовательское хранилище; её атомарное
  постоянное состояние и связь с полным capture остаются P07.04.2.
