# EV-052: реестр схем и допуск до writable-открытия

Шаг: P07.08.1. База: `1fd2de7`. Ветка: `feat/p07-08-schema-migrations`.
Состояние: `verified` локально; Windows/нативный Android product-check passed.
Коммита/PR/новых CI/интеграции нет.

## Карточка

- Цель: неподдерживаемая, чужая или повреждённая база не изменяется
  при открытии; известная схема проходит общий допуск.
- Требования: спецификация §1/1.1, T10/A46/M08, DEC-006,
  [ADR-0035](../../architecture/decisions/0035-schema-admission.md), ADR-0030/0034.
- Зависимости: P07.07 done, EV-050/051, PR #43 head 4ecbb5d, merge 1fd2de7,
  три успешных PR checks Windows/Linux/Android, исходная ветка удалена.
- Scope: реестр/SQL v1, read-only admission/worker, известный layout validator
  копий, бинарный эталон, тесты/docs. Новая продуктовая схема не вводится.
- Проверки: `bun scripts/check-product.mjs` и `--android`, нативный AOSP
  API33/x86_64, release/unsafe guards x86_64/arm64.
- Обратимость: исходные DB/WAL/journal сохраняются; повтор после устранения
  причины, restart и обратная правка без потери истории/receipt.
- Ориентир 300 строк превышен одной матрицей допуска/сохранности с реальным
  hot-journal crash и независимым бинарным эталоном.

## Матрица

Девять новых тестов schema::tests, включая вспомогательный child test:

1. Эталон v1 с закреплённым SHA-256 читается; Unicode ID, actor и прежний
   request/result сохраняются; правка/restart/обратная правка оставляют
   два изменения Automerge и прежний receipt.
2. Схема 99 в DELETE/живом WAL даёт UnsupportedSchema даже при другом
   BEGIN IMMEDIATE; DB/WAL/journal и чужая активная транзакция сохраняются.
3. FK-ошибка отклоняется до смены journal_mode; после исправления открытие
   успешно. Проверяются именно FK, не только quick_check.
4. Чужая identity, ложная пустота 0/0 с таблицами, версия 0, неполный layout
   и неожиданный индекс не включают WAL и не сбрасывают данные.
5. Не-SQLite/усечённая SQLite не считаются пустыми и не переписываются.
6. Смена версии/layout/FK после preflight отклоняется повторной проверкой
   initialize под writer lock с сохранением DELETE и файлов.
7. Preflight не создаёт отсутствующий файл и не инициализирует пустой;
   обычное открытие затем создаёт начальную схему.
8. Вспомогательный child test без окружения — безопасный пустой тест.
9. Реальный hot journal будущей базы после завершения дочернего процесса
   без деструкторов: отказ без восстановительной записи, DB/journal сохранены.

Прежние 76 storage-тестов, включая снимки/публикацию/crash, сохраняются.
SHM/locks не входят в побайтовую гарантию. Проверяется схема 1, не выпущенная
линейка исторических схем и не реальная цепочка миграций.

## Результат и передача

Windows: fmt/Clippy, 10 access + 7 contract + 85 storage tests,
release all-targets/all-features, 4 независимых отказа unsafe,
Rust/OpenAPI/TS и TS compile passed. Android: те же 102 теста нативно
AOSP API33/x86_64, один новый hot-journal child и прежние crash-тесты,
release all-targets/all-features двух ABI, 8 независимых отказов unsafe;
native OpenAPI совпадает с host. Runtime после этих прогонов не менялся.
При финальном просмотре закреплены LF для SQL и binary для SQLite-эталонов
в .gitattributes; git check-attr подтвердил правила. SQL и бинарник,
использованные обоими прогонами, не менялись.
Логи/условия/хеши — только `docs/reports/p07-08-1/`.

Целевые прогоны исправили вывод типа worker initialization, hex digest,
нормализацию CRLF исходного Rust SQL при генерации эталона (как в rustc),
выключение FK enforcement при подготовке повреждения и ожидаемый JSON
результата. Последующие целевые 9 тестов и полный Windows-check прошли.

T10/A46/M08 partial, A45/M01/M02 not_run, DEC-006 open. Полная цепочка,
startup gating до сверки и контроллер повтора — P07.08.2/.3. P07/P07.08
целиком не закрываются. Безопасный hot-journal отказ не равен служебному
режиму P07.09. Физический arm64/APK/Linux локально, power-loss, произвольные
FS и бюджеты всего приложения не проверены. Схема/API/зависимости/CI прежние.
Проверка quick_check/FK выполняется дважды при открытии; стоимость на больших
пользовательских базах пока не измерена. Горячий путь команд её не повторяет.

Пять правил: отказ сохраняет состояние, есть обратная правка; общая доверенная
инфраструктура человека/агента без обхода прав; обновлены docs; паритет
проверяется нативно; SQLite — источник фактов, runtime-реестр — описание схем.
После проверки — публикация по поручению. P07.08.2 готовится на интегрированной
P07.08.1; зависимые непроверенные изменения не накапливаются.
