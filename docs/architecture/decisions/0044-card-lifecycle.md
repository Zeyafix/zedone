# ADR-0044: жизненный цикл карточки и причинная принадлежность колонке

Дата: 2026-11-07. Статус: техническое решение P04.03.

Продуктовые правила ADR-0007/0008/0013 сохраняются. Проверки и ограничения —
[EV-067](../../agent/verification/EV-067-card-lifecycle.md).
Расширение P04.04 проверяется отдельно в
[EV-068](../../agent/verification/EV-068-card-completion.md).

## Контракт и хранение

Команды card.create/read/list/edit/trash/restore/history/set_completed проходят через один
Service/core/guard/replay и timed transaction. Чтение требует Read пространства,
изменения — ReadWrite. Новая мутация требует активных пространства и колонки.
Подтверждённый повтор не повторяет действие, но требует действующих прав.
ID карточки — случайный ненулевой 128-битный ID в 32 lowercase hex, сохранённый
клиентом вместе с намерением до доставки; ID команды независим.

Карточка — один корневой Map `card:<id>` в прежнем документе пространства:
format=zedone.card.v1, title, description, column, position, completed,
tags Map, lifecycle, history Map. Принадлежность хранится строкой column;
будущее перемещение меняет её без копирования объекта. Новая карточка добавляется
после максимальной позиции карточек своей колонки, включая корзину.
Восстановление сохраняет ID, положение, теги и выполнение.
SQL v4, формат архивного контейнера и зависимости не меняются.

P04.04: `card.set_completed` задаёт bool явно в существующем регистре completed.
Одна команда обеспечивает установку и обратное снятие; колонка/порядок/текст/теги
и история не меняются. Команда использует общую проверку expected/прав/конфликта
и активного состояния. Даже совпадающее значение требует актуальности; успешный
noop не меняет причинную версию карточки. Повтор возвращает прежний receipt,
не отменяя последующего снятия отметки или новой правки. Изменение выполненности
делает прежние команды карточки и связанной колонки устаревшими.

Заголовок обязателен: пустая строка или строка только из Rust Unicode whitespace
отклоняется как invalid_request; остальные символы сохраняются точно,
без обрезки или нормализации. Описание допускает пустую строку и хранит
исходный Markdown/HTML как текст. API не выполняет разметку и не загружает ссылки.

Снимок возвращает все различные варианты текстов, колонок, позиций, выполнения,
теги, состояние, группы удаления и version. История читается отдельно страницами,
чтобы не копировать её в каждый receipt правки или результат списка карточек.
Любой собственный
спорный регистр делает карточку conflicted и блокирует обычные изменения всех
полей. Чтение сохраняет варианты; выбор варианта остаётся P06. Повреждённые
форматы, спорная идентичность Map и неизвестные поля карточки дают отказ.
List исключает только однозначную корзину при include_trashed=false;
порядок детерминирован по columns/positions/ID и не заменяет поиск P04.07.

## История, актуальность и атомарность

Создание сохраняет начальную пару title/description. Каждая отдельная
успешная команда edit, действительно изменившая текст, добавляет одну пару
из сохранённого состояния. Неизменившийся текст, чтение, отказ, корзина,
восстановление и повтор команды не добавляют текстовой версии.
Ключ версии `<subject>:<command-id>` берётся из доверенного guard и исходной
команды; sequence — следующий локальный номер, не часы и не глобальная
очерёдность независимых правок. При одинаковом номере порядок чтения задаётся ID.
Обратная правка прежней парой текста создаёт новую версию и сохраняет остальные.
P04.03 предоставляет дискретные правки. Серии автосохранения, 30-секундная
граница и восстановление по ID добавлены в P04.08 —
[ADR-0049](0049-card-editing-history.md); очистка истории остаётся P04.09.
card.history принимает after, limit (1–100) и expected. Первая страница допускает
after=null/expected=null; следующая требует next и исходную version истории.
Ответ содержит space/card, versions, next и version. История имеет собственную
причинную проекцию, включая удалённые записи и объекты: изменение между страницами
даёт stale_state, после чего чтение начинают заново новым намерением. Другая
карточка или изменение только выполнения не меняет версию истории. Повтор ранее
выполненного чтения возвращает исходную страницу. Размер страницы — транспортная
граница, количество сохраняемых версий не ограничено. Хранилище пока разбирает
историю одной карточки для построения страницы; индексирование/нагрузочные бюджеты
остаются будущей приёмкой, отдельный источник данных не вводится.

Card.version включает причинные идентичности всех операций карточки, в том
числе перезаписанных/удалённых тегов, положения и состояния. Подветка history
исключается по пути объекта, включая удалённых потомков. Техническое завершение
истории не делает правку устаревшей. Другие известные карточки/колонки,
корневая history, receipts и peer progress исключены; неизвестные корневые
данные включаются консервативно, также после удаления. Версия связана с space/card.
Перед любой новой мутацией expected сравнивается с ней в той же транзакции.
Изменение с возвратом не оживляет старую команду. stale_state требует перечитать
и подготовить новое действие, без автоматической подстановки свежей версии.

Текст, история, CRDT-журнал и receipt коммитятся вместе. SQL/commit-отказ
откатывает их целиком; после неизвестного исхода повторяется точный исходный
запрос. Повтор старого удаления не отменяет восстановление, повтор восстановления
не отменяет новое удаление. Новое удаление получает новую группу.

## Защита контейнеров и совместимость

Column.empty учитывает реальные ссылки всех карточек, включая корзину и
спорное положение. Column.version включает причинную проекцию карточек,
когда-либо ссылавшихся на неё: состав/данные, смену колонки и удалённую
принадлежность. Это консервативно: последующая правка ранее перемещённой карточки
может потребовать перечитать прежнюю колонку. Соседняя карточка без такой связи
не меняет её версию. Проекции и связи собираются один раз для списка,
без повторного декодирования журнала для каждой колонки.
Колонки без истории карточек сохраняют прежний алгоритм версии.

Trash/restore контейнера с содержимым по-прежнему отклоняются целиком;
групповое удаление остаётся P04.09. Старый runtime воспринимает новые card-ключи
как неподдерживаемое содержимое и также отказывает удалению, не теряя карточки.
Space.version учитывает карточки, но исключает их историю, как корневую history.
Никаких производных SQL-полей или отдельного источника данных для агента нет.
