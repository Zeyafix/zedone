# ADR-0038: время и граница фиксации доступа

Дата: 2026-11-05. Статус: техническое решение P03.05.3.

Публичный вход использует только часы storage, после захвата SQLite writer lock.
В схеме v3 хранится единственная верхняя отметка наблюдённого Unix-времени.
Она не входит в снимки пространств и обновляется также при отказе команды.
Схемы 1/2 неизменны; переход 2→3 проходит общий защищённый startup с полной
копией и архивами. Новая установка начинает с отметки 0, без выдачи прав.

SystemTime ОС — доверенный календарный источник; Instant задаёт нижнюю границу
прошедшего времени внутри процесса. Время клиента не принимается. Откат ниже
наблюдённой отметки, переполнение или отказ источника дают unavailable.
Сохранённая отметка проверяется вновь под writer lock каждым процессом.
При восстановлении календарного времени работа возобновляется; обхода или
сброса отметки через API нет. Истёкшее наблюдённое разрешение не оживает при
restart или откате часов; требуется новая явная выдача с новым ключом.

Авторизация проверяет срок перед обработчиком и после него. Storage повторяет
проверку наиболее раннего использованного срока после flush непосредственно
перед commit. Истечение до этой точки отменяет весь эффект и receipt. После
финальной проверки уже начатый commit завершается: истечение во время самого
commit не отменяет зафиксированную команду. Отзыв сериализован writer lock.
Ответ и внешние эффекты разрешены только после успешного commit.

Операция работает внутри savepoint. При отказе/панике откатываются её данные,
но максимальное наблюдённое время фиксируется внешней транзакцией. Ошибка
фиксации остаётся outcome_unknown; потеря ответа не доказывает отсутствие эффекта.

Это защита относительно наблюдённого времени и доверенной ОС. Без внешнего
источника нельзя обнаружить неизвестное время, проведённое с выключенным
устройством и изменёнными часами. Instant не обещает учитывать сон на каждой
платформе. Подмена ОС, удаление/откат всей SQLite относятся к границе доверия
и P07.09; эта работа не открывает восстановление старой базы.

Основание: [SystemTime](https://doc.rust-lang.org/std/time/struct.SystemTime.html)
не монотонен; [Instant](https://doc.rust-lang.org/std/time/struct.Instant.html)
монотонен, но не определяет календарное время и одинаковый учёт сна.
