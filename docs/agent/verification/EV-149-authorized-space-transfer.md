## Реализация

`core::snapshots` задаёт два конкретных request/output и SnapshotStore.
Экспорт требует Read; импорт, как создание, ActiveGrant и назначает ReadWrite
только своему субъекту, сохраняя его срок/отзыв. Свежие права и receipt читаются
в той же BEGIN IMMEDIATE, что захват/публикация. Повтор экспорта возвращает тот
же архив/дату, повтор импорта тот же ID; после сужения доступа к копии даже её
receipt не возвращается. Чужой администратор не получает содержимое копии.

Один `capture_export` используется внутренним export_snapshot и публичным
портом. Порт flush_document внутри своей транзакции также сохраняет pending
правки при доверенной композиции до захвата. Архивная pending-история не меняет
исходную сессию. Прежний import_snapshot проверяет и переписывает полный граф;
новый порт добавляет доступ в той же транзакции. Ошибки SQL/receipt отравляют
контекст; timed_transact сохраняет контроль срока до окончательной фиксации.

Лимиты бинарного архива 1 MiB/10000 changes определены в ядре; обе hex-схемы
строятся из той же константы. HTTP/IPC/CLI/network используют одну пару handlers,
Service/CLI/network — общий request_limit, клиент сохраняет большое импортное
намерение до доставки. Hex и JSON не являются серверными путями. Схема SQLite,
зависимости и raw импорт .2 не меняются. Договор —
[ADR-0076](../../architecture/decisions/0076-authorized-space-transfer.md).

## Проверки и исправленные первичные отказы

Четыре storage-проверки: все границы commit, в том числе AfterResult и
AfterCommit с restart/replay; реальные SQL-отказы выдачи доступа и receipt с
перехватом ошибки; истечение во время работы; полный отказ экспортного бюджета.
Три adapter-проверки: HTTP/IPC/local CLI и настоящий TLS/network на архиве
больше 64 KiB, lost-reply/restart, две независимые копии, корзина/возврат;
строгий JSON/неверный ID/hex/бюджет/mismatch; Read/нет доступа другому участнику,
смена ключа/сужение прав/отзыв. Общий клиент проверяет durable намерение,
потерянный ответ и response validation, включая нечётный hex/лишний перевод строки.

Первичная storage fixture создавала и экспортировала незафиксированный граф
через SQL-only захват. Порт получил штатный flush_document в той же транзакции;
финальная fixture снова проверяет композицию, без документирования обхода.
Первичное ожидание mismatch до проверки прав исправлено: недоступный новый
экспорт должен дать access_denied. Ошибка имени shutdown в TLS helper и Clippy
is_multiple_of исправлены до финального прогона. Старые проверки числа операций
обновлены с 73 до 75 с явным включением обеих завершённых команд.

min/maxLength в Ajv привели к внешнему runtime import, запрещённому автономным
валидатором. Выбран строгий bounded hex pattern без изменения генератора или
ослабления проверки, с точным концом строки. Сам pattern затем вынесен в один
schema builder от MAX_ARCHIVE_BYTES. Итоговый OpenAPI побайтово прежний после
этого выделения; затронутые Clippy/contract/целевые проверки повторяются на
финальном дереве. Первичные отказы сохранены в ignored reports и не считаются
успешной приёмкой. Проверка журнала нормализует CRLF/LF при сравнении текста;
исходные EV-146/147/148 и import .2 не изменены.

## Пять правил и границы

- Обратимость: две копии независимы; обычные корзина/восстановление проверены.
  Экспорт не меняет граф/сессию; файловые действия остаются .4.
- Человек/агент: одна авторизованная пара Rust API через HTTP/CLI/IPC и общий
  клиент; обходов SQLite нет. Форма файлового выбора пока не включена.
- Документация: agent/user/development/ADR, очередь и журнал обновлены.
- Паритет: общий Rust и конкретные HTTP/IPC/CLI команды проверяются на Windows
  и native Android API33. Файловый UI/APK, физический arm64 runtime и Linux здесь
  не принимаются; Android release обеих ABI проверяется штатно.
- Источник истины: прежняя SQLite/Automerge и тот же формат/visitor, производные
  OpenAPI/TS/runtime validator и budgets из ядра. Новых моделей хранения нет.

Все 98 определения/состояния, 72 строки проблем и POST.01 сохраняются. Полные
P07.02/T10/A25/A32 не приняты: файл/UI и итоговая матрица — P07.02.4,
восстановление исходного пространства — P07.03. Рост receipts остаётся DEC-009.
Изменения локальные, без нового commit/push/PR/CI/интеграции.
