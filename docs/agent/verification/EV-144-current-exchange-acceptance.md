# EV-144 — приёмка текущей реализации обмена

Дата: 2026-11-21. P06.13.2.1, база `d80995e`, ветка
`test/p06-13-2-version-compatibility` с локальными итогами EV-143/LOG-782.

## Карточка

- Цель: свести 36 критериев EV-142 с полным текущим договором и актуальными
  доказательствами Windows/Android/UI/API, выполнить обязательные недостающие
  проверки. A47/GAP-050 отложены в POST.01 по LOG-781, без объявления успеха.
- Зависимости: P06.02, P06.10, P06.11, P06.13.1 интегрированы в базе;
  EV-107/138/139/141. Текущие source fingerprints EV-142 проверяются отдельно.
- Охват: карта требований/ревизий/платформ/транспортов, текущая маршрутизация
  тестов и найденные недостающие проверки. Продуктовые API, протоколы,
  форматы, схема, права и интерфейс не меняются без подтверждённого дефекта.
- Проверки: аудит требований и тестов, сверка source/contract fingerprints,
  сырых итогов CI PR #119 и локальных EV; затем конкретные команды найденного
  среза, native/Device по применимости. Результаты записываются после запуска.
- Обратимость и ошибки: данные/APK/OS-слоты изменяющего стенда сохраняются
  и восстанавливаются; используются общий Service/API и штатные ограничения.
- Граница: независимый дефект получает отдельный малый шаг; оптимизация CI
  остаётся на паузе. Коммиты, push, PR и merge в этом запуске не выполняются.
- Результат: 36 критериев сопоставлены, найденный CI-пробел исправлен локально;
  настоящий парный APK и Device-срез прошли. Новый CI и наблюдение холодной
  загрузки модели A51 остаются непроверенными; P06.13.2/P06/T09 не приняты.

## Найденный пробел обязательного CI

`check-pairing-app.mjs --container-deletion` включает отдельное удаление
карточки, восстановление в другую колонку, конфликты удаления колонки и
пространства, атомарный отказ очистке и минимальное восстановление поздних
правок. EV-135–137 подтверждают прежние локальные API/Device-прогоны.
На базе `d80995e` Android matrix и `pairingSlices` не выбирали этот селектор;
default runner также его не вызывал. Поэтому 26 успешных checks PR #119 нельзя
приписывать этой парной матрице. Native Rust и browser проверки имеют
собственный подтверждённый охват.

Выбранный проверяемый срез — включить существующий селектор в постоянный
CI и проверить настоящий текущий Windows ↔ Android APK с сохранением
240 секунд fixture, 15 минут job и всех прежних checks. Это восполнение
обязательного охвата, а не возобновление оптимизации CI.

Пробел выделен в `P06.13.2.1.1` / GAP-051. Добавлены обязательный Android
job `pairing-container-deletion`, точное соответствие `--container-deletion`,
прежняя подготовка production APK и запуск в default runner. Guards проверяют
новый маршрут, каждый отказ bootstrap/build/runtime, сигналы и отказ каждого
из пяти верхних child suites. Прежние selectors и проверки сохранены.
Полный ожидаемый CI теперь 27: 15 Android, 3 Linux, 6 Windows и 3 strict
aggregates. Эти 27 checks ещё не выполнялись; 26 SUCCESS относятся к PR #119.

## Актуальность доказательств

- Проверенная база — `d80995e`, её дерево равно head `e93ffd5` PR #119.
  Сохранённый итог содержит точный набор 26 успешных checks. Это прежний
  результат, без нового обращения к GitHub или объявления нового CI.
- Product crates, API, UI, manifests/locks и Android acceptance-код прежние.
  Относительно EV-142 меняются только шесть файлов маршрутизации/guards:
  workflow, Android dispatcher/guard, shell preparation/guard и default
  pairing runner. Их новые маршруты проверены отдельно ниже.
- EV-142 содержит актуальные полные Windows/native Android, Chrome/Opera
  desktop/touch и отдельный pairing обоих браузеров; истинный APK `--fields`
  подтверждает сохранённые выборы после BUG-010. Повтор этих неизменённых
  сценариев для документационного сопоставления не требуется.
- Новый парный `--container-deletion` восполняет актуальную APK-проверку
  удаления после более поздних изменений общего ядра. Для UI используется
  отдельный seed и настоящий IPC; он не подменяет независимые сетевые реплики.
- Прежние Device и физические доказательства сохраняют точный охват EV.
  Android CI shell не вызывает все browser conflict runners: полный
  desktop/touch прогон не объявляется полным native UI-прогоном.

## Незавершённые части и передача

- GAP-051: изменение постоянного CI локально проверено; для закрытия нужны
  все ожидаемые 27 SUCCESS на опубликованном head и интеграция этого среза.
- GAP-052/A51: первый запуск без GMS/модели и готовая модель проверены отдельно,
  но холодная первая загрузка GMS-модели не наблюдалась. Нужна подходящая
  отдельная чистая среда GMS без готовой модели; ручной fallback без сети,
  затем готовность и повтор сканирования продукта. Чужие данные GMS не очищать.
  В текущем Device доступен только AOSP API33 без GMS; он не подменяет эту ячейку.
- A47/GAP-050 остаются в POST.01; это единственная согласованная отсрочка
  межверсионной части. Остальные отсутствующие доказательства не исключаются
  из приёмки. Полные P06.13.2.1/P06/T09 и A51 не объявляются завершёнными.
- Неизвестные причины прежних CI-отказов и прочие GAP/DEC сохраняются.
  Новый локальный успех не закрывает их. Все 98 определения/состояния
  критериев остаются прежними, A26 passed; оптимизация CI на паузе.

Пять правил соблюдены в проверенном срезе: обратные restore/правки и полное
восстановление стенда; общий Service/API человека и агента; актуальные EV и
developer docs; настоящий Windows/Android и отдельный native Device UI;
один авторитетный граф/права, без отдельной модели статуса или пользовательских
