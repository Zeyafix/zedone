# Продуктовое Rust-ядро

Допуск SQLite до writable-открытия и реестр неизменяемых SQL-layout описаны
в [ADR-0035](decisions/0035-schema-admission.md). Обычные команды принимают
текущую версию, архивный validator — известную; факты остаются в одной базе.
Начальный реестр содержит только схему 1. Цепочка миграций/startup gating
и повторы остаются P07.08.2/.3.

Решения: [ADR-0027](decisions/0027-product-core-boundaries.md),
[ADR-0028](decisions/0028-atomic-storage.md).
[ADR-0029](decisions/0029-core-authorization.md) определяет проверку доступа.
[ADR-0030](decisions/0030-command-replay-and-freshness.md) — актуальность и повторы.
Текущее состояние — P03.05.1: контракт, атомарное хранение, политика прав,
механизм повторов и общий JSON-конверт с производными TypeScript-типами.
Продуктовых операций и пользовательских входов ещё нет; ограниченный обработчик
существует только в тестах.

P07.01 добавляет внутренний формат полного журнала одного пространства:
[ADR-0032](decisions/0032-space-snapshot-format.md). Захват из SQLite согласован
одной read-транзакцией; декодирование не меняет базу и не выдаёт права.
Импорт/восстановление и публичный доступ ещё не реализованы.

P07.07.1 добавляет внутренний кандидат предмиграционного комплекта: полную
SQLite-копию и архивы всех пространств из того же состояния, захваченного
под writer lock. Повторное чтение/проверка и явное удаление кандидата описаны в
[ADR-0033](decisions/0033-pre-migration-backup-candidate.md). Кандидат не разрешает
миграцию; её связь с захватом/безопасной заменой и сам переход схем остаются
P07.07.2/P07.08. Полная копия не заменяет архивы пространств и не выдаёт права.

## Владение и зависимости

| Граница | Ответственность | Состояние |
| --- | --- | --- |
| `zedone-core` | Прикладные правила, запросы/результаты, общие ошибки; без платформы и прямого доступа к SQL/Automerge | Контракт и проверка прав в `crates/core`; операции впереди |
| `zedone-storage` → core | Одна SQLite устройства; внутренняя модель Automerge, транзакции и результаты | `crates/storage`: worker и начальная схема; продуктовые порты и проекции по потребности |
| Адаптеры → core | HTTP/CLI и Tauri IPC; декодирование, передача учётных данных, кодирование | P03.05; пакеты/оболочка ещё не созданы |
| Точка сборки → core/storage/адаптеры | Создание рабочего контекста хранения и управление жизненным циклом | Вместе с соответствующими входами |

Прототипы — независимый workspace и доказательства, а не библиотека продукта.
`scripts/check-product.mjs` проверяет наследование запрета unsafe и границу
зависимостей core; добавление зависимости требует явного пересмотра этой границы.

## Модель команды

Каждый реализованный запрос будет обычным строгим Serde/utoipa-типом с
`Command::NAME` и `Command::Output`. Обработчик в core получает запрос и
проверенный контекст доступа; адаптер не может подменять проверки прав,
актуальности или повторов. Сам trait только связывает типы, не выдаёт полномочий
и не выполняет операцию. P03.03 добавляет общий guard `with_authorized`;
реализация источника учётных данных и прав ещё впереди.

Изменяющая операция должна проходить общую последовательность: проверка входа
и доступа → проверка прежнего результата команды → исходные условия актуальности
для ещё не выполненной команды → изменение → согласованная фиксация данных,
истории, обмена и результата → ответ. Повтор по известному ID возвращает
прежний результат без новой правки. P03.02 реализует атомарное хранение,
P03.03 — политику прав, P03.04 — общий `replay::execute`/`require_current`
и минимальный `ReplayTransaction`. Storage-композиция проходит `BEGIN IMMEDIATE`
и возвращает успех только после commit. ID связан с проверенным субъектом;
изменённый запрос выполненного ID даёт `command_mismatch`. Результат повтора
подтверждает прежнее действие, не становится текущим view.
Результат локальной записи не означает доставку реплике.

`StateVersion` — 32-байтовая производная от версионированной области, проверяемых
данных/вариантов/состава и их причинных идентичностей. Изменение с возвратом
не оживляет старый признак; техническая фиксация истории и несвязанные объекты
не входят в проекцию. Storage использует уже закреплённый sha2; core не зависит
от SQL/Automerge/хеширования. Точные проекции карточек/контейнеров проверяются P04.
Записи результатов не истекают автоматически. До восстановления старых баз или
очистки результатов нужна защита от нового выполнения старых намерений в P07.

Внутренний `CommandResult<T>` — Rust Result. Его стандартные JSON-теги `Ok`/`Err`
не становятся транспортным протоколом; отображение закрепляется P03.05.
Имена полей, типы, ошибки и описания операций имеют один Rust-источник;
OpenAPI и `api/schema.d.ts` — проверяемые производные.
Общий JSON-конверт, отделение учётных данных, строгие варианты ответа и границы
типизации определены в [ADR-0031](decisions/0031-shared-command-wire-contract.md).
Схемы конверта не регистрируют доступную операцию; `paths` остаётся пустым.

| `CommandError.code` | Смысл |
| --- | --- |
| `invalid_request` | Вход не соответствует контракту |
| `access_denied` | Действие не разрешено; отсутствие объекта не должно обходить проверку доступа |
| `not_found` | Разрешённая цель не найдена |
| `stale_state` | Исходное состояние устарело; нужны перечитывание и новое явное действие |
| `command_mismatch` | Тот же ID повторён с иной операцией/целью/параметрами |
| `unavailable` | Действие недоступно, достоверно не зафиксировано |
| `outcome_unknown` | Факт фиксации неизвестен; успех или окончательный отказ не подтверждены |

Это категории контракта; их выдача реальными обработчиками проверяется
в соответствующих шагах. Ошибка не переносит произвольную строку исключения
на границу API. Диагностика остаётся локальной; UI локализует коды отдельно.

## Общая проверка доступа

`access::with_authorized` вызывает доверенный `AccessTransaction` заново для
каждой операции и получает актуальное разрешение аутентифицированного субъекта.
Требования по пространствам/режимам и отдельному администрированию задаёт
обработчик core. Отозванное, истёкшее, отсутствующее или чужое разрешение не
допускает вызов обработчика, даже для чтения сохранённого результата команды.
Доступ к данным и администрирование не выводятся друг из друга.

Порт должен работать внутри одной рабочей транзакции с операцией, исключая
параллельное изменение прав; часы — доверенный инфраструктурный источник.
Их конкретные реализации, персистентный отзыв и bootstrap ещё не созданы.
До этого пользовательские входы не открываются. Права не принимаются из
запросов/копий пространств и не кэшируются в клиенте как источник разрешения.
Полный договор, срок и ограничения — ADR-0029; политика не задаёт формат ключей.

## Хранение после P02

Правила из [модели Automerge](automerge-model.md) сохраняются как вход P03.02:
одна база устройства, изоляция сырого снимка одного пространства, стабильные
прикладные ID, сохранение конфликтов/отложенных изменений, согласованная запись
документа/actor/peer. Вне транзакции нет успешного частичного изменения.
Сырые Automerge ID и SQLite-строки не входят в командный контракт.

P03.02 использует ограниченную асинхронную очередь к одному SQLite worker,
загружает только затронутые пространства и дописывает changes, включая orphan
changes. Производных таблиц полей нет; история хранится вместе с данными в графе.
Граф/actor/peer/результат согласованы одной транзакцией. Полный выбранный граф
пока загружается на каждую операцию; стоимость растёт с историей. Это не
доказательство бюджета всего приложения и не ограничение роста.
Схема 1 создаётся только в пустой новой базе; чужая/неподдерживаемая база
отклоняется. Подробности и ограничения — ADR-0028.
Независимого второго хранилища текущих полей нет.
Проверенный общий снимок всего файла SQLite не заменяет снимок пространства.

## Текущая проверка

Host и Android используют одинаковые тесты контрактов/хранения и бинарник экспорта.
Проверка компилятором запрещает unsafe в библиотеке, генераторе и интеграционных
тестах на host и обоих Android targets. Тесты хранения проверяют SQL-отказы,
конкуренцию, отмену ожидания и аварийное завершение процесса до/после commit.
Тесты core проверяют общую матрицу прав, срок/отзыв, снижение полномочий,
отказ до чтения цели/результата и ошибки источников; session существует только
в тестах. APK/UI, продуктовая аутентификация/сохранение прав, операции,
HTTP/CLI/IPC и полный бюджет приложения в этом срезе не принимаются;
результаты — EV-044/EV-045/EV-046.

EV-047 добавляет синтетическую ограниченную команду и её обратное действие,
конкурентные доставки/разные worker, отказы актуальности/прав до lookup,
сохранение поздних правок, ошибки сериализации/SQL, потерю ответа и пять новых
crash/reopen границ на платформу. Источник прав и clocks остаются тестовыми;
продуктовый доступ/проекции и общий UI/API ещё не проверены.

## Предмиграционный комплект

P07.07.2 объединяет новый capture P07.07.1 и доверенный обработчик одной
writer-транзакцией. Служебное свидетельство commit хранится в существующем
`command_results` отдельно от пользовательских ID и графов пространств.
Файловый индекс последнего успешного комплекта — проекция свидетельства;
SQLite остаётся единственным источником факта фиксации. Полные копии являются
архивами со служебными данными, не вторым текущим хранилищем.

Публикация проходит после проверки целевого результата и самого комплекта;
старый каталог удаляется только после проверки нового индекса. Перезапуск
сверяет свидетельство, не выполняет обработчик повторно. Непринятые кандидаты
не продвигаются автоматически. Протокол, ограничения синхронизации каталогов
на Windows и граница process-crash/power-loss — ADR-0034/EV-051.
P07.08 добавляет атомарную цепочку исторических схем/архивных адаптеров и
общий startup gate: Storage для обычных обработчиков/обмена выдаётся только
после допущенной текущей схемы и сверки commit/публикации. Один Startup хранится
владельцем жизненного цикла установки на весь запуск; одна automatic-попытка,
после отказа явный retry, при restart новая automatic. Отмена ожидания не
запускает вторую миграцию. `Storage::open` использует тот же gate, а не обход.

Продуктовый реестр остаётся v1; v2/v3 из crash/исторической матрицы существуют
только в тестах. Источник прав, внешние входы и служебное восстановление ещё
не реализованы. Договор и ограничения —
[ADR-0036](decisions/0036-atomic-migration-startup.md),
[EV-053](../agent/verification/EV-053-atomic-migration-chain.md),
[EV-054](../agent/verification/EV-054-startup-attempts.md).
