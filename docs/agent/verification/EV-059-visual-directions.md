## Результат

«Кальку», «Графит», «Прилив», «Сад» и «Спектр». Каждый вариант — один адаптивный

[документации эксперимента](../../development/visual-exploration.md) и README вариантов.

## Выполненные проверки

- Chromium/Playwright через `file://`, без сервера: пять вариантов на ширинах
  1280, 360, 390 и 412 px. Все 20 компоновок открылись без ошибок JavaScript,
  HTTP(S)-запросов и горизонтального переполнения документа. Фон и карточки
  просмотрены на снимках ПК и 390 px. Проверен синтаксис inline JavaScript.
- Десять сценарных прогонов: каждый вариант на 1280 и 390 px. Поиск находит
  карточку в другой колонке; на телефоне при необходимости выбирается её вкладка.
  Проверены очистка поиска, открытие карточки, редактирование с отменой, сохранение,
  буквальный вывод пользовательского HTML, ширина диалога, создание, удаление,
  восстановление, обратное редактирование и возврат исходных данных после reload.
  Все десять прогонов прошли. Исходные различия доступных имён у «Сада» исправлены
  автором и проверены повторно на обеих ширинах.
- Каталог: все пять переключателей загружают соответствующие файлы в обе рамки
  и меняют ссылку отдельного открытия; три режима просмотра и три ширины телефона
  работают; сброс демо перезагружает обе сессии. Каталог без горизонтального
  переполнения на 360, 390 и 800 px; ошибок JavaScript нет.
  Отдельно при 1500 × 1500 проверены сброс реальных правок в обеих рамках и
  прямое открытие `#04-garden`. Все локальные HTML-ссылки и whitespace 13 файлов

- Для показа в чате подготовлена копия каталога с inline-документами всех вариантов.
  `html_preview`: ширина 728 px, высота содержимого 1888 px, consoleMessages пуст.

## Пять правил и границы доказательств

| Правило | Что подтверждено |
| --- | --- |
| Обратимость | В каждом макете работают отмена редактирования, обратное изменение, удаление и восстановление карточки. Reload сбрасывает весь эксперимент. Глубина undo различается и описана в README. |
| Человек и агент | Действия доступны через одни семантические элементы управления; сценарии использовали labels/roles. Продуктовый API не подключён, его паритет этим не принимается. |
| Документация | Каталог, README направлений, development-инструкция, эта EV и журнал отражают результат и ограничения. Пользовательское поведение продукта и архитектура не менялись. |
| ПК и Android | Проверена адаптивная HTML-компоновка и одинаковый набор базовых действий. APK, Device/WebView, касания на устройстве и нативный паритет не проверялись. |
| Источник истины | Один исходный набор карточек, собственное единое состояние страницы для всех размеров экрана. Каждая рамка — независимая сессия; настоящей синхронизации нет. |

Это визуальное исследование, а не реализация P04/P05 и не утверждённая дизайн-система.
Продуктовые критерии, P03.05/BUG-004 и очередь от этих результатов не меняются.
Следующий шаг: разработчик выбирает направление и необходимые сочетания решений;
перенос в продукт и проверки платформ требуют отдельного задания.
