# ADR-0039: общий вход и сохранение клиентского намерения

Дата: 2026-11-05. Статус: техническое решение P03.05.4.

`zedone-adapters::Service` принимает отдельно операцию, исходный JSON и ключ.
Он выбирает конкретный Rust decoder и фиксированный core handler, затем
`Storage::timed_transact`. Адаптер не принимает callback, часы, субъект или
требования доступа. Обработчики `access.inspect`/`access.revoke` требуют
ManageAccess до чтения цели или receipt. Отзыв проверяет исходную StateVersion.
Проекция версии включает область, срок, отзыв и все текущие/старые хеши ключей,
поэтому повторная выдача не оживляет старое намерение. Хеши наружу не выходят.
Последнего бессрочного администратора нельзя отозвать до передачи управления.
Обратное действие — явная новая выдача с новым ключом через доверенный host;
формы выдачи, подтверждение и подключение устройств остаются P06.

Все три входа используют тот же Service и JSON-ответ после commit:

- HTTP: POST `/v1/commands/access.inspect` и `/v1/commands/access.revoke`,
  `Content-Type: application/json`, `Authorization: Bearer <64 lowercase hex>`.
  Лимит исходного тела 64 KiB; двойные/неизвестные поля отклоняет Rust decoder.
  Доставленный JSON-конверт имеет HTTP 200; успех определяет только `status`.
  Ответы не кэшируются, CORS не включён. Origin разрешается только по точной
  настройке доверенного host; сам Origin/Host прав не даёт. Прочие origins,
  двойная авторизация и неверное framing отклоняются. Listener и его lifecycle
  предоставляет host; внешняя сеть требует доверенного защищённого канала P06.
- CLI: `zedone --database <existing-file> --key-file <private-file>
  --operation <name>`, исходный JSON на stdin, конверт на stdout, exit 0 при
  успехе/1 при ошибке команды/2 при ошибке вывода. Ключа в argv или логах нет.
  CLI не создаёт установку, не вызывает bootstrap и не обходит startup gate;
  миграция без настроенного host-комплекта закрыта. На Android тот же бинарник.
- IPC: `zedone_command` принимает производный из Rust
  `invocation: { operation, request }` и отдельно `credential`.
  `request` — исходная JSON-строка: промежуточный Value не должен стирать
  дубли полей. Tauri State содержит тот же Service, generate_handler готов
  для подключения в P05; bridge компилируется для обеих Android ABI. Само
  приложение/WebView/lifecycle относится к P05/P06, не создаётся адаптером.

Права передаются отдельно от конверта; секрет — только предъявленный ключ,
не выводится из имени устройства/localhost. Никакого сетевого bootstrap,
переноса тестовых прав или чтения всей базы не появляется. Снимки пространств
не содержат прав. Выдача/замена и доставка секрета остаются доверенными
инфраструктурными операциями до протокола P06.

`client/commands.ts` использует производные Rust/OpenAPI-типы и openapi-fetch.
Новое намерение получает 128 бит из `crypto.getRandomValues`, проверяется
ненулевое значение; весь JSON сохраняется до первой отправки. Хранилище
незавершённых намерений не содержит ключей и перечисляет ID после restart.
Ошибка сохранения не допускает отправку. Мутация формы после подготовки не
меняет сохранённый запрос. Все доставки используют исходные байты и условия.

Автоматически выполняются максимум три попытки, паузы 250/1000 ms, таймаут
каждой попытки 10 s. Повторяются транспортная ошибка, потеря/некорректность
ответа, unavailable и outcome_unknown. Timeout IPC не отменяет уже принятое
worker задание. После исчерпания — сохранённое намерение и явный повтор.
Отказ прав/stale/mismatch/invalid/not_found прекращает автоматические попытки;
запрос остаётся для выяснения предыдущего неизвестного исхода. Stale требует
перечитать и подготовить новое явное действие, а не подставить новую версию
в прежний ID. Только подтверждённый success удаляет запись; ошибка удаления
сохраняет возможность безопасного повтора. Отдельное явное удаление pending
означает отказ от выяснения, а не отмену уже принятой операции.

HTTP-клиент не отправляет ключ в URL, не следует redirect и не использует
cookies. Незащищённый HTTP допустим только для буквального loopback; удалённый
адрес требует HTTPS. Ключ предоставляет host при каждой попытке; механизм
его выдачи/защищённого хранения остаётся P06. Pending store не становится
базой приложения или источником авторизации.

Обоснование API библиотек: [Axum](https://docs.rs/axum/0.8.9/axum/),
[openapi-fetch](https://openapi-ts.dev/openapi-fetch/api),
[Tauri State](https://v2.tauri.app/develop/state-management/) и
[IPC commands](https://v2.tauri.app/develop/calling-rust/).
Закреплены уже проверенные в прототипах версии Axum 0.8.9, Tauri 2.12.5 и
openapi-fetch 0.17.0; продукт не зависит от workspace прототипов.

Pending-намерение также хранит ID исходного субъекта отдельно от JSON-команды.
Одобренный credential provider host возвращает пару субъект/ключ. Смена ключа
того же субъекта допускает повтор, а смена субъекта останавливает доставку с
identity_changed: прежний запрос не отправляется от другого участника. Этот ID
не выдаёт полномочий и не заменяет независимую аутентификацию Rust по ключу.

Проверка ответа в клиенте также выводится из Rust/OpenAPI: закреплённый
Ajv 8.20.0 генерирует standalone ESM `api/validate-response.js` и его d.ts при
`--write-types`. Product-check сверяет оба артефакта побайтово. Некорректный
конверт или вложенный результат не удаляет pending и не подтверждает успех.
Ajv — только dev-зависимость; в клиент не включаются библиотека или runtime eval.
Источник: [Ajv standalone](https://ajv.js.org/standalone.html).

Варианты AccessScope представлены отдельными строгими struct и untagged union,
как CommandResponse: это сохраняет additionalProperties:false и в Serde, и в
utoipa/OpenAPI. Проверки контракта и клиента отклоняют лишние вложенные поля,
не ослабляя схему из-за ограничений вывода internally tagged enum.
