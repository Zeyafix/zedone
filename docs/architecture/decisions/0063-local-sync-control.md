# ADR-0063: локальное намерение обмена и общая пауза пространства

Дата: 2026-11-16. Статус: технический срез P06.03.1; проверки —
[EV-108](../../agent/verification/EV-108-sync-control-storage.md).

Продолжение полного P06.03 по LOG-585 — [ADR-0064](0064-space-exchange.md)
и [EV-109](../../agent/verification/EV-109-space-exchange.md). Ниже исходная
граница .1; .2 разрешает сохранять выбор ещё не полученного пространства,
добавляет staging и подключает общий API. FK на documents для настроек снят,
первая доставка создаёт готовый документ атомарно. Права/пауза/revision и
сохранность готовых данных сохраняются; стартовая схема остаётся v1.

## Решение

- `sync_selections` хранит явный локальный выбор пары пространство/подключение.
  Ключ подключения — общий request ID существующего pairing-процесса, одинаковый
  на принимающей стороне в SQLite и на исходящей стороне в защищённой OS-сессии.
  Повторное подключение получает новый ID и не наследует прежний выбор.
  FK на локальный access principal не вводится: исходящее подключение хранится
  в OS registry и не создаёт такого локального principal.
- `sync_spaces` хранит отдельную явную паузу всего пространства. Она относится
  к входящему и исходящему обмену со всеми устройствами. Смена выбора устройства,
  восстановление связи, совместимость или чтение настроек не снимают паузу;
  снять её может только отдельное явное действие. Это локальное состояние,
  оно не распространяется как содержимое Automerge-документа.
- Отсутствующая запись означает «не выбрано» и «явной паузы нет». Это не
  разрешает обмен: будущий engine обязан в своей транзакции дополнительно
  проверить действующее подтверждённое подключение, актуальные права на это
  пространство, локальное намерение обеих сторон и совместимость.
  ID подключения и запись выбора не являются учётными данными или выдачей прав.
- Выбор/отключение и пауза/возобновление выполняются доверенным `WriteContext`
  вместе с остальными изменениями `BEGIN IMMEDIATE`. Успех — только после commit.
  Ошибка примитива помечает весь контекст неуспешным даже при перехвате ошибки.
  Никаких сетевых эффектов до commit этот слой не выполняет.
- У каждой записи собственная возрастающая revision. `StateVersion` включает
  область, идентификаторы, значение и revision; возврат к прежнему bool не
  оживляет старое намерение. Переполнение отклоняет транзакцию. Действующий
  no-op не увеличивает revision. Records с false не удаляются, чтобы сохранить
  защиту ABA; automatic cleanup не вводится.
- Эти таблицы не заменяют `peers.state`: прогресс Automerge, actor, changes,
  пользовательская история и command receipts не меняются при отключении.
  Пауза и выбор имеют отдельные версии и не делают свежие правки карточек
  устаревшими. Пауза одной пары не моделируется отдельным флагом peer.
- Начальная схема v1 изменяется на месте по ADR-0047. Синтетический эталон
  получает только новые пустые таблицы; все прежние строки сохранены.
  Предыдущая база разработки отклоняется до writable-открытия без миграции,
  удаления и автоматического сброса. Для новых сборок выбирается пустой каталог.

## Граница среза

Это конкретные storage-примитивы подготовки обмена, как `set_peer_state` в
ADR-0028. Прямого пользовательского/агентского доступа к ним нет; API/CLI/UI и
сетевой приём подключаются после рабочего защищённого обмена в P06.03.2/.3.
Они будут использовать одни проверки core, без прямой записи агента в SQLite.
Пауза должна перепроверяться при допуске сетевой работы и перед фиксацией
входящих данных; этот storage-срез ещё не доказывает такую интеграцию.

Выбор пространства на устройстве, где его ещё нет, начальная доставка,
ограничения направления при read-only, compatibility handshake и сетевые
повторы относятся к следующим срезам. Эта запись не объявляет их готовыми
и не закрывает DEC-002/003 либо T09/A03/A08/A48.
