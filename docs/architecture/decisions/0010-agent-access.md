# ADR-0010: чтение и срок «До отзыва» по умолчанию для агента

Дата: 2026-10-26.

Статус: принято разработчиком. Реализация и техническая проверка не выполнены.

## Контекст

Для агента уже согласованы отдельные доступы к выбранным пространствам, режимы чтения и чтения с изменением, отзыв доступа и отдельно выдаваемые административные права. Требовалось выбрать начальный режим формы выдачи доступа.

Разработчик выбрал чтение по умолчанию с явным включением разрешения на изменения. Начальное чтение с изменением рассмотрено как альтернатива.

Дополнительно разработчик выбрал срок обычного доступа «До отзыва» по умолчанию с возможностью задать ограниченный срок при выдаче. Начальный срок 24 часа рассмотрен как альтернатива.

## Решение

- В форме выдачи агенту доступа к выбранным пространствам первоначально выбран режим «Чтение».
- Для чтения с изменением требуется явный выбор при выдаче доступа. Этот режим допускает создание, изменение, перемещение и удаление объектов в пределах разрешённых пространств по общим правилам.
- Доступ создаётся после подтверждения выдачи; открытие формы и её начальное значение сами по себе ничего не разрешают.
- Для обычного доступа к выбранным пространствам по умолчанию выбран срок «До отзыва»: разрешение действует до явного отзыва. При выдаче можно выбрать ограниченный срок; после его истечения доступ прекращается, а продолжение требует нового явного разрешения. Любой доступ можно отозвать раньше.
- Форма передаёт выбранный режим в общий API. Проверки в Rust-ядре обязательны независимо от формы: доступ с чтением не разрешает изменяющие команды.
- Административные права на устройства и управление доступами выдаются отдельно. Обычное чтение или изменение пространств не предоставляет их.
- Действуют общие операции изменения и отзыва прав. Правило одинаково для человека и агента, Windows и Android.

## Границы и технические вопросы

Решение определяет начальные значения формы, явное разрешение изменений и срок обычного доступа. Формат учётных данных, хранение и техническая реализация отзыва/истечения, точный контракт выдачи и обработка отсутствующих параметров API остаются вопросами DEC-003. Формат задания срока, изменение срока уже выданного доступа и поведение начатых операций на границе истечения ещё проектируются. Начальное значение формы не является основанием незаметно выдавать право изменения через другой адаптер.

Срок разрешения и срок технических учётных данных могут различаться: выбор «До отзыва» не предписывает бессрочный технический ключ. Механизм обновления учётных данных ещё не выбран и не должен незаметно продлевать истёкшее разрешение. Решение о сроке относится к обычному чтению/изменению выбранных пространств; срок отдельно выдаваемого административного доступа и одноразового приглашения на подключение устройства этим выбором не определён.

Новые режимы и библиотеки не вводятся. Полномочия полной копии и аварийного восстановления всей базы остаются отдельным открытым вопросом; обычное чтение/изменение не объявляется достаточным для этих операций.

## Проверка и правила проекта

Уточнены сценарий 8 спецификации и A08: начальные чтение и срок «До отзыва» в форме, отсутствие доступа до подтверждения, явное включение изменения, выбор ограниченного срока, прекращение доступа по истечении и раннему отзыву, разрешённые чтения и отказ изменяющим командам при чтении, отдельные административные права. Продолжение после истечения требует нового явного разрешения. Общий контракт и проверки прав относятся к T06; полный UI и API на обеих платформах проверяются в A08. Все критерии сохраняют `not_run`.

Изменение и отзыв прав обеспечивают обратные действия. Общий API, паритет Windows/Android и одно авторитетное состояние прав в Rust-ядре остаются требованиями. Документация отражает выбор; реализации и приёмки пока нет.
