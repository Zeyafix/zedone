# ADR-0031: общий JSON-контракт команды и результата

Дата: 2026-11-05.

Статус: техническое решение P03.05.1; требования ADR-0029/0030 сохраняются.
Проверки — [EV-048](../../agent/verification/EV-048-transport-contract.md).

## Решение

`core::wire::CommandRequest<C>` содержит `id`, `operation`, `parameters`.
`id` — ненулевой массив из 16 целых байтов 0…255; он передаётся executor без
преобразования, поэтому существующие ключи receipts не меняются. Новое намерение
требует нового криптографического ID на клиенте; генератор и политика доставок
будут проверены вместе с адаптерами P03.05.4. Повтор сохраняет весь конверт.
`operation` точно совпадает с `C::NAME`; `parameters` декодируются в конкретный
строгий Rust-тип команды, включая исходные условия. Общий `decode_request`
возвращает `invalid_request` при ошибке JSON, полей, имени или ID, не отражая
в ошибке входной текст. Прикладную валидацию и права всё равно проверяет обработчик.

Учётные данные передаются отдельно от JSON-команды. Субъект, разрешения и часы
получает доверенная инфраструктура после ожидания транзакции; транспорт не может
подставить их из конверта. Декодирование не аутентифицирует и не исполняет запрос.
HTTP-маршруты, статусы/заголовки, CLI и IPC закрепляются в P03.05.4 после прав/часов.

`CommandResponse<T>` имеет два различимых варианта:

- `{"status":"ok","result":T,"replayed":false}` — подтверждённое исходное
  выполнение; `replayed:true` возвращает его прежний результат без новой мутации.
- `{"status":"error","error":{"code":"…"}}` — один из семи общих кодов.
  `outcome_unknown` не является успехом или доказательством отсутствия записи.

Успех сериализуется только после возврата успешно зафиксированной транзакции,
не по промежуточному `Execution` внутри callback. Результат не является свежим
view и не отменяет позднюю правку/обратное действие. Политика повторов остаётся
ADR-0030: `stale_state` требует нового явного намерения, а неизвестный исход —
сохранения первоначального ID и запроса. Rust `Result` с `Ok`/`Err` не является
форматом транспорта. Лишние поля и смешанные варианты отклоняются.

## Схемы и производные

OpenAPI получает конверты с `serde_json::Value` только как общие схемы,
без регистрации тестовой операции или `paths`. Неизвестные параметры/результат
такого конверта не заменяют конкретные типы будущих операций. При добавлении
операции её схема выводится из того же обобщённого Rust-типа с конкретным `C`/`T`.
Контрактный тест проверяет строгие объекты и точные границы байтовых массивов;
`StateVersion` остаётся 32 байтами, формат хранимых данных не меняется.

Для ответов использованы два строгих struct и объединение: текущий utoipa
не переносит `deny_unknown_fields` с internally tagged enum в каждую ветку.
Так OpenAPI и Serde выражают один договор без ручной правки JSON-схемы.
Для байтовых массивов Rust задаёт явные длины и диапазон элементов; типовой
вывод utoipa для массива не отражает эти ограничения полностью.

`api/schema.d.ts` воспроизводимо генерируется закреплённым openapi-typescript
из проверенного Rust/OpenAPI. Product-check сверяет оба артефакта побайтово
и компилирует положительные/отрицательные TypeScript-примеры. Прямая правка
производных не заменяет исходник; CI проверяет дрейф на Windows/Linux/Android.
Генератор разворачивает ID в tuple длины 16; для массивов длины 32 оставляет
`number[]` из-за собственного ограничения размера. TypeScript не проверяет
диапазон байтов или ненулевой ID: обязательная проверка выполняется Rust.

## Границы

Нового runtime-входа, хранилища прав/часов/bootstrap, продуктовой операции или
UI нет. Тестовые права и обработчик не включаются в библиотеку. P03.05 разделён
до реализации; родитель и T06 не завершены. Схема SQLite 1, Rust-зависимости
и прототипы не меняются; перед персистентными правами обязательны P07.07/P07.08.
Генератор и TypeScript закреплены отдельным root package/lock, без зависимости
продукта от workspace прототипов. Root node_modules не входит в Git.
