Один вопрос проверки — актуальность и атомарность повторного исполнения.
Объём превышает ориентир 300 ручных строк из-за одной матрицы отрицательных,
конкурентных и аварийных сценариев на двух платформах, а также договора портов.
Независимых продуктовых действий/рефакторинга/обновлений пакетов нет.

## Реализованный договор

Общий `core::replay::execute` проверяет текущие права до receipt lookup.
Область ID — проверенный стабильный субъект в локальной установке; формат ключа
не смешивается с низкоуровневыми записями storage. Сохраняются тип операции,
цели, параметры и первоначальное условие актуальности. Изменённый запрос
выполненного ID отклоняется; идентичный возвращает исходный результат без
вызова обработчика. `Execution::replayed` не означает актуальность объекта.

Невыполненная команда сравнивает исходный `StateVersion` с авторитетным
состоянием перед изменением внутри той же write-транзакции. В проекцию входят
проверяемые данные и причинные идентичности их изменений: возврат прежних
значений не оживляет старую команду. Несвязанные данные/техническая история
не входят в признак. Общий primitive даёт фиксированные 32 байта SHA-256;
точные продуктовые проекции P04 ещё впереди.

`Storage::transact` фиксирует данные и receipt одной `BEGIN IMMEDIATE`
транзакцией. Ошибка вставки receipt помечает контекст неуспешным даже после
перехвата; callback не может сообщать успех клиенту до commit. Прежний `write`
остаётся доверенной инфраструктурой. Схема SQLite 1, прежние версии пакетов,
OpenAPI, прототипы и workflow YAML не меняются. Прямой sha2 0.11.1 и тестовый
utoipa уже присутствовали в lock; новых пакетов/версий нет. Core не получает
SQL/Automerge/sha2-зависимостей.

Источник доступа, часы и синтетическая карточка существуют только в тестах.
Это не продуктовая команда выполнения, не база прав и не новый публичный API.
Полный договор — [ADR-0030](../../architecture/decisions/0030-command-replay-and-freshness.md).

На платформу десять отдельных дочерних остановок без деструкторов: пять прежних
storage и пять новых executor. Это не физическое отключение питания.

| Сценарий | Проверенный результат (passed) |
| --- | --- |
| Повтор после обратного действия/restart | Прежний результат, текущее состояние/история сохранены, без третьего эффекта |
| Изменённые параметры/цель/условие/операция | `command_mismatch`, эффект один |
| Семантические поля карточки | Изменение текста/тега/выполнения/колонки/порядка/корзины отклоняет старую невыполненную команду; новое явное действие проходит |
| Изменение с возвратом | Новое намерение со старым признаком отклоняется; повтор выполненного ID разрешён без эффекта |
| Контроли | Техническая история/другое пространство не меняют признак карточки |
| Вложенная проекция | Данные/состав/порядок/причинные изменения меняют признак; это не приёмка удаления контейнера |
| Конкуренция | 40 доставок одного ID через два worker → один эффект; 16 разных намерений от одной версии → один успех, остальные stale |
| Права/очередь | Отзыв/граница срока/снижение прав закрывают сохранённый результат до lookup; отзыв за время ожидания также запрещает исполнение |
| Субъект/ID | Другая идентичность не получает чужой результат; нулевой ID отклоняется |
| SQL/повреждение | Receipt SQL-отказ откатывает изменение; повреждённый результат не запускает обработчик; перехват ошибки record не даёт commit |
| Сериализация | Ошибка результата откатывает эффект; ошибка проекции — unavailable |
| Потеря ответа/паника | Отмена future не отменяет принятое задание; panic до commit → unknown, исходный повтор исполняется один раз |
| Fault/crash | Пять fault и пять отдельных дочерних process-stop границ: повтор после commit читает receipt, до commit исполняется заново один раз |

Синтетическая история остаётся прежней при выполнении/снятии выполнения;
счётчик эффектов доказывает отсутствие повторной мутации. Product-история
текста/серии/группы удаления P04 этим не принимаются. Чтение, права и последняя
проекция происходят на worker после ожидания транзакции.

## Ограничения и правила проекта

- Обратимость: проверено выполнение → снятие → повтор старой команды без
  отмены снятия. Продуктовые действия P04 ещё не созданы.
- Человек/агент: одна политика ядра без привилегированного транспорта;
  HTTP/CLI/IPC/UI впереди. Прямой доступ агента к SQLite не разрешён.
- Документация: ADR, архитектура, разработка, агентские правила, очередь и журнал
  отражают срез. Изменений пользовательского интерфейса нет.
- Паритет: одинаковые 56 тестов Windows/нативного Android x86_64 и обе
  Android ABI release/unsafe passed; физический arm64, APK/UI и локальный Linux
  не входят в приёмку.
- Источник истины: одна SQLite/Automerge и её command_results; версия производна,
  не становится второй копией данных. Реальный источник прав/часы ещё предстоит.

Результаты не истекают и не ротируются; цена роста остаётся DEC-009. Откат/утрата
базы, восстановление старой копии и очистка сведений требуют отдельной защиты
до соответствующих сценариев P07. Настоящий restart не удаляет receipt.
Надёжность времени/отзыва/аутентификации, bootstrap и их атомарная реализация
обязательны до внешних входов P03.05/P06. Клиентские таймауты/попытки ещё не
определены. T06/A05/A07 остаются partial; A55/A56 не объявляются пройденными
по общему primitive, DEC-003/DEC-009 open. Производительность приложения,
физическое отключение питания и продуктовый обмен не проверялись.
