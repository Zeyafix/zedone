Один результат проверки: пригодность текущего интегрированного среза P01.

API 33 x86_64 эмуляторе без изменения измеряемых исходников и APK. Цель —
сопоставить полные серии и расходы наблюдателя с сохранёнными телефонными
результатами. Сохранены прежние контроли, точные bitmap/ADB/PNG-сверки,
независимая проверка статистики/снимков A/B и очистка собственного эмулятора.
Локальные полные серии, отдельный отказ подготовки поиска, независимые проверки
и сравнение расходов — `docs/reports/p01-11/emulator-transports-review.md`.

приложения от ОС, WebView, ABI, захвата и транспорта; A62 остаётся partial.

проверить только lossless `Deflater(BEST_SPEED)` того же RGBA OS-участка.

## Физическое продолжение

По поручению разработчика scope расширен только на явный физический
ARM64/API 33 профиль целевого Android-устройства и его восстановление.
До установки — снимки A/B через IPC исходного debug-прототипа, резервная копия
APK и проверка совпадения сертификатов. При несовпадении подписи прогон
останавливается без удаления приложения. Во время измерения используется
release/instrumentation без CDP; после возвращаются снимки, исходный APK,
прежний тестовый APK (либо удаляется созданный измерителем) и настройка
удержания экрана при USB-питании. Прикладные операции/модель/права не меняются.
Критерии: T02/T04/A62, те же полные серии/контроли и отдельные результаты
эмулятора/телефона. Изображение ОС телефона не выдаётся за свет матрицы;
открытие/выполнение карточки, полный UI/IME и продуктовая приёмка не добавляются.
Машинные доказательства/ограничения — docs/reports/p01-11/release-pixel-review.md.

## Продолжение: OS-захват через UiAutomation

База `cb54e54`. По поручению разработчика продолжен GAP-006 с подключённым
телефоном. Scope: отдельный Java test APK, его socket-адаптер, существующий
Android pixel-сценарий и agent/development документация. Цель — уменьшить
расходы передачи полного PNG без изменения прикладных операций и границы времени.
`UiAutomation.takeScreenshot()` получает изображение ОС; обрезка выполняется
после захвата. Часы host-драйвера по-прежнему включают команды, захват, PNG,
передачу и декодирование. DOM/rAF не завершают интервал.
Команда/ожидание DOM/выравнивание объединены в одну evaluation; пауза перед
первым release-захватом явно входит в host-интервал, не форсирует кадр и не
заменяет OS-совпадение. Эталоны требуют двух совпадающих ADB PNG и сверки
native-наблюдателя; попытки подготовки сохраняются отдельно от измерений.

План проверок: сборка обеих ABI; побайтное совпадение с независимым ADB-захватом
для неподвижного участка; прежние отрицательные контроли; полные серии,
снимки A/B, возврат исходных APK и настройки экрана; общий `bun run check`.
Условия и результаты конкретной машины сохраняются только в
`docs/reports/p01-11/uiautomation-pixel-review.md`. Отсутствующие операции,
системный ввод, физическая матрица и продуктовая приёмка не добавляются.

Драйвер ждёт готовую страницу WebView до подключения CDP и использует
DOM-команды без современных locator visibility helpers, требующих более нового
Chromium. Полифилл в приложение не добавляется. Прерванные и неуспешные попытки
сохраняются отдельно и не входят в успешные серии.

Успех выполнения сценария не означает попадание во временной ориентир.
Превышения в UI нельзя скрывать или компенсировать вычитанием кадров/накладных расходов.
Граница кадра через два requestAnimationFrame ещё не подтверждена независимым
наблюдением физического показа; GAP-006. A62 — partial, P01.11/P01 не завершены.

интервал подтверждённого DOM-изменения. Такой контроль не даёт основания вычитать
кадры или объявлять ориентир достигнутым. Результаты конкретных запусков,
