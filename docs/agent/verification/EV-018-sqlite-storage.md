Реализованы запись и повторное открытие базы/процесса, буквальный Unicode-поиск,
согласованный логический снимок A без B, обратные команды, отказ записи без
частичного результата и отзывчивость UI/echo при ожидании блокировки SQLite.
Оба транспорта используют одни модели Rust/OpenAPI. База прототипа изолирована
от продуктовых данных; HTTP остаётся только на loopback, сервер APK — P01.10.

## Проверки

| Проверка | Результат |
| --- | --- |
| `bun run check` | Пройдено: fmt, Clippy с запретом предупреждений, 9 Rust-тестов, release, повторяемость OpenAPI/TS/IPC-команд, vue-tsc и Vite, HTTP/Chromium |
| `bun run check:http` с Chrome | Пройдено на отдельном временном профиле |
| `bun run check:http` с Opera | Пройдено на отдельном временном профиле; общий лимит расширенного набора проверок увеличен с 45 до 90 секунд |
| `bun run android:build` и `bun run android:build aarch64` | Оба debug APK собраны с bundled SQLite |
| `bun run check:android` | Пройдено на AOSP Android 13/API 33 x86_64 без GMS: реальный WebView/IPC, та же форма и данные, работа без сети, force-stop/перезапуск |

Фиксированный профиль A: 3 колонки, 30 карточек, 820 строк описаний;
41 273 байта UTF-8 JSON, SHA-256
`6153192a7ac81161fb30c15586fb7b5a76717418b810c61fab799ef857b98554`.
Проверено точное содержимое, включая комбинируемое `café`, кириллицу и emoji;
HTTP и IPC возвращают один результат.

Реальные проверки отказов включают неверный внешний ключ после начала замены
пространства (прежние A/B сохраняются), SQLITE_BUSY при отдельной эксклюзивной
транзакции (echo и UI продолжают работать), явное чтение после ошибки,
идемпотентность seed/delete и восстановление ранее сохранённого снимка.
HTTP дополнительно проверяет потерю ответа уже выполненного удаления: интерфейс
не сообщает об успехе/откате, последующее чтение обнаруживает сохранённый результат.
Параллельные запросы snapshot/restore принимают только полную прежнюю или новую
версию; Rust-тест держит одну read-транзакцию через параллельный commit в WAL.

Начальные остановки проверок относились к драйверу: в PATH был другой Node,
15 секунд не хватило для установки большого APK, тест lock-helper ожидал иной
относительный Android-каталог. Использован уже подготовленный portable Node LTS,
лимит установки увеличен, каталог helper согласован с Tauri; приложение ради
драйвера не патчилось. Системные инструменты не переустанавливались.
Прежние 45 секунд общего HTTP-прогона оказались недостаточны в Opera для
добавленных сценариев; после увеличения лимита весь набор пройден. Этот лимит
драйвера не является измерением или ослаблением продуктовых целей A62.

## Границы результата

Схема и JSON временные; история, корзина, конфликты, права, миграции и Automerge
не реализованы. Поиск использует Rust lowercase/contains без индекса и без
обещания полного Unicode case folding. Продуктовые A19/A62, DEC-005 и прочие
открытые решения не закрываются. Отдельный HTTP-сервер APK остаётся в P01.10.
Физический телефон и составной ввод русской IME не проверены; arm64 — сборка,
исполнение проверено на x86_64 эмуляторе. Новые Linux/Actions/PR не запускались.

Снимок формы хранится в памяти до перезагрузки; постоянная резервная копия и
страховочный снимок перед продуктовым восстановлением относятся к P07.
Транспортное ожидание без ответа не считается откатом: автоматического повтора
изменения нет, после перезапуска можно явно прочитать БД.

Объём больше ориентира 300 строк: один проверяемый срез хранения включает общий
контракт/транзакции, обе границы транспорта, обратные операции и их сквозные
проверки; отрыв Android/отказов оставил бы T03 неподтверждённым. Сгенерированные
OpenAPI/TypeScript и Cargo.lock проверены отдельно от ручных изменений.
Исходные логи, отпечатки и APK остаются только в игнорируемой `docs/reports/`
и каталогах сборки. Публикация, коммит и слияние не выполнялись.

Инструкции: [разработчик/API](../../development/sqlite-prototype.md),
[пользователь](../../user/prototype-storage.md). Обратные операции, общий API,
документация, паритет ПК/эмулятора и единый источник данных/моделей проверены
в пределах этого синтетического среза.

Следующее действие — проверить новые Windows/Linux и Android Actions и
интегрировать P01.05 при поручении на публикацию. Шаг остаётся `verified`,
T03 — `partial`; зависимый P01.06 не начинается до `done`.
