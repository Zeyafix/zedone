## Реализация

`CardHistory.vue` получает страницы только через прежний `card.history` и
operation-specific validator. Первое чтение не задаёт expected, следующие
передают history.version и next. При отказе страницы не смешиваются;
явное обновление перечитывает карточку и сбрасывает выбор/страницы. Поздний
ответ после unmount игнорируется. Заголовок и описание выводятся буквальным
текстом; ни HTML, ни удалённые картинки истории не исполняются/не загружаются.

`CardEditor` использует прежние flush/finish/requestClose при переходе из
ввода: история не прячет неопределённый результат или невалидный черновик.
Переход ожидает уже начатую доставку, включая автосохранение при blur.
При открытии фиксируются субъект и card.version. Выбранный text_version
отправляется через прежние prepare/CommandClient и журнал намерений;
после подтверждения перечитывается текущая карточка. Старый receipt не
подменяет более поздние данные. История и состояние страницы не кэшируются.
Ядро, схема, контракты, зависимости и бюджеты CI не менялись.

## Проверки и обнаруженные ограничения

- Типы и Vite build passed. Общий целевой `check-ui-history.mjs` прошёл
  desktop/touch: парный preview без HTML/сети, восстановление первой версии,
  обратное восстановление третьей, совпадающая пара новой версией, история
  после remount, переход из непрерывного ввода одной серией, strict stale,
  отказ без потери более новой правки, пагинация >25 версий и отказ старому
  history token, пустая история и следующая причинная версия.
- Проверки доставки на host: отказ локальной записи без запроса, access_denied
  без автоматического повтора, потеря ответа после реального commit,
  три доставки одного JSON, reload и исходный replay после поздней правки
  без ещё одной версии; ошибка чтения не показывается пустой историей.
  Все domain-команды проходят настоящий Service/SQLite; инъекции касаются
  только доставки, локальной persistence и сообщений об отказе.
- Android Device/agent-device, настоящий IPC: просмотр/буквальный HTML,
  первая версия → новая четвёртая → восстановление третьей новой пятой,
  возврат к карточке, ввод обоих полей/автосохранение/finish при переходе,
  Back, светлая/тёмная темы и restart. API на копии нативных данных проверил
  семь точных пар, сохранность тегов/выполнения/места и остальных карточек.
  Обе итоговые debug ABI и manifest passed; локальный CI-драйвер не запускался.
- Исходные 24 product/WebView файла восстановлены: имена и SHA-256 совпадают;
  системная тема возвращена к исходной светлой, Device выключен. Основная
  синтетика/ключи/архивы удалены штатной локальной процедурой восстановления.
  Удаление дополнительной проверочной синтетической копии в игнорируемом
  native-check автоматически отклонено `blocked by policy`; копия оставлена
  локально, публикуемые файлы её не содержат. Это ограничение уборки,
  а не дефект продукта.
- Первоначальные неуспешные проверки сохранены в локальных логах:
  старый host binary после одной Vite-пересборки, потеря перехода в историю
  при blur/активной доставке (исправлено ожиданием requestClose), раннее
  ожидание старого DOM после refresh и вызов Playwright checkVisibility
  при DOM-чтении в сенсорной fixture (исправлен тест, не ослаблены assertions).
  Один полный запуск столкнулся с Windows lock shell-fixture.exe во время
  параллельной подготовки Device-данных; подготовка закончена перед повтором.
  Ошибки ручного Android-драйвера — quoting @ref/неподдерживаемый флаг жеста
  и ранний snapshot при restart — исправлены штатными командами Device;
  они не принимаются за дефекты продукта или успех сценария.
