Охват — прежний изолированный Rust-пробник A/B с двумя полями title/text:
присваивания представлены неизменяемыми Map со скалярным `value`.
Markdown не объединяется посимвольно. Читаются все значения и
идентификаторы операций; обычная правка карточки с конфликтом отклоняется.
Явное решение записывается новым изменением после проверки прочитанного
состояния. Независимые разные решения дают новый конфликт.

Проверены независимые изменения разных полей, заголовка и Markdown, выбор
существующего варианта и объединённого текста, оба направления обмена,
повторную/переставленную доставку изменений, сохранение/перезапуск с конфликтом
и с двумя ещё не обменянными решениями. Перестановки изменений не выдаются за
поддержку произвольного порядка сообщений одной сессии sync.

Новых UI/HTTP/IPC-входов, продуктовых карточек, контейнеров, тегов и форматов
резервных копий нет. T05/DEC-002 остаются открытыми до дальнейших шагов P02/P03;
A04/A23/S04 получают только частичные доказательства до продуктового P06.

## BUG-003 и выбор модели

Во время разработки прямой scalar `put` при выборе существующего победителя
не сохранил независимое решение при поздней правке другой реплики. В исходниках
закреплённого Automerge 0.12.0 `OpsFound::resolve_action` такой выбор превращается
в удаление других операций без нового присваивания выбранного значения.
Каждая правка/решение теперь создаёт новый Map через `put_object` и один раз
записывает его `value`; последующие правки заменяют присваивание целиком.
Это штатные операции библиотеки, без патча или собственного CRDT. Отдельный
регрессионный тест выбирает победивший и другой исходный текст на обоих участниках
и проверяет новые ID и сохранение обоих решений. BUG-003 resolved локально;
поведение отражено в ADR-0002 и документации прототипа.

## Правила проекта и ограничения

- Обратимость: после разрешения обоих полей выполнены новая правка и возврат
  текста с обменом на обе реплики; исходные варианты сохранены в истории.
- Человек/агент: один CLI вызывает один внутренний Rust-модуль. Прямое изменение
  SQLite применяется только для отрицательных тестов, не как прикладной вход.
- Документация: очередь, журнал, ADR-0002 и описание прототипа обновлены;
  пользовательские операции приложения пока не добавлены.
- Паритет: тот же пробник выполнен на Windows и Android x86_64; физический
  arm64 и новый APK/WebView-путь не проверялись, arm64 только собран.
- Источник истины: документ/actor/peer фиксируются в SQLite вместе; JSON —
  только ожидания проверки, не источник восстановления или редактирования.

Проверки переставляют изменения `apply_changes`, а не сообщения внутри одной
сессии sync, которой нужен надёжный упорядоченный поток. Неполученные изменения
перед сохранением итогового набора здесь не моделируют продуктовый сетевой буфер.
Продуктовые права/контракты, запись несколькими процессами, kill/power-loss внутри
commit, контейнеры, теги, удаления против правок, рост/память и бюджет всего
приложения остаются последующим шагам. Увеличение числа объектов на присваивание
требует измерений в P02.06. Формат временных баз изменён, миграция старых пробников
не является гарантией выпущенного продукта.

Объём превышает ориентир 300 строк: модель присваивания, конфликт/разрешение,
регрессия BUG-003, один сценарий перезапусков обеих платформ и необходимые
отрицательные проверки образуют одно наблюдаемое поведение. Независимые
продуктовые функции и последующие шаги P02 в этот срез не включены.
