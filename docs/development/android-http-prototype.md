# Ограниченный HTTP в APK — P01.10

Общий `core::http` содержит маршруты echo/QR/приглашения/SQLite для ПК и APK.
APK клонирует тот же `Storage`, который обслуживает IPC: путь, семафор и
SQLite общие. HTTP не становится отдельной копией состояния интерфейса.
Модели локального управления `HttpSessionRequest/Status` генерируются из Rust
в OpenAPI components и TypeScript. IPC-команда `http_session` не является
удалённым маршрутом: ключ не разрешает управление сервером или выдачу прав.

## Запуск и обратное действие

Соберите/установите APK по [Android-инструкции](android-prototype.md).
В форме «Тестовый HTTP-доступ» задайте конкретный IP этого устройства и порт.
Для локальной проверки подходит `127.0.0.1`, порт `0` выбирает свободный порт.
Для сети нужен настроенный Tailscale на обоих устройствах и его IP Android.
Допускаются loopback, IPv4 `100.64.0.0/10` и IPv6 `fd7a:115c:a1e0::/48`;
адрес должен реально принадлежать устройству. Wildcard, LAN и публичные IP
отклоняются; при ошибке bind нет перехода на `0.0.0.0`.
Реальная доставка на Tailscale-адрес Android пока не проверена.

По умолчанию разрешены только read/snapshot синтетического A и stateless
операции. Для seed/delete/restore/move требуется явное «Разрешить изменения A»
при запуске. Все операции B запрещены. Для смены прав остановите доступ и
запустите заново. Локальный IPC сохраняет полномочия владельца прототипа.

После запуска форма показывает endpoint и случайный ключ на 256 бит.
Ключ передаётся только заголовком `Authorization: Bearer …`, не query-string.
Ключ хранится в памяти, не в SQLite, настройках, URL или логах приложения.
«Остановить и отозвать» закрывает listener и отзывает ключ, повтор безопасен.
Native Suspended/Destroyed отзывает доступ, Resumed/Focused(true) разрешает
новый явный запуск. Focus учитывает игнорирование первого onResume в Tao
после пересоздания Activity. JavaScript очищает отображение, но не управляет
решением об отзыве. Сон/Home/пересоздание/force-stop не возобновляют доступ.

Уже допущенная операция SQLite может завершиться после отзыва или потери
ответа. Считать тайм-аут откатом нельзя: перечитайте состояние через IPC
либо новую разрешённую сессию; автоматического повтора изменения нет.
Ограниченный HTTP ждёт ответ до 5 секунд; явная остановка ждёт завершения
обслуживания до 6 секунд, при ошибке ключ остаётся отозванным.

## ПК: то же локальное управление

После `bun run check`, из `prototypes/`:

```powershell
./target/release/serve-echo.exe --limited target/p01-10-synthetic
```

На Linux используется `./target/release/serve-echo`. Процесс читает по одной
JSON-строке из stdin и возвращает `{"Ok":…}` либо `{"Err":…}`:

```json
{"action":"start","address":"127.0.0.1","port":0}
{"action":"status"}
{"action":"stop"}
```

Для изменений добавьте `"access":"write"` в start; отсутствие access означает
read. EOF/завершение процесса отзывает сессию. Не публикуйте вывод start/status:
он содержит временный ключ. Обычный режим serve-echo остаётся локальным
неограниченным синтетическим адаптером для существующего браузерного стенда.

## Запрос агента

Для разрешённой сессии отправьте POST `/prototype/storage` с JSON
`{"action":"snapshot","space":"A"}` или
`{"action":"read","space":"A","query":"ЁЖ"}`.
Остальные схемы берутся из `prototypes/openapi.json`.
Без ключа/с неверным ключом — 401; недостаточно прав/пространство B — 403;
браузерный Origin — 403, CORS не включён. Ошибки тела/ядра сохраняют прежнюю
валидацию; например, устаревшее перемещение возвращает 503 без изменения.
Запрос управления `/prototype/http-session` отсутствует (404).
После остановки возможны разрыв соединения или 401 на прежнем соединении.

## Воспроизведение проверок

Команды `bun run check`, `bun run android:build`,
`bun run android:build aarch64`, `bun run check:android` прежние.
Общий сценарий выполняет реальные запросы к ограниченному HTTP на ПК и в APK.
Для эмулятора runner создаёт временный adb forward к порту **внутри APK**;
это подтверждает Axum/SQLite/права и не подтверждает Tailscale.
Отдельная instrumentation-проверка реально пересоздаёт Activity.
Runner дополнительно проверяет форму, Home, сон, возврат и force-stop.
CI использует тот же runner; факт наличия сценария не означает успешные Actions.

Для отдельной будущей сетевой проверки: подключить ПК/Android к tailnet,
разрешить нужный TCP-порт политикой сети, запустить сессию на IP Android,
вызвать тот же API с ПК напрямую **без adb forward**, проверить 401/403,
равенство IPC, отзыв, Home/сон/возврат и отключение сети.
Включение Tailscale, изменение его политик и установка на личный телефон
не выполняются локальным runner. Реальные адреса, данные сети и логи — только
в `docs/reports/`. Результаты/непроверенные ячейки — [EV-023](../agent/verification/EV-023-android-http.md).

Этот временный стенд не содержит продуктовых прав, протокола подключения,
синхронизации, TLS сервера или обещания фоновой доступности. Основания и
границы переноса — [ADR-0025](../architecture/decisions/0025-limited-prototype-http.md).
