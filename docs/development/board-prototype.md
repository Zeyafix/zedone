# Доска P01.06

Один синтетический срез проверяет Reka UI, перетаскивание и сохранение порядка
на ПК и в APK. База, маршруты и запуск — из [P01.05](sqlite-prototype.md).
Инструкция интерфейса — [прототип доски](../user/prototype-board.md).
Приёмка и ограничения — [EV-019](../agent/verification/EV-019-board-interactions.md).

## Общие команды человека и агента

Rust `StorageRequest` расширяет тот же POST `/prototype/storage` и IPC `storage`.
Имена команд и TypeScript выводятся из Rust/OpenAPI. Жест, диалог и обратная
команда вызывают одну операцию. Прямой записи порядка из JavaScript нет.

| action | Поля помимо action | Семантика |
| --- | --- | --- |
| move_card | expected, card, column, position | ID карточки, индекс целевой колонки и позиция в её списке **после исключения переносимой карточки** |
| move_column | expected, column, position | Исходный и конечный индекс колонки; её карточки перемещаются вместе с ней |

Индексы начинаются с нуля. Для карточки допустимо добавление после последней
карточки и в пустую колонку. `expected` — полный результат `snapshot`, без
поисковой фильтрации. В пределах `BEGIN IMMEDIATE` ядро сравнивает его с БД,
проверяет координаты, сохраняет изменение и читает результат до commit.
Устаревший/повторно доставленный изменивший порядок запрос получает отказ без
новой записи. Некорректный индекс, отсутствующий объект и SQL-ошибка также
не оставляют частичного изменения. Пространство B сохраняется.

Пример агента, PowerShell после `bun run serve`:

```powershell
$api = 'http://127.0.0.1:4317/prototype/storage'
$initial = Invoke-RestMethod $api -Method Post -ContentType 'application/json; charset=utf-8' -Body '{"action":"seed","space":"A"}'
# Для фиксированного начального набора: карточка 1 из колонки 0, позиции 0.
$request = @{ action = 'move_card'; expected = $initial.snapshot; card = 1; column = 1; position = 0 } | ConvertTo-Json -Depth 10
$after = Invoke-RestMethod $api -Method Post -ContentType 'application/json; charset=utf-8' -Body $request
$request = @{ action = 'move_card'; expected = $after.snapshot; card = 1; column = 0; position = 0 } | ConvertTo-Json -Depth 10
Invoke-RestMethod $api -Method Post -ContentType 'application/json; charset=utf-8' -Body $request
```

Для произвольного состояния сначала прочитайте `snapshot` и вычислите исходную
позицию. `seed` не сбрасывает ранее изменённую доску. Для колонки обратная
операция меняет местами исходный и конечный индексы и содержит новый `expected`.

## Клиент и зависимости

`Board.vue` хранит подтверждённый снимок отдельно от производных списков
VueDraggablePlus. Временное перемещение списков не считается сохранением.
При отказе клиент автоматически читает БД; при отказе чтения скрывает временный
порядок и блокирует новые перемещения до явного чтения. Неизвестный результат
не превращается в успех или утверждение об откате; автоматического повтора записи нет.
Кнопка отмены вызывает обратное перемещение, а не восстановление всей доски.

Сложный компонент — только Dialog из `reka-ui 2.11.0`; простые поля/кнопки — HTML.
Диалог использует focus trap, доступные заголовок/описание, Escape и возврат фокуса.
Запись в истории WebView позволяет системной кнопке «Назад» закрыть диалог прежде
выхода из Activity. Диалог не содержит редактируемого текста: экранная клавиатура
и русский ввод дополнительно проверяются существующей echo-формой.

`vue-draggable-plus 0.6.1` уже включает SortableJS **1.15.2** в своём ESM bundle;
отдельная runtime-копия `sortablejs` не установлена. Используются ручки, задержка
250 мс только для касания, порог 5 px, fallback-перенос и встроенная AutoScroll.
Текст карточек остаётся доступен для обычной прокрутки. Весь текст сохраняется,
на доске показана первая строка описания. Минимальное оформление общее для ПК/APK;
полный дизайн и темы остаются в P05.

Для строгой проверки типов дополнительно закреплены `vue-component-type-helpers`
(публичные декларации Reka UI) и `@types/web-bluetooth` (декларации VueUse).
Bluetooth в приложение не добавляется. `@types/sortablejs` закреплён отдельно.
В декларации VueDraggablePlus колбэки с расширенным `DraggableEvent` конфликтуют
с унаследованными колбэками Sortable при `strictFunctionTypes`. Однострочный
[Bun patch](../../prototypes/patches/vue-draggable-plus@0.6.1.patch) исключает
переопределённые колбэки из базового интерфейса перед их объявлением.
Runtime не меняется; `strict` и проверка деклараций зависимостей сохраняются.
Patch воспроизводится `bun install --frozen-lockfile`; удалить его можно после
исправления upstream и повторной строгой проверки при обновлении зависимости.
Библиотеки и type-пакеты используют MIT; отдельные уведомления пакетов сохраняются
при установке, включая встроенный Sortable. Полное оформление выпуска — P08.

## Проверка и границы

`bun run check` включает Rust-тесты, генерацию/типы, Vite и HTTP/UI production bundle.
`bun run check:http` повторяет сценарии в браузере из `PROTOTYPE_BROWSER_PATH`.
`bun run android:build`, `bun run android:build aarch64` и `bun run check:android`
проверяют APK по [Android-инструкции](android-prototype.md).
Общий модуль `board-scenarios.mjs` проверяет равенство явной команды и жеста,
обратимость, фокус, сортировку, перенос между колонками, прокрутку и автопрокрутку
по обеим осям. Драйверы добавляют реальный SQL-отказ после начала записи, потерю
ответа после commit и перезапуск с изменённым порядком. Общий лимит HTTP-прогона
300 секунд учитывает расширившийся набор и медленный запуск действий в Opera;
это лимит тестового драйвера, не результат измерения A62.

Снимок как условие актуальности, позиционные идентификаторы колонок и перезапись
синтетического пространства остаются временными механизмами P01. Схема БД и
исходный профиль не меняются. Продуктовые версии, ID колонок, идемпотентные
повторы, история, права, конфликты и Automerge относятся к P02–P06.
Внешний HTTP APK остаётся в P01.10. Этот шаг не закрывает T02/A41 целиком.

Официальные руководства: [Reka Dialog](https://reka-ui.com/docs/components/dialog),
[VueDraggablePlus](https://vue-draggable-plus.pages.dev/en/guide/),
[SortableJS](https://github.com/SortableJS/Sortable).
