Один вопрос проверки — общий guard актуального доступа перед обработчиком.
Ориентир 300 ручных строк превышается из-за полной матрицы отказов и документации
одной границы; независимых функций, новых зависимостей и схемы хранения нет.

## Реализация

`with_authorized` заново вызывает доверенный `AccessTransaction`, проверяет
аутентифицированного субъекта против субъекта разрешения, точные пространства,
режим, срок и отзыв, затем передаёт субъекта обработчику. Административная
область отделена от доступа к данным. Пустые требования отклоняются.
Проверка предшествует чтению цели и прежнего результата команды.
Производного кэша прав и отдельного пути локального пользователя нет.
Точный договор порта и границы — [ADR-0029](../../architecture/decisions/0029-core-authorization.md).

Порт аутентификации/локального состояния и доверенные часы ещё не реализованы
в продуктовой инфраструктуре. Тестовый session существует только под cfg(test).
Проверки не доказывают выпуск ключей, персистентный отзыв, реализацию блокировки
в базе, защиту от отката времени, bootstrap, UI или HTTP/CLI/IPC.
Продуктовых входов ещё нет; схема SQLite 1 и OpenAPI не меняются.

## Проверки

| Проверка | Результат |
| --- | --- |
| Windows `bun scripts/check-product.mjs` | fmt/Clippy, 10 access + 3 contract + 20 storage tests, release всех targets/features, OpenAPI — passed |
| Android `bun scripts/check-product.mjs --android` | Те же 33 теста нативно на AOSP API33/x86_64; идентичный OpenAPI; release всех targets/features x86_64/arm64 — passed |
| Unsafe | 12 независимых отказов компиляции core/storage на host и двух Android ABI, включая локальный allow — passed |
| Матрица доступа | Чтение/изменение/пустой набор пространств/администрирование; точные ID, отсутствие wildcard и проверка всех целей до эффекта — passed |
| Идентичность/отказы | Пустые/неверные/отсутствующие учётные данные, отсутствующее разрешение, другой/пустой субъект, ошибка источника/часов — без вызова обработчика |
| Актуальность прав | Снижение чтение-с-изменением → чтение, отзыв до следующего вызова, отказ до чтения сохранённого результата — passed |
| Срок | До границы разрешено, на границе и после запрещено; время получено после разрешения учётных данных, новое разрешение после истечения — passed |
| Администрирование | Отдельная область, срок/отзыв; не разрешает данные и не выводится из обычного доступа — passed |
| Защита цели | Нет чтения цели/ошибки not_found до проверки прав; разрешённый обработчик сохраняет свою ошибку и получает аутентифицированного субъекта |

Изначальные девять сценариев прошли до добавления отдельной регрессии истечения
во время разрешения учётных данных. После неё оба полных финальных прогона
выполнены на окончательном составе исходников. Ошибок тестов/компиляции в этих
прогонах не было; fmt выполнен перед проверками. Зависимости, OpenAPI, schema 1,
прототипы и workflow YAML не менялись. Проверки автоматически входят в прежние
product-check jobs; новых GitHub CI этого объёма пока нет.

Собственный read-only AVD остановлен после прогона, удаляемый remote sandbox
очищен драйвером. Инструменты не устанавливались; физические устройства не
менялись. Данные машины, логи и SHA-256 — `docs/reports/p03-03/verification.json`.
Linux локально, физический arm64, APK/WebView и полный бюджет не проверялись.

## Правила проекта

- Обратимость: проверены ограничение и отзыв прежних полномочий, а также новое
  разрешение после истечения; реальные операции управления правами — впереди.
- Человек и агент: одна проверка core без особых привилегий по транспорту;
  реальный общий API и UI ещё не реализованы.
- Документация: ADR, архитектура, разработка, очередь и журнал отражают срез.
  Пользовательского поведения пока нет, инструкция UI не добавляется.
- Паритет: одинаковые 33 теста Windows/нативного Android x86_64, обе Android
  ABI release/unsafe прошли; физический arm64 и APK/UI не входят в срез.
- Источник истины: guard получает текущее разрешение через доверенный порт;
  нового хранилища/схемы/кэша прав нет. Реализация локального состояния впереди.
