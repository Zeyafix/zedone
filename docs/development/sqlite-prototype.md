# SQLite-прототип P01.05

`rusqlite 0.41.1` с `bundled` собирает SQLite из закреплённой Cargo-зависимости
для host и APK; системная SQLite в приложение не подключается.
Обоснование возможностей: [rusqlite](https://docs.rs/rusqlite/0.41.1/rusqlite/).
Это проверка T03, а не продуктовая схема, формат резервной копии или реализация
Automerge. Исходный профиль — [методика P01](prototypes.md#методика-времени-для-p01).

## Изоляция и контракт

Одна `synthetic.sqlite3` содержит A и B, колонки и карточки с составными внешними
ключами. Host по умолчанию использует `prototypes/target/synthetic-storage/`
при запуске `bun run serve` из `prototypes/`. Его второй CLI-аргумент после порта
задаёт другой каталог. APK использует подкаталог `p01-05-synthetic` в своём
локальном каталоге данных, отдельно от любых будущих продуктовых данных.
Автотесты host используют новый временный каталог и удаляют только его.

Rust `StorageRequest` определяет общий POST `/prototype/storage`, команду IPC
`storage`, OpenAPI и типы клиента. Параметры файлов и произвольный SQL через API
не принимаются; пространства ограничены A/B. UI и тестовый агент используют
одни операции:

| action | Поля | Результат |
| --- | --- | --- |
| seed | space | Создать отсутствующий фиксированный набор; существующий не перезаписывать |
| read | space, query | Читать/искать, не изменяя данные |
| snapshot | space | Полное согласованное состояние только выбранного пространства |
| restore | snapshot | Атомарно заменить указанное в снимке пространство; другое сохранить |
| delete | space | Удалить выбранный набор; повтор безопасен |
| move_card | expected, card, column, position | Переместить карточку с проверкой исходного снимка; [P01.06](board-prototype.md) |
| move_column | expected, column, position | Переместить колонку вместе с карточками; [P01.06](board-prototype.md) |

Ответ содержит `snapshot` либо `null` для отсутствующего/удалённого пространства.
Снимок JSON содержит только синтетические колонки и карточки, без истории,
корзины, прав, конфликтов и сведений обмена: этих моделей ещё нет.
Сохранённый в форме снимок живёт до закрытия/перезагрузки формы; агент может
сохранить JSON-ответ отдельно и передать его той же операции `restore`.

Например, из PowerShell после запуска `bun run serve`:

```powershell
$api = 'http://127.0.0.1:4317/prototype/storage'
$request = @{ action = 'seed'; space = 'A' } | ConvertTo-Json
Invoke-RestMethod $api -Method Post -ContentType 'application/json; charset=utf-8' -Body $request
$request = @{ action = 'snapshot'; space = 'A' } | ConvertTo-Json
$saved = Invoke-RestMethod $api -Method Post -ContentType 'application/json; charset=utf-8' -Body $request
$request = @{ action = 'delete'; space = 'A' } | ConvertTo-Json
Invoke-RestMethod $api -Method Post -ContentType 'application/json; charset=utf-8' -Body $request
$request = @{ action = 'restore'; snapshot = $saved.snapshot } | ConvertTo-Json -Depth 10
Invoke-RestMethod $api -Method Post -ContentType 'application/json; charset=utf-8' -Body $request
```

HTTP привязан к loopback. Доступ к API из APK извне не добавлен; P01.10 ещё
предстоит. Тестовые операции не имеют продуктовых прав и не экспортируются
как API работы с реальными пространствами.

## Транзакции, поиск и отказы

Чтение всех таблиц снимка выполняется одной транзакцией. Изменяющие команды
используют `BEGIN IMMEDIATE`; внешние ключи включены. Ошибка любого SQL или
commit возвращает отказ, транзакция откатывается. Только успешный commit
подтверждает сохранение. Запрос восстановления с неверной колонкой проверяет
реальный отказ после начала замены и сохранность прежнего состояния.

Режим журнала прототипа — стандартный DELETE. До четырёх соединений выполняются
в `tokio::spawn_blocking`, разрешение семафора ожидается асинхронно. Рабочий поток
владеет разрешением до завершения, даже при потере клиента. SQLite ждёт занятую
базу не более двух секунд за попытку блокировки; async runtime, UI и echo могут
продолжать работу. Это начальная схема эксперимента, не результат измерения
продуктовой нагрузки и не окончательная политика числа соединений.

Поиск сканирует заголовок и текст отдельно через Rust `to_lowercase` и буквальный
`contains`, обрезая только края запроса. Проверяются кириллица, различие е/ё,
точные внутренние пробелы/табуляция/LF, emoji, исходное комбинируемое написание
`café`, спецсимволы без SQL/поисковых операторов и порядок доски.
Unicode case folding, нормализация, индексы, конфликты и права продуктового
поиска ещё не приняты; DEC-005/A19 остаются открытыми.

Клиент хранилища не запускает автоматических повторов или тайм-аута изменяющей
операции. Ошибка транспорта может следовать после commit: сообщение требует
явного чтения результата перед новым изменением. Это проверяется на HTTP
с выполненным удалением и потерянным ответом. Транспортное ожидание без ответа
не считается откатом; для зависшего IPC остаётся перезапуск и явное чтение.

## Проверки и очистка

После `cargo fetch --locked` и установки JS-зависимостей — `bun run check`.
Он проверяет Rust, контракт, Vue-типы, сборку, HTTP и UI. Есть реальные перезапуск
HTTP-процесса, блокировка SQLite из отдельного соединения, отзывчивый echo,
отказ записи, восстановление и потеря ответа после commit.
Rust-тест дополнительно держит read-транзакцию через параллельный commit в WAL,
проверяя, что колонки и карточки снимка относятся к одной версии. Это режим
конкурентного теста, а не молчаливое переключение журнала приложения.

На Android выполните обе сборки и `bun run check:android` по
[Android-инструкции](android-prototype.md). Общие сценарии вызывают настоящий IPC
и HTTP и сравнивают данные. SQLite AOSP через `adb run-as` только удерживает
тестовую транзакцию `BEGIN EXCLUSIVE`/`ROLLBACK`, не меняя прикладные данные.
Проверяются UI/IPC при этой блокировке, реальный отказ, чтение, force-stop и
повторное открытие APK. Работа формы проверяется при заблокированной сети.

Удаление/восстановление наборов выполняется через API и UI. Удаление APK удаляет
его отдельную БД. Для host можно удалить только свой каталог синтетического
прототипа после остановки процесса, предварительно проверив абсолютный путь.
Системные настройки, чужие SQLite-файлы и общие профили браузеров не изменяются.
Результаты и ограничения — [EV-018](../agent/verification/EV-018-sqlite-storage.md).
