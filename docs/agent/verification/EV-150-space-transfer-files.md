## Реализация

Свёрнутый блок SpaceTransfer в списке и внутри пространства использует
space.export/space.import через прежние workspace-api/CommandClient/очередь
shell. Подготовленный экспорт остаётся в памяти до сохранения/убирания;
отмена записи не создаёт новый снимок. Потерянный результат обеих команд
проверяется в общем списке с исходным ID, включая reload/restart.
Импорт требует отдельного подтверждения после выбора файла и перечитывает
список после успеха. Новых прикладных команд, схем или зависимостей нет.

Windows проверяет размер File до чтения и передаёт бинарный Blob браузеру,
честно сообщая о передаче скачивания, а не гарантированной записи. Android
files.rs передаёт бюджет ядра в Kotlin SAF: только выбранный content URI,
ограниченное чтение limit+1 и запись вне главного потока. URI остаётся в Kotlin;
произвольных путей в API и широких storage permissions нет. При ошибке записи
мост пытается удалить только созданный документ; подготовленные байты остаются
для повтора. Атомарность произвольного провайдера при power-loss не обещана.
Договор расширен в [ADR-0076](../../architecture/decisions/0076-authorized-space-transfer.md).

## Исправленные первичные отказы

Device выявил потерю file-picker результата: visibilitychange запускает
проверку доступа, а v-if удалял компонент и его busy listener. Исправлено
сохранением компонента через v-show при прежней блокировке операций без
ready; финальная браузерная регрессия перепроверяет доступ с подготовленным
архивом, настоящий Device подтверждает отмену и успешный возврат.

Первичные fixture-ожидания `title` вместо `titles`, переиспользование CSS-класса
очереди и гонка Windows build с работающим fixture исправлены до финального
штатного успешного прогона. Подготовка native fixture исправлена на согласованную
SQLite backup-копию с учётом WAL; перенесён только собственный test seed.
Ошибки кратких/старых Device refs исправлены по подсказкам инструмента.
Системный RecyclerView принимал физический pan на 1 px через тот же agent-device;
обычная AX-активация элементов не открывала их. Обход через adb/CDP не использовался.
Первичные отказы сохранены в reports и не выданы за успешные проверки.

## Пять правил и передача

- Обратимость: отмена/убирание выбора/повтор сохранения и корзина/возврат
  копии проверены; исходник, другой импорт и файл не меняются от правок копии.
  Собственные экспортированные файлы удалены при очистке средствами ОС.
- Человек/агент: прежние две авторизованные команды/безопасные повторы
  через общий API; файловые адаптеры не подменяют ядро.
- Документация: user/agent/development/ADR/очередь/журнал обновлены.
- Паритет: Windows Chrome/Opera и настоящий Android APK через Device
  подтверждают файловый сценарий; обе ABI собраны, физический arm64 отдельно.
- Единый источник: SQLite/Automerge и Rust-контракт прежние; UI не хранит
  второй граф и сверяет свой ранний fileLimit с производной схемой.
