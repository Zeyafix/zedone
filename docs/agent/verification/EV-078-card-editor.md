## План оформления и сохранности

Прежние токены canvas/ink/accent/surface/border, системная типографика и
Reka Dialog сохраняются. В просмотре — явные «Редактировать» и выполнение.
Редактор содержит заголовок/описание и читаемое состояние сохранения;
предупреждение ухода показывает несохранённый ввод без ложного успеха.
История версий остаётся общим API и будущим P05.09, Markdown — P05.04.

Автосохранение: debounce 500 мс, не более 2 секунд непрерывного ввода до
очередной отправки; IME composition не отправляется наполовину. Локальный
черновик записывается синхронно до доставки; это пользовательский ввод и
исходное предусловие, без ключа/прав/доски. Одна команда доставки остаётся
неизменной, последующий ввод хранится отдельно. Новый begin_editing после
возобновления не использует прежнюю сессию; finish на явном выходе и уходе
в фон завершает серию. Неожиданное закрытие не обещает сетевую фиксацию:
сохраняются черновик/уже подготовленная команда и требуется их восстановление.

После stale свежие данные показываются отдельно от ввода; перенос своего
текста на прочитанную версию требует нового явного действия. Подтверждённый
старый ответ не заменяет актуальный текст. Черновики имеют отдельные ID;
Web Locks предотвращают одновременную запись одного черновика вкладками,
не заменяя версии/права ядра. Источник API:
[Web Locks](https://w3c.github.io/web-locks/). Доступность проверяется на
реальном WebView; при отсутствии нельзя молча разрешать потерю черновика.
