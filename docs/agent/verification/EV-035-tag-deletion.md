Один наблюдаемый результат: при удалении тега против назначения на другой
реплике человек и агент могут общим CLI/Rust-путём просмотреть конфликт и
явно сохранить тег с назначениями либо подтвердить удаление. Конкурирующие
решения остаются вариантами; карточки, текст, колонка и другие теги сохраняются.
Обычное редактирование затронутых карточек заблокировано до решения.

Охват оценён до кода: техническое состояние существования и назначений
выводится из причинных регистров существующего пробника; удалённые исходные
ID сохраняются технически, повторное создание получает новый ID.
Операция и её матрица сохранности неделимы: при превышении ориентира 300 строк
причина — проверка двух решений, aliases, конкуренции и атомарности на обеих
платформах. Новых зависимостей и продуктового формата хранения нет.

Полное восстановление пространства из снимка — P02.06/P07; продуктовые
UI/HTTP/IPC/права, APK/WebView, физический arm64, полная Unicode-политика,
масштаб/память остаются за пределами этого шага.

| Android `bun run check:automerge --android` | CLI x86_64/arm64 собраны; API 33/x86_64: 26 фаз отдельных нативных процессов и 74/74 теста пробника passed |
| Оба решения | Сохранение тега оставляет старые и независимые назначения; подтверждённое удаление снимает все назначения исходных aliases; карточки/текст/колонки/другие теги и одноимённый тег другого пространства сохранены |
| Блокировки | При спорном удалении все четыре поля и назначения других тегов затронутых карточек заблокированы; просмотр и оба явных решения доступны; другое пространство доступно; собственный конфликт текста не снимается решением тега |
| Обратные состояния/отказы | После сохранения доступны снятие/назначение и обратные правки четырёх полей; удалённый тег не восстанавливается, новое создание имеет новый ID без старых назначений; чужой/устаревший выбор, сохранение без конфликта, повторное удаление и обычные правки удалённого ID отвергаются без записи |
| Конкуренция/доставка | Равные решения не конфликтуют, разные/поздние остаются вариантами; допустимая правка после локального решения сохраняется; повторные/переставленные/старые изменения сохраняют снимок, heads и число изменений после SQLite reload |
| Атомарность | SQLite AFTER UPDATE ABORT при обычном удалении и каждом решении оставляет документ/actor/peer и обе реплики неизменными после повторного открытия |
| Наблюдение | Изменение назначений делает старое удаление недопустимым; изменение другого тега не обесценивает выбор; собственный конфликт карточки запрещает обычное удаление назначенного тега |
| Совместимость с поздним созданием | После удаления/повторного создания и прихода независимого создания выбор имён существующих тегов снимает блокировку без восстановления/переименования удалённого ID |

Проверка последней комбинации сначала воспроизвела постоянную блокировку:
старый расчёт ожидал новое имя технически сохранённого удалённого ID.
Расчёт группы скорректирован до финальных прогонов: удалённые ID сохраняются
в документе, но не входят в выбор имён существующих тегов. После исправления
полный Windows и Android прошли на финальном runtime. Новых открытых багов нет.

Ориентир 300 строк превышен одной общей матрицей сохранности удаления:
два решения, исходные aliases, конкуренция, атомарность и две платформы.
Состояние `life` добавлено в синтетическую фикстуру; формат таблицы SQLite
и продуктовая схема не менялись. Чтение карточек/тегов — проекция того же
документа; JSON-отпечатки не используются для восстановления.
