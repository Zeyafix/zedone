# ADR-0035: версионированные схемы и допуск базы до записи

Дата: 2026-11-05. Технический срез P07.08.1, DEC-006 open.
Требования: спецификация §1/1.1, T10/A46/M08. Проверки —
[EV-052](../../agent/verification/EV-052-schema-admission.md).

## Решение

`storage/schema` хранит реестр известных версий и неизменяемые SQL-описания
layout. Текущая версия определяется последним элементом. `schema/v1.sql`
сохраняет исходный SQL схемы 1: версия, четыре таблицы и ограничения прежние.
При изменении добавляются новая запись, SQL и защищённый переход; исторические
описания остаются. Архивный validator использует известную версию,
обычные команды — только текущую. Факты и данные остаются в одной SQLite.
SQL-файлам закреплён LF в .gitattributes: include_str читает их буквально,
а checkout CRLF иначе изменил бы sqlite_schema. SQLite-эталоны помечены binary.

До writable-открытия worker проверяет существующий файл через
SQLITE_OPEN_READ_ONLY в одной read-транзакции: application_id, user_version,
точный sqlite_schema, все строки quick_check и foreign_key_check.
Неизвестная версия даёт UnsupportedSchema; чужая identity/layout или нарушение
FK — InvalidDatabase. SQL/файловая ошибка — Unavailable без текста исключения.
Writer lock и смена journal_mode для этой проверки не нужны.

Отсутствующий файл и действительно пустая SQLite (identity 0/0 без объектов)
допускают создание начальной схемы. Preflight сам не создаёт файл и не является
разрешением обойти повторную проверку. Перед принятием/инициализацией базы
проверки повторяются под BEGIN IMMEDIATE. WAL и synchronous FULL настраиваются
только после успеха. Нечитаемая или повреждённая база не считается пустой.

## Сохранность и границы

SQLite может потребовать восстановительную запись для чтения hot rollback
journal. Read-only проверка отказывает и сохраняет исходные файлы: открывать
их на запись лишь ради распознавания версии нельзя. Это безопасный отказ,
не полный служебный режим P07.09. Проверяется сохранность DB/WAL/journal;
SHM и транзитные reader locks не входят в побайтовую гарантию.
URI/immutable не добавляются: читается актуальная SQLite вместе с WAL,
а не только заголовок основного файла.

Бинарный эталон v1 построен из SQL интегрированной ревизии 1fd2de7 и содержит
синтетическое Unicode-пространство, фиксированный actor и прежний результат
команды. SHA-256 закреплён тестом; запись идёт только в копию. Это проверка
совместимости, не второй источник runtime SQL и не официально выпущенная база.

Реальные переходы/схема 2 не вводятся. P07.08.2 должен связать исторический
capture/validator, все переходы одной транзакции и свидетельство P07.07,
закрывая обычные входы до сверки; P07.08.3 — управлять повторами.
Нет публичных UI/API, новых полномочий или автоматического восстановления.
ADR-0030/0034 сохраняются; power-loss/Windows directory durability не приняты.
Новых зависимостей и unsafe нет.

Основания: [SQLite read-only open](https://www.sqlite.org/c3ref/open.html),
[quick_check](https://www.sqlite.org/pragma.html#pragma_quick_check),
[foreign_key_check](https://www.sqlite.org/pragma.html#pragma_foreign_key_check).
