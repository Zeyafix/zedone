# ADR-0066 — Явное разрешение названий контейнеров

Статус: P06.05.1 done — PR #103/head b5c228d, merge 6781490 после всех 17 SUCCESS
в attempt 1 и свежей CLEAN readiness; EV-111/LOG-602. Схема и протокол прежние;
поля карточек P06.05.2 и полный P06.05/T09 отдельно.

## Основание

Спецификация §1.2 п.3–4 требует сохранять названия одного контейнера и разные
независимые решения. Обычный rename уже отказывает при конфликте. Существующие
скалярные регистры Automerge `name` предоставляют все варианты; новая схема
хранения для разрешения не нужна.

## Решение

Отдельные `space.resolve_name`/`column.resolve_name` проходят общий Service,
права пространства, replay и строгую версию объекта внутри одной SQLite
транзакции. В состоянии активного контейнера при нескольких разных `names`
записывается одно выбранное либо новое имя в прежний регистр. Пустая строка
допустима по прежним правилам. ID, порядок и содержимое не заменяются.

Проверяется существующий `version`, включая содержимое контейнера: его изменение
после просмотра требует нового явного решения. Повтор возвращает сохранённый
результат после повторной проверки доступа; не повторяет запись поверх поздней
правки. Сбой до commit откатывает граф и receipt вместе. Разные независимые
решения дают несколько актуальных значений после обмена. Одинаковые значения
дедуплицируются в прежней проекции, технические операции сохраняются.

Обычные rename/trash/move конфликтующего контейнера по-прежнему запрещены;
работа с содержимым при конфликте только названия продолжается. UI перестаёт
смешивать эту блокировку с запретом работы с карточками/тегами. Конфликт места
колонки не разрешается именованием; обычные блокировки места сохраняются.

## Проверки и границы

EV-111 содержит реальные результаты Windows/Android, UI/HTTP/CLI, независимых
решений, отказов и сохранности. Текст карточки, удаление и прочие конфликты
остаются отдельными шагами. Формат `zedone.space.v1`, protocol 1, SQLite schema 1
и ACL не меняются. Дополнительного хранилища вариантов/состояния UI нет.
