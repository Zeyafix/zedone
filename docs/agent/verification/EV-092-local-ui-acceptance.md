## Новая приёмочная проверка

Охват превышает ориентир 300 строк из-за одного приёмочного результата:
общий сценарий двух платформ сопровождается полной таблицей доказательств
и границ для 14 критериев. Независимые исправления продукта, рефакторинг
и изменения инфраструктуры в этот срез не включены.

`scripts/check-ui-accessibility.mjs` подключён к штатным host и native CI
runners после очистки истории, без новых зависимостей/таймаутов/CI-бюджетов.
Проверяет оба оформления на настройках, доске, карточке, выборе версии,
диалоге перемещения, очистке и доске с увеличенным корневым шрифтом.
Клавиатурный путь обходит реальный tab order; radio выбирается стрелками,
а checkbox — пробелом. Проверяются видимый outline, возврат фокуса из истории
и карточки, отсутствие изменения CardSnapshot/истории при отмене и просмотре.
Перед закрытием перемещения проверка ждёт установки фокуса в Reka Dialog.

Rendered-проверка рассматривает доступные названия обычных элементов и диалога,
непрозрачный текст/фон и горизонтальный размер страницы. Порог контраста 4.5:1,
для крупного текста 3:1; неподдержанное смешивание полупрозрачности даёт отказ.
Прокрутка доски/кода внутри своих областей разрешена. Полного аудита WCAG,
экранного диктора, всех сочетаний zoom/шрифтов и физического телефона нет.

Негативные контроли на отдельной синтетической установке отвергли текст с
одинаковыми цветами текста/фона и outline:none для клавиатурного фокуса.
После снятия первой подмены положительная проверка представления прошла.
Контроли/логи остаются в игнорируемой docs/reports/p05-10.

Первые ошибки собственного сценария (Tab вместо стрелок в radio-группе,
ранний Escape до фокуса move-диалога, ожидание только h1 вместо заголовка
выбранного списка) исправлены без изменения продукта или ослабления проверок.
Финальная целевая матрица Chrome/Opera desktop/touch прошла отдельно.

## Android Device и сохранность

Запуск/касания/ввод/прокрутка/Back/изменение системного размера шрифта и
перезапуск выполнены только текущей командой agent-device из Device.
Снимки просмотрены через device_screenshot. Локальный read-only клиент проверял
представление/фокус; прикладные команды/снимки данных получал через настоящий
`zedone_command`/Service. Прямой записи в SQLite и локального запуска CI UI-драйвера нет.

Подтверждены обычные светлая/тёмная темы, paired history/буквальный HTML,
фокус заголовка выбранной версии, отмена Back, состав очистки и его отмена,
явный перенос выполненной карточки с тегом в другую колонку и возврат в исходную.
Возврат в колонку проверен отдельно от исходного места внутри колонки.
Тема сохраняется после relaunch; маршрут при relaunch возвращается к общему
списку, сохранение маршрута здесь не заявляется. Через API явно добавлены
длинные имена пространства/колонки и парный текст карточки; переносы и доступ
к содержимому просмотрены на Device. При font_scale 1.75 остаются доступны
меню/настройки и прокрутка, страница не получает горизонтального overflow.
Это системное увеличение Android, не утверждение о 200% Android.

Исходный системный размер шрифта восстановлен через agent-device и перечитан.
Все 23 исходных product/app_webview файла восстановлены с точным совпадением
имён/SHA-256. Синтетические базы/ключи/архивы удалены, API forward снят,
Device выключен. Последующий запуск восстановленного приложения не выполнялся,
чтобы не менять восстановленные WebView-файлы.

## Результаты команд и передача

- `bun run ui:check`: exit 0, оба целевых Windows-браузера. Типы/build,
  fmt/Clippy -D warnings/три shell tests, весь прежний desktop/touch набор,
  Markdown и host-воспроизведение touch-сценария прошли. Явный локальный
  Node override отличается от базы CI; версии/команды/сырые логи находятся
  в игнорируемой docs/reports/p05-10. Прежнее предупреждение Vite о chunk >500 kB
  остаётся. Полный запуск начат до подключения нового сценария к runner;
  он не объявляется полным интегрированным запуском нового runner.
- Финальные `checkHistoryCleanup` → `checkAccessibility` выполнены именно
  в порядке штатного runner для Chrome/Opera, desktop и touch без
  checkVisibility. Все четыре связки passed; после них localStorage пустой,
  системное оформление восстановлено. Каждый новый сценарий проверил 14 экранов.
  Это отдельный целевой прогон окончательных исходников, без повторения всего
  долгого набора. Синтетические установки после завершения удалены.
- `bun scripts/check-product.mjs`: exit 0, 283 Rust-теста (33+17+7+226),
  23 client tests/239 assertions, fmt/Clippy/release/unsafe guards,
  Rust→OpenAPI→TypeScript→validator и contract types passed.
- `bun scripts/check-product.mjs --android`: exit 0, те же 283 native Rust
  tests, 23 client/239 assertions, контракт и обе release ABI общего продукта,
  native sandbox cleanup/unsafe guards passed. Вместе с host — 21 guard.
  Этот CLI-набор не управляет UI и не заменяет Device.
- `bun scripts/build-ui-android.mjs x86_64` и `aarch64`: exit 0, обе debug APK
  и manifest identity/launcher/cleartext passed. Release APK/физический arm64
  не проверялись.
- `node --check` трёх затронутых scripts и `git diff --check` passed.
  Негативные контроли проверили отказ при невидимом фокусе/контрасте 1:1.
  Новый Android CI UI-драйвер локально не запускался; его исполнение с новым
  сценарием остаётся условием интеграции.
- Финальный audit подтвердил прежние определения/состояния всех 98 критериев,
  все 499 исходных LOG-записей и пять исходных dirty EV побайтово. Продуктовые
  UI/Rust/контракт/схема/зависимости не менялись. Собственное сравнение native
  данных учитывает, что перемещение меняет version/placement и scope token
  history.inspect, но не пары версий или их байты. Content/history при переносе
  и возврате сохранены; просмотр/отмена/оформление после явной длинной правки
  не изменили ни одного CardSnapshot или scope истории.

Пять правил соблюдены в проверенном срезе: обратные действия/отмена с прежними
исключениями очистки; общий Service/API человека и агента; user/agent/development
docs; обе платформы с явно указанными границами Device/CI; один авторитетный
Service/SQLite/Automerge, представление не хранит независимую предметную модель.

P05.10 verified локально в test/p05-10-ui-acceptance от ee81ce7. Новых BUG/GAP
не обнаружено; GAP-007/012/013 и DEC прежние. T08/P05 и полные связанные A
не повышаются до нового CI/интеграции и оставшегося обменного охвата.
Далее ревью/интеграция этой ветки; новый продуктовый шаг не начат.
