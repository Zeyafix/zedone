# ADR-0081 — Каталог файлов копий и безопасная смена папки

Статус: принято для реализации P07.05. Продуктовые требования A29/A42/A57
не меняются; приёмка реализации фиксируется отдельно в EV-161.

Каталог восстанавливается из самих файлов, без прежней SQLite-базы, настроек,
индекса и подключения. Ежедневные каталоги распознаются по namespace, полному
`space.bin` и согласованному `commit.json` ADR-0080. Страховочный снимок
восстановления использует прежний `zedone-restore-candidate-*/space.bin`:
полный проверенный кандидат пригоден как снимок даже при утрате прежнего
свидетельства операции. Частичные/повреждённые кандидаты не показываются
как исправные. У полного предмиграционного комплекта проверяются manifest
и хеши всех файлов; каталог показывает его отдельные снимки пространств.
Сам каталог не открывает `database.sqlite` для записи или восстановления.

Общий `backup_io` различает локальную файловую систему и явно выбранное
Android SAF tree. Локальные автоматические снимки и восстановление используют
тот же порт. SAF разрешает только локальные Documents providers и хранит
persistable URI permission; сетевые/cloud providers не являются локальной
папкой. Потеря доступа возвращает отказ, без переключения или другой папки.
Архив сохраняет прежний формат и бюджет 1 MiB/10000 changes; перенос больших
файлов комплекта использует проверяемые блоки 64 KiB. SQLite writer lock
сериализует перенос, создание, ротацию и отдельное удаление копий.

## Явное разрешение папки

Права пространства и Administration не превращаются в неявный доступ ко всем
копиям. Отдельное локальное действие выбора папки выдаёт вызывающему субъекту
непредсказуемый handle с режимом чтения либо управления. При выборе управления
действующая папка также явно включается в охват переноса. Windows использует
системный диалог, Android — SAF. Локальный CLI может явно выбрать доступный
ему путь с тем же режимом. Сетевой command API принимает только handle,
никогда произвольный путь. Browser/IPC chooser доступен лишь локальной сессии;
действующий ключ проверяется до выбора и перед сохранением разрешения.

Handle привязан к субъекту и проверяется вместе со свежим сроком/отзывом
основного доступа. Отдельная команда forget отзывает handle, не удаляя файлы
и не меняя действующую папку. Разрешения переиспользуются для совпавших
папки/субъекта/режима; бюджет — 64 на субъект, превышение отказывает без
изменения файлов. Чтение папки включает её снимки очищенных пространств и
прежних установок; это явное полномочие выбранной папки, не поиск по всем
файлам устройства. Чтение снимка не выдаёт прав восстановления пространства.
Аварийная замена всей базы и её полномочия остаются P07.09.

## Перенос и удаление

Настройка расположения, поколение, точный перечень ожидающих исходников и
очередь отдельного удаления хранятся в SQLite, в существующем внутреннем
namespace `command_results`. Новая схема не нужна. Новый запрос переноса
проверяет исходное поколение и разрешения текущей и целевой папок. Совпавшая
папка — отсутствие изменений; вложенные локальные папки запрещены.

1. Прочитать и проверить управляемые файлы, включая снимки очищенных
   пространств и целые предмиграционные комплекты. Посторонние файлы не трогать.
2. Копировать, синхронизировать и перечитать каждый файл в новой папке.
   Совпавший полный файл можно переиспользовать; чужая коллизия отклоняется.
   Собственный transfer marker разрешает продолжить только побайтово
   совпадающий префикс незавершённой записи. Маркер не является копией каталога.
3. Одной транзакцией зафиксировать новое расположение, поколение, receipt
   и перечень исходников. До commit исходная настройка и файлы сохраняются.
4. После commit снова проверить новые файлы и удалить только перечисленные
   исходники с прежними хешами. При отказе оставить новое расположение и
   постоянное `cleanup_pending`; повтор/перезапуск продолжает удаление.

Пока перенос ожидает очистки, новые файловые мутации не меняют его перечень.
Рабочие пространства остаются доступны. Явный cleanup и фоновое обслуживание
продолжают завершение. Ошибка после переключения не откатывает расположение.
Окончательная публикация и очистка не выводятся из успеха одного copy syscall.

Отдельное удаление снимка сначала фиксирует намерение и убирает ссылку из
ежедневного/страховочного состояния, затем удаляет только проверенные файлы.
Дневная квота, рабочий граф, доступы и обмен сохраняются. Весь предмиграционный
комплект нельзя частично разрушить удалением одного его snapshot: каталог
разрешает чтение, а удаление полного комплекта требует отдельного сценария.

Чтение каталога не запускает очистку, создание, перенос, ротацию, импорт,
восстановление или обмен. Ошибки отдельных распознанных копий отражаются
счётчиком; превышение бюджетов отказывает без усечённого успешного результата.
Ограничение обхода — 10000 записей папки, результата каталога — 1 MiB JSON.
Файлы и индекс каталога не становятся вторым авторитетным рабочим графом.

Гарантии process-crash не означают физическую power-loss durability.
Windows сохраняет прежнее ограничение directory sync ADR-0077/0080; SAF
проверяет завершённые записи и `fd.sync`, но ОС/накопитель сохраняют свои
ограничения долговечности и отзыва URI permission.

Служебные записи читаются строго: неверный request tag, отсутствующее обязательное
поле current/pending и неверный абсолютный/SAF root дают отказ, а не отсутствие
настройки. Перечни cleanup проверяют допустимые ID, имена, уникальность и корни
до файловых действий. Повреждение настройки не возвращает каталог по умолчанию.
Индекс миграции распознаётся только после проверки структуры и digest manifest;
он переносится после комплекта, а удаление исходного индекса сверяет сохранённые
байты независимо от уже удалённых исходных файлов комплекта.

После возврата из системного chooser UI ожидает повторную проверку доступа и
заново сверяет субъект; transient checking не теряет выбранную папку. Отмена
перечитывает прежнее состояние и сохраняет его в форме. Длинные пути переносятся
по ширине экрана; местонахождение копий хранится только в общем ядре.
