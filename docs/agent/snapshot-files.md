# Снимки пространств: границы текущего среза

P07.02.3 добавляет общие команды `space.export` и `space.import` через
HTTP/CLI/IPC. Авторитетный контракт — `api/openapi.json`, типы и runtime
validator генерируются из него. Агент не пишет SQLite и не вызывает доверенные
storage callbacks вместо команд. Восстановление исходного пространства —
отдельный будущий сценарий P07.03; файловый UI — P07.02.4.

| Команда | Параметры | Результат и права |
| --- | --- | --- |
| `space.export` | `space` | `{archive}`: lowercase hex полного ZEDSPACE v1; Read исходника |
| `space.import` | `archive` | `{space}`: ID независимой копии; действующий доступ, ReadWrite копии только вызывающему |

Каждая команда использует обычный конверт с ненулевым случайным `id`,
точным `operation` и `parameters`; ключ передаётся отдельно. Для экспорта
достаточно чтения, в том числе пространства в корзине или с конфликтами.
Для импорта не нужны права на исходник, чьих локальных ID может не существовать.
Администрирование само по себе не даёт чтения чужого пространства.
Срок и отзыв вызывающего доступа действуют и для новой копии.

При потере ответа повторять весь прежний запрос и ID. Повтор экспорта
возвращает первоначальный архив, повтор импорта — первоначальный ID без
дубликата, в том числе после перезапуска. Новая намеренная копия требует нового
ID; автоматическая замена ID после outcome_unknown запрещена. Свежие права
проверяются до receipt; для повторного результата импорта нужен Read копии.
После успеха использовать `space.read` с новым намерением для актуальных данных.

Бюджет одной операции: бинарный архив до 1 MiB и 10000 changes; поле `archive`
содержит до 2097152 hex-символов. Импорт допускает до 3 MiB JSON через все
адаптеры; прочие обычные команды остаются в 64 KiB. Превышение экспорта —
unavailable без частичного архива, неверный/слишком большой/неполный импорт —
invalid_request без новой копии. Файл и исходник не изменяются. Не усекать
архив и не повторять отказ с новым ID автоматически. Архив содержит полную
историю и пользовательский текст; не включать его в логи или публикации.
Файловые мосты .4 должны ограничить чтение до этого бюджета до загрузки файла.

Обратные действия над копией — прежние правки, `space.trash`/`space.restore`
с актуальной version. Они не затрагивают исходник и другие импорты.
Договор — [ADR-0076](../architecture/decisions/0076-authorized-space-transfer.md),
проверки — [EV-149](verification/EV-149-authorized-space-transfer.md).

P07.02.1 добавляет внутренний `Storage::export_snapshot`: полный продуктовый
журнал и последняя сохранённая пара незавершённого редактирования читаются
согласованно. Дополнительная версия истории создаётся только в копии графа;
исходная сессия продолжается без изменений. Исходный `Storage::snapshot`
остаётся захватом raw журнала без дополнения pending-истории. Проверки и
границы — [EV-147](verification/EV-147-product-export-snapshot.md).
Это доверенный storage API без внешней авторизации. Публичная команда .3 использует тот же захват внутри транзакции прав/replay;
отдельная проверка ключа перед storage-вызовом не заменяет её. Файловые операции остаются .4.

P07.02.2 добавляет доверенный `WriteContext::import_snapshot`: проверенный
полный архив преобразуется в независимый граф с новыми ID и публикуется
атомарно с остальными действиями вызывающей транзакции. Права, ключи, receipts,
сессии и подключения не переносятся; исторический subject — сведения об авторе,
не разрешение. Не использовать этот метод как обход общего API.
Архив с недостающими зависимостями отклоняется целиком без изменения файла;
требуется полный журнал исходного устройства и новый экспорт. Договор —
[ADR-0075](../architecture/decisions/0075-independent-space-import.md),
проверки — [EV-148](verification/EV-148-independent-space-import.md).
Публичная команда .3 атомарно добавляет получателя и receipt; файловый UI остаётся .4.

Технический договор —
[ADR-0032](../architecture/decisions/0032-space-snapshot-format.md), проверки —
[EV-049](verification/EV-049-space-snapshot-format.md).

- Не изменять исходный файл при проверке, ошибке версии или преобразовании.
  Для преобразования использовать отдельную рабочую копию; эталоны прежних
  версий сохранять, не заменять новым форматом.
- Успешный checksum означает целостность байтов, не доверие к архиву и не права.
  Метаданные даты/пространства не заменяют авторизацию и доверенное время.
- Не переносить права, учётные данные, peer progress, локальный actor для записи
  и receipts из архива пространства. Исторические actor IDs внутри изменений
  нужны графу и не являются разрешениями.
- Перед импортом/будущим восстановлением проверить продуктовую модель, права,
  budgets и условия соответствующего шага. Чтение графа не реализует новые ID,
  страховочный снимок, паузу обмена и причинное восстановление.
- Сохранять защиту ADR-0030 от повторного исполнения старых намерений при
  восстановлении/откате базы; отсутствие receipts в файле не доказывает, что
  команда не была выполнена. Полная предмиграционная копия — отдельный формат.

Команды проверки разработчика —
[product-core](../development/product-core.md#формат-снимка-пространства).
Пользовательский файловый сценарий остаётся P07.02.4.
