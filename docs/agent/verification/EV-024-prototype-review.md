Изменения прикладных операций, зависимостей и модели данных вне этого шага.

повторное открытие. Неполные серии не закрывают A62 или весь этап P01.

Ориентир размера PR превышен одной связанной проверкой: общий измеритель,
два адаптера запуска/очистки и воспроизводимая методика нужны для одного
результата Windows/Android. Зависимости и прикладной контракт не меняются.

## Продолжение GAP-006

Продолжение GAP-006 от `410519d`: проверить Chrome/Windows без фиксированного
смещения интерфейса браузера, затем добавить отдельный Android-профиль
независимого захвата изображения ОС на явно выбранном AOSP-эмуляторе.
Физический телефон, приложение, зависимости и контракт вне этого продолжения.
Проверки: полные серии доступных действий, отрицательные контроли наблюдателя,
сохранённые снимки/восстановление и общий `bun run check`. Для Android отдельно
учитываются накладные расходы ADB и неопределённость при превышении верхней
границей ориентира; физическая матрица и старые rAF-отчёты не переоцениваются.
Размер изменения определяется одним результатом платформенной проверки;
адаптер Android и его контроли сохраняют одну границу проверки/документации.

## Воспроизводимая проверка доступного среза

Команды и границы — [воспроизводимая инструкция](../../development/prototype-measurements.md).
Сырые отчёты, их хеши и проверка совпадения исходников находятся в игнорируемом
`docs/reports/p01-11/verification.json`; общий исходный код сценария доступен
в `prototypes/scripts/measure-*.mjs`.

| Проверка | Что проверять |
| --- | --- |
| `bun run check` | fmt/Clippy/тесты/release, Rust→OpenAPI→TS, vue-tsc под Node, Vite и прежние HTTP/браузерные сценарии |
| `bun run measure:desktop chrome` | Сохранение, отображение и обратное действие в headless Chrome |
| `bun run measure:desktop opera` | Тот же сценарий в Opera; превышения сохраняются, пригодность кадрового наблюдателя проверяется отдельно |
| `bun run measure:desktop opera-headed --headed` | Тот же сценарий в обычном окне Opera, без отключения кадровых лимитов; режим и результаты хранятся в отдельном локальном отчёте |
| `bun run measure:desktop:pixels opera` | Отдельный Windows-профиль: консервативные верхние границы до ожидаемых пикселей рабочего стола, реальные отрицательные контроли, эталоны каждого состояния, снимки и хеши production-артефактов |
| `bun run measure:android` | AOSP API 33 без GMS, реальный IPC/WebView, восстановление исходного A; debug/эмулятор |
| `bun run measure:android:pixels` | Отдельный debug/AOSP профиль: ADB screencap, полный маркер/заголовки, реальная задержка callback и скрытый commit, перенос внутри видимой колонки и отмена, поиск/сброс, force-stop/Home и восстановление A |
| Контроль статистики | Ближайший ранг p95, медиана, отказы, пустая серия и отдельный запуск браузера без своего бюджета |
| Контроль отказа наблюдателя | Обычное завершение кадра должно дать отсчёт, остановленный кадр — сохранённый тайм-аут |

Для каждого доступного интерактивного направления — пять прогревов и
тридцать измеряемых повторов; запуск — две серии по десять, браузер ПК отдельно.
Исходный синтетический профиль задан в EV-018: 30 карточек, 820 строк
описаний, 38 510 байт UTF-8 текста и 41 273 байта JSON; SHA-256
`6153192a7ac81161fb30c15586fb7b5a76717418b810c61fab799ef857b98554`.
История не имитируется: модели истории в этом срезе нет.

Драйвер ждёт готовую страницу WebView до подключения CDP и использует
DOM-команды без современных locator visibility helpers, требующих более нового
Chromium. Полифилл в приложение не добавляется. Прерванные и неуспешные попытки
сохраняются отдельно и не входят в успешные серии.

Успех выполнения сценария не означает попадание во временной ориентир.
Превышения в UI нельзя скрывать или компенсировать вычитанием кадров/накладных расходов.
Граница кадра через два requestAnimationFrame ещё не подтверждена независимым
наблюдением физического показа; GAP-006. A62 — partial, P01.11/P01 не завершены.
Для GAP-006 сравнить частоту кадров до/после чтения доски, после перемещения
и перезагрузки, со статической страницей; фиксировать visibility/focus и отдельно
интервал подтверждённого DOM-изменения. Такой контроль не даёт основания вычитать
кадры или объявлять ориентир достигнутым. Результаты конкретных запусков,
диагностика и ограничения машины остаются только в `docs/reports/p01-11/`;
в общий EV и журнал они не переносятся по правилам repository-privacy.md.
Продолжение диагностики — [протокол разграничения DOM/кадра/показа](../../development/prototype-measurements.md#диагностика-кадрового-наблюдателя-gap-006):
одинаковая сборка в headless и обычном окне, минимальный HTML, трасса Viz и
отдельные интервалы DOM. Локальные выводы, отрицательные контроли, трассы и
условия воспроизведения — `docs/reports/p01-11/GAP-006-root-cause.md`;
короткие диагностические повторы не заменяют полные серии или приёмку экрана.
Выбор другого режима и отключение кадровых лимитов нельзя задним числом
применять к старым отсчётам. GAP-006 остаётся open до подтверждения наблюдателя.
Runner поддерживает явный `--headed`; `environment.browser_mode` различает
режимы без изменения общего измерителя и условий серий. Полные результаты
конкретного headed-прогона, кадровая диагностика, исключённые попытки и передача
сохраняются только в `docs/reports/p01-11/opera-headed-review.md`.
Обычные rAF-runner записывают общий `ui_measurement_evidence`: уровень `diagnostic`,
`presentation_validation: not_validated`, `ui_acceptance_eligible: false`.
Успешное выполнение сценария и отсутствие превышений rAF-proxy не являются
доказательством достоверного UI-бюджета; это относится и к концу времени запуска.
В desktop-отчёте записываются источник выбора браузера и исполняемый файл.
Протокол независимого наблюдения различает задержку от системного ввода и
консервативную верхнюю границу от запуска наблюдателя до DOM-команды;
проверяются задержка, скрытый результат, тайм-аут, прежнее состояние и видимость
тестового окна. Локальные эксперименты, границы и состояние —
`docs/reports/p01-11/measurement-reliability.md`. Валидация физической матрицы не заявляется.
Добавлен отдельный [Windows-пиксельный runner](../../development/prototype-measurements.md#независимые-верхние-границы-по-пикселям-windows).
Он наблюдает изображение ОС на часах QPC и различает достаточную верхнюю границу
и неопределённость при её выходе за ориентир. Эталоны должны включать полное
изменённое содержимое, а контроли — задержку сохранения, скрытый результат и
устаревшее изображение. Это не подтверждение физической матрицы и не автоматическая
валидация других браузеров/Android или прежнего rAF-наблюдателя. Локальные отчёты,
исключённые попытки, хеши, проверки и актуальное продолжение —
`docs/reports/p01-11/windows-pixel-review.md`. A62 partial, GAP-006 не закрыт.
Продолжение добавляет калибровку Windows без фиксированного смещения панелей
Chrome/Opera и отдельный [Android-пиксельный профиль](../../development/prototype-measurements.md#независимые-верхние-границы-по-пикселям-android).
Масштаб, границы захвата и полные эталоны проверяются до серий; тайм-ауты,
прежнее изображение и превышения верхних границ не переименовываются в успех.
Локальные доказательства, исходные отказы, PNG/хеши и передача продолжения —
`docs/reports/p01-11/platform-pixel-review.md`. Это не физическая/release
приёмка или закрытие A62; обычные rAF-профили остаются диагностическими.
Открытие содержимого карточки и отметка выполнения отсутствуют; продуктовый UI,
полный IME, память/рост, первый запуск после установки и физическая приёмка
в этот результат не входят. Новый CI и интеграция не выполнялись.

Обратимость и сохранность проверяются снимком и обратной командой, человек и
агент используют те же операции Rust, обе платформы — один сценарий. Документация
пользователя не меняется, так как прикладное поведение не менялось; agent/development
и архитектурные документы отражают новый инструмент проверки. Один Storage
остаётся авторитетным, UI и данные отчёта не становятся рабочим хранилищем.
