# ADR-0070: причинная проекция независимых созданий тегов

Дата: 2026-11-18. Реализация P06.07.1, проверка — EV-128.
Развивает принятые ADR-0012/0046; не меняет продуктовые правила.

## Идентичность

Источником истины остаётся Automerge-граф пространства. Нового каталога aliases,
служебных merge-команд и нормализации имён на клиенте нет. Начальное имя и
зависимости создания извлекаются из изменения, создавшего `tag:<id>`.
Современное имя не определяет идентичность: переименование против нового
создания и коллизия двух переименований не объединяют теги.

Внутри одного Unicode-ключа начального имени объединяются только независимые
создания. Группа должна состоять из попарно независимых созданий. Если цепочка
независимости соединяет причинно упорядоченные создания, вся такая компонента
сохраняет отдельные ID и блокировку имён: это поздний мост ADR-0012. Явный выбор
разных имён и его UI относятся к последующей реализации конфликтов имён.

Представляющий ID — минимальная исходная строка ID группы. Чтение по любому
исходному ID возвращает один и тот же TagSnapshot с этим представляющим `tag`.
Списки пространства/тегов и назначения карточек содержат представляющий ID
один раз. Исходные объекты не удаляются; обычные команды принимают любой ID
группы. Новое независимое создание с меньшим ID может сменить представляющий
ID; сохранённые команды остаются исходными, дальнейшие действия требуют чтения.

## Причинная история и запись

Для имени, жизненного цикла и связи карточки с группой вычисляется причинный
фронт значений всех aliases. Значение исключается, когда другое актуальное
присваивание наблюдало его в своих зависимостях. Время и порядок доставки не
используются. Из независимых исходных написаний выбирается первое по строке
Automerge operation ID; ключ сравнения никогда не становится отображаемым именем.
Независимые последующие переименования сохраняют все разные варианты.

Переименование и изменение жизненного цикла записывают все известные объекты
группы, назначение/снятие — все известные ключи её ID в карте связей карточки.
Одна обычная транзакция сохраняет граф и receipt. Это поглощает наблюдавшиеся
значения, сохраняя причинно независимые поздние изменения. Повтор receipt
не применяет запись повторно. Назначения разных тегов не заменяют друг друга.
Снятие против независимого повторного назначения остаётся конфликтом карточки;
его явное решение — P06.07.2.

Токен тега учитывает объекты и связи всей группы. Старые версии не принимаются
после объединения или изменения состава. Права проверяются прежним общим ядром
до обращения по alias; прямого доступа к графу у клиента не появляется.

## Границы

Контракт JSON, схема SQLite и формат снимка не меняются. До завершения плана
старые сборки разработки не входят в поддержанную совместимость (ADR-0047).
Новые зависимости и отдельное хранение производных данных не добавляются.
Проекция один раз собирает группы при чтении каталога; чтение карточек использует
тот же каталог. Сокращение графа не должно удалять основания идентичности;
продуктовая компактизация пока не реализована и требует отдельной приёмки.

Полные A49/T09, решения позднего моста/коллизий имён, S05 и совместная UI/парная
приёмка не объявляются завершёнными этим срезом.

Продолжение P06.07.2–.4: [ADR-0071](0071-tag-conflict-resolution.md) задаёт
явные решения S05 и позднего моста. Граница первоначального EV-128 сохраняется.
