# Android-сканер и ручной ввод P01.09

Закреплены Rust `tauri-plugin-barcode-scanner =2.5.3` и JS
`@tauri-apps/plugin-barcode-scanner 2.5.3`. В выпущенном Android-модуле:
CameraX 1.5.1 и `play-services-mlkit-barcode-scanning:18.1.0`, динамическая
модель через GMS. Сканирование — только QR, задняя камера, `windowed: true`:
прозрачный WebView оставляет видимую кнопку отмены над камерой.

Разрешение Android CAMERA запрашивается только по явному нажатию.
Камера необязательна в manifest. Локальная capability окна `main` разрешает
только scan/cancel/check-permissions/request-permissions. Настройки ОС и
вибрация через плагин не разрешены. Доступа удалённым страницам нет.

Общая Rust-функция `invitation` принимает один из двух синтетических запросов:

```json
{"source":"manual","address":"http://192.0.2.1:4317","code":"SYNTHETIC-ONLY"}
```

```json
{"source":"qr","text":"{\"address\":\"http://192.0.2.1:4317\",\"code\":\"SYNTHETIC-ONLY\"}"}
```

HTTP `POST /prototype/invitation` и IPC `invitation({ request })` возвращают
одинаковые точные поля `address`/`code`, без нормализации. Пустые/пробельные поля,
неверные типы и неизвестные поля отклоняются. Это инспекция синтетического
JSON, а не проверка сетевого адреса, кода или доверия к устройству.
Хранения, DNS, подключения, обмена, ожидания подтверждения и выдачи прав нет.
Модели, OpenAPI, TypeScript и имя IPC происходят из Rust.

Камера — источник текста; та же прикладная операция доступна без неё человеку
и агенту. Raw-ответ камеры хранится только в текущей форме и позволяет повторить
инспекцию после отказа IPC. Просроченные ответы после отмены игнорируются.

Плагин логирует ошибки ML Kit, но не завершает scan с ошибкой модели; поэтому
после 20 секунд без результата вызывается cancel с нейтральным сообщением.
Тайм-аут не доказывает отсутствие модели и не является ошибкой приглашения.
Если отмена не подтверждена за 5 секунд/отклонена, новые сканирования запрещены
до перезапуска; ручной ввод остаётся доступным. Это не отмена будущих
изменяющих прикладных команд.

MainActivity передаёт «Назад» кнопке отмены только при активном сканере, иначе
сохраняет навигацию Wry. `onStop`, `visibilitychange` и `pagehide` отменяют
сканирование. Скрытие WebView системным диалогом разрешения само по себе не
отменяет запрос разрешения. Плагин и его Maven-зависимости не форкались.

В Tauri 2.12.5 исправлен BUG-001: после пересоздания Activity нативные плагины
освобождаются и создаются для актуальных Activity/WebView с прежней конфигурацией.
Версионный патч и его откат описаны в
[android-patches](../../prototypes/src-tauri/android-patches/README.md).
Gradle проверяет SHA-256 исходника зависимости и собирает замену в build-каталоге,
не меняя общий Cargo registry. При обновлении Tauri патч нужно пересмотреть.
Полномочия и общий Rust-контракт остаются прежними.

## Воспроизведение

Из `prototypes/`: `bun run check`, обе `bun run android:build [aarch64]`,
затем `bun run check:android` с явным ANDROID_SERIAL AOSP API 33 по
[Android-инструкции](android-prototype.md). Chrome/Opera проверяются через
`PROTOTYPE_BROWSER_PATH` и `bun run check:http`. Первоначальная загрузка
Cargo/Maven/JS-зависимостей требует сети; установленные ручные формы — нет.

Общий тест `invitation-scenarios.mjs` сравнивает HTTP/IPC, точный Unicode,
неверные данные, отсутствие запросов по адресу, отказ транспорта/повтор и очистку.
`scanner-scenarios.mjs` проверяет реальные системные разрешения, камеру,
отмену/повтор/«Назад»/Home и отсутствие клиента камеры через dumpsys.
На время этой проверки только тестовый эмулятор переводится в режим полёта
с выключенным Wi-Fi; прежние значения восстанавливаются в finally.
После прогона CAMERA у тестового APK отзывается при остановленном процессе.
Отдельно внедряются ответы сканера для проверки UI/IPC; это не оптическое чтение.

Android-сборка также создаёт instrumentation APK. Перед UI-сценариями Android
runner выполняет реальный `ActivityScenario.recreate()`: проверяет владельцев
плагинов/WebView, освобождение старого владельца и сохранность конфигурации.
Подробности ручного запуска — в README патча. Параметр AndroidX
`waitForActivitiesToComplete=false` позволяет опубликовать JUnit-результат до
закрытия последнего окна Tauri; исключения и проверки не подавляются.

Физическая проверка: на Android с GMS/готовой моделью отсканировать
SVG с экрана ПК для нескольких длин/Unicode/масштабов, сравнить точные исходные
поля, отменить/повторить и проверить первый запуск без модели и повтор после
загрузки. На физическом Galaxy A32/Android 13 уже проверены три точных чтения
(59/90/606 UTF-8-байт, масштабы 8/4), ручной UI/IPC, отмена/«Назад»/фон
и освобождение камеры; GAP-002 закрыт. Модуль на телефоне был доступен через GMS:
сетевую первую загрузку не наблюдали. Первый сеанс дал белый экран;
перезапуск восстановил превью. После полной переустановки BUG-001 воспроизведён:
при `CONFIG_ASSETS_PATHS` Android пересоздаёт Activity, а нативные плагины
сохраняют уничтоженную Activity и старый WebView. CameraX не регистрирует камеру
для уничтоженного владельца. Причина подтверждена JDWP и исходниками закреплённых
версий. BUG-001 исправлен в менеджере Tauri: две полные переустановки дали native
STREAMING без перезапуска процесса, новая сборка точно прочитала Unicode QR с
экрана ПК; разработчик подтвердил превью и чтение. Диагностика, регрессионный тест
пересоздания Activity и фактические результаты описаны в EV-022.
Результаты: [EV-022](../agent/verification/EV-022-qr-scanner.md).
