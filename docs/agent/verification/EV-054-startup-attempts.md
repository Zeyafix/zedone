# EV-054: попытки запуска и итоговая матрица P07.08

Шаг: P07.08.3 и итоговый P07.08. База: `9041216`.
Ветка: `feat/p07-08-migration-startup`; LOG-268.
Состояние: `verified` локально; весь согласованный инфраструктурный объём
P07.08 реализован и проверен. Коммита/PR/новых CI/интеграции нет.

## Карточка

- Цель: одна автоматическая попытка на запуск; явный повтор после отказа
  с новыми проверками/копией; следующий запуск опять допускает automatic.
  Ни один обычный worker не выдаётся до безопасного завершения.
- Требования: §1/1.1, T10/A45/A46/M02/M08, ADR-0030/0034/0035,
  [ADR-0036](../../architecture/decisions/0036-atomic-migration-startup.md).
- Зависимости: интегрированный P07.08.1 и локальный P07.08.2
  [EV-053](EV-053-atomic-migration-chain.md). Разработчик прямо поручил весь
  оставшийся P07.08 в одной ветке; публикация/слияние не выполняются.
- Scope: `startup::Startup`, состояние и владение ожидающим результатом worker,
  общий допуск `Storage::open`, матрица попыток/исторических схем, docs.
- Команды/платформы — EV-053; новые инструменты не устанавливаются.
- Обратимость: отказ сохраняет исходник; явный повтор после исправления,
  новый запуск и обычная обратная правка сохраняют историю/копии.

## Проверки попыток

15 новых тестов в `startup::tests`, включая один безопасный без env child-test
и проверку возрастающего реестра/сохранения всех переходов. Матрица цепочки —
EV-053. Дополнительно:

- Ошибка оставляет Failed с категорией причины. Второй automatic возвращает
  RetryRequired без новой попытки/файлов; retry использует новые бюджеты, дату
  и состояние исходника. Прежний кандидат не переиспользуется и не удаляется.
- Изменение исходника на неподдерживаемую схему перед retry обнаруживается
  повторным preflight; после устранения причины новый запуск автоматически
  выполняет необходимую цепочку.
- Нет настроек/недоступна папка/неподтверждён исходный layout: миграция не
  начинается; fallback/автосоздания другой папки нет.
- Пропажа/повреждение committed-копии не выдаёт Storage и не продвигает индекс.
  После исправления retry только завершает подтверждённую публикацию.
- Сокращённый `Storage::open` не обходит свидетельство: без настроек отказывает;
  общий Startup с правильной папкой допускает тот же worker.
- Отмена ожидания сохраняет Running и receiver результата в контроллере.
  Automatic уже использован; retry ждёт прежнюю попытку, а не запускает новую
  с другими параметрами. В итоге создаётся один комплект.
- Текущая схема и restart не создают ещё одну копию; исходные actor/peer/
  request/result/история и обратная правка проверены в общей матрице.

## Приёмка и передача

Финальные `bun scripts/check-product.mjs` и `--android` завершились с кодом 0.
Windows: fmt/Clippy, 10 access + 7 contract + 100 storage tests, release
all-targets/all-features, четыре независимых отказа unsafe, идентичные
Rust/OpenAPI/TS и TS compile. Android: те же 117 тестов нативно AOSP API33/x86_64,
release all-targets/all-features x86_64/arm64 и восемь независимых отказов unsafe;
контракт совпадает с host. Шесть новых migration process-crash/restart,
прежние crash-тесты и hot-journal отказ сохраняются.

Первые целевые прогоны исправили перенос registry в callback записи, видимость
тестовых helpers и новые имена adapter-функций. После просмотра общая ветка
startup/публикации повторно проверяет актуальную версию под блокировками;
receiver незавершённой попытки принадлежит контроллеру. Для окончательной матрицы
добавлены явное сохранение peer-state, отказы layout/исторического адаптера,
настоящий deferred-FK COMMIT, сохранение прежнего комплекта и инварианты реестра.
После финальных двух прогонов runtime/тесты не менялись.

Логи/условия/SHA-256 и очистка собственного read-only AVD —
`docs/reports/p07-08/verification.json`. Проверены полный diff и локальные
ссылки затронутых документов. P07.08.2/.3 и итоговый P07.08 `verified`;
`done` требует публикации/CI/интеграции, которых в этом поручении нет.
Следующий шаг — публикация этого состава по поручению, затем оценка
P03.05.2/P07.09 по их зависимостям. Другой этап сейчас не начинается. Общая приёмка T10/A45/A46/M01–M04/M08 остаётся partial: публичных
адаптеров/полномочий, продуктовых переходов и официально выпущенной линейки
ещё нет. P07.09 не реализуется этим шагом; hot-journal отказ не равен
аварийному восстановлению. Power-loss, Windows directory durability,
физический arm64/APK/локальный Linux и бюджеты приложения не проверены.

Пять правил: rollback/обратная правка/явное удаление orphan; общий worker для
будущих входов человека/агента без обхода прав; обновлённые docs/ADR/EV;
одинаковый runtime и тесты двух платформ; одна SQLite для фактов и один
runtime-реестр схем, файловый индекс — проекция, копии — архивы.
