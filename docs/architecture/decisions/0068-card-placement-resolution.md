# ADR-0068: явный выбор целого места карточки

Дата: 2026-11-17. Статус: реализовано в P06.06.1 и интегрировано PR #106/806d8e6 после всех 17
успешных проверок; приёмка
[EV-114](../../agent/verification/EV-114-card-placement-conflicts.md).

## Решение

Обычная `card.move` по-прежнему отказывает при собственном конфликте карточки.
`card.inspect_placements` через общий Service возвращает снимок и варианты
положения с ближайшим однозначно размещённым соседом. Подпись места вычисляется
ядром по прежнему Rank/ID-порядку; UI не вводит независимый алгоритм рангов.

`card.resolve_placement` принимает целую сохранённую `CardPlacement` и версию
карточки. Под writer lock проверяются права ReadWrite, replay, актуальность,
наличие нескольких мест и активные пространство и выбранная колонка.
Для удаления отдельной карточки выбор места сохраняет группу корзины.
Группа удаления контейнера блокирует этот выбор.
[ADR-0073](0073-card-deletion-conflicts.md).
Несохранённые пары отвергаются, декартово произведение
колонок и рангов не создаётся. Для legacy без `placement` варианты можно
восстановить только при единственной колонке; неоднозначные пары не угадываются.

Выбор записывает прежний scalar register `placement` вместе с receipt в одной
транзакции. Внутри неё старые варианты удаляются и выбранная пара присваивается
заново: оптимизация Automerge put существующего победителя в delete проигравших
не должна превращать решение в старую операцию, которую поглотит независимый
выбор. Независимые решения обязаны оставаться новыми причинными присваиваниями.
Историческая проекция состава колонок пропускает delete-операции без значения,
сохраняя прежние set и их причинную историю. Формат, SQLite schema и sync protocol не меняются. Изменение текста,
истории, тегов, выполнения и восстановления объектов не выполняется. Остальные
конфликты не снимаются; разные независимые решения снова конфликтуют. Совпавшие
семантические варианты по-прежнему объединяются существующим чтением register.

UI показывает карточку один раз в «Конфликтах» и предлагает явный выбор без
предварительно отмеченного значения. Отмена не отправляет запись. Выбранный ранг
не пересчитывается при перемещении соседа: подпись показывает текущее окружение,
но решением остаётся сохранённое место. Ошибка/неизвестный исход используют
прежнюю очередь намерений. Обратное действие — новая обычная move.

## Границы

Стабильный порядок разных объектов между одними соседями остаётся прежним
ADR-0045 и проверяется двумя репликами. Сосед со своим спорным местом не
используется для подписи, собственный конфликт текста не исключает однозначного
соседа. Карточки внутри колонки со спорным названием/порядком сохраняют доступные
действия. Выбор позиции самой колонки — отдельный P06.06.2; совместная приёмка
всего P06.06 и полный T09 остаются открытыми.
