# EV-091 — объём и ручная очистка пользовательской истории

Дата: 2026-11-14. Шаг: P05.11. Состояние: verified локально, без коммита/PR/нового CI/интеграции.

## Карточка шага

- База: main/c859afb179f5fb207b123bbde1794e76ed995e9c; отдельная ветка
  `feat/p05-11-history-cleanup-ui`. Шесть исходных dirty agent-документов

  очистить показанные доступные версии, сохранив текущие поля и спорные версии.
- Требования: T08/A12/A21/A31, §1.2 спецификации, ADR-0013/0051.
- Зависимости: P05.09/PR #87/c859afb/EV-087; P04.09.4/PR #75/ce44703/EV-075.
- Охват: общий Vue UI, прежний Service history.inspect/clear и журнал намерений,
  общий desktop/touch/native сценарий и user/agent/development документация.
  API/хранилище/контракт не меняются; P05.10/P06/физический arm64/release вне шага.
- Проверки: типы/build и полный ui:check Chrome/Opera; состав/UTF-8 байты/отмена,
  очистка карточки/пространства с корзиной, пустой/retained preview, strict stale,
  исходный replay после поздних версий, отказы/сохранность и очереди после restart;
  Android Device IPC и обе debug ABI/manifest. Реальные команды и результаты
  и фактические результаты приведены ниже.
- Обратимость: отмена до отправки; очистка истории — согласованное исключение
  без отмены (ADR-0051). Обязательны предупреждение и отдельное подтверждение.
- Визуальный план: прежние Segoe UI/Georgia и токены интерфейса: canvas #e4e8e6,
  surface #f2f4f3, ink #202d28, accent #315b50, border #a6b5ad, error #934131;
  тёмная тема использует существующие переменные. Слева выровненные сводка
  области/байтов, состав пар версий с ID карточек, затем предупреждение и
  checkbox подтверждения. Без нового набора карточек/декоративных графиков;
  существующие диалог, переносы и 44px кнопки сохраняют единый интерфейс.
- Результат: UI реализован и verified локально; полный Chrome/Opera ui:check,
  финальная целевая матрица, Device/IPC и обе debug ABI passed. Новый CI,
  коммит/PR/merge не выполнялись. Точная база по-прежнему c859afb.
- Далее: ревью и интеграция ветки; затем P05.10. Полные критерии остаются
  partial до требуемого полного UI/обменного охвата.

## Реализация и локальные проверки

`HistoryScope` и прежний диалог `SpacesView` показывают состав, текущие
логические UTF-8 байты, очищаемые/retained версии и буквальные пары полей.
Входы карточки/пространства используют один `history.inspect/clear`;
checkbox обязателен, пустой/полностью retained состав недоступен для отправки.
Область/субъект/expected не обновляются при подтверждении или отказе.
Старый receipt не заменяет текущий view, повтор проходит через прежнюю очередь.
Поздний inspect после закрытия карточки не открывает диалог повторно.
Новые зависимости/хранилище/изменения контракта/фоновые очистки отсутствуют.

Изменение превышает ориентир 300 строк из-за одного неделимого сценария
безопасной очистки: preview/подтверждение и проверки отсутствия лишнего
охвата/исходного replay на desktop/touch/native нельзя принимать порознь.
Посторонний рефакторинг и инфраструктурные изменения не добавлены.

- Типы `node node_modules/vue-tsc/bin/vue-tsc.js -p ui/tsconfig.json` и
  `bun run ui:build` passed. Базовый Vite warning chunk >500 kB остаётся.
- Целевая Chrome 157.0.8103.51 desktop и legacy touch/360px/dark матрица passed:
  точные пары/ID/UTF-8/отмена, карточка и пространство с корзиной, strict stale
  обеих областей без rebasing, пустая история/продолжение causal sequence,
  неизменность всех CardSnapshot и чужой pending series с последующим finish.
  Host fault-проверки: смешанный/полностью retained preview, ошибки чтения,
  видимая ошибка внутри прежней карточки, quota до отправки, настоящий отказ
  доступа, потерянные ответы/три идентичных JSON, reload и точный replay после
  новой версии. Финальная проверка позднего inspect дополняется ниже.
- Общий сценарий включён в существующие desktop/touch и Android CI runners;
  локально CI-драйвер Android не запускался. Таймауты/assertions прежних
  сценариев и бюджеты CI не изменены.
- Обе финальные debug ABI x86_64/aarch64 и manifest passed через
  `bun scripts/build-ui-android.mjs <ABI>`. Логи final2 в ignored p05-11.

## Android Device / настоящий IPC

Все открытия/касания/прокрутки/Back/перезапуск выполнены через возвращённую
Device команду agent-device. Снимки просмотрены через device_screenshot.
Отдельный локальный API-клиент подключался к уже открытой WebView только для
вызовов `zedone_command` и чтения Service, без управления интерфейсом.
Все данные синтетические; исходные product/app_webview сохранены до установки.

Подтверждены preview карточки/пространства, отсутствие
отправки до checkbox, отмена Back, светлая/тёмная темы, пустая история и
недоступное подтверждение, настоящая late agent edit через IPC и stale отказ.
Старый состав остался; 6 версий, включая позднюю, и все карточки сохранены.
После relaunch очередь/отказ сохраняются; проверка результата не очищает
позднюю версию. После явного удаления отклонённой записи новое чтение
позволяет очистку. Очистка карточки убрала её 4 версии, оставив 2 чужие,
включая корзину; очистка пространства убрала оставшиеся 2. Все три
CardSnapshot после обеих очисток точно равны снимкам перед очисткой:
текст/теги/выполнение/место/состояние/версии не поменялись. Объём 379 байт
в начале, 473 после поздней правки, 188 после очистки карточки, затем 0.
Native-proof.json сохраняет точные утверждения. На финальном APK после
последнего guard повторно проверены пустой preview/блокировка/Back.

Проба потери native IPC ответа не сработала: подмена неизменяемого bridge
не перехватила запросы, операция прошла обычным успешным путём. Эта проба
не считается проверкой unknown-result/replay на Android; такой охват есть
на host, общий native CI ещё не выполнен. Сырые артефакты сохранены локально.

Первый перенос restore-архива через exec-in не совпал по SHA-256; проверка
остановила восстановление до изменения product/app_webview. Повторный перенос
через adb push/run-as cp совпал. Итоговые имена и SHA-256 всех 25 исходных
файлов совпали, синтетические базы/ключи/архивы удалены; Device выключен.
Ошибки собственного helper при выборе ещё не видимой кнопки исправлены
прокруткой через agent-device; это не дефекты продукта и не успех проверок.

## Границы приёмки

Полный `bun run ui:check` Chrome 157.0.8103.51 и Opera/Chromium 157.0.8103.39
exit 0: типы/build/fmt/Clippy -D warnings/три shell tests, все прежние
workspace/cards/editor/moves/tags/search/trash/history/Markdown/lifecycle
и четыре desktop/touch очистки. Явный локальный Node 26.8.1 override,
база CI 24.22.1 прежняя. Лог ui-check-final2.log в ignored p05-11.
Этот полный прогон предшествует только финальному guard принадлежности
закрытой формы при позднем inspect (три строки условия/захват source).
После guard типы, Vite build, обе Android ABI/manifest и вся финальная
целевая desktop/legacy-touch матрица обоих браузеров passed отдельно;
cleanup-{chrome,opera}-final-guard2.log. Отдельный host build в существующем
изолированном target исключил блокировку exe продолжающегося полного прогона.
Тот же bounded delayed-response тест без guard отверг старую сборку точным
assertion 1 !== 0 (повторно открытый диалог), финальный guard прошёл его
без ослабления проверок/таймаутов. Первые ошибки тестового locator-click
при удалённом checkVisibility устранены использованием существующего tap;
finally ограничен 10s и ждёт только фактически начатый route.

Синтаксис трёх JS runner, diff --check, все 98 прежних определений/состояний
критериев и побайтовая неизменность четырёх исходных EV подтверждены.
Прежние dirty записи журнала/очереди сохранены; чужие изменения не убирались.
Нового CI/PR/интеграции нет.
Полные P05/T08/A12/A21/A31 остаются partial: итоговая P05.10/обмен P06,
физический arm64 и release UI не принимаются этим локальным шагом.

Пять правил в срезе: отмена до отправки/явное ранее принятое исключение
необратимости clear; общий API/guard/журнал человека и агента; обновлены
user/agent/development/ADR и этот EV; общий UI на Windows desktop/touch и
Android Device/IPC с указанными границами native faults/CI; один Service/
SQLite/Automerge остаётся источником данных, preview/receipt не становятся
отдельным хранилищем. Новых BUG/GAP/продуктовых решений нет.
