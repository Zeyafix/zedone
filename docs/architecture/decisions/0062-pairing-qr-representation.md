# ADR-0062: QR как представление существующего приглашения

Дата: 2026-11-16. Статус: P06.02.1–.3 интегрированы в main/caaf6df через
[PR #100](https://github.com/Zeyafix/zedone/pull/100), head 9551a35,
все 17 Windows/Linux/Android checks SUCCESS; EV-106/EV-107/LOG-582.
Оптика текущего APK на Galaxy A32 принята локально, GAP-030 resolved.

## Решение

QR содержит JSON с тремя обязательными полями: `format` со значением
`zedone-pairing-v1`, `address` — IP:порт и `offer` — прежний составной код
`zd1:<invitation>:<pin>:<code>`. Не вводятся новые права, ключи или протокол
подтверждения. Отдельный маркер отличает продуктовые данные от синтетического
прототипа и постороннего QR; неизвестный формат отклоняется.

Адрес разбирается тем же `SocketAddr`, что ручной session.prepare: IPv4 или
IPv6 в квадратных скобках, ненулевой порт, не unspecified IP. Представление
адреса каноническое; offer передаётся точно без нормализации. Составной код
проверяет существующий Offer::decode. Вход ограничен 1024 UTF-8 байтами;
пустые, неполные, неизвестные и повторяющиеся поля отклоняются. DNS/URL,
команды, собственный TLS pin и права из дополнительных полей не принимаются.

Чистый генератор `core::qr` переносит проверенный qrcodegen 1.8.0 из P01:
ECI 26, все UTF-8 байты, Medium ECC с автоматическим повышением без увеличения
версии, автоматическая маска, версии 1–40. Матрица без quiet zone; единый
SVG сохраняет белые поля по четыре модуля. Переполнение
отклоняется без обрезки. Генератор не получает платформенных/сетевых зависимостей;
core разрешает qrcodegen явно, зависимость от prototype crate отсутствует.

Host API с прежним ManageDevices:

- `offer.qr {address}` читает текущее исходящее приглашение через offer.read
  и возвращает `{text, modules, invitation}`. При отсутствии открытого кода —
  not_found. Не создаёт новое приглашение или identity; сохраняет прежнюю
  recovery-публикацию уже сохранённого offer.read после прерванного создания.
  Адрес задаётся явно, как при ручной передаче; доступность сети не проверяется.
- `session.decode_qr {text}` возвращает `{address, offer}` без сетевого запроса,
  записи сессии или использования кода. Это только проверка представления,
  а не срока/актуальности/подлинности приглашения. Доверие к источнику QR
  обязательно; действующий сервер проверяется прежним TLS pin из offer.

Доставка общая: DeviceControl/DeviceHost, Android device_session IPC,
same-origin `/host/devices/<operation>`, защищённый `/v1/host/<operation>`
и существующий CLI --endpoint. Обычный Service/OpenAPI команд пространств
не расширяется; OS slots, SQLite и receipts не получают QR-копию секрета.

После разбора пользователь проверяет адрес/название и явно вызывает прежние
session.prepare/submit. Агент выполняет те же операции. Сканирование не
означает отправку или подтверждение. До явного подтверждения приглашающей
стороной нет доступа/обмена; cancel/reject/unlink и новый ключ прежние.
Срок, отмена, использование и блокировка кода проверяются сервером даже
для ранее сохранённого изображения. Ошибка разбора не трогает исходное
приглашение, счётчик попыток или существующую сессию.

QR содержит секрет уровня ручного одноразового кода: не писать в журналы,
чат, argv, localStorage или обычные намерения. Возврат через авторизованный
host нужен для явного показа, ответы HTTP уже no-store. Матрица также секретна.

## Граница и проверка

P06.02.1 принимает формат/генерацию/host API. В P06.02.2 добавлены общий SVG,
Android Scanner 2.5.3 с QR-only/windowed-режимом, явным разрешением, отменой,
Back/фоном и сохранением ручного ввода. Показ сверяет свежий snapshot и скрывается
по сроку; неверный QR не меняет форму. Scanner ограничивает ожидание 20 секундами,
игнорирует поздние ответы и закрывает камеру до передачи текста в общий разбор.
Ошибка остановки не разрешает вторую камеру; повтор доступен после перезапуска.
Состояние драйвера общее для пересоздаваемых форм: уход из настроек не сбрасывает
неподтверждённую остановку и не позволяет перекрыть незавершённое разрешение/отмену.
Используется прежний общий BUG-001 lifecycle patch с проверкой upstream SHA-256,
без замены сканера/ML Kit; поддержка патча при обновлении Tauri обязательна.
Итог двух устройств — P06.02.3. T09/A51 и DEC-003 целиком не закрываются.

Проверки: независимый jsQR 1.4.0 читает продуктовую матрицу для IPv4/IPv6
с полями четыре модуля и масштабами 2/4/8; результат проходит общий разбор
и существующие TLS/pending/права/подтверждение/обратные действия. Native
Windows/Android используют те же тесты; камера не подменяется декодером.
Фактические результаты и ограничения — [EV-106](../../agent/verification/EV-106-pairing-qr-contract.md)
и [EV-107](../../agent/verification/EV-107-pairing-qr-ui.md). Windows SVG и
Android screenshot читаются независимым декодером; парный Windows↔APK runner
проверяет QR API/TLS/CLI/права/обратные действия. Оптика текущего APK отдельно
проверена на Galaxy A32/Android 13 arm64 с GMS: выполнены
четыре точных оптических чтения, повтор, запрос без доступа до явного read-only
подтверждения Windows, restart/отказ/отмена/отвязка/сохранность и cleanup.
GAP-030 resolved. Холодная первая загрузка модели и настоящий Tailscale не
подтверждены этим прогоном через USB reverse; все 98 состояния критериев прежние.

Альтернатива — отдельный QR endpoint подключения — создала бы второй процесс
выдачи прав и повторов. Использование JSON прототипа без маркера принимало бы
непродуктовые данные. Принято представление действующего Offer с явным форматом.
