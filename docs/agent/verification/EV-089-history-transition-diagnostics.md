# EV-089 — диагностика сенсорного перехода из редактора в историю

Дата: 2026-11-14. Шаг: CI.06. Состояние: диагностика verified локально; публикация/новый CI ожидаются.

## Карточка шага

- Цель: установить причину отказа перехода к истории в Linux shell CI PR #87.
- База: head c975d0f, исходный отказ на e4f24a3. Два dirty документа CI.05
  сохранены; продукт/UI не меняются на этапе диагностики.
- Scope: bounded read-only диагностика вокруг существующего сенсорного
  перехода в `scripts/check-ui-history.mjs`, EV/журнал/очередь.
- Критерии: T08/A21, GAP-025. Первоначальный desktop history passed;
  touch history остановился на прежнем 10s ожидании после нажатия
  «История версий» во время редактирования. Failure state показывал доску
  без диалога, alerts отсутствовали. Причина закрытия не записана.
- Проверки: текущая матрица истории desktop/touch; контролируемый локальный
  touch trace с CPU slowdown; затем фактическая диагностика CI при повторении.
- Инварианты: прежний реальный tap/верификация/таймаут/assertions, никаких
  повторов касания, DOM clicks, polyfill или изменения UI для прохождения теста.
- Диагностика: последние 20 pointer/click/focus событий, категории элементов,
  положение кнопки, наличие диалога/редактора/истории. Текст/ввод/ключи,
  receipts и сохранённые намерения не записываются. Обработчики удаляются
  после перехода; первоначальная ошибка пробрасывается без замены.
- Результат: локальный целевой touch trace с замедлением CPU прошёл;
  исходный Linux отказ не воспроизведён и не объявлен устранённым.
  Локальная Chrome desktop/touch матрица с дополнительной диагностикой passed. Root cause и исходный Linux сценарий не объявляются исправленными.
- Далее: не прерывать уже запущенный c975d0f ради другой диагностики;
  получить expected/actual Android CLI по CI.05, затем опубликовать CI.06
  вместе с обоснованной следующей правкой и прочитать реальные события Linux.

Остальные items исходного уведомления проверены: prototype-ui и обе Android
shell jobs отказали на прежнем CLI preflight (GAP-024); android и Linux
aggregates строго отвергли failure дочерней matrix. Это корректный отказ gate,
а не отдельная первопричина. Исходные логи — только `docs/reports/p05-09/`.

Controlled negative probe намеренно направил настоящий native tap в кнопку
закрытия вместо перехода. Прежний TimeoutError сохранился, bounded диагностика
зафиксировала close-button событие/отсутствие диалога, повторов касания нет.
Это проверяет обработку отказа, не устанавливает причину исходного Linux CI.
После получения CLI expected/actual CI.06 включается в следующий head вместе
с исправлением CI.05; новый реальный CI и GAP-025 остаются открытыми.
