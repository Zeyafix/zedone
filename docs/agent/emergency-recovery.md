# Аварийное восстановление через общий API

Обычный доступ, включая Administration, не разрешает `maintenance.execute`.
Нужен отдельный служебный ключ, выданный локальным владельцем. Чтение не даёт
права восстанавливать базу; отзыв проверяется до выдачи сохранённого результата.
Не читайте и не меняйте SQLite напрямую для обхода служебного режима.

HTTP/IPC используют обычную оболочку команды: `id` — ненулевые 16 случайных
байт, `operation` — `maintenance.execute`, `parameters` — MaintenanceCommand
из [Rust/OpenAPI](../../api/openapi.json). `inspect` читает причину, phase,
доступные полные копии, сохранённые проблемные состояния и `version`.
Изменения передают последнюю `version` в `expected`.

- `enter` останавливает обычный worker и обмен; `retry` явно проверяет запуск.
- `prepare` принимает ID полной копии из inspect; проверка не заменяет базу.
- `cancel` отменяет подготовку; `apply` заменяет всю базу по ID плана.
- `rollback` возвращает raw-комплект с закрытым обычным доступом.
- `continue` доступен владельцу для явно подтверждённого продолжения
  Applying/Reverting после потери исходного намерения.
- `delete_problem` отдельно удаляет сохранённый raw-комплект.
- Владелец использует `issue_access`/`revoke_access`; `writable: false`
  разрешает только сведения. `expires_ms` задаёт срок служебного доступа.

Для выбора папки требуется отдельный локальный порт владельца. Сетевой
служебный ключ не превращается в произвольный доступ к файловой системе.
В CLI есть `--maintenance-endpoint`, `--key-file`, `--stdin`; передайте
сохранённую оболочку команды в stdin, ключ — отдельным файлом. Loopback адрес
действующего служебного API отображается в настройках.

Перед apply/rollback/continue явно согласуйте причину, копию и охват всей базы
с владельцем в рамках поручения. Храните исходные ID и параметры до доставки;
при неизвестном результате повторяйте прежний запрос. Отзыв/истечение прав
закрывает replay. `stale_state` требует нового чтения и нового осознанного
намерения; не меняйте сохранённую команду автоматически.

После восстановления старые обычные ключи и подключения не работают.
Пространства на паузе; открытие, новые права, выбор папки копий с управлением
и подтверждённое переподключение — отдельные явные действия. Полные исходные
копии и raw не удаляются восстановлением. Подробные последствия —
[в пользовательской инструкции](../user/emergency-recovery.md).
