P02.04 разделён до реализации: назначения (P02.04.1), идентичность/создание/
объединение/имена (P02.04.2), удаление тега против назначения (P02.04.3).
Этот срез отвечает на один вопрос: сохраняет ли модель состояния отдельной
связи все варианты при независимых изменениях. Фиксированные пространства,
карточки и теги не являются продуктовой командой создания. Идентичность связи
определяется Object ID карточки и тега, а не именами. Продуктовые входы,
права, Unicode-сравнение имён, объединение идентификаторов, удаление тега и
рост/память не входят в срез. Ориентир 300 строк может быть превышен:
действие/обратное действие, блокировки, явные решения, сбой и проверка
перезапуска на двух платформах образуют одну проверку; имена/удаления отделены.

## Результаты

| Проверка | Результат |
| --- | --- |
| Windows `bun run check` | Пройдено: fmt/Clippy, 56 Rust-тестов (10 новых), release workspace, 14 фаз отдельными CLI-процессами, контракт/типы, Vue/Vite, HTTP/UI и прежние драйверы |
| Android `bun run check:automerge --android` | Пройдено: 14 фаз нативными процессами API 33/x86_64 и 37/37 тестов пробника; CLI x86_64/arm64 собраны |
| Назначения | Разные теги одной карточки сохраняются вместе со старым назначением; одинаковые независимые назначения/снятия не создают ложного конфликта; тег не удаляется снятием |
| Идентичность | Связь адресуется Object ID тега, чужое пространство/неизвестный ID отклоняются; одноимённый тег другого пространства независим; карточки, текст и история сохраняются |
| S05 и решения | Снятие против повторного назначения сохраняет два варианта. Оба решения доступны; разные автономные решения/позднее решение дают новый конфликт, одинаковые не дают ложного конфликта |
| Блокировки и обратимость | Спорная связь блокирует обычные правки/назначения всей карточки; другая карточка доступна. Выбор связи не снимает конфликт текста. Назначение/снятие обратимы через один метод |
| Отказы | Неверный/устаревший выбор не меняет fingerprint; ID операций проверяются даже при совпадении значений. SQLite AFTER UPDATE ABORT сохраняет обе реплики после повторного открытия |
| Доставка/перезапуск | Все циклические сдвиги прямого/обратного порядка полного набора изменений с двукратной доставкой сохраняют heads, число изменений, все ID/варианты; проверено повторное чтение SQLite |

## Ограничения и передача

Обратные назначения/снятия, общий Rust/CLI-путь человека и агента, документация,
нативный паритет Windows/Android x86_64 и авторитетная SQLite подтверждены в
пределах пробника. Новых зависимостей и продуктовых входов нет. Контрольный JSON
не используется как хранилище. Read-only эмулятор остановлен, временные каталоги
драйверов удалены; логи, хеши и передача — docs/reports/p02-04-1/.

T05/A39/S05 partial: продуктовые UI/HTTP/IPC/права, положение и выполнение
карточки с назначениями, физический arm64 и новый APK/WebView не проверялись.

схема остаются будущими шагами; ссылки на Object ID в этом временном формате
не определяют будущую модель алиасов объединённых тегов. DEC-002/DEC-005 открыты.
