# ADR-0018: проверять новые версии через GitHub Releases автоматически и вручную

Дата: 2026-10-27.

Статус: принято разработчиком. Реализация и техническая проверка не выполнены.

## Контекст

Для ZeDone уже выбраны загрузка приложения с GitHub, уведомление о новой версии и ручные скачивание и установка. Требовалось определить источник сведений о версиях и способ запуска проверки.

Разработчик выбрал GitHub Releases, автопроверку раз в сутки при работающем приложении и ручную команду «Проверить обновления». Режим только ручной проверки рассмотрен как альтернатива. Выбранный автоматический режим можно выключить и снова включить.

## Решение

- Сведения о новых версиях берутся из GitHub Releases проекта. Готовые установщик Windows и APK публикуются там же.
- При работающем ZeDone включённая автопроверка выполняется раз в сутки. Работа проверок при закрытом APK не обещается.
- Доступна отдельная ручная команда «Проверить обновления», в том числе при выключенной автоматике.
- Автопроверку можно выключить и снова включить. Настройка сохраняется локально на устройстве; её изменение и просмотр, ручная проверка и результат доступны через общий API в пределах выданных прав.
- Ошибка сети не препятствует работе с пространствами и не выдаётся за успешную проверку отсутствия обновлений.
- Скачивание и установка остаются ручными. Это решение не включает автоматическое скачивание, установку или миграцию по результату проверки версии.
- Правила одинаковы для Windows и Android, человека и агента.

## Открытые технические вопросы

Технический отсчёт суток и время первой проверки, поведение после перезапуска и возврата сети, сравнение версий и выбор релиза, работа с кэшем, пределы запросов и повторов, сетевой клиент и полномочия изменения общей настройки определяются в DEC-008/P08. Выбор режима не задаёт обещания фонового выполнения Android или мгновенной доставки уведомления о выпуске.

Для публикаций публичного репозитория GitHub предоставляет Releases API с чтением публичных ресурсов без обязательной аутентификации. При реализации учитываются ограничения запросов, обработка ошибок и кэширование; технические детали проверяются на выбранных версиях, отдельный учётный доступ пользователя GitHub этим решением не вводится.

## Проверка и правила проекта

Добавлены сценарий 60 и A60/P08: автоматическая и ручная проверки, выключение и повторное включение автоматики, ручная команда при выключенной автоматике, новая версия/отсутствие новой версии/ошибка сети, сохранение работы с пространствами, общий API в пределах прав на Windows/Android. Скачивание и установка остаются ручными. Критерий имеет статус `not_run`.

Выключение и включение обеспечивают обратимость настройки. Документация отражает выбор; общий API, паритет платформ и единое авторитетное локальное состояние остаются требованиями, а не результатами реализованного приложения.
