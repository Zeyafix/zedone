# EV-042 — безопасное сокращение хранения Automerge

## Карточка P02.06.2

- База `4724117`, общая ветка P02.06 по прямому поручению разработчика.
  Зависимость .1/EV-041 реализована; девять целевых Rust-тестов passed.
- Цель: заменить поток изменений компактным представлением того же полного
  графа и освободить свободные страницы SQLite без удаления причинных сведений.
- Требования T05/S10, ADR-0002, §1.2 (неограниченное отсутствие связи),
  история/очистка и поздние независимые данные P02.05.
- Область: внутренний Rust/SQLite/CLI. `save()`/строгий `load()` сохраняют граф,
  Object ID, все варианты и отложенные изменения. JSON не становится хранилищем.
  SQLite `VACUUM` — отдельная стадия после транзакционного переупаковывания.
- Проверки: старые реплики после очистки/сокращения, конфликты, история,
  сохранённые снимки, actor/peer/пауза, повторы и перезапуск, отказы записи/VACUUM,
  незавершённая доставка изменений. Общие Windows/Android-проверки после .3.
- Обратимость: данные не изменяются; исходные сохранённые снимки доступны.
  Удаление старых значений из причинного графа не объявляется безопасным сокращением.
- Размер: одна матрица сохранности с реальными отказами и отдельными процессами;
  превышение 300 строк необходимо для проверки тех же данных, а не нового функционала.
- Результат: verified локально; физическое удаление истории/предел роста не доказаны.
- Источник API: [Automerge Rust 0.12.0](https://docs.rs/automerge/0.12.0/automerge/struct.Automerge.html#method.save).

## Реализация и проверки

- Компактное представление строго загружается повторно; совпадают heads,
  полная последовательность хешей изменений и недостающие зависимости.
  Повторная сериализация совпадает; локальные actor/peer не меняются.
- Реальный поток base + `save_after()` уменьшается при переупаковке; повтор уже
  компактного представления не изменяет объём. Пустые страницы отдельной базы
  после удаления синтетического BLOB освобождаются, целостность SQLite `ok`.
- Отказ после обновления второй реплики откатывает переупаковку обеих. Ошибка
  VACUUM на read-only соединении сохраняет корректное состояние; повтор успешен.
  Снимки/пауза/история переживают обслуживание и повторный запуск.
- Изменение без ещё доставленной зависимости сохраняется после упаковки;
  последующая доставка зависимости приводит к исходному состоянию/истории.
- Три нативные CLI-фазы принимают после сокращения старую независимую правку
  и новую карточку внутри очищенной колонки: обе попадают в конфликты,
  очищенный сосед не возвращается. Источник — SQLite, JSON только отпечаток.
- Общий финальный результат и измерения — EV-043. Графовая сборка мусора,
  удаление прежних байтов Automerge и ограниченный рост не заявляются.
