# ADR-0076: авторизованный экспорт и независимый импорт

Дата: 2026-11-24. Статус: реализация P07.02.3,
[EV-149](../../agent/verification/EV-149-authorized-space-transfer.md).

## Решение

`space.export` и `space.import` входят в общий CommandRequest/CommandResponse
и один Rust handler для HTTP/CLI/IPC. Формат ZEDSPACE v1 и преобразование
[ADR-0075](0075-independent-space-import.md) сохраняются. Файловый UI P07.02.4
использует эту же пару команд и очередь исходных намерений;
[EV-150](../../agent/verification/EV-150-space-transfer-files.md).

Файловые адаптеры передают только байты: браузерные File/Blob в Windows и
системные ACTION_OPEN_DOCUMENT/ACTION_CREATE_DOCUMENT в Android. URI выбранного
документа остаётся внутри Kotlin, произвольных путей/URI в HTTP или командах
ядра нет. Чтение ограничено до загрузки целого файла; разбор/контроль
целостности/продуктовой модели остаётся общим. Подготовка архива отделена от
сохранения: отмена или отказ файла не заменяют исходное намерение. Системный
провайдер не даёт общей гарантии атомарной записи при power-loss; приложение
сообщает ошибку и сохраняет подготовленные байты для повторного сохранения.

Экспорт требует Read исходного пространства. Проверка актуального доступа,
захват полного журнала с pending-историей и запись неизменного результата
выполняются в одной транзакции. Дата берётся из доверенных часов внутри
первого выполнения. Повтор возвращает те же байты после свежей проверки прав,
даже если исходник позже изменился. Новый снимок требует нового намерения.
Исходный граф, actor и сессия редактирования не изменяются.

Импорт, как `space.create`, требует действующего доступа. Подлинность архива
не заменяет полномочий. Независимый граф, ReadWrite только вызывающему
субъекту и receipt с ID новой копии публикуются атомарно. Ключ/срок/отзыв
вызывающего субъекта сохраняются; другие участники доступа не получают.
Исторические авторы в архиве не становятся участниками. Повтор с тем же ID
и архивом возвращает прежний ID, включая restart/потерю ответа/неизвестный
исход commit; новый ID команды означает отдельный импорт. Изменённые
параметры выполненного ID дают command_mismatch после проверки полномочий.
Для возврата результата импорта повторно требуется Read созданной копии.

Срок проверяется до/после работы; штатный timed_transact также проверяет
его после flush. Отказ записи доступа/receipt отравляет WriteContext,
даже если вызывающий код перехватил ошибку. До commit успех не возвращается.
Права, ключи, peers, sync selections и receipts исходника не переносятся.
Текущая SQLite-схема и зависимости прежние; общий рост receipts остаётся DEC-009.

## Представление и бюджеты

Архив передаётся строкой lowercase hex в поле `archive`; это те же байты
файла, а не путь к файлу на сервере. Выбран существующий в sync способ
передачи бинарных данных без новой зависимости или другого транспорта.
Публичный бюджет одной команды — 1 MiB бинарного контейнера и 10000 changes,
до декодирования/SQL-чтения и после преобразования/добавления истории.
Hex удваивает размер; HTTP/CLI/IPC/network и общий клиент допускают до
3 MiB JSON только для импорта, обычные команды сохраняют 64 KiB.
Существующий sync.push сохраняет прежний бюджет 3 MiB.

Это техническая граница текущей разовой передачи, не предел пространства
или обещание пика памяти/времени. Превышение экспорта даёт unavailable,
недопустимый/неполный/неподдержанный/слишком большой вход импорта —
invalid_request. Частичных архивов и частичных пространств нет.
OpenAPI, TS и автономный runtime validator генерируются из Rust.
Ограничение hex задано bounded pattern, совместимым с автономным валидатором.

## Обратимость и границы

Новая копия использует прежние изменения/корзину/восстановление и очистку,
не затрагивая исходник/файл/другой импорт. Экспорт — неизменяемая копия;
файловое сохранение/удаление и отмена выбора проверяются отдельно в .4.
Архив содержит пользовательские данные и историю: не публиковать его и
не выводить в диагностику. Полученный ID импорта не заменяет свежее чтение.
Восстановление исходного пространства, backups и защита полного отката
базы остаются отдельными шагами P07.
