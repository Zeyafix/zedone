# ADR-0082: восстановление отсутствующего пространства после переустановки

Дата: 2026-11-27. Статус: реализация P07.06; актуальная проверка и ограничения —
[EV-162](../../agent/verification/EV-162-reinstallation-recovery.md).

## Допуск и полномочия

ADR-0016 реализуется отдельными inspect_missing/restore_missing; обычный
recovery.restore не получает fallback, а его обязательный страховочный снимок
сохраняется. Новая установка определяется отсутствием документа исходного ID,
а не состоянием всего приложения: в ней допустимы другие пространства. Пустой,
нечитаемый, trashed и purged документ остаётся существующим. Запрос SQL EXISTS
должен успешно подтвердить отсутствие; ошибки чтения не превращаются в false.
Продуктовая очистка оставляет документ и причинную границу purged.

Обе операции требуют действующего локального доступа, как space.create/import.
Это разрешает создание только отсутствующего локального пространства из
проверенного предоставленного архива. Только вызывающему субъекту добавляется
ReadWrite; администрация не расширяется. Новые права остальных агентов выдаются
явно и могут изменяться/отзываться. Restore receipt требует свежего ReadWrite
того же пространства, включая replay после изменения/отзыва/истечения прав.
Сохранившийся другой аппарат продолжает управлять своими разрешениями отдельно.

## Согласованное применение

Inspect принимает архив и возвращает исходный ID, названия и версию, связанную
с проверенным контейнером и отсутствием. Restore повторяет проверки в одной
BEGIN IMMEDIATE вместе с публикацией. Граф, право вызывающего субъекта, постоянная
пауза sync_spaces и receipt фиксируются одной транзакцией. Изменённый архив,
старое условие и появившийся документ останавливают публикацию целиком. Нет
снимка отсутствующего состояния, filesystem witness или удаления исходного файла.
Неизвестный исход commit проверяется повтором того же намерения; replay не
восстанавливает повторно и не меняет явно возобновлённую паузу.

Проверяются контейнер, ID, все применённые операции известной модели и ссылки
по прежнему validator восстановления. История Automerge с ожидающими зависимостями
сохраняется; используются прежние ID продуктовых объектов. Поверх исходной
истории создаётся новая причинная операция существующим planner восстановления.
Локальный actor документа генерируется заново; технический actor исходника и
его учётные данные для дальнейшего редактирования не переиспользуются.
Неизменившиеся поля не получают присваивания, поэтому независимые правки другого
устройства сохраняются. Архив не включает ключи, grants, peers или receipts.

Повторное подключение новой установки проходит обычные приглашение, pending и
явное подтверждение. Прежняя запись устройства на другой стороне не становится
записью новой установки; она управляется отдельно обычным unlink. Выбор
пространства для нового подключения и restart не снимают pause; требуется отдельный
recovery.pause/sync.pause после проверки результата. Обратные операции —
space.trash/restore, pause/resume, unlink и изменение/отзыв прав.

Схема SQLite, формат ZEDSPACE, протокол обмена и полномочия аварийного отката
всей базы прежние. Папочный каталог и выбор файла только подготавливают операцию;
мутация выполняется после отдельного подтверждения общим API Windows/Android.
Границы hardware power-loss и физического arm64 runtime явно сохраняются в EV.
