# Воспроизведение окружения (P00.07)

Цель — проверить, что [Windows Quick Start](quick-start-windows.md) позволяет подготовить среду и повторить проверки одними командами разработчику и агенту. Для Linux/Android используйте [инструкцию CI](android-environment-ci.md). Приёмка T13–T17 находится в [плане-журнале](../agent/plan-journal.md); состояние конкретной машины — только в `docs/reports/state.json`.

## Перед проверкой

1. Прочитайте локальное состояние и доказательства P00.04/P00.06. Запишите базовую Git-ревизию, существующие изменения, версии инструментов, активный Rust toolchain, установленные Rust-цели и Cargo CLI.
2. Для чистой установки используйте отдельный Windows 11 x64 ПК или VM, где проверка `emulator -accel-check` проходит. Запишите, какие инструменты уже присутствовали. Наличие чистого SDK или нового AVD само по себе не означает чистую Windows.
3. Переустановка инструментов на рабочем ПК требует явного поручения разработчика, проверенного восстановления и штатных деинсталляторов. До удаления загрузите установщики закреплённых версий и проверьте указанные SHA256/подписи. Сохраните состав компонентов Build Tools, настройки, профили и авторизацию; исключения разработчика имеют приоритет. Системные изменения требуют UAC; перезагрузку выполняет разработчик после сохранения работы.
4. Для повторной проверки установленной среды ничего удалять не требуется. Результат записывается как повторная проверка, без утверждения о чистой установке.

Из корня репозитория в PowerShell 7 сохраните только затрагиваемые переменные. Это не выгрузка всего окружения: токены и ключи в отчёт не включаются. Для нового прогона используйте новый каталог, не перезаписывая прежние снимки.

```powershell
$reproductionReports = 'docs/reports/p00-07'
New-Item -ItemType Directory -Path $reproductionReports -Force | Out-Null
$snapshotPath = Join-Path $reproductionReports 'environment-before.json'
if (Test-Path -LiteralPath $snapshotPath) { throw 'Снимок уже существует; выберите новый каталог отчёта.' }
$environmentSnapshot = foreach ($scope in @('User', 'Machine', 'Process')) {
    foreach ($name in @('PATH', 'JAVA_HOME', 'ANDROID_HOME', 'ANDROID_SDK_ROOT', 'NDK_HOME', 'ANDROID_AVD_HOME')) {
        [pscustomobject]@{ scope = $scope; name = $name; value = [Environment]::GetEnvironmentVariable($name, $scope) }
    }
}
ConvertTo-Json -InputObject @($environmentSnapshot) | Set-Content -LiteralPath $snapshotPath -Encoding UTF8
```

## Прогон и ожидаемые результаты

| Проверка | Действие и доказательство |
| --- | --- |
| Windows, T13 | Пройдите разделы 1–2 Quick Start. Сохраните версии, успешные Cargo build/run/fmt/Clippy и `Hello, world!`; проверьте наличие Chrome/Opera. Повторите общий `scripts/check-windows-environment.ps1` из раздела 5. |
| Android, T14 | Пройдите раздел 3: SDK-пакеты с закреплёнными ревизиями, JDK/CLI/NDK/Tauri, Rust-цели, ускорение, запуск AVD, `adb`, Android 13/API 33/x86_64, отсутствие GMS и `ZEDONE_ANDROID_TOOLCHAIN_OK`. Наличие SDK без запуска AVD не является успехом. |
| Средства выпуска и связи, T15 | Повторите раздел 4: ISCC компилирует синтетический EXE; Tailscale отвечает и его состояние записано; GitHub API читается в необходимом объёме. Вход в tailnet, подпись и публикация принимаются позднее. |
| CI, T16 | Сверьте реальные завершённые Windows/Linux Actions с проверяемой ревизией и EV-008/EV-009. Запись workflow без успешного run не подтверждает CI. При изменении проверочных скриптов или версий повторите затронутый CI. |
| Повтор и обратимость, T17 | Удалите только свой проверочный пример после проверки его абсолютного пути и воссоздайте теми же командами. Проверьте остановку своего AVD, удаление тестового файла на устройстве и сохранность прежних AVD/настроек. Не удаляйте общий SDK, профили и приложения ради очистки примеров. |

При унаследованных старых Android-переменных перечитайте User-значения только в текущий процесс, затем проверьте соответствие SDK-каталогов:

```powershell
foreach ($name in @('JAVA_HOME', 'ANDROID_HOME', 'NDK_HOME', 'ANDROID_SDK_ROOT')) {
    $savedValue = [Environment]::GetEnvironmentVariable($name, 'User')
    if ($savedValue) { [Environment]::SetEnvironmentVariable($name, $savedValue, 'Process') }
}
if (-not $env:JAVA_HOME -or -not $env:ANDROID_HOME -or -not $env:NDK_HOME) {
    throw 'Подготовьте Android-переменные по Quick Start.'
}
if ($env:ANDROID_SDK_ROOT -and $env:ANDROID_SDK_ROOT -ne $env:ANDROID_HOME) {
    throw 'ANDROID_SDK_ROOT и ANDROID_HOME указывают на разные SDK.'
}
```

Сохраняйте stdout/stderr и код завершения каждой команды. Остановитесь на первом неожиданном отказе; ожидаемый отказ ISCC на некорректном сценарии или отказ проверки версии записывается отдельно от успешного smoke. После `adb emu kill` дождитесь исчезновения своего serial из `adb devices`: отправленная команда ещё не подтверждает завершение процесса. Чужие эмуляторы и общий сервер adb не останавливайте.

## Отмена и отчёт

Порядок удаления установленных средств и восстановления выбранных версий описан в [Quick Start](quick-start-windows.md#обновление-отмена-и-результаты), отмена Linux-настроек/CI — в [Android CI](android-environment-ci.md#actions-ограничения-и-отмена). Возвращайте только изменённые вами значения из исходного снимка. Не восстанавливайте весь PATH поверх более поздних изменений и не удаляйте существующие до проверки инструменты. При намеренной переустановке сохраните также доказательство отсутствия инструмента перед новой установкой и результат восстановления.

Локальный отчёт должен содержать режим проверки (чистая ОС, чистая переустановка инструментов на существующей ОС или повторный запуск), команды/коды, фактические версии, результаты отмены, ограничения и следующий шаг. Непроверенные установки, исключённые инструменты и недоступные платформы указывайте явно. Кеши/сохранённые настройки и существующие компоненты ОС ограничивают вывод о чистоте среды. Данные машины и снимки остаются в `docs/reports/`; общая инструкция и EV не должны содержать локальные пути, сетевые адреса и сведения об учётных записях.

Проверенные команды и общие исправления инструкции фиксируются в [EV-010](../agent/verification/EV-010-environment-reproduction.md), затронутые критерии и передача — в журнале. P01 начинается после принятого результата P00.07; успешная подготовка среды не закрывает DEC-001 и не доказывает пригодность Tauri, Gradle, Bun/OpenAPI или самого приложения.
