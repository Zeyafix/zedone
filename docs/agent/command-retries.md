# Актуальность и повтор команды: текущая граница

Общий механизм P03 используется готовыми командами P04 через HTTP/CLI/IPC:
[доступ](access.md), [пространства](spaces.md), [колонки](columns.md),
[карточки](cards.md), [теги](tags.md) и [очистка](cleanup.md). Напрямую вызывать
низкоуровневый storage или менять SQLite агенту нельзя. Итоговая матрица
контракта P03.06 и границы проверки — [EV-084](verification/EV-084-adapter-acceptance.md).

Договор JSON — [ADR-0031](../architecture/decisions/0031-shared-command-wire-contract.md),
доставка — [ADR-0039](../architecture/decisions/0039-command-adapters-and-delivery.md).
Сохранять следует все `id`, `operation`, `parameters`, включая исходные условия.
`status:ok`/`replayed:true` подтверждает прежнее выполнение, не свежесть данных.
`status:error` с `outcome_unknown` не разрешает автоматически создавать новый ID.
Учётные данные/субъект/права не добавляются в этот JSON. Агентского обхода через
низкоуровневое хранилище или общий конверт со свободными parameters нет.

Для всех клиентов действуют правила ADR-0007/0008/0014:

- При неизвестном исходе сохранять исходные ID, операцию, цели, параметры и
  условия актуальности. Повтор доставки продолжает прежнее намерение.
- Результат повтора подтверждает прежнее выполнение. Он не заменяет актуальную
  карточку или контейнер и не отменяет более поздние правки.
- `stale_state` требует перечитывания и нового явного действия с новым ID.
  Автоматически подставлять новую версию в старое намерение нельзя.
- `command_mismatch` означает изменение запроса уже выполненного ID.
  Исправление не сводится к автоматической генерации другого ID.
- Права нужны при каждом обращении, включая получение прежнего результата.
  Недоступность и `outcome_unknown` не означают отсутствие данных или отказ записи.

Клиент сохраняет весь запрос до отправки, без ключей, и перечисляет pending ID
после restart. Максимум три автоматические попытки: паузы 250/1000 ms, timeout
10 s каждая. Повторяются потеря/некорректность ответа, транспортная ошибка,
unavailable/outcome_unknown. После них — явный повтор исходного запроса.
Отказ доступа/stale/mismatch/invalid/not_found останавливает автоматический цикл;
прежнее намерение сохраняется для выяснения возможного неизвестного исхода.
После подтверждённого успеха pending удаляется. Явное удаление pending не
отменяет уже принятое worker задание. Время и права проверяются и для receipt.

Технический договор — [ADR-0030](../architecture/decisions/0030-command-replay-and-freshness.md),
проверки — [EV-057](verification/EV-057-command-adapters.md).

Pending-намерение также хранит ID исходного субъекта отдельно от JSON-команды.
Одобренный credential provider host возвращает пару субъект/ключ. Смена ключа
того же субъекта допускает повтор, а смена субъекта останавливает доставку с
identity_changed: прежний запрос не отправляется от другого участника. Этот ID
не выдаёт полномочий и не заменяет независимую аутентификацию Rust по ключу.
