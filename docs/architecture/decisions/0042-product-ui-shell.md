# ADR-0042: общая оболочка интерфейса и локальные хосты

Дата: 2026-11-06. Статус: техническое решение P05.01.

`ui/` содержит один Vue/TypeScript-интерфейс для браузера Windows и Tauri APK.
Оболочка предоставляет разделы «Пространства» и «Настройки», адаптивную навигацию,
светлую/тёмную/системную тему и проверку локального доступа. Изменяющие операции,
редактор, поиск и списки предметных данных остаются последующими шагами P05.
Экран оболочки явно сообщает об этой границе; демо-данные не переносятся в продукт.

Расширение P05.02 (EV-066): граница выше описывает исходный P05.01.
Общий интерфейс теперь предоставляет просмотр/создание/переименование/корзину/
восстановление пустых пространств и колонок через существующий общий Service.
Карточки, полный состав контейнеров и их окончательная очистка остаются будущим
шагам. Неизвестные данные и конфликты не обходятся на клиенте.
Список — свежая проекция API, форма фиксирует исходную версию объекта;
receipt подтверждает доставку, после него данные перечитываются.
До отправки сохраняется только исходное намерение через прежний CommandClient
по ADR-0030; эта очередь с параметрами переживает перезапуск, не содержит ключа
и не становится источником прав/состояния объектов. Обновление не меняет старую
команду, после stale требуется новое явное действие. Отдельное подтверждённое
удаление записи очереди не объявляет отмену уже принятого изменения.
На Android Back сначала закрывает форму/меню, затем выходит из доски/настроек.

Проверка доступа выполняет настоящий `space.list` через существующие HTTP/IPC
и `Service`. Ответ валидируется производным operation-specific валидатором.
Каждая явная проверка — новое чтение с новым случайным ID, без сохранения списка
в браузере. Проверка не означает синхронизацию, непрерывную доступность или
сохранение пользовательского ввода. Таймаут ограничивает ожидание десятью секундами;
поздний IPC-ответ не переопределяет новую проверку. После возвращения на экран
проверка обновляется. Поллинг и изменяющие запросы отсутствуют.

Точка сборки — отдельный Cargo workspace `ui/src-tauri`, зависящий от продуктовых
crates по path. Причина границы — платформенное исключение генерируемого JNI
по ADR-0024; в shell действует `deny(unsafe_code)` с единственным исключением
в `entry_point`. Core/storage/adapters сохраняют `forbid(unsafe_code)` и собственную
матрицу product-check. Собственного unsafe/FFI нет; зависимости от прототипов нет.
Windows development host встраивает собранные HTML/JS/CSS, слушает только
`127.0.0.1` на случайном порту и соединяет same-origin UI с тем же HTTP router.
Поставка, трей и единый Windows-процесс остаются P08.

Независимые Cargo workspaces не требуют дублировать физический build output.
Штатные product/UI-драйверы используют корневой target с разделением Cargo по
target triple/profile/features/flags; прототипы сохраняют свой target. Никаких
копирований готовых бинарников в обход Cargo или подмены fingerprint нет.
tauri-build — optional build-dependency за feature android-shell, включаемым
Android build-драйвером; browser host не компилирует ненужный packaging tool.
Прямой Android build без feature отклоняется явно. Это не сокращает тестовую
матрицу: feature проверяется настоящими APK обеих ABI, host — обычными тестами.

Хост открывает одну `zedone.sqlite` штатным Storage startup; он не выдаёт права,
не вызывает bootstrap и не обходит миграционную проверку. В новой установке
прав нет. Пока протокол P06 не реализован, доверенная локальная точка сборки
может прочитать заранее подготовленный `local-session.json` из своего каталога:
строгие subject/key, ограничение 4096 байт, без ключей в URL/аргументах/логах.
Отсутствие файла означает «Доступ не настроен», ошибка файла/базы — недоступность.
Наличие файла не доказывает прав: их повторно проверяет core по предъявленному ключу.
Это внутренний порт доставки ранее выданного секрета, не пользовательский
протокол подключения, не выдача и не ОС-хранилище секретов P06.

`/host/session` и `shell_session` предоставляют ключ только доверенному локальному
интерфейсу в памяти для обычного HTTP/IPC. Windows проверяет точный Host, Origin
и Fetch Metadata; ответы no-store, CORP same-origin, CSP без внешних ресурсов,
запрет frame embedding. Cookies/CORS/remote listener отсутствуют.
Android IPC доступен только встроенному локальному WebView; внешняя навигация
не добавляется. Перезагрузка теряет JS-копию ключа; localStorage её не получает.
ОС-доступ того же пользователя к локальным файлам соответствует модели доверия
разблокированного устройства. Доставка/отзыв/начальное подтверждение — P06.

В исходном P05.01 localStorage содержит только предпочтение темы;
P05.02 добавляет описанную выше очередь намерений. Выбор «Как на устройстве»
удаляет его; недоступность storage не блокирует интерфейс и показывается явно.
Это настройка представления, не копия пространств, прав или результатов.
Навигация использует fragment history и семантические ссылки; модальное меню —
Reka Dialog с trapping/возвратом фокуса и Escape. Android Back сначала закрывает
меню, затем возвращается из настроек, на корневом экране следует платформе.

Визуальное направление опирается на выбранные «Графит», «Шов» и «Минерал»:
тихая боковая навигация, плоская рабочая поверхность, serif только в заголовках.
Утверждённые основы тем `#111514/#84b7a8` и `#e4e8e6/#315b50` сохраняются.
Внешних шрифтов/изображений и фоновой анимации нет. Доступность проверяется
клавиатурой/касаниями, именами, контрастом текста, шириной 360 px и масштабом.

JS и CSS сборки имеют явный target Chrome 101 для штатного AOSP WebView.
Оптимизация не должна заменять max-width на range syntax, отсутствующий в этом
WebView. Выбранная radio-тема оформляется производным классом Vue вместо :has;
для высоты есть 100vh fallback перед 100dvh. Готовый APK проверяется на Device,
адаптивный HTML в новом браузере сам по себе не доказывает совместимость.

Синтетический fixture — отдельный test/example target, не команда приложения.
Он нужен для настоящих HTTP/IPC проверок в изолированном каталоге. Его bootstrap
не переносится в release APK/host. Результаты и ограничения — EV-064.
