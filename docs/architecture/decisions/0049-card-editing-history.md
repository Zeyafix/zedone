# ADR-0049: сессии редактирования и восстановление текстовой версии

Дата: 2026-11-07. Статус: техническое решение P04.08.

Продуктовые границы ADR-0013, актуальность ADR-0007 и безопасный повтор
ADR-0008 сохраняются. Проверки: [EV-073](../../agent/verification/EV-073-card-history.md).

## Общий контракт

Четыре команды card.begin_editing/autosave/finish_editing/restore_text проходят
через тот же Service/core/guard/replay/timed transaction, что card.edit.
Все требуют ReadWrite пространства, активной карточки/родителей, отсутствия
конфликтов и актуальной version всей карточки. Субъект определяется ключом,
время — TransactionClock; клиент не задаёт участника, дату или номер истории.
Тип транспорта и человек/агент не выбирают способ группировки.

begin_editing — явное начало новой сессии с завершением прежней серии карточки.
ID этой команды в 32 lowercase hex становится session. Одновременно действует
одна сессия карточки: новое начало заменяет прежнюю, незаписанный ввод другого
клиента должен сохраняться клиентом после stale_state. До первого сохранения
начало/завершение не создают текстовой версии. Сессия связана с пространством,
карточкой и доверенным субъектом, session не даёт дополнительных прав.

Каждое намерение autosave имеет независимый ID и прежнюю session. Автосохранение
меняет текущий текст и сохраняет последнюю пару серии, но не добавляет видимую
версию на каждую доставку. Новая изменённая пара до 30 секунд продолжает серию
и начинает отсчёт заново. При паузе >=30 секунд старая серия завершается;
новый текст создаёт следующую. Совпадающая пара не продлевает отсчёт.

Граница паузы логическая: без наблюдателя отдельный фоновый таймер/процесс
не нужен. Свежая card.history материализует уже наступившую границу в той же
транзакции перед пагинацией; autosave проверяет её перед продолжением.
Чтение до границы не завершает серию и не меняет её участника/отсчёт.
После границы Read-доступ может материализовать только уже сохранённую пару:
новые текстовые данные/права он не создаёт. Для обновления истории клиенту нужен
новый ID чтения: повтор возвращает прежнюю страницу по обычному receipt.

Действительно изменяющая текст card.edit завершает открытую серию и добавляет
свою отдельную версию. Это даёт этапы «человек → агент → человек» без объединения
через дискретную правку. finish_editing завершает серию и удаляет сессию.
Корзина также завершает серию и удаляет сессию; восстановление из корзины её
не открывает. Изменения выполнения/тегов/места сами по себе не являются
текстовыми версиями; после них старое expected отклоняется.

restore_text принимает text_version из истории выбранной карточки и текущую
card.version. Выбранные заголовок и описание записываются новой дискретной
версией, после завершения прежней серии. История сохраняется целиком;
повтор команды не повторяет восстановление и не отменяет позднейшие правки.
Явное восстановление уже совпадающей пары также добавляет видимую версию,
при этом версия текущих полей карточки может остаться прежней: history
исключена из её причинной проекции. Несуществующая версия даёт not_found.

## Сохранность и жизненный цикл

Завершённые версии остаются в прежней history Map документа Automerge.
Пара в локальной card_editing — журнал незавершённой серии, а не редактируемый
второй экземпляр текущей карточки. Одна строка на карточку содержит субъект,
сессию, ID первого изменяющего autosave, последнюю успешно сохранённую пару
и доверенное время последней правки. ID версии — subject:first-command-id;
локальный sequence выбирается при завершении, без глобального порядка по часам.
Видимая версия после создания не перезаписывается.

Текст, журнал серии, готовая история и receipt фиксируются одной SQLite-
транзакцией. Сбой/отказ не оставляют половину изменения, повтор/чтение/noop
не создают дубликатов. Неправильный expected/конфликт/ключ отклоняется перед
вызовом обработчика; неуспешная операция не становится границей серии.

Доверенный host вызывает Storage::recover_editing_sessions до выдачи Service
при каждом новом запуске приложения. Общий open_shell подключает это для
Windows и APK Android. В одной транзакции оставшиеся пары превращаются в
версии, затем все старые сессии удаляются. Используется сохранённая пара серии,
а не текущий текст: более поздние текущие значения не переписываются.
Повтор после сбоя самой фиксации завершает серию один раз; после неизвестного
commit повторная recovery безопасна. Графы обрабатываются по пространству и
освобождаются внутри транзакции, не удерживая все документы одновременно.

После перезапуска вкладки/клиента перед историей и новым вводом выполняется
новая begin_editing. Сначала следует выяснить исход прежних незавершённых
намерений точным повтором; подтверждение старого autosave не является свежим
состоянием. Уже завершённый begin при повторе не открывает старую сессию.
Подключение этих правил к редактору и событиям вкладки проверяется в P05.
Одноразовая CLI-команда не считается запуском host: Storage::open сам не
закрывает сессии, чтобы чтение/доставка из CLI не прерывали редактор.

Начальная схема v1 расширена по ADR-0047, промежуточных миграций нет.
Синтетический эталон обновлён с сохранением всех прежних строк. Прошлые базы
разработки не мигрируют и не сбрасываются. Локальный lifecycle не переносит
права или сессии в снимок пространства; обмен завершённой истории,
подготовка незавершённой серии к продуктовой копии/экспорту и восстановление
из таких копий проверяются в P06/P07. Публичный API не выполняет SQL.

## Оставшиеся границы

Частота автосохранения, UI редактора/истории и обработка событий вкладки — P05;
синхронизация/конфликты/ветвящаяся история — P06; ручная очистка — P04.09.
Группировка не разрешает независимые текстовые конфликты. Реальный UI,
физический arm64 и итоговые нагрузочные бюджеты не принимаются этим решением.
