# EV-070: теги и назначения карточкам

Дата: 2026-11-07. Шаг: P04.06. Состояние: done в согласованном API-срезе.

## Рабочая карточка

- База: main/ef80c746107a9fdaa61e05f23f6a3b3bb2593ef0, исходное дерево чистое.
- Ветка: feat/p04-06-tags. Зависимость P04.03 интегрирована PR #58;
  P04.04/.05 также в базе (EV-068/069).
- Цель: жизненный цикл тега и его связи с карточкой через общий Rust Service.
- Требования: T07/A20/A30/A32/A39, спецификация §1/§11, ADR-0012/0030/0044.
- Охват: tag.create/read/list/rename/delete, card.set_tag, общее сравнение имён,
  причинные версии/права/replay, атомарное удаление назначений, контракт и docs.
- Обратные действия: назначение/снятие, переименование обратно. Удаление тега
  без отдельного восстановления — согласованное исключение спецификации;
  новый ID с тем же именем не возвращает прежние связи.
- Проверки: Windows `bun scripts/check-product.mjs`, Android
  `bun scripts/check-product.mjs --android` через эмулятор Device, UI-shell
  `bun run ui:check`, полный diff/производные/ссылки.
- Одна граница проверки: идентичность тега, связи и их удаление должны оставаться
  согласованными в одной транзакции. Ориентир 300 строк превышается из-за общего
  контракта, защищённого формата и матрицы сохранности; части без обратных действий
  или с неработающим удалением не публикуются.
- Unicode-политика DEC-005 принята разработчиком: NFC/Unicode case folding,
  Unicode White_Space, исходное написание и различие е/ё; ADR-0046. UI тегов — P05.06;
  автоматическое объединение/продуктовый обмен/решения конфликтов — P06.
- Результат: PR #65, окончательный head bbfec96, merge e6bf604 после семи
  успешных checks Windows/Linux/Android. Исходная ветка удалена; подробности ниже.
- Следующее действие: P04.07 после отдельного поручения; новая реализация не начата.

## Матрица проверки

| Область | Проверка |
| --- | --- |
| Жизненный цикл | Создание/read/list, исходное написание, переименование/обратное, noop, явное назначение/снятие, теги разных пространств |
| Unicode | Кириллица/Unicode-края/е-ё, Café в двух формах, Straße/STRASSE, греческая сигма/ypogegrammeni, й/и+breve; внутренние пробелы/диакритика/турецкие формы/широкая A/zero-width различаются |
| Уникальность | Занятое имя при create/rename отклоняется без изменения ID/связей, свободное Все→Всё допустимо |
| Сохранность | Удаление снимает связи активных/trashed карточек, сохраняя остальные поля/историю/корзину; новый ID не возвращает связи; старый ID занят |
| Актуальность | Версии карточки/тега, stale до noop, назначения→снятие не оживляют старый delete; правка только текста не расширяет область удаления |
| Повторы | Старое назначение после снятия/удаления возвращает исходный receipt, смена параметров/версий даёт mismatch; restart и потерянный ответ |
| Атомарность | create/rename/set_tag/delete на AfterWork/AfterChanges/AfterResult/BeforeCommit/AfterCommit; настоящий SQL abort удаления не снимает часть связей |
| Конкуренция | Два workers: assign/delete допускают одного; независимые разные назначения объединяются, false против true сохраняет конфликт при повторах/перестановке |
| Блокировки | Удаление против позднего назначения блокирует карточку; спорное только имя не блокирует текст, но запрещает назначение/снятие этого тега |
| Права | Read не меняет, чужое пространство недоступно, срок/отзыв блокируют новые команды и replay; карточка/родители в корзине не принимают новые назначения |
| Совместимость | Защищённый v5→v6 сохраняет raw graph/space token/receipt, старый writer не допускается; прежний v4→current тест и исторические crash/migration проверки сохранены |
| Адаптеры | HTTP/IPC/настоящий CLI всех шести команд, undo/replay/restart, malformed/stale/занятое имя и отсутствие restore |
| Клиент | Исходные ID/Unicode-имя/present/обе версии сохранены при stale/restart/потерянном ответе; Rust-derived response validation |

## Пять правил и границы

- Обратимость: назначить/снять, переименовать обратно; удаление тега без restore
  — ровно согласованное исключение, новое создание не возвращает связи.
- Человек/агент: один Rust Service/guard/receipt через HTTP/CLI/IPC.
- Документация: user/agent/development/architecture, ADR-0046, очередь/журнал.
- Паритет: нативные Windows/Android x86_64 проверены, обе Android ABI собраны;
  UI тегов не принят.
- Источник истины: одна SQLite/Automerge, один Rust Unicode-компаратор,
  Rust-derived контракт/TS/валидатор, клиент хранит только намерения доставки.

Полный runtime/tests/docs diff и изменения обоих lock-файлов просмотрены;
существующие версии зависимостей не обновлялись. Генерируемые файлы получены
штатным генератором и проверены побайтово. Проверены 466 относительных целей
Markdown по существованию (без повторной проверки всех якорей исторического
журнала); `git diff --check` passed. Отпечатки затронутых источников обновлены.
Результаты ссылок только docs/reports/p04-06-doc-links.json.

В конце ревью усилена существующая проверка: после снятия уже существующего
назначения token тега отличается также от состояния с назначением, а не только
от состояния до первого назначения. Подготовленный delete с обеими прежними
версиями отклонён. Целевой тест Windows passed; полный Android product-check
повторён с усиленным тестом и passed (те же 225/19/183, обе ABI/unsafe/контракт).

Срез ограничен P04.06. UI P05.06, продуктовый обмен/автообъединение/aliases и
