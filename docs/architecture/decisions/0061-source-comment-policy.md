# ADR-0061: запрещать комментарии в собственных исходниках при сборке

Дата: 2026-11-16. Основание: прямое поручение разработчика удалить комментарии
в отдельной ветке и останавливать сборку при их появлении; уточнение — только
собственные файлы. Статус: принято в рамках этого поручения.

## Решение

Общая проверка `scripts/source-comments.mjs` и одна политика путей используются
Cargo, Vite и Android Gradle. Проверяются файлы на диске, включая новые;
документация, внешние зависимости и сторонние исходники исключены. Исключения
содержат конкретные пути и происхождение, а не разрешённые фрагменты комментариев.
Лицензионные уведомления стороннего кода остаются на месте.

JavaScript/TypeScript, Vue и CSS разбираются закреплёнными парсерами;
PowerShell — штатным токенизатором. Для Rust, Kotlin/Java/Gradle, SQL, XML,
ProGuard и shell используются лексические правила соответствующих синтаксисов.
Распознавание строк и комментариев проверяется отдельными отрицательными и
положительными случаями. Проверка не изменяет исходники при сборке и не имеет
опции обхода.

Cargo использует build script и отслеживаемые входы вместо shell wrapper над
компилятором. Это добавляет Bun, JS dev-зависимости и `pwsh` к требованиям
самостоятельной Rust-сборки. Подготовка CI устанавливает корневые зависимости
для всех host-срезов. В runtime приложения эти зависимости не попадают.

Документирующие комментарии не заменяются атрибутами `doc`. Для сохранения
публикуемого API используются явные метаданные OpenAPI; поля, для которых
utoipa не поддерживает `schema(description)`, получают описания через общий
modifier. Формы типов и ограничения остаются Rust-производными. Проверка
генерации и прежние тесты контракта предотвращают дрейф артефактов.

## Последствия и отмена

Объяснения и эксплуатационные ограничения надо поддерживать в `docs/`.
Новые языки или корни исходников требуют расширения общей политики и тестов.
Вызов отдельного компилятора вне сборки проекта не обеспечивает этот запрет.

Для отмены убрать вызовы общей проверки из build scripts, Vite и Gradle,
затем удалить политику и её проверки. Удалённые тексты доступны в истории Git;
возврат комментариев не меняет данные пользователя или прикладной API.
