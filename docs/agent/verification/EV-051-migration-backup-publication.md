# EV-051: публикация предмиграционного комплекта и перезапуск

Шаг: P07.07.2. База: `cf0fe77`.
Ветка: `feat/p07-07-2-backup-publication`. Состояние: `verified` локально,
без коммита/PR/новых CI/интеграции.

## Карточка

- Цель: связать новый capture с одной транзакцией до commit и безопасно
  опубликовать комплект после проверки результата, сохранив прежний при ошибке.
- Требования: спецификация §1/1.1, T10/A28/A44/M03/M04, DEC-006,
  [ADR-0034](../../architecture/decisions/0034-migration-backup-publication.md),
  ADR-0030/0033. Зависимости P07.07.1/EV-050 и P07.01 доступны в `cf0fe77`.
- Scope: общий capture, доверенная publication-инфраструктура, служебное
  свидетельство в существующем result store без смены схемы, файловая
  блокировка/индекс, явное удаление orphan, тесты и документация.
- Проверки: полные `bun scripts/check-product.mjs` и `--android`:
  Windows, нативный AOSP API33/x86_64, release/unsafe обеих Android ABI.
- Отказы/обратимость: rollback до commit, OutcomeUnknown после его попытки,
  сверка без повторной мутации, очистка только конкретного прежнего каталога
  после подтверждения нового; обратная правка и явное удаление orphan.
- Размер: ориентир 300 строк превышен одной неделимой матрицей сохранности
  SQLite и файлов при ошибках, остановке и перезапуске процесса.

## Матрица

14 новых тестов `migration_backup::publication::tests`:

1. Успешная замена полного комплекта, строго предоперационная база,
   обратная правка и перезапуск не меняют архив.
2. Ошибки в семи точках: неполная копия, готовый capture, до/после commit,
   до/после публикации и перед очисткой. Прежние файлы сохраняются до
   подтверждения нового индекса; сверка идемпотентна.
3. Ошибка обработчика, отказ target validator, отложенный FK-отказ настоящего
   SQLite commit и неверный результат откатывают операцию без замены копии.
4. Ошибка проверки уже зафиксированного результата запрещает новую попытку;
   сверка повторяет проверку/публикацию, не изменение.
5. Настоящая файловая ошибка при замене индекса после commit, устранение
   причины и завершение публикации без повторного выполнения операции.
6. Пропавший/повреждённый committed-кандидат и поддельный индекс не дают
   автоматического fallback; прежние файлы остаются неизменными.
7. Готовый orphan не продвигается; удаляется только явно; попытки удалить
   текущий комплект, путь вне папки или файл блокировки отклоняются.
8. Другой SQLite writer исключён от capture до commit; другой publisher
   не получает файловую блокировку на всех контрольных границах.
9. Отмена ожидания после admission сохраняет подтверждённый результат,
   доступный последующей сверке.
10. Дочерний crash-процесс; без окружения это безопасный пустой тест.
11. Семь дочерних процессов завершаются без деструкторов в точках из п.2;
    родитель открывает SQLite, подтверждает старый/новый результат,
    неизменность прежней копии и двукратную безопасную сверку.
12. Два настоящих worker не выполняют параллельно две операции в одной папке.
13. Повреждение готового кандидата до commit откатывает операцию.
14. Индекс без свидетельства отвергается, потерянный индекс со свидетельством
    строится заново; посторонний orphan остаётся на месте.

Прежние 62 storage-теста, включая 11 тестов capture, сохраняются.
Проверяется схема 1 и синтетическая транзакция; цепочки реальных миграций и
совместимость всех выпущенных схем здесь не принимаются.

## Границы и передача

T10/A28/A44/M03/M04 остаются partial: инфраструктура не является готовой
пользовательской миграцией. P07.07/P07 целиком не закрываются. P07.08 должен
подключить source/target-схемы, startup gating, повтор по правилам спецификации
и целевой validator; при повреждении требуется служебный режим P07.09.
Публичных входов или полномочий на всю базу ещё нет. При восстановлении всей
базы обязательна защита от оживления намерений по ADR-0030.

Файлы sync_all на обеих платформах, каталоги fsync на Unix. Windows-барьер
долговечности каталога std/tempfile не предоставляют: crash-процессы не доказывают
power-loss. Не проверены физический arm64/APK, локальный Linux, произвольные
файловые системы и бюджет всего приложения. Новых зависимостей/unsafe,
изменений SQL/версий/Cargo.lock/OpenAPI/TS/прототипов/CI нет.

## Результат проверки

Оба финальных product-check завершились с кодом 0:

| Проверка | Windows | Android |
| --- | --- | --- |
| Access/contract/storage | 10 + 7 + 76 passed | Те же 93 passed нативно x86_64 |
| Новые тесты публикации | 14 passed, 7 дочерних crash | Те же 14 passed, 7 дочерних crash |
| fmt/Clippy/release host | passed | Общие исходники проверены на host |
| Release всех targets/features | passed | x86_64 + arm64 passed |
| Негативные компиляции unsafe | 4 отказа | 8 отказов обеих ABI |
| Rust/OpenAPI/TypeScript | совпадают, TS compiled | Native OpenAPI совпадает |

Первые целевые компиляции исправили mutability callback в тесте и тип
SQL-параметра, Clippy — вложенный if/лишнюю ссылку. При итоговом просмотре
активное ожидание admission в двух тестах заменено асинхронным oneshot-сигналом;
после этого оба финальных прогона повторены. Runtime после них не менялся.
Локальные логи, условия, SHA-256 и
очистка — `docs/reports/p07-07-2/verification.json`.
Следующее действие — публикация P07.07.2 по поручению. После интеграции проверить
готовность P07.07 целиком и оценить P07.08, не начинать его автоматически.

Пять правил проверяются в границах инфраструктурного среза: удаление orphan и
обратная правка; один будущий core-путь человека/агента без обхода прав;
документация; одинаковые тесты Windows/Android; свидетельство в одной SQLite,
файловый индекс и копии не заменяют авторитетную базу.
