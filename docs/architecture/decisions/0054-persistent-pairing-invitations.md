# ADR-0054: сохраняемые приглашения без выдачи доступа

Дата: 2026-11-14. Техническое решение P06.01.2.1;
[EV-095](../../agent/verification/EV-095-pairing-invitations.md).

## Граница

Первый срез P06.01.2 реализует только административную подготовку приглашения.
Защищённый канал/хранилище host secrets, неподтверждённый запрос устройства,
подтверждение/выдача доступа и отвязка имеют отдельные зависимые шаги.
Приглашение не создаёт subject, ключ доступа, права, peer или выбор пространств.
Нового сетевого входа для неподтверждённых устройств нет. DEC-003 остаётся open.

## Контракт

Общий клиент один раз готовит независимые случайные ID (128 бит) и код
(256 бит CSPRNG, 64 строчные hex-цифры). Код остаётся у создающего приглашение;
сохранить его отдельно до отправки команды обязан вызывающий host. В API
попадают только ID и `SHA-256("zedone/invitation-code/v1\0" || raw_code)`.
`\0` здесь — один нулевой байт; назначение отличается от access-key/v1.
Проверочное значение не работает как Bearer. Отображение/доставка кода,
проверка другой стороны и ограничение попыток будут определены в канале;
само наличие verifier не аутентифицирует устройство или сервер.

Все четыре команды требуют ManageDevices через прежний core guard:

- `invitation.create`: invitation и verifier; ID/verifier никогда не
  переиспользуются, даже после отмены/истечения. Нулевой verifier запрещён.
- `invitation.inspect`: invitation, без кода/verifier в ответе.
- `invitation.cancel`: invitation и expected из свежего просмотра;
  отменяет также истёкшее приглашение. После отмены прежний expected устарел.
  Повторная отмена с актуальным expected безопасна и не меняет версию.
- `invitation.list`: after (null/отсутствие для начала), до 50 записей в
  порядке ID; next — исключительный cursor или null. Включает отменённые и
  истёкшие записи. Все страницы не являются одной общей транзакцией.

Срок фиксирован: десять минут от доверенного времени первой успешной команды
create. Клиент не выбирает часы или срок. На границе `now >= expires` статус
expired; cancelled имеет приоритет. Действует общий точный диапазон времени
ADR-0053. Если срок не помещается в него, создание возвращает unavailable.
Отмена и просмотр не продлевают срок. Для следующего приглашения создаются
новые ID/код; оживление отменённого/истёкшего приглашения запрещено.

## Хранение и повторы

Таблица pairing_invitations в единственной стартовой схеме v1 хранит
ID, уникальный verifier, created_ms, expires_ms и cancelled. Это локальное
состояние установки, вне Automerge и снимков пространства; полная копия базы
сохраняет его как остальные служебные данные. Старые базы разработки
отклоняются без записи/автоматического сброса по ADR-0047.

StateVersion включает ID, verifier, оба времени и флаг отмены. Вычисляемый
статус expired не меняет версию: отмена безопасна и после истечения срока.
Проверка expected, запись приглашения/отмены и receipt находятся в одной
авторизованной транзакции; кодов в командах, receipts и ответах нет.
При повторе возвращается исходный результат, включая тогдашний статус.
Это подтверждение прошлого выполнения, а не текущая пригодность к подключению.
Для свежего просмотра нужен новый command ID. Старый create после отмены
никогда не восстанавливает приглашение; отзыву/истечению прав вызывающего
подчиняется также replay. В будущем запрос устройства обязан заново проверять
состояние/срок под тем же writer lock, а не доверять старому receipt.

Авторитетные данные — SQLite/Service, контракт — Rust; OpenAPI/типы/валидатор
производны. Новых зависимостей, правил прав или механизмов времени нет.
HTTP/CLI/IPC выполняют одни команды на Windows/Android. Полная приёмка
подключения двух устройств и интерфейса этим срезом не заявляется.
