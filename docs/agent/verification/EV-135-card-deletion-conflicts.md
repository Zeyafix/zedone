# EV-135 — удаление отдельной карточки против независимой правки

## Карточка P06.09.1

- База `a5501e1`, ветка `feat/p06-09-deletion-conflicts`.
  Зависимости P06.04 / EV-110 и P05.08 / EV-086. Требование A14,
  спецификация §1.2.4, прототип [EV-036](EV-036-card-trash.md).
- Сохранить данные и исходный ID, показать отдельный конфликт и дать два
  явных решения через общий Service. Возврат из корзины остаётся доступен.
- Принятая модель использует причинную историю прежнего `lifecycle` и
  payload-операций. [ADR-0073](../../architecture/decisions/0073-card-deletion-conflicts.md).
- Проверки охватывают два SQLite-устройства, пять областей правок, оба решения,
  позднюю доставку, права, устаревшие запросы, откат, повтор после перезапуска,
  атомарный запрет очистки. UI проверяет отсутствие предвыбора, отмену, сохранение
  правки и повторное открытие. Парный APK использует отдельный селектор
  `--card-deletion` и прежние бюджеты стенда.

## Наблюдения

- Исходная регрессия воспроизведена на двух продуктовых репликах: карточка с
  независимой правкой ошибочно отображалась как `Trashed`. После изменения
  классификации первый тест прошёл на Windows.
- Новый сценарий Chromium прошёл на desktop/light и touch/dark с настоящим
  HTTP, по одному решению на каждом режиме. Подтверждены отмена, отсутствие
  предвыбора и сохранённый заголовок после перезагрузки. Первая попытка
  прочитала старый бинарник из другого target-каталога, вторая потребовала
  дождаться диалога во время его чтения. Пройденный повтор использовал
  корневой target и ожидание видимого заголовка.
- Windows `--host-tests`: 412 обычных Rust-проверок, из них 310 storage,
  Clippy, 27 клиентских тестов, 8 тестов контракта и точное совпадение
  производных. Поиск 1000 карточек — 16 841 мс при прежнем пороге 30 с.
  Первая попытка остановилась на второй проверке числа API-операций, исправлено
  ожидание до 70 и повторён полный набор.
- Android x86_64 `--android-native`: 409 обычных Rust-проверок, из них
  310 storage, проверка unsafe/comment, контракт Android совпал с Windows.
  Оба парных нативных протокольных прогона прошли. Поиск — 11 960 мс.
- Chromium `--main` и `--conflicts` завершились успешно. Проверка Vue типов
  и production bundle успешны. Отдельный тестовый x86_64 APK и
  instrumentation APK собраны, identity и manifest проверены.
- Первый парный прогон подтвердил оба решения и отказ очистки по TLS.
  В Device подтверждены отсутствие предвыбора, сохранение в корзине,
  обычное восстановление и правки после перезапуска. Стенд прочитал пустой
  маркер между созданием файла и записью `passed`, поэтому общий результат
  этой попытки failed. Исходный APK и файлы приложения восстановлены по
  SHA-256.
- Во второй попытке действия в APK и обмен снова прошли, но Bun вернул пустое
  содержимое из ранее созданного `Bun.file` даже после атомарной публикации
  маркера. Таймаут сохранён как failed, данные и APK восстановлены. На
  каждой итерации стенд теперь заново открывает файл и ждёт непустой результат.
  Отдельная проверка подтвердила отсутствующий, пустой и опубликованный маркер.
- Контрольный `--card-deletion` прошёл на Windows Credential Manager ↔ Android
  APK/Keystore. Подтверждены оба направления независимой правки, оба решения,
  атомарный отказ очистки, повторная доставка и обычное восстановление.
  В Device проверены просмотр, отсутствие предвыбора, выбор корзины, обратное
  восстановление и сохранённый текст после перезапуска за 23 483 мс.
  Итог `passed/restored=true/cleanup=true`. Исходный APK, app files и прежний
  debug APK в рабочем каталоге сверены по SHA-256. Device выключен.

## Смешанные конфликты P06.09.1

Для отдельно удалённой карточки выбор места и назначения через прежние
команды сохраняет причинную группу удаления. Тест на двух SQLite-репликах
прошёл в обоих порядках. Выбор поля первым оставляет конфликт удаления
доступным. Выбор корзины первым оставляет спорные поля доступными, а после
явного выбора карточка остаётся в корзине. Обычное восстановление возвращает
исходный ID с выбранными местом и тегом. Попытка выбрать место у участника
группы удалённой колонки отклоняется без изменения карточки.

Windows `--host-tests` и Android `--android-native` прошли с 312 тестами
storage на каждой платформе, прежними проверками контракта и порогом поиска
30 с. Поиск 1000 карточек занял 11 680 мс на Windows и 12 257 мс на Android.
Chromium `--main` и `--conflicts` прошли, финальный встроенный Vue bundle
дополнительно сверён в host fixture и повторно проверен на desktop/light
и touch/dark. В touch проверено переключение между корзиной и активной
доской. Первая финальная пересборка fixture получила Windows access denied,
пока предыдущий браузерный прогон держал exe. Повтор после его завершения
прошёл с прежними таймаутами. APK x86_64 и проверка манифеста прошли.

Парный `--card-deletion` подтвердил оба решения, а также выбор места и назначения
через TLS/API/CLI на Windows ↔ Android APK с сохранением группы и ID.
В Device выбраны корзина, сохранённое место и назначение. После обычного
восстановления и перезапуска видны выбранная колонка, текст и тег.
Автоматический жест прокрутки не вывел кнопку места в видимую область.
Проверка продолжена через тот же Device-сеанс с явным расстоянием прокрутки
и свежими accessibility snapshots. После успешной проверки перезапуска
стенд завершился с `passed/restored=true/cleanup=true`. Исходный APK, файлы
приложения и локальный debug APK восстановлены по SHA-256. Device выключен.

GAP-040 закрыт, P06.09.1 имеет статус `verified` (LOG-717).
При продолжении работы все 7 целевых тестов `cargo test -p zedone-storage
deletion_conflicts` повторно прошли на Windows.

Конфликты контейнеров, поздние правки после окончательной очистки и полный
T09 входят в P06.09.2–.4. GitHub CI и интеграция не выполнялись.
