# EV-108 — локальный выбор пространств и явная пауза

Дата: 2026-11-16. Рабочая карточка P06.03.1.

## Рабочая карточка

- База: main/caaf6df, отдельная ветка `feat/p06-03-space-sync`.
  Исходные пять dirty документов P06.02 сохранены; их точный baseline —
  ignored `docs/reports/p06-03-baseline/manifest.json`.
- Цель: локальный выбор пространства для конкретного подключения и общая
  явная пауза переживают перезапуск, обратные действия и сбой без изменения
  содержимого пространства или технического прогресса Automerge.
- Требования: T09/A48, §1/§6 спецификации, ADR-0028/0047/0063.
- Зависимости: P06.01 done (EV-104/LOG-568), P04.10 done
  (EV-076/LOG-376); доступны в caaf6df.
- Объём: доверенный storage-примитив, две таблицы начальной схемы v1,
  синтетический эталон схемы, проверки и документация. UI/HTTP/CLI ещё не
  публикуют незавершённые операции; права и передача — следующие срезы.
- Обратимость/отказы: выбор/отключение, пауза/возобновление; отказ устаревшему
  намерению, в том числе после ABA; откат всей транзакции при SQL/commit failure;
  сохранность всех пространств, actor, changes, receipts и peer progress.
- Проверки: `bun scripts/check-product.mjs`,
  `bun scripts/check-product.mjs --android` через Device,
  `git diff --check`; отдельные native тесты описываются по результату.
- Один вопрос проверки: сохраняется ли точное локальное намерение обмена
  атомарно и независимо от содержимого и progress? Объём превышает ориентир
  300 строк из-за неделимой проверки действия/обратного действия/сбоев/перезапуска
  и обязательного доказательства отказа старой стартовой схеме без сброса базы.

## Результат

Реализованы `ReadContext::space_sync_control/sync_selection` и
`WriteContext::set_space_sync_paused/set_sync_selected`. Отсутствующий выбор
выключен; отсутствие явной паузы не означает разрешения передачи.
Пауза общая для пространства, выбор изолирован по pairing request ID.
Отключение и повторное включение сохраняют паузу; reverse не удаляет граф,
историю или progress. Все записи требуют существующее пространство.

Обе настройки проверяют собственную `StateVersion` с revision: устаревшее
намерение отклоняется после изменения и после возврата к исходному bool.
Нет отдельного кэша: чтение и изменение выполняются в текущей SQLite-транзакции.
Перехваченный отказ тоже запрещает commit всей изменяющей транзакции.

Изменяется только текущая стартовая схема по ADR-0047. Эталон SHA-256
`69fec1a276272a6711baaf8c670334a04ca2c958eee6b4e1107167dde109c220` сохраняет
все строки 12 прежних таблиц и добавляет две пустые. Предыдущая база разработки
отклоняется до writable-открытия, её файлы сохраняются побайтово.

Продуктовый dirty source — семь файлов storage (включая тесты/SQL/эталон),
base caaf6dffcf67e3be63532ef730e693924502672f; агрегат SHA-256
`f1da23bdfebf1015518447c674c3640d1b2f0651c43f42ef544023092899e7ee`.
Точный состав, отпечатки требований и raw результаты — ignored
`docs/reports/p06-03-checks/`; машинные пути не публикуются.

## Пять правил и передача

- Обратимость: выбор/отключение и пауза/возобновление сохраняют данные;
  обратный bool не оживляет старое намерение.
- Человек/агент: новых внешних действий ещё нет; существующие общий Service,
  API/CLI/IPC и права не менялись. Открытие новых операций отложено до полного
  безопасного сценария .2/.3; прямой записи агента в SQLite нет.
- Документация: очередь/журнал/EV, developer guidance и ADR-0063 отражают срез.
  Доступное поведение пользователя не изменилось; прежняя инструкция
  [данных разработки](../../user/development-data.md) сохраняет силу.
- Паритет: общий storage проверен на Windows/native Android, обе release ABI и
  guards passed. UI, оптика и настоящий обмен содержимым .1 не затрагиваются;
  arm64 runtime и производительность не заявляются.
- Единый источник: одна SQLite; настройки не дублируют граф/историю/progress
  и не заменяют подтверждённую OS-сессию либо действующие права.
