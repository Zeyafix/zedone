# ADR-0083: побайтовое сохранение проблемного состояния

Дата: 2026-11-28. P07.09.1; §1.1.5/6 спецификации, T10/M05/M06.
Проверки: [EV-163](../../agent/verification/EV-163-problem-state-preservation.md).

## Решение

`Startup::preserve_problem_state` доступен только после завершённого отказа
запуска, когда этот контроллер не выдал Storage. Он не повторяет миграцию,
не открывает SQLite, не восстанавливает базу и не включает обмен.
Новый/работающий/успешный запуск отвергает сохранение.

Сохраняется состояние после завершённого отказа. Предшествующая read-only
проверка SQLite может изменить служебный SHM; crash-тест отдельно проверяет,
что база/WAL/rollback journal при отказе не изменились. Сам захват и его проверка
не меняют ни один из четырёх файлов, включая SHM.

В указанной существующей приватной папке создаётся отдельный случайный каталог.
База, `-wal`, `-shm` и `-journal` копируются как обычные файлы под фиксированными
именами без исходного пути. SQLite Backup API здесь неприменим: повреждение
или hot journal могут требовать записи для открытия SQLite. Каждый исходный
файл должен быть обычным файлом; отсутствие sidecar фиксируется в манифесте,
отсутствие базы — отказ. Каталоги и символические ссылки вместо файлов отвергаются.

Чтение потоковое, с общим явным бюджетом байтов всех четырёх файлов. Содержимое
синхронизируется, SHA-256 и размеры фиксируются в манифесте
`zedone.problem-state` версии 1. Затем повторно проверяются исходные файлы,
включая появление/удаление sidecar, и копия. Изменение источника или ошибка
отвергает публикацию; новый временный каталог очищается best effort. Прежние
комплекты, источник, предмиграционный индекс и ежедневные копии не меняются.
Неуспешное копирование не разрешает аварийную замену базы.

На Unix синхронизируются каталог комплекта и родитель; Windows имеет прежнее
ограничение std на долговечность записи каталога. Процессный crash не доказывает
аппаратный power-loss. Прерванный процесс может оставить незавершённый каталог;
без корректного манифеста/полной проверки он не принимается.

Доверенный вызывающий код обязан владеть жизненным циклом установки и исключать
других писателей. Повторная сверка байтов обнаруживает изменения, но не является
блокировкой. Межпроцессное исключение до разрушительной замены обязательно
реализуется в P07.09.2. Этот порт пока не подключён к пользовательским входам.

## Ожидание, перезапуск и обратная операция

Копирование выполняет отдельный поток; Startup хранит receiver результата.
Отмена async-ожидания не запускает второе копирование и не разрешает retry
миграции одновременно с первым. Следующий вызов с той же папкой и бюджетом
забирает тот же результат; изменённые параметры отвергаются. После получения
результата Failed сохраняется; следующий retry по-прежнему явный. При уничтожении
контроллера уже полностью сохранённый комплект не удаляется.

`ProblemState::open` после перезапуска проверяет тип/версию манифеста, бюджет,
наличие базы и все размеры/хеши. `verify` подтверждает только сохранённые байты,
а не исправность SQLite. `discard` явно удаляет проверенные известные файлы и
каталог; изменение комплекта или посторонние файлы блокируют удаление до
любого удаления. Рекурсивного удаления пользовательского пути нет.

## Границы

`ProblemState` не является `PreparedBackup` и не принимается как исправный
предмиграционный комплект. Схема SQLite, формат ZEDSPACE, receipts и права не
меняются. Полная замена базы, защита старых намерений/ключей при откате ADR-0030,
отдельные полномочия вне повреждённой базы, общий API/UI и служебный режим
приложения остаются P07.09.2–.4. До них M05/M06 не принимаются целиком.
