# ADR-0058: жизненный цикл защищённой сессии устройства

Дата: 2026-11-15. P06.01.2.5.1, EV-101. Продолжает ADR-0055/0057.

## Перенос и восстановление

Один SessionLifecycle владеет host namespace и сериализует весь цикл чтения,
сетевого запроса и записи. Host не запускает второго владельца того же namespace.
Фиксированный connected-pairing-v1 дополняет pending-pairing-v1 на Windows
Credential Manager и Android Keystore. Формат защищённой записи остаётся ZDPN v1:
сохраняются исходные request ID, ключи и pin, без изменения или регенерации.
Наличие этого слота означает только локальную готовность, а не право доступа.

Refresh выполняет peer inspect через прежний pinned TLS с новым внутренним
случайным command ID. Чужой request/invitation/label, неверный subject,
replayed-ответ, ошибка протокола/сети/хранилища не разрешают перенос или очистку.
Для confirmed сначала создаётся постоянная копия без перезаписи, затем читаются
и сравниваются точные байты; только после этого удаляется временная копия.
Проверка удаления также обязательна. Равные записи в двух слотах означают
прерванный перенос: refresh продолжает его. Разные или повреждённые записи
сохраняются без выбора, замены или автоматического исправления.

Потеря подтверждения записи/удаления может вернуть unavailable даже после
изменения OS-store. Следующее чтение и свежий refresh восстанавливают состояние.
Если исход свежего inspect неизвестен, все имеющиеся копии сохраняются.

## Очистка и права

Pending не становится connected по submit, историческому confirm или локальному
состоянию. Cancel/unlink сохраняют исходные ID/expected для точных повторов;
они сами не удаляют слот. Только свежие cancelled/rejected/unlinked разрешают
очистку. При двух копиях сначала удаляется временная. Если очистка прервалась,
оставшаяся копия позволяет повторить свежий inspect. Новое create не заменяет
ни один существующий слот, включая нечитаемый.

Cancelled/rejected/pending поверх постоянного connected считаются противоречивым
ответом; запись сохраняется. Обычный отзыв/ротация приводит к unlinked; права
проверяет прежний access_* при каждом действии, в том числе при replay команды.
Истечение grant не удаляет сессию автоматически. Ключ заимствуется host-кодом,
никогда не выдаётся renderer, JSON-командой или новым endpoint.

Слоты не содержат копии прав; SQLite/Service остаются единственным реестром.
Локальные пространства, история, identity и receipts не меняются при очистке.
Для нового подключения требуются новое приглашение, request ID и ключ.

## Граница приёмки

Это host-компонент. Постоянный listener, композиция API/CLI и подключение
Android PluginHandle к процессу приложения следуют в P06.01.2.5.2/.3.
Новый слот поддержан Kotlin store и закрытым Rust host bridge, но отдельная
проверка Keystore не заменяет полный Rust→Kotlin→TLS app flow.
Формы, Tailscale физических устройств и обмен пространствами остаются отдельно.
