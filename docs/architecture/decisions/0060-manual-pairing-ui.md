# ADR-0060: ручное подключение и управление доступами в оболочке

Дата: 2026-11-15. P06.01.3–.4, EV-103. Продолжает ADR-0053–0059.

## Общая композиция

Controller владеет одним DeviceHost и одним управляемым TLS listener. Windows
shell и Android IPC используют один dispatcher: host.start/stop/status,
offer.create/read и прежние session.*. Старые native start/stop также вызывают
Controller. Политика остаётся в DeviceHost/Service, не в Vue или транспорте.
Авторизация выполняется после ожидания host mutex. Доступ к данным другой
стороны не проксируется через административный renderer.

Web host принимает только собственные Host/Origin/fetch-site, точный JSON
content-type, один Bearer и ограниченное тело. Секретные результаты получают
no-store/CSP/защиту от встраивания как прежняя оболочка. TLS host предоставляет
offer.* тем же административным ключом; CLI --endpoint использует pinned TLS.
CLI --listen и UI host.start вызывают один DeviceHost::start. Закрытие приёма
не отзывает права и не удаляет identity. Автоматический приём после запуска — P08.

## Исходящее приглашение

Отдельный OS-слот outgoing-invitation-v1 содержит исходный составной Offer.
Windows Credential Manager и Android Keystore используют прежние границы
хранения/размеров/AAD; renderer не получает чтения произвольного слота или
постоянного ключа. Схема SQLite не меняется.

Перед публикацией код записывается и перечитывается побайтово. ID приглашения
служит также неизменным ID invitation.create; verifier выводится из сохранённого
кода. После сбоя повтор публикует ровно тот же запрос, не продлевает срок и не
создаёт новый код. Свежее invitation.inspect определяет текущую пригодность.
Результат open позволяет показать код для доверенной передачи; receipts и
очередь команд его не содержат. offer.read не создаёт новый секрет. Явный
offer.create заменяет только подтверждённо терминальное приглашение. Ошибка
чтения/расшифрования не считается отсутствием. Активное приглашение отменяется
общей invitation.cancel; новая генерация не оживляет старое.

## Формы и повтор

Vue хранит только проекцию ответов и ввод. Версии фиксируются свежим inspect
при открытии формы; refresh не подменяет expected. Доступы используют общий
CommandClient и прежнюю очередь намерений. Отказ после возможной потерянной
доставки сохраняет исходное намерение. UI показывает причину, исходный повтор
и отдельное подтверждаемое удаление записи доставки. Удаление записи не отменяет
операцию и не меняет данные.

Session cancel/unlink сохраняют только subject, operation, id и expected;
код/pin/ключ остаются в OS lifecycle. Запись и повтор сериализованы Web Locks,
при недоступном безопасном хранении действие не отправляется. При prepare с
потерянным ответом status обнаруживает существующую попытку; повтор не заменяет
её адрес, имя или ключ. Очистку секрета выполняет только свежий TLS refresh.

Чтение и «До отзыва» — defaults общего компонента формы. Ни пространства, ни
RW, ни administration не выбираются неявно. Выдача/замена агентского доступа
принимает только публичные subject/verifier, подготовленные получателем.
Verifier не является Bearer. Замена всегда требует новый ключ. Полномочия
восстановления базы и bootstrap не добавляются.

## Проверка

Два shell fixtures упражняют настоящий UI/Service/TLS и immutable retry.
Windows использует настоящие OS stores, Linux CI — явно тестовый Memory;
продуктового fallback нет. Native Device проверяет формы APK/Keystore.
Существующий debug-only pairing-acceptance дополнен изолированным UI-каталогом
по случайному маркеру и проверяемой очисткой своих OS-слотов. Bootstrap, маркеры
и тестовые ключи не входят в обычный APK; feature по-прежнему запрещён в release.
QR, обмен, физический arm64 и реальный Tailscale этим решением не принимаются.
