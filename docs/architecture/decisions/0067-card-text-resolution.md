# ADR-0067 — Явное разрешение текста карточки

Статус: P06.05.2 done — PR #104/head 8e6bfe7, merge 4592bb3 после всех 17 SUCCESS в attempt 1 и свежей CLEAN readiness; [EV-112](../../agent/verification/EV-112-card-text-conflicts.md)/LOG-607. Итоговый P06.05/полный T09 отдельно.

## Основание

Допроверка 2026-11-21 выявила BUG-010 в сохранённых вариантах; P06.05.2
возвращён в работу. Исправление и проверка ведутся в P06.13.1/EV-141.

Product-spec §1 требует сохранения независимых текстов, автоматического
объединения разных полей и явного выбора/ручного объединения одного поля.
До решения всех собственных конфликтов обычные изменения карточки запрещены.
ADR-0013 требует пары заголовка/описания одной сохранённой версии истории.

## Решение

`card.resolve_text` принимает итоговые `title`, `description` и актуальный
`expected=card.version`. Команда допустима только при нескольких разных
заголовках либо описаниях. Пользователь явно подтверждает всю текстовую пару:
выбирает варианты полей независимо или вводит объединённый текст. Пустой
заголовок запрещён; пустое описание допустимо и выбирается явно.

Команда проходит прежние ACL/replay/SQLite и `CardStore.edit_card`. В одной
транзакции завершается прежняя серия ввода, записываются регистры title/description,
новая видимая версия с обоими полями и receipt. Существующая история не удаляется.
ID, место, теги, выполнение и lifecycle не меняются. Разрешение текста доступно
и при других конфликтах/удалении и не восстанавливает объекты; обычные операции
остаются заблокированными, если сохраняется другой собственный конфликт.

Разные решения одного конфликта сохраняются новыми вариантами при обмене.
Одинаковые значения дедуплицируются прежней проекцией, технические операции
остаются в Automerge. Неизвестная поздняя правка не исчезает после разрешения.

Уточнение P06.13.1/BUG-010: конфликтующий регистр title/description сначала
удаляется и записывается новым причинным присваиванием в той же транзакции.
Это сохраняет независимый выбор уже видимого победителя scalar-регистра.
Неконфликтующее неизменённое поле не получает дополнительного присваивания;
видимая история по-прежнему содержит одну пару на команду.
Повтор команды заново проверяет доступ и возвращает прежний receipt без записи
поверх поздней правки. Устаревшая версия требует нового явного действия.

Обратный путь — обычная новая правка либо восстановление версии истории после
разрешения собственных конфликтов. Отмена формы не создаёт команду.

## Границы

Новое хранилище вариантов/истории не вводится. Формат `zedone.space.v1`, protocol 1,
SQLite schema 1 и механизм обмена прежние. UI использует тот же API, что HTTP/IPC/CLI.
Прочие разрешения и полная матрица P06.05/T09 проверяются отдельно.
