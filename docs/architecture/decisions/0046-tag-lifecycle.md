# ADR-0046: теги, Unicode-сравнение и назначения

Дата: 2026-11-07. Unicode-правило принято разработчиком в этом поручении.
Реализация P04.06; результаты — [EV-070](../../agent/verification/EV-070-tags.md).

## Сравнение имён

Края имени обрезаются по Unicode White_Space (`str::trim`, закреплённый Rust).
Внутренние пробелы сохраняются. Ключ сравнения — канонический Unicode case
folding с результатом в NFC: NFD → default full case fold → NFC. Предварительное
разложение обеспечивает каноническое сравнение также для греческих букв с
ypogegrammeni. Локаль устройства и специальные турецкие правила не используются.
Сохранённое имя никогда не заменяется ключом: исходное написание, регистр и
краевые пробелы доступны чтению и последующему переименованию.

`Café`/`Café`, `Straße`/`STRASSE` и `Σ`/`ς` имеют равные ключи;
`Все`/`Всё`, `Cafe`/`Café`, внутренние один/два пробела, латинские `A`/`Ａ`
различаются. Совместимостная нормализация NFKC, удаление диакритики и невидимых
непробельных символов не добавляются. Пустое после trim имя отклоняется.
Правило едино для создания, переименования, чтения/сортировки и будущих
продуктовых операций обмена/разрешения имён. Текстовый поиск и сравнение имён
пространств этим решением не определяются.

Используются `icu_casemap` и `icu_normalizer` версии 2.4.0 с compiled_data;
таблицы встроены, I/O и локальная ICU ОС не требуются. Семейство ICU4X 2.4.0
уже было закреплено в Cargo.lock транзитивно. Добавлены только case mapping/data
и его небольшие вспомогательные crates; остальная разрешённая граница core
не расширяется. Обновление таблиц, меняющее равенство имён, требует явной
проверки коллизий и совместимости формата, не обычного незаметного обновления.
Основание алгоритмов: [UAX #15](https://www.unicode.org/reports/tr15/),
[ICU4X CaseMapper](https://docs.rs/icu_casemap/2.4.0/icu_casemap/struct.CaseMapper.html),
[ComposingNormalizer](https://docs.rs/icu_normalizer/2.4.0/icu_normalizer/struct.ComposingNormalizer.html).

## Идентичность и команды

`tag.create/read/list/rename/delete` и `card.set_tag` используют прежние общие
Service, guard и receipt. Тег принадлежит одному пространству; его ID не зависит
от имени. `tag.rename` не объединяет существующие теги, занятое имя отклоняется.
`tag.list` сортирует по ключам имён и затем ID; `include_deleted` открывает
технические отметки удаления, а не корзину. `tag.read` также читает такую отметку.

`card.set_tag` задаёт один ID тега и явный `present: true/false`, исходную версию
карточки и `expected_tag`. Набор остальных тегов не переписывается. Все версии
проверяются до noop; повтор исходной команды возвращает исходный receipt после
проверки текущих прав и никогда не восстанавливает позднее снятый тег.
Переименование/снятие обратно выполняется новой командой с актуальными версиями.

Тег хранится корневым Map `tag:<id>` с `zedone.tag.v1`, `name` и `deleted`.
Связь остаётся в прежней Map `card.tags` как регистр bool. Явный false хранит
причинную историю снятия и конфликт со встречным назначением. Несколько значений
связи блокируют обычные изменения карточки; независимые разные связи объединяются.
Спорное только имя тега блокирует его назначение/снятие, сохраняя редактирование
текста/выполнения/положения карточки и работу с другими тегами (ADR-0012).

## Удаление и сохранность

Удаление проверяет причинную версию тега с историей его назначений. Новая связь
или назначение→снятие делают старое удаление устаревшим. Правка только текста
не расширяет удаление и не меняет эту часть версии. Команда атомарно ставит
false всем известным назначениям, включая карточки в корзине, и deleted=true
тегу. Карточки, текстовая история, выполнение, место и группы корзины сохраняются.
Собственный конфликт затронутой карточки или lifecycle-конфликт колонки
останавливает всю операцию без частичной записи. Удаление против полученного
позже независимого назначения сохраняет конфликт; назначения не теряются молча.

Тег не попадает в корзину и не имеет команды restore — явное исключение
спецификации. Старый ID остаётся занят технической отметкой. Повторное создание
с тем же именем использует новый ID и не возвращает связи. Полный снимок хранит
граф со связями и отметками, а пользовательское восстановление пространства
остаётся P07.03; оно не объявляется реализованным этим срезом.

Причинные токены учитывают присваивания, а не только текущие значения; ABA
не оживляет старые команды. Тег учитывает свои связи и корни имён пространства
для сохранности конфликтов уникальности. Карточка с реальными назначениями
также учитывает корни имён тегов; изменение имени другого тега может потребовать
новое чтение. Это консервативная область актуальности, не отдельный индекс.
Список карточек строит проекцию тегов один раз, а не для каждой карточки.

## Формат и границы

Семантическая схема 6 добавлена с прежним DDL и архивным адаптером. Защищённый
startup требует проверенную предмиграционную копию; графы/actor/peer/receipts
не переписываются. Старый registry не допускает v6. Прежние документы и токены
карточек без тегов сохраняются, старые receipts остаются исходными результатами.

UI тегов добавлен в P05.06: управление пространством и назначения в карточке
используют прежний контракт/версии/очередь намерений. Клиент не сравнивает имена
по собственной Unicode-политике и не хранит отдельный каталог тегов. Подтверждение
удаления объясняет отсутствие корзины/restore; подписи на карточках читаются из
общих snapshot. Проверки и границы — [EV-083](../../agent/verification/EV-083-tags-ui.md).

Автоматическое объединение независимых одинаковых созданий,
aliases, причинная политика исходных написаний и явные решения конфликтов — P06;
модель пробника не подменяет продуктовую приёмку. В этом срезе синтетически
полученные коллизии сохраняются и блокируют операции с тегом. Совместимость
обмена согласуется отдельно до приёма удалённых изменений. Полный масштаб,
физический arm64 и выпуск APK не принимаются.
