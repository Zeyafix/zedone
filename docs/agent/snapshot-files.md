# Снимки пространств: границы текущего среза

P07.01 реализует только внутренний формат и согласованный захват журнала;
публичных команд экспорта/импорта/восстановления ещё нет. Агент не должен
записывать архив напрямую в SQLite или объявлять чтение файла восстановлением.
Будущие команды человека и агента будут использовать одно ядро и свежие права.

Технический договор —
[ADR-0032](../architecture/decisions/0032-space-snapshot-format.md), проверки —
[EV-049](verification/EV-049-space-snapshot-format.md).

- Не изменять исходный файл при проверке, ошибке версии или преобразовании.
  Для преобразования использовать отдельную рабочую копию; эталоны прежних
  версий сохранять, не заменять новым форматом.
- Успешный checksum означает целостность байтов, не доверие к архиву и не права.
  Метаданные даты/пространства не заменяют авторизацию и доверенное время.
- Не переносить права, учётные данные, peer progress, локальный actor для записи
  и receipts из архива пространства. Исторические actor IDs внутри изменений
  нужны графу и не являются разрешениями.
- Перед будущим импортом/восстановлением проверить продуктовую модель, права,
  budgets и условия соответствующего шага. Чтение графа не реализует новые ID,
  страховочный снимок, паузу обмена и причинное восстановление.
- Сохранять защиту ADR-0030 от повторного исполнения старых намерений при
  восстановлении/откате базы; отсутствие receipts в файле не доказывает, что
  команда не была выполнена. Полная предмиграционная копия — отдельный формат.

Команды проверки разработчика —
[product-core](../development/product-core.md#формат-снимка-пространства).
Пользовательского сценария для этого внутреннего среза нет.
