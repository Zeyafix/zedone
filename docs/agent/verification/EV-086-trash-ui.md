## Реализация

`SpacesView` снимает прежнее ограничение пустого контейнера. При открытии
действия свежий snapshot фиксирует исходный expected; состав показывает
активных членов группы и более раннюю корзину с разными подписями.
Group mutation не получает вычисленный клиентом список членов. При неизвестном
contents подтверждение недоступно. Карточка отдельно восстанавливается в
активную колонку своего пространства с исходными expected/expected_column;
частичного восстановления удалённого пространства нет.

`TrashPanel` перечисляет удалённые колонки и карточки, включая карточки
удалённых колонок, без копирования доменных данных в localStorage. Есть
выбранные объекты, вся корзина пространства и сам удалённый root. Вложенный
состав формирует только `trash.inspect`. `TrashScope` показывает literal text,
выполнение/теги/состав и конфликты, не исполняя HTML. Перед purge есть отдельная
отметка необратимости; отмена не создаёт намерение. После отказа корзины
текущие данные перечитываются, исходная форма/намерение не получают новую
версию. После unknown/restart повторяется прежний JSON; старый receipt
никогда не устанавливается как текущее представление.

Общий `prepare`/`CommandClient` сохраняет намерение до отправки; права и
атомарность остаются в прежнем Service. После purge root интерфейс возвращается
к списку пространств. Rust/контракт/DDL/зависимости/CI-бюджеты не менялись.
User/agent/development/ADR-0051 обновлены. Новые независимые цели не добавлены.

## Матрица проверок

Общий `check-ui-trash.mjs` подключён к штатным host desktop/touch и Android CI.
Его доменные данные проходят настоящий Service/SQLite/HTTP или IPC; отдельные
injection cases помечены и не принимают продуктовую синхронизацию:

- Состав перед действием, literal HTML, отмена/Escape/возврат фокуса;
  групповое удаление/восстановление колонки и пространства с сохранением
  более ранних групп/текста/тегов/выполнения/истории.
- Поздняя правка карточки отклоняет column.trash; переименование тега
  отклоняет space.trash; изменение выбранной колонки отклоняет card.restore.
  Ни одного частичного действия; после нового чтения/явного действия успех.
- Отдельное восстановление из удалённой колонки в активную; последующее
  восстановление контейнера и очистка прежней колонки не затрагивают карточку.
  В удалённом пространстве отдельное восстановление запрещено интерфейсом.
- Выбор колонки и её вложенной карточки не дублирует состав; прежняя корзина
  включена. Отмена purge, блокировка до отметки подтверждения, stale после
  восстановления члена, новый явный preview, сохранность активных соседей.
- Валидный контрактный ответ с conflicts блокирует всё подтверждение;
  отсутствующий contents не считается пустотой. Это UI-проверки представления,
  реальное объединение/разрешение конфликтов P06 не заявляется.
- Read access_denied/malformed preview не создают mutation pending;
  реальный write access_denied не повторяется автоматически и не меняет данные.
  Quota не допускает отправку purge. После трёх потерянных ответов сохраняется
  точный JSON; reload/replay не очищает новую корзину и не повторяет старое
  групповое удаление после восстановления агента.
- Whole-space purge явно показывает root и возвращает к общему списку;
  последующее чтение даёт not_found. Просмотр истории/полей через общий API
  подтверждает сохранность объектов вне очищаемого состава.
