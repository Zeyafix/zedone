# ADR-0027: границы продуктового ядра и контракт команд

Дата: 2026-11-05.

Статус: техническое решение P03.01. Продуктовые требования не меняются;
результаты проверки — [EV-044](../../agent/verification/EV-044-product-core-boundaries.md).

## Основания

P01 подтвердил общий Rust-путь для HTTP и Android IPC (ADR-0026).
P02 подтвердил ограниченную модель Automerge/SQLite, но полная загрузка,
построение view и сохранение графа дорожают с ростом данных (EV-043).
Прототипы содержат синтетические входы, собственные тестовые права и
проверочные снимки; их копирование не создаёт продуктового ядра.

## Решение

- Продукт — корневой Cargo workspace; `prototypes/` остаётся независимым
  workspace со своим lock-файлом и не входит в зависимости продукта.
  Существующие закреплённые Serde/utoipa переиспользуются без обновления версий.
- `zedone-core` владеет прикладными правилами и Rust-контрактом. Сейчас
  материализованы только контракт команд, общие ошибки и экспорт схемы.
  `Command` связывает тип запроса, имя операции и тип результата. Он не является
  обработчиком или основанием доступа. Конкретные команды добавляются вместе
  с реализацией; синтетической команды для заполнения API нет.
- В P03.02 отдельный `zedone-storage` будет владеть SQLite и внутренней
  интеграцией Automerge: загрузкой, транзакциями, actor/peer и производными
  представлениями. Порты хранения выделяются в core по фактической потребности;
  storage зависит от core, core не зависит от SQLite/Automerge.
- HTTP/CLI-адаптеры и Tauri-оболочка зависят от core, а точка сборки приложения
  соединяет core и storage. Адаптеры декодируют вход, передают учётные данные
  и кодируют результат; прикладные проверки/права не дублируются в них.
  Конкретный обработчик выбирается из того же Rust-описания команды.
  Пакеты создаются по мере реализации, пустых заглушек storage/адаптеров нет.
- Синхронный rusqlite выполняется в выделенном рабочем контексте вне UI и
  сетевого event loop. Локальная запись последовательна; точная очередь,
  порты, загружаемые документы и транзакции проверяются P03.02.
- Все собственные Rust-targets продукта наследуют `unsafe_code = "forbid"`.
  Общая проверка проверяет наследование каждого пакета и негативную компиляцию
  каждого target, включая попытку ослабления через `allow(unsafe_code)`.
  У зависимостей могут быть внутренние unsafe; их код этот запрет не охватывает.
  Платформенная точка входа должна быть изолирована отдельным обоснованным
  пакетом при её появлении; исключений в продукте P03.01 нет.

## Последствия и границы

Serde-модели и utoipa в core — осознанная зависимость выбранного Rust-контракта,
а не дублирующий DTO-пакет. Общие ошибки не содержат путей, SQL или ключей.
Типизированный результат обработчика не сериализуется как стандартный Rust Result;
транспортное представление и отображение на HTTP/CLI/IPC проверяются P03.05.
Идентификаторы команд, preconditions, область/срок результатов повторов — P03.04;
P03.01 не вводит неподтверждённых форматов и сроков.

Публичный OpenAPI сейчас содержит только схемы ошибок и пустой `paths`.
Это проверяемая начальная граница контракта, а не работающий API.
TypeScript/IPC-генерация и реальные адаптеры — P03.05.

Одна база устройства и один авторитетный набор данных сохраняются. Проекции
восстанавливаются из него, не становятся вторым владельцем данных. Физическое
удаление причинного графа, окончательная гранулярность и формат выпуска
не объявляются решёнными. DEC-002/DEC-009 остаются открыты.

## Рассмотренные варианты

Перенос всего prototype-core сохранил бы синтетические входы и полный view/save
в горячем пути. Единый пакет с Axum/Tauri/SQL смешал бы платформу и правила;
отдельный пакет для каждого будущего модуля создал бы пустые абстракции.
Выбраны один минимальный пакет сейчас и направленные зависимости при расширении.
