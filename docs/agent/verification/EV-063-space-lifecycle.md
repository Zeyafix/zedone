Модель и точные границы — [ADR-0041](../../architecture/decisions/0041-space-lifecycle.md).
Ориентир 300 ручных строк превышен из-за одного неделимого жизненного цикла:
создание должно сразу иметь обратимое удаление/восстановление, атомарный доступ
создателю и одинаковые безопасные повторы/отказы через все входы. Независимая
подготовка модели прав уже вынесена и интегрирована отдельным PR #49.

## План матрицы

- Любой действующий субъект создаёт объект с точным RW; readonly на прежнем
  пространстве и admin не расширяют чужие данные; срок/отзыв сохраняются.
- Список ограничен текущими правами, включает корзину только явно; сортировка
  по именам/ID, конфликты имён первыми и без дублирования объекта.
- Переименование и обратная правка, корзина/восстановление, повтор после поздних
  правок/восстановления и снятия прав, mismatch, restart, конкурентные writers.
- Причинная версия: изменение с возвратом имени/состава, удалённые вложенные
  объекты, исключение технической history/чтения/receipts/peers/другого пространства.
- Реальные SQL-отказы/контрольные точки до и после commit; отсутствие объекта
  без прав, прав без объекта или потерянного журнала/receipt.
- Конкретные Rust decoder/handlers и операция ответа в клиенте; одинаковые
  HTTP/IPC/настоящий CLI на Windows и нативном Android, обе ABI/unsafe/контракт.

## Итоговая локальная проверка

Окончательные Windows `bun scripts/check-product.mjs` и Android
`bun scripts/check-product.mjs --android` — **passed**: по 164 Rust-теста
(12 core access, 7 contract, 134 storage, 11 adapters), 14 клиентских/97 assertions,
fmt/Clippy/release Windows, release обеих Android ABI с Tauri bridge,
21 независимый отказ unsafe, Rust/OpenAPI/TS/standalone validators и consumers.
Это 13 новых Rust-тестов и два клиентских относительно EV-062; прежняя
матрица также пройдена. Изменения runtime после окончательных прогонов не вносились.

Эмулятор открыт и остановлен средствами Device, нативные процессы/реальный CLI
запущены штатным драйвером. Sandbox удалён в finally. UI/APK/WebView/физический
arm64 и новая сетевая синхронизация не проверялись этим срезом.
Логи/хеши/сведения машины — только `docs/reports/p04-01/verification-spaces.json`,
`spaces-final-windows.log`, `spaces-final-android.log`.

## Приёмка неделимого P04.01

| Результат | Доказательство |
| --- | --- |
| Создание с точным RW | readonly-субъект создаёт новое пространство, прежний readonly сохраняется; admin сохраняет администрацию, чужие пространства закрыты; коллизия ID не присваивает доступ |
| Чтение/список | Точные текущие права, варианты имени, один объект при конфликте, порядок имён/ID и корзина по явному include_trashed; повтор старого списка после снятия права отклонён |
| Переименование | Unicode сохраняется, обратная правка новой командой; исходная версия не оживает после возврата имени |
| Корзина/восстановление | Логическое удаление, сохранённые actor/журнал/права/идентичность, разные группы удалений; повтор старого удаления/восстановления сохраняет более позднее обратное действие |
| Повторы/конкуренция | Один эффект двух workers, исходный receipt/ответ, отказ mismatch и stale без новой версии/группы; restart/потеря ответа клиента не создают второй объект/право |
| Причинная актуальность | Удалённые вложенные данные/состав меняют версию даже при прежнем пустом состоянии; history/чтение/receipt/peer/другое пространство не меняют её; порядок доставки не влияет |
| Атомарный отказ | Реальный SQL abort receipt, отказы до/после flush/перед commit, неизвестный исход после commit; не остаются пространство без прав, права без пространства или частичная правка |
| Срок/отзыв | Истечение после работы и перед финальным commit откатывает пространство и RW; реальный отзыв запрещает повтор через HTTP/IPC/CLI; повтор создания не возвращает позднее снятые права |
| Общий API/контракт | Все шесть операций через единый Service/core, реальный CLI и IPC/HTTP; строгий decoder отвергает подмену субъекта/прав/операции/ID и дубли полей; неверный UTF-8 HTTP path возвращает общий JSON-отказ; клиент не принимает ответ другой операции |

Итоговая локальная проверка родителя P04.01 пройдена в согласованном объёме
пустого пространства. До финальных CI/интеграции P04.01.2 и родитель имеют
`verified`, а не `done`. Текущие факты публикации — Git/GitHub и
`docs/reports/p04-01/publication-spaces.json`.

## Пять правил

- Обратимость: переименование обратно и корзина/восстановление проверены;
  повтор сохраняет позднее обратное действие и прежние группы.
- Человек и агент: одни guard/handlers/Service, одинаковые HTTP/IPC/настоящий CLI;
  пользовательский UI P05 пока отсутствует и не объявляется принятым.
- Документация: инструкции пользователя/агента/разработчика, архитектура,
  ADR-0041, очередь, журнал и EV обновлены.
- Паритет: одинаковые 164 нативных Rust-теста Windows/Android x86_64,
  обе ABI release с Tauri bridge; UI/APK/WebView/физический arm64 вне охвата.
- Источник истины: одна SQLite/Automerge для данных/истории/прав/receipt;
  контракт/операции/параметры/validators выведены из Rust, pending — только доставка.

T07/A01/A05/A08/A56 получают только ограниченные доказательства этого среза;
полный T06/P03, P04, P05/P06 и A56 контейнера с содержимым не закрываются.
Бюджеты роста/памяти всего приложения и служебный откат базы остаются прежними
DEC-009/P07.09. За пределы порученного P04.01 работа не расширяется.
