## Продолжение P06.02.3 — LOG-578

2026-11-16 повторно проверена доступность среды: Device показывает только
выключенный Android 13/AOSP x86_64, `adb devices -l` не показывает подключённых
устройств. В SDK установлен только образ API 33/default без GMS. Подтверждён
прежний source SHA-256 `3af77b3820e1e1f581fa69abaf074e72306fe4873afdd261abd15c8c409497dd`;
отпечатки двух текущих APK сохранены в ignored
`docs/reports/p06-02-optical/preparation.json`. Это подготовка, не новая
runtime-проверка и не доказательство оптического чтения. GAP-030 остаётся open.
Разработчику задан вопрос о подключении Android с GMS; ответа на момент записи нет.

Сценарий после появления устройства:

1. Найти его через Device и получить свежую команду `device_open`.
   Проверить ABI/GMS и исходную установку. До установки тестового APK сохранить
   исходный APK и manifest SHA-256 всех app files; использовать отдельный fixture
   и отдельный namespace OS-ключей. Старые локальные helpers с зашитым
   `emulator-5554` не запускать на телефоне без адаптации к обнаруженному устройству.
2. На Windows создать свежее приглашение через прежний host/UI и показать SVG.
   При действующем разрешении камеры прочитать QR именно нативным сканером APK.
   Сравнить точные address/offer через read-only проверку, не публикуя секрет.
   Проверить сохранение названия и отсутствие session.prepare/submit/доступа
   до явного действия пользователя. Повторить успешное чтение после отмены.
3. Отправить запрос из заполненной формы. На телефоне проверить pending без
   доступа, на Windows — ID запроса и отсутствие grant. Явно выбрать пространство
   и подтвердить default read-only, затем проверить состояние/разрешённое чтение/
   отказ записи через прежний общий API.
4. Выполнить отвязку и повторное подключение с новым приглашением; отдельно
   проверить отказ на Windows и отмену незавершённого запроса на телефоне.
   Сканирование прежнего использованного/отменённого QR не должно обходить
   серверный отказ или менять локальные пространства/историю.
5. Проверить повтор сканирования после доступности распознавания. Успех чтения
   подтверждает готовность модели в этот момент, но не доказывает холодную
   первую загрузку. Не очищать данные GMS ради искусственного холодного состояния;
   невоспроизведённый случай сохранить ограничением.
6. Очистить только свои ключи/transport rules/fixtures, восстановить исходный APK
   и все app files, сравнить SHA-256. Сохранить фактические результаты оптики,
   прав/обратимости/сохранности и отдельный охват arm64/Tailscale. Только после
   полного результата пересмотреть GAP-030 и состояние P06.02.3/P06.02.

Разработчик явно возобновил работу после переподключения. Device обнаружил
физический Galaxy A32/Android 13, ABI arm64-v8a, установленный GMS. Свежая
