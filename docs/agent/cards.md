# Карточки через общий API

Карточка принадлежит пространству и колонке. Используйте общие
HTTP/CLI/IPC, как у [колонок](columns.md); прямые записи в SQLite не являются API.
Rust — источник `api/openapi.json`, TypeScript и валидаторов ответов.

| Операция | Параметры | Доступ пространства |
| --- | --- | --- |
| `card.create` | space, card, column, title, description | ReadWrite |
| `card.read` | space, card | Read/ReadWrite |
| `card.history` | space, card, after, limit, expected | Read/ReadWrite |
| `card.list` | space, include_trashed | Read/ReadWrite |
| `card.edit` | space, card, title, description, expected | ReadWrite |
| `card.set_completed` | space, card, completed, expected | ReadWrite |
| `card.trash` | space, card, expected | ReadWrite |
| `card.restore` | space, card, expected | ReadWrite |

Создайте `card` через `newCardId()` и сохраните вместе с точным намерением:

```ts
const card = newCardId();
const pending = await prepare(subject, "card.create", {
  space, column, card, title: "Прочитать книгу", description: "",
}, store);
await client.deliver(pending);
```

ID команды независим от ID карточки. Изменения требуют активных родителей.
Заголовок не может быть пустым или состоять только из Unicode whitespace;
описание может быть пустым. Текст сохраняется точно. edit задаёт оба поля
одной дискретной правкой; он не является автосохранением непрерывного ввода.
Карточка добавляется в конец колонки, корзина/восстановление сохраняют место.

CardSnapshot содержит space/card, titles/descriptions/columns/positions/completed
со всеми различными вариантами, tags, state, deletion_groups и version.
CardList содержит cards; include_trashed обязателен. Спорные карточки
остаются в списке, обычные изменения блокируются. card.history содержит пары
title/description с id, subject и локальным sequence; sequence не определяет
порядок независимых правок на разных устройствах. Начальная пара сохраняется
при создании, каждая отдельная правка — новой версией; чтение/повтор/отказ
или правка неизменившихся данных не создают версию. Историю можно вернуть
новой edit с выбранной парой и актуальной version без удаления прежних версий.

История читается страницами: первый запрос задаёт after=null, expected=null
и limit от 1 до 100. Ответ содержит versions, next и собственную version истории,
а также space/card. Для следующей страницы передайте next в after и эту version
в expected; если next=null, чтение закончено. При изменении истории между
страницами получаете stale_state — начните чтение заново новым намерением.
Не передавайте version истории вместо version карточки при редактировании.
Снимки карточек и результаты их изменений не содержат копии всей истории.

Для expected используйте version самой карточки. Изменение текста, тегов,
выполнения, колонки, порядка или корзины делает старое действие устаревшим,
даже после возврата прежнего значения. stale_state требует перечитать карточку
и подготовить новую команду. Ввод сохраняют отдельно от результата команды;
нельзя подменять expected и автоматически отправлять старую правку.
conflict требует разрешения, которое остаётся отдельным шагом P06.

`card.set_completed` явно задаёт `completed: true` или `completed: false`.
Обе операции требуют активной карточки и родителей. Колонка не определяет
выполнение: команда не меняет принадлежность, порядок, текст, теги и историю.
То же значение с актуальной version — успешный noop без новой версии карточки;
устаревшая version отклоняется даже при совпадении требуемого значения.
После изменения описания старая отметка выполнено получает `stale_state`.
Корзина/восстановление сохраняют выполнение. Для снятия отметки прочитайте
актуальную карточку и подготовьте новое намерение:

```ts
const pending = await prepare(subject, "card.set_completed", {
  space, card, completed: false, expected: snapshot.version,
}, store);
await client.deliver(pending);
```

При неизвестном результате повторите исходное сохранённое намерение с тем же
ID, параметрами и expected. Receipt подтверждает прежнее выполнение и не
является свежим состоянием для замены view. Для нового read/list нужен новый
ID. После отзыва или истечения доступа повтор также запрещён.
Ключ не сохраняется в намерении, не передаётся как параметр команды и не логируется.

UI редактора, теги/перемещения, серии истории и групповая корзина
контейнеров остаются последующими шагами. Наличие карточек, в том числе в корзине,
блокирует текущую корзину/восстановление колонки. Архитектура —
[ADR-0044](../architecture/decisions/0044-card-lifecycle.md).
