# Пространства через общий API

Жизненный цикл колонок внутри пространства описан в [отдельной инструкции](columns.md).

P04.01 предоставляет шесть операций через одни Rust handlers/guard/replay/Storage.
Авторитетный контракт — `api/openapi.json`; типы и runtime validator — его
производные `api/schema.d.ts` и `api/validate-response.*`. Агент не пишет SQL
и не вызывает доверенные storage callbacks вместо общего API.

| Операция | Параметры | Требование |
| --- | --- | --- |
| `space.create` | `space`, `name` | Любой действующий доступ; ID отсутствует |
| `space.read` | `space` | Точный Read/ReadWrite |
| `space.list` | `include_trashed` | Действующий доступ; только разрешённые пространства |
| `space.rename` | `space`, `name`, `expected` | ReadWrite, активное пространство без конфликта |
| `space.trash` | `space`, `expected` | ReadWrite, активное пустое пространство без конфликта |
| `space.restore` | `space`, `expected` | ReadWrite, пустое пространство в корзине без конфликта |

`space` — новый случайный ненулевой 128-битный ID в 32 lowercase hex.
Генерировать его один раз и сохранять в намерении создания. ID команды —
отдельные 16 случайных байтов. Имена сохраняются точно, включая Unicode,
пробелы и пустую строку; равные имена не объединяют разные объекты.
`expected` берётся из `version` последнего чтения, не из часов или счётчика.

Конверт/ключ описаны в [инструкции доступа](access.md). HTTP:
POST `/v1/commands/<operation>`, исходный JSON и Bearer отдельно. CLI:
`zedone --database <existing-db> --key-file <private-key-file> --operation <operation>`;
JSON на stdin, результат на stdout. IPC: `zedone_command` с invocation/request
и отдельно credential. Установка должна пройти защищённый startup; путь к базе
не выдаёт полномочий. Не передавать субъект/права/Clock в параметрах команды.

Создание коммитит объект, журнал, точный RW создателю и receipt вместе.
Прежнее администрирование/пространства/ключ/срок сохраняются. Совпадение
существующего ID даёт stale_state без присвоения доступа и раскрытия данных.

## Чтение и обратные действия

SpaceSnapshot содержит `space`, все различные `names`, состояние
`active`/`trashed`/`conflicted`, `deletion_groups`, `empty`, `version`.
Список возвращает `spaces`. `include_trashed=false` исключает корзину,
`true` включает её. Спорное состояние не скрывается как окончательно удалённое.
Конфликтующие имена идут первыми по ID; остальные — по Unicode lowercase,
исходному имени и ID. Администратор без точного доступа видит пустой список.

Актуальное read/list требует нового намерения: повтор возвращает исходное
чтение. Если хотя бы одна цель сохранённого списка больше не разрешена,
повтор даёт access_denied без старых закрытых данных. Повтор создания при
действующем разрешении возвращает исходный собственный результат, но не выдаёт
снятый позже RW заново и не читает поздние правки.

Обратное переименование — новая команда с актуальной версией. Корзина
сохраняет объект/actor/историю/права; восстановление — новое действие по версии
в корзине. Повтор старого удаления после восстановления не удаляет ещё раз
и не создаёт группу; повтор старого восстановления не отменяет позднее удаление.
Иной запрос выполненного ID даёт command_mismatch. При неизвестном исходе
сохранить весь исходный запрос, включая ID и expected.

stale_state требует нового чтения и явного действия без автоматической замены
версии. conflict означает нерешённое имя/состояние; обычная правка не выбирает
вариант, отдельное разрешение относится к P06. Непустое/неизвестное содержимое
блокирует корзину/восстановление этого среза; частичного удаления/ложного успеха нет.

## Клиент

`newSpaceId()` и `prepare(subject, "space.create", {space, name}, store)`
сохраняют намерение до отправки. CommandClient после ошибки/restart доставляет
тот же ID. Одобренный ключ/субъект доставки берутся из host credential provider;
pending хранит только доставку, не данные пространства или полномочия.
Операции/параметры/результаты/validators выведены из Rust/OpenAPI; ответ другой
операции не подтверждает намерение. UI остаётся P05, содержимое — следующим P04.
