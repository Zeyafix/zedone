# Работа с исходниками без комментариев

Перед изменениями прочитать [правило для разработчиков](../development/source-comments.md).
В собственный код не добавлять обычные комментарии, doc-комментарии или
комментарии-директивы подавления ошибок. Обоснования и инструкции помещать в
соответствующий раздел `docs/`; описания API — в явные метаданные контракта.

Проверить `bun run check:comments` и штатную сборку затронутого среза.
При изменении самой проверки выполнить `bun run test:comments` и подтвердить
отказ соответствующей сборки на временном комментарии, затем её восстановление
после удаления комментария. Файлы чужих изменений не использовать для проб.

Сторонние исходники и лицензии сохранять. Новый сторонний файл можно исключить
только с явным происхождением в политике; нельзя исключать собственный файл,
чтобы обойти запрет. Сгенерированные из нашего контракта TypeScript-файлы
обновляются через генератор. Если комментарий уже попал в артефакт, сначала
удалить только комментарий, не меняя типы, затем повторить генерацию и проверки:
общая проверка останавливает и Cargo-компиляцию генератора. Продуктовые действия человека и агента, их API
и данные эта политика не меняет.
