# EV-055: постоянные права и аутентификация

## Карточка P03.05.2

- База: `eb05e1a`, чистое дерево; ветка `feat/p03-05-2-persistent-access`.
- Цель: аутентификация и актуальные разрешения из одной SQLite-транзакции
  с операцией, устойчивые к перезапуску, замене и отзыву доступа.
- Требования: T06/A08, спецификация §5/§10, ADR-0010/0016/0029/0030.
- Зависимости: P03.05.1 (PR #40, merge `50fe374`); P07.08 (PR #45,
  head `931cce2`, merge `eb05e1a`, три финальных CI SUCCESS; ветка удалена).
- Scope: неизменяемая схема v2 и переход v1→v2 с предмиграционной копией;
  внутренний источник AccessTransaction/ReplayTransaction, однократный bootstrap,
  выдача/замена/отзыв, проверки и документация. Публичные адаптеры, доверенные
  часы, подключение устройств и аварийное восстановление остаются будущим шагам.
- Проверки: `bun scripts/check-product.mjs`, `bun scripts/check-product.mjs --android`;
  реальные credential/grant, admin/data isolation, expiry/denial, restart/replay,
  конкурирующие writers, ошибки/rollback, исходный эталон v1 и архивы.
- Обратимость: смена прав в обе стороны; отзыв с явной новой выдачей и новым
  секретом, старый ключ не оживает. Bootstrap не повторяется после отзыва.
- Превышение ориентира 300 строк обусловлено одной границей безопасности:
  схема/миграция, проверка перед receipt/операцией и атомарный отзыв должны
  проверяться совместно. Независимые часы и сетевые входы исключены.
- Результат: `verified` локально; финальные Windows/Android-проверки passed.

## Результат

Реализован [ADR-0037](../../architecture/decisions/0037-persistent-access.md):
схема v2, защищённый переход v1→v2, системный случайный ключ и отдельный субъект,
хеши текущих/старых ключей в SQLite, однократный bootstrap, административно
защищённые выдача/замена/отзыв/просмотр. `WriteContext` реализует оба порта core;
проверка прав, данные и receipt сериализуются одной writer-транзакцией.

Десять новых storage-тестов проверяют:

- Bootstrap только один раз, изоляцию admin/data, передачу администрирования,
  отказ удалению/понижению последнего администратора и сохранность при restart.
- Настоящие ключи, точные пространства, Read/ReadWrite, неправильные данные,
  исключительную границу срока и отказ при недоступных часах.
- Новую выдачу/изменение в обе стороны с тем же субъектом; невозможность
  повторно использовать любой прежний ключ или перезаписать субъекта выдачей.
- Отзыв перед receipt lookup; после новой выдачи прежний результат возвращается
  в той же области субъекта без повторной правки и отмены более новых данных.
- Другой writer не меняет права внутри операции; ожидающее обращение и другой
  worker видят уже отозванный доступ. Сохранённых разрешений соединения нет.
- SQL-отказ на втором пространстве не оставляет частичного разрешения/данных,
  даже если callback перехватил ошибку; ошибка до commit откатывает отзыв
  и частичный bootstrap. Пустые/неверные области и сроки отклоняются.
- Повреждённый маркер останавливает read-only preflight с сохранением базы.
- Продуктовый переход с независимого эталона v1 сохраняет actor/receipt;
  создаёт проверенную полную историческую копию и не выдаёт права. Без настроек
  копий миграция отказывает без изменения исходника; restart проходит сверку.
- Побайтовая неизменность снимка пространства при отзыве; полная копия содержит
  отзыв и неактивные ключи. Секреты отсутствуют в SQLite/графе/receipts.

Обе финальные команды завершились с кодом 0:

```powershell
bun scripts/check-product.mjs
bun scripts/check-product.mjs --android
```

Windows: fmt/Clippy всех targets/features, 10 core access + 7 contract +
110 storage tests (127 всего), release всех targets/features, четыре отказа
unsafe. Android: те же 127 тестов нативно в AOSP API33/x86_64, release всех
targets/features x86_64/arm64, восемь отказов unsafe. Rust/OpenAPI/TypeScript
совпадают, TS compile passed. Прежние crash/restart/отказы миграции сохранены.
После этих прогонов runtime/тесты не менялись. Логи, условия, SHA-256 и очистка
собственного read-only эмулятора — `docs/reports/p03-05-2/verification.json`.

В первых прогонах исправлены тип SQLite timestamp, обращение теста к private
helper, исторические тесты с обязательной настройкой копий и непредставимый
на Windows наносекундный тест. Новое прошлое время отклоняется; тест точности
использует представимую микросекунду поверх будущей даты. Clippy исправлен до
финальных прогонов. Это не зарегистрированные регрессии принятой реализации.

T06/A08 и миграционные критерии остаются `partial`: Clock при откате/перезапуске,
реальные UI/HTTP/CLI/IPC, подтверждения/доставка/хранение ключа клиентом,
подключение устройств и аварийное восстановление ещё не реализованы. Не приняты
физический arm64, APK/WebView, локальный Linux, power-loss/долговечность каталога
Windows, бюджеты всего приложения и официально выпущенная историческая линейка.
Административные права не расширяются на обслуживание всей базы.

Пять правил: обратные смена/отзыв/новая выдача и передача последнего admin;
один guard/worker будущих входов человека и агента; актуальные docs/ADR;
одинаковые нативные тесты Windows/Android с обеими ABI; одна SQLite для прав,
данных и receipts, без прав в графе/снимке пространства. Пользовательских входов
в этом срезе нет; их паритет ещё не принят.
