# ADR-0078: восстановление существующего пространства как новое действие

Дата: 2026-11-25. Статус: реализация P07.03; проверки и границы —
[EV-152](../../agent/verification/EV-152-existing-space-recovery.md).

## Общая операция

Человек и агент используют `space.recovery.inspect`, `space.recovery.restore`,
`space.recovery.read_backup` и `space.recovery.pause` через один core handler,
HTTP/CLI/IPC и производный Rust-контракт. Серверные пути не принимаются.
Inspect/read_backup требуют Read, restore/pause — ReadWrite существующего
пространства. Свежие полномочия и сроки проверяются до работы и после неё,
включая replay. Read-only администрирование не выдаёт права на данные.

Restore принимает полный ZEDSPACE, ID исходного пространства и исходный
StateVersion из inspect. Он включает hashes всех changes (также ожидающих
зависимости), текущую серию редактирования, паузу и ссылку на последний
страховочный снимок. Старое условие не обновляется автоматически.
Архив должен совпадать по ID и общей исходной истории с существующим графом;
проверяются все применённые операции известной модели и их ссылки. Orphans
не отбрасываются. Технический бюджет архива — прежние 1 MiB/10000 changes;
новые операции также ограничены. Это не предел размера пространства.

Рабочий журнал не заменяется старым. В прежних объектах создаются новые
присваивания/удаления, конфликтующие скаляры возвращаются конкурентными ветвями.
Неизменившиеся поля не получают лишнего присваивания. Объекты, известные только
после снимка, скрываются обычным purge/deleted; raw changes остаются. История
возвращается с прежними авторами, парами текста и sequence, но новыми техническими
IDs записей: независимые восстановления и поздняя фиксация серии не создают
коллизий структурных map-объектов. ID пространства, колонок, карточек и тегов
сохраняются. Другие пространства, права, ключи, peer progress и receipts не
откатываются; существующие серии редактирования этого пространства закрываются.
Повтор старого выполненного намерения возвращает прежний результат без мутации.

## Причинные конфликты

Конфликт удаления против правки может быть производным от истории, даже при
одном текущем lifecycle. Простое копирование значений теряет такой конфликт.
Необязательный bool `restored_conflict` в соответствующем объекте сохраняет его
как часть нового действия. Он действует, пока новое явное изменение lifecycle
(для тега — deleted) не наблюдает эту отметку. Обычное разрешение конфликта
снимает её тем же причинным правилом, без отдельной команды или вторичного
состояния в SQL/UI. Нормальные независимые изменения продолжают проверяться
прежними алгоритмами; отметка не заменяет их.

Поздний тег-алиас, которого не было в снимке, помечается `retired_by_restore`
и скрывается отдельной удалённой группой. Он не меняет представителя восстановленной
группы. Независимое позднее назначение снова участвует в обычной проверке
конфликта удаления и не отбрасывается. Восстановленные семантические варианты
назначений проверяются по тому же каталогу. Обе отметки — известные bool-поля
продуктового графа, учитываемые экспортом/импортом/обменом и версиями состояния.
SQLite-layout и контейнер не меняются; политика начальной схемы ADR-0047 прежняя.
Неизвестная модель старым бинарным файлом не принимается как поддержанная.

## Страховочный снимок и commit

До мутации, под непрерывным BEGIN IMMEDIATE создаётся и повторно проверяется
новый полный страховочный файл из ADR-0077. Папка по умолчанию принадлежит
установке и находится рядом с базой (`имя-базы.backups`); не создаётся повторно
при пропаже уже действующей папки. Выбор/перенос папки остаётся P07.05.
Недоступность папки не допускает fallback и восстановления без снимка.

Граф, постоянная пауза обоих направлений, receipt и служебный witness
фиксируются одной SQLite-транзакцией. Witness хранится под отдельным внутренним
ключом прежнего command_results и содержит строго проверяемые basename,
пространство/дату, длину/SHA-256 текущего и прежнего файла. Пользовательские
receipts не перезаписываются. Witness — авторитетная ссылка на последний
успешный снимок; файлового индекса с независимой истиной нет.

Только committed-witness разрешает очистку прежнего снимка после проверки нового.
Очистка сериализована SQLite writer lock; она удаляет только известный space.bin
и затем пустой собственный каталог. Посторонние файлы, ссылки и другие
пространства не удаляются. Ошибка очистки оставляет cleanup_pending; успех
восстановления не превращается в ложный откат. Повтор очистки не повторяет
восстановление. Перед следующим restore незавершённая очистка должна пройти.
Готовые orphan-кандидаты после ошибки/остановки не продвигаются сканированием.

Read_backup возвращает байты только последней committed-копии после проверки
длины/SHA-256/контейнера и свежих прав. Её можно сохранить файлом или выбрать
для нового обратного восстановления тем же API. Каждый новый restore делает
новый страховочный снимок, заменяя последний только после успеха. Ежедневная
ротация не участвует. Pause/resume используют ту же sync_spaces и revision,
что прежний sync.pause; restart, чтение, выбор устройства и replay паузу не снимают.

Power-loss, долговечность каталога Windows и произвольный файловый провайдер
не выводятся из успешного process/restart-теста. Поддержка произвольной папки,
каталог, новая установка без текущего состояния и аварийный откат всей базы —
отдельные P07.05/P07.06/P07.09. Этот API не восстанавливает отсутствующее пространство.
