## Рабочая карточка

- Цель: удалить колонку со всеми её активными карточками одним действием и восстановить только участников этой группы.
- Требования: T07/A06/A07/A15/A55, раздел 1.2 спецификации, ADR-0007/0008/0014.
- Зависимости: P04.05/EV-069, P04.06/EV-070, P04.08/EV-073 интегрированы в базе.
- Охват: общий Rust core/storage, прежние column.read/list/trash/restore через HTTP/CLI/IPC, производные контракта, тесты и документация.
- Проверки: состав до действия; прежняя корзина и другая колонка; единый group ID; stale по данным/тегам/положению/составу, ABA, конфликт без частичного действия; pending history, SQL rollback, неизвестный commit/replay, права/отзыв/restart; полный product-check Windows/Android.
- Обратимость: восстановление колонки возвращает только объекты, удалённые тем же действием; прежние отдельные удаления сохраняются. Текст/теги/выполнение/порядок/история не теряются.
- Размер: неделимая пара действий с одной транзакцией и общим preview/контрактом; превышение 300 строк ожидается из-за матрицы отказов и адаптеров. Генерируемые артефакты учитываются отдельно.
- Исключено: UI P05.08, пространство и восстановление карточки в другую колонку P04.09.2, окончательная очистка P04.09.3, очистка истории P04.09.4, продуктовый обмен P06, физический arm64 и выпуск.
- Результат: общий API и полные product-check Windows/Linux/Android passed; PR #73/head 7b81c45 интегрирован в 0f42d1f после семи SUCCESS.
- Далее: готовый P04.09.2; новая реализация не начата.

Сырые логи и сведения машины хранятся только в игнорируемой `docs/reports/`.

## Реализация и проверка

[ADR-0050](../../architecture/decisions/0050-column-trash-groups.md): прежние
column.read/list возвращают contents, а trash/restore работают с одной
группой. Core до изменений проверяет весь состав и expected. Колонка и активные
карточки получают общий ID группы; восстановление не меняет прежнюю корзину.
Новые таблицы/формат графа/DDL/зависимости не вводятся. Старые базы разработки
не мигрируют/не сбрасываются по ADR-0047. Данные установок не менялись.

Полные команды `bun scripts/check-product.mjs` Windows и
`bun scripts/check-product.mjs --android` passed:

- По 253 Rust-теста: 17 core, 7 contract, 24 adapters, 205 storage.
- Windows fmt/Clippy/release и 7 unsafe guard passed; обе Android release ABI
  и 14 unsafe guard passed, экспорт контракта Android совпал с Windows.
- 22 клиентских теста / 217 assertions, TypeScript и Rust-derived
  OpenAPI/типы/standalone validator passed.
- Отдельно `cargo test --manifest-path ui/src-tauri/Cargo.toml --locked --offline`:
  все 3 shell integration tests passed. Vue types под установленным Node 26.8.1
  и `bun run ui:build` passed; baseline Node остаётся 24.22.1, это ограничение
  локального инструмента, не проверка baseline CI.

Android x86_64 выполнен нативно на эмуляторе, открытом штатным Device.
Runner удалил свой изолированный sandbox; эмулятор выключен через Device,
вернув исходное состояние. UI приложения не изменялся и групповой UI не проверен.
Физический arm64/release APK и продуктовый обмен не проверялись.

Проверены:

- Общая группа/обратное восстановление, прежняя корзина, сохранение текста,
  выполнения/тегов/порядка/истории, изоляция другой колонки, новый ID группы
  после нового удаления; restart и оба старых повтора не меняют новое состояние.
- Stale по title/description/completed/position/column/tags/lifecycle, имени/
  положению колонки и имени назначенного тега; causal return имени тега не
  оживляет expected. Изменение тега после удаления отклоняет старое restore.
- Все прежние варианты конфликтов карточки также отклоняют групповое удаление;
  конфликт текста либо удаления тега против назначения отклоняет групповое
  восстановление без изменения остальных членов. Конфликт только имени тега
  сам по себе не превращается в конфликт карточки по принятому ADR-0046.
- Чтение, техническая история, peer progress и данные другой колонки без
  прежних связей сохраняют version. Состав и данные preview получены вместе.
- Отказы AfterWork/AfterChanges/BeforeCommit для обоих направлений;
  реальный SQL-отказ внутри группы после изменения другого члена и при записи
  receipt; откат включает pending history и session. AfterCommit даёт unknown,
  точный повтор возвращает committed группу без второй версии. Прежняя session
  после удаления/восстановления не позволяет продолжить старое autosave.
- Два независимых workers сериализуют edit против trash: одна команда
  выполняется, другая получает stale; текст не теряется. HTTP/CLI/IPC дают
  одинаковый stale/preview/группу/replay/restart; read-only и отозванный ключ
  не обходят прежний guard/receipts. Прежняя матрица прав/expiry сохранена.

Предварительный прогон выявил устаревшее ожидание запрета непустой колонки и
ошибку новой fixture: конфликт имени тега не является конфликтом карточки.
Тесты приведены к действующему договору без изменения семантики тегов;
проверяется конфликт удаления против назначения. Открытых BUG/GAP не добавлено.
