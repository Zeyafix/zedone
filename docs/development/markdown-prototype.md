# Markdown P01.07

Срез показывает ответ существующего Rust echo через общий компонент
`client/MarkdownView.ts`. Источник — точный текст HTTP/IPC, а не HTML или состояние
загрузки. Продуктовые операции сохранения/чтения карточек остаются в P04/P05.
Пользовательский сценарий: [просмотр](../user/prototype-markdown.md).

## Конфигурация

Закреплены markdown-it **15.0.3**, DOMPurify **3.4.17**, JS/Rust Tauri Opener
**2.7.2**. markdown-it поставляет собственные TypeScript-декларации;
дополнительный `@types/markdown-it` не нужен. Lock-файлы фиксируют транзитивные
зависимости. Общие Rust/Bun/Node/JDK/NDK не меняются.

`client/markdown.ts` использует пресет `commonmark` и явный `html: false`.
Основание профиля — CommonMark **0.31.2**, заявленный markdown-it
([история версий](https://github.com/markdown-it/markdown-it/blob/15.0.3/CHANGELOG.md)).
Нет расширений таблиц/чекбоксов, linkify, typographer и подсветки кода.
Ограничение вложенности остаётся стандартным для пресета (20).

До передачи HTML на очистку image renderer заменяет каждое изображение инертным
`span` с внутренним индексом. Адрес хранится отдельно от HTML. DOMPurify работает
с HTML-профилем, дополнительно запрещены `img`, `src`, `srcset`, `style`;
возвращается очищенный DOM fragment. Контролируемый код строит Vue-узлы из него,
добавляет обработчики ссылок и `RemoteImage.vue`; исходный HTML не вставляется
через `v-html`. Кнопки изображения не вкладываются в ссылку даже для `[![...]](...)`.

Только абсолютные HTTP/HTTPS-адреса активны в этом срезе. Неподдерживаемые адреса
не исполняются; это ограничение прототипа, а не новая продуктовая политика URI.
`img` с `referrerpolicy="no-referrer"` появляется после отдельного нажатия.
Скрытие удаляет узел, повтор создаёт новую попытку, новый ответ echo пересоздаёт
просмотр и сбрасывает согласие на загрузку. Кеш браузера не отключается.
Событие `error` изображения не раскрывает точную сетевую причину, поэтому UI
сообщает возможные причины и предлагает повтор без изменения текста.

Браузер ПК использует `target="_blank"`, `rel="noopener noreferrer"`.
На Android нажатие вызывает `openUrl`, а автоматический JS-обработчик Opener
отключён во избежание двойного открытия. Локальная capability только для окна
`main` разрешает `opener:allow-open-url` с `http://*`/`https://*`, без файлов,
remote-origin capabilities и остальных команд плагина. CSP допускает HTTP/HTTPS
в `img-src`; `connect-src`, запрет скриптов/объектов и остальные границы сохранены.
Само разрешение CSP не инициирует загрузку.

## Проверка

После `cargo fetch --locked` и `bun install --frozen-lockfile` в `prototypes/`:

```powershell
bun run check
bun run check:http
bun run android:build
bun run android:build aarch64
bun run check:android
```

Для `check:android` нужны подготовленные переменные и запущенный тестовый AOSP
API 33 AVD по [Android-инструкции](android-prototype.md). Chrome/Opera выбираются
существующей переменной `PROTOTYPE_BROWSER_PATH`, без пользовательских профилей.

Общий `scripts/markdown-scenarios.mjs` проверяет production bundle и установленный
WebView: синтаксис/Unicode/буквальный HTML/XSS, точность исходника, ноль запросов
до нажатия, одну загрузку, скрытие, отключённую через CDP сеть и повтор,
редактирование при ошибке, сброс согласия и очистку. PNG-ответы — локальные
перехваченные фикстуры; внешние сервисы для изображений не нужны.
На ПК проверяется отдельная вкладка без opener; Android проверяет реальный
ACTION_VIEW и активность отдельного браузера, исходный URL WebView, отказ
недопустимым URI на native-границе, ошибку bridge и повтор открытия.

Доказательства и ограничения: [EV-020](../agent/verification/EV-020-markdown.md).
Обратное действие — очистка/скрытие; данные echo не записываются. Изменения прав,
история, конфликт поля текста, выполнение карточки и полная A50-приёмка сюда
не входят. Производительность A62 этим шагом не измеряется.
