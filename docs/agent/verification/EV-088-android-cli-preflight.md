  Прежнее поведение сохраняется в базе Git.
- Отказ: mismatch по-прежнему останавливает проверку, ни версия, ни диапазон
  разрешённых значений не расширяются.
- Результат: первоначальные product-native/product-arm64/prototype-native
  jobs, а также prototype-ui PR #87 остановились на одинаковом
  `Unexpected Android CLI version` до runtime-наборов. В прежнем PR #86

- Далее: прочитать ожидаемое/фактическое значение нового CI, исправить
  доказанную причину отдельной правкой, затем получить все 17 SUCCESS/readiness.

## Установленная причина и исправление

Все четыре названные jobs c975d0f получили 1.1.16919734 вместо требуемой
1.1.16717390 из ожидаемого SDK-пути. Архив с прежним проверенным SHA-256
содержит ELF launcher: его строки включают загрузку
`https://dl.google.com/android/cli/latest/…/android-cli` и установку в
пользовательский tool cache. Прежний pin закреплял launcher, а не CLI,
поэтому новая upstream latest-версия меняла результат чистого runner.

Workflow до первой SDK-команды загружает настоящий исполняемый файл из
`https://dl.google.com/android/cli/1.1.16717390/linux_x86_64/android-cli`,
проверяет новый `android.linux_cli_sha256`, заменяет только launcher в
одноразовом SDK и немедленно проверяет прежнюю требуемую версию. Затем
работают все прежние SDK install/preflight/runtime проверки. `latest`
и кеш launcher больше не определяют используемую версию. Имеющиеся
версия CLI, архивы/хэши SDK/эмулятора и budgets не меняются.

Две независимые HTTPS-загрузки побайтово совпали. Локально исполнен
настоящий блок workflow с подставным сетевым источником: успешная
проверенная версия устанавливается; download/hash/version failure
останавливают setup; неподтверждённые байты не исполняются и не заменяют
исходный launcher. Actionlint всего Android workflow с ShellCheck,
ShellCheck preflight и оба routing guards passed. Windows не исполняет
Linux ELF: окончательная проверка настоящей версии и runtime остаётся
за новым Android CI. GAP-024 не закрывается до этого подтверждения.

Опубликовано в PR #87/head cbf90ec; новый CI pending. Требуется весь набор
18 SUCCESS, включая штатную дополнительную Windows environment проверку
из-за изменения pin metadata. Body/медиа прочитаны обратно; LOG-488.
Реальная приёмка Linux runner ещё ожидается, прежние локальные границы сохранены.

## Первый запуск на чистом runner

Head cbf90ec во всех шести Android jobs прошёл SHA-256 настоящего pinned CLI,
но остановился на первом точном сравнении `--version`: исполняемый файл сначала
печатает `Unpacking embedded installation…`, условия/метрики и затем версию.
Этот установочный вывод попал в command substitution; дрейфа версии в этом
отказе не установлено. Сначала workflow отдельно выполняет успешный вызов
`--no-metrics --version`, затем вторым вызовом сохраняет прежнее точное сравнение.
Ненулевой исход инициализации немедленно останавливает setup; повторов после
отказа, фильтрации строки версии или расширения разрешённых значений нет.

Реальный workflow block локально прошёл valid/first-run/download-failure/
corrupt/wrong-version/execution-failure probes. Первый запуск с баннером
допускается только после успешной инициализации и точного второго результата;
ошибка исполнения сохраняет исходный код 19, download failure — 23.
Непроверенные байты не исполняются и не заменяют launcher. Actionlint/ShellCheck
и оба routing guards passed. Настоящий Linux ELF и весь Android runtime
ожидают новый CI; GAP-024 остаётся открытым. LOG-489.

Исправление первого запуска опубликовано в PR #87/head 19a5a3f; все 14
runtime suites и Windows environment IN_PROGRESS, aggregates ожидаются.
Требуются все 18 SUCCESS/readiness; body/две картинки проверены. LOG-490.

Повторное уведомление об Android failures относится к cbf90ec. Все шесть
сырых логов подтверждают прежний first-run вывод после успешного SHA-256;
aggregate job 132347491400 строго отказал с `RESULT: failure` дочерней matrix.
На текущем 19a5a3f GitHub jobs API показывает completed/success шага
`Install pinned Android tools in an isolated SDK` во всех шести Android jobs:
